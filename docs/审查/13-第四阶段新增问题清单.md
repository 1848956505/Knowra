# 第四阶段新增问题清单

基线 B4，2026-09-06。以下 3 项均已在 local-json 真实 HTTP 与 V4 浏览器复现，均为 P2；尚未修复。第三阶段问题证据升级见 [11 报告](11-第四阶段审查报告.md)，不重复编号。

## S4-01：文本搜索丢弃当前多标签条件

- 定位：[search-service.js](../../apps/api/src/modules/knowledge/application/search-service.js) 第 7～23 行；[useNotesIndexData.ts](../../apps/web-v4/src/features/notes/useNotesIndexData.ts) 第 31～43 行。PostgreSQL async 搜索服务有相同字段遗漏，但未做实库验证。
- 触发：准备 A/B 两篇均命中文本的笔记，只给 A 添加筛选标签。在资料页先按该标签筛选，再输入共同关键词。
- 预期：继续只返回 A。实际：加入搜索词后 A/B 同时出现；HTTP H11 和浏览器 B04 均确认。
- 原因：前端发送 `tagIds`/`tagMatch`，普通查询支持；搜索服务只解构并转发旧的 `tagId`，丢失新参数。标签仍在界面中表现为选中，结果已放宽。
- 影响：带文本的服务端搜索不满足标签组合语义；不能外推所有本地筛选入口均受影响。关联 F-02、查询契约一致性目标。
- 建议：统一列表与搜索的筛选对象，双驱动同时接入多标签参数。验收覆盖 all/any、单标签、空搜索、组合收藏/回收站与分页，确保筛选总数与展示一致。
- 证据：H11/B04，见 [最终汇总](证据/阶段4/最终流程汇总.json)；[搜索后截图](证据/阶段4/B04-搜索后混入未标记笔记.png)。

## S4-02：新空间未同步建立系统标签分组

- 定位：[knowledge-space-service.js](../../apps/api/src/modules/knowledge/application/knowledge-space-service.js) 第 7～18 行；[local-data-relations.js](../../apps/api/src/infrastructure/local-data-relations.js) 第 133 行起的分组补齐逻辑。
- 触发：空 local-json 存储启动后创建默认空间，不重启服务，打开新建标签并输入名称。
- 预期：首次使用就具备普通标签等 4 个系统分组，可创建标签。实际：HTTP 查询分组为 0；浏览器新建标签按钮禁用。重启相同 fixture 后分组变为 4。
- 原因：建空间服务只保存空间；系统分组由已有快照升级路径按空间补齐，未随新空间建立。常驻老数据和测试前重启会掩盖该缺口。
- 影响：全新安装或新 owner 的首次标签流程不可用。只确认本地驱动，不推断 PostgreSQL 初始化表现。关联 F-08/F-03、首次使用和恢复一致性目标。
- 建议：在创建空间的业务单元中幂等创建系统分组；保留旧快照升级，但不依赖重启完成初始化。验收空存储、重复默认空间请求、持久化失败及重启后不重复建组。
- 证据：H12/B08；[首次使用截图](证据/阶段4/B08-新空间不能快速创建标签.png)。

## S4-03：批量 Markdown 导入报错后隐藏部分成功

- 定位：[note-service.js](../../apps/api/src/modules/knowledge/application/note-service.js) 第 104～112 行；[workspaceSlice.ts](../../apps/web-v4/src/store/slices/workspaceSlice.ts) 第 71 行起。
- 触发：在导入对话框选择两篇 Markdown，第一篇合法，第二篇含被拒绝的 HTTP 图片地址，点击“导入 2 篇”。另有 HTTP 场景以第二篇同级重名触发失败。
- 预期：失败的批次整体回滚，或明确返回并展示逐项成功/失败和安全重试方式。实际：接口返回 422，界面保留导入失败提示，没有报告首篇成功；首篇已落盘且重启后仍在，第二篇不存在。
- 原因：本地批量服务用 `items.map(importMarkdown)` 逐项保存，无覆盖整批的事务；前端只在完整成功后加载最新数据。安全 URL 拒绝本身正确，问题是前项提交与整体错误语义不一致。
- 影响：用户无法从失败提示判断哪些内容已导入，重试可能再遇重名或重复导入。没有证据表明已有笔记被删除，因此定 P2。关联 F-04、数据完整性与可恢复性目标。
- 建议：明确批次语义。当前单一成功/失败契约宜采用整批校验和事务；若需要部分成功，则 API 返回逐项结果并让 UI 显示/刷新及仅重试失败项。涉及文件时需保留补偿路径。
- PostgreSQL async 实现使用 Promise.all 逐项调用，也需专项检查事务边界；本报告不把代码相似性当成实库复现。
- 验收：第二项格式/引用/重名错误、磁盘中断、重试及应用重启；断言 HTTP、页面列表、笔记版本和附件一致。
- 证据：H13/B10；[导入错误截图](证据/阶段4/B10-导入失败但首篇已落盘.png)只证明页面错误，首篇落盘和重启结论由 [浏览器结构化结果](证据/阶段4/浏览器批量导入结果.json)及脚本中的读取断言证明。
