# 知识离线同步与 AI 接入准备

本轮按用户远程操作的限制，使用隔离临时资料库、真实 HTTP、真实页面和打包应用自动化完成验证，不要求用户手动验收，不向正式资料库写入测试知识。

## 交付范围

1. 发布此前保存、备份恢复、目录管理和知识审核修复；服务器先从 2.20.1 更新到已独立验收的 2.23.0，再发布包含本轮能力的 2.24.0。
2. 桌面开放知识候选创建、编辑、确认、归档及恢复，知识、来源证据、笔记版本及标注依赖作为关联事务同步。同步结果刷新知识界面，但不修改正在编辑的内容和原始并发基线。
3. 补齐知识表单持久恢复草稿：保留候选 ID、标注修订、笔记版本和编辑时间基线；按资料集隔离，纳入备份，成功保存或明确放弃才清理。清理草稿失败后重试不会重复提交已成功的 API 写入。
4. 增加与模型供应商无关的 AI 提炼输入输出契约及测试，不读取密钥、不调用模型，现有 `ai.available=false` 保持不变。

## 同步与保存约束

- 云端通过 `knowledge-items-v1` 声明支持能力。旧云端继续同步笔记；知识留在本机待传，并显示升级提示。
- 来源证据内容不可通过同步改写；服务端根据来源现状重算健康，非手动知识只有有效来源才可确认。
- 双方修改同一知识时保留完整恢复记录并展示字段对照。含知识的关联冲突只允许采用本地或云端，不提供仅合并正文的“保留两篇”。
- 相同正文在两端产生不同版本 ID 时，来源引用映射到云端版本，防止知识永久卡在待传队列。
- 旧 JSON/SQLite 中“摘录已变、知识仍确认”的记录在升级时安全转为待修订，原始摘录保留；修复原子进入同步日志，再次启动不重复产生修订。非法导入依旧拒绝。
- 来源在云端永久删除后，冲突选择云端须以最新删除记录为准，不得用旧基线恢复已删除笔记。本机未采用知识仍留在冲突恢复记录中。
- 编辑提交丢失响应且应用已重启时，恢复表单仍使用旧基线，可能提示冲突；此时先核对已保存内容，也可导出草稿。不会擅自更新基线并覆盖新内容。

## AI 准备与下一阶段边界

`knowledge-extraction-contract.js` 使用已保存的分析范围与不可变笔记版本形成稳定请求，限制输入/输出大小、候选数量和字段；输出引文必须逐字匹配范围且满足 UTF-16 边界，模型不能指定来源记录或确认状态。通过校验仅表示引用位置有效，不能证明陈述语义正确。

后续真实接入仍需提供商配置、凭据管理、持久化任务、超时取消、重试、预算与批量原子入库。提炼结果必须进入候选审核流程。实现与验收说明见 [AI 知识提炼接入契约与验收](../知识库与试题模块/基础/AI知识提炼接入契约与验收.md)。
