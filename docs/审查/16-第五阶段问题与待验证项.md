## S5-01：请求超限变为断连或代理 500（P2，已证实）

- 定位：[request.js](../../apps/api/src/http/request.js) 第 19～25 行；[api-proxy.mjs](../../apps/web-v4/server/api-proxy.mjs) 第 1～14 行；[app.mjs](../../apps/web-v4/server/app.mjs) 的 catch 分支。
- 触发：真实 POST 发送 8,388,626 字节 JSON，略大于 8 MiB 默认上限。大正文、批量导入或带附件的整库导入都可能达到该边界。
- 预期：可识别的 413/PAYLOAD_TOO_LARGE，并让客户端显示准确大小限制；不写入数据。
- 实际：直连 API 得到 ECONNRESET；经本项目生产代理得到 HTTP 500、正文 `fetch failed`。之后 health 仍 200，未观察到进程崩溃或成功写入。
- 原因：parseBody reject 后立即 request.destroy()，服务端错误响应没有送达；生产代理将网络失败映射为通用 500，且先全量缓冲请求。
- 影响：错误契约与可恢复操作体验失效。有限请求证明了断连，不据此宣称无限内存攻击已复现。关联 N-17、Q-01/Q-04 和 F-06。
- 建议：在受控大小边界返回 413，处理后续输入与连接生命周期；生产代理设置对应限额并保留可识别错误。验收上限前/后字节、Content-Length 与流式传输、直连/生产代理、连接复用和客户端提示。
- 证据：[安全恢复并发结果](证据/阶段5/安全恢复并发结果.json) S02；脚本 `security-recovery.mjs`。

## S5-02：备用替换中断后启动静默创建空库（P1，已证实的故障注入路径）

- 定位：[atomic-json-file.js](../../apps/api/src/infrastructure/atomic-json-file.js) 第 63～85 行；[file-data-store.js](../../apps/api/src/infrastructure/file-data-store.js) 第 26～37 行。
- 触发：首次 rename 报 EPERM，进入保留备份的备用替换；旧主文件移到 `.bak` 后、新临时文件替换前，进程被强制终止。
- 预期：下一次启动识别未完成替换，恢复完整文件或显式进入恢复流程，不将已有数据视为全新安装。
- 实际：`.bak` 与 `.tmp` 均保留，主文件不存在；createFileDataStore 按“文件不存在”新建空库。原空间不再出现在工作状态，旧数据仍在备份中，需要人工处理。
- 验证：macOS 上通过原函数提供的 fileSystem 适配器注入 EPERM，执行实际 rename，在子进程内 SIGKILL，再用原 store 启动。正常 rename 前/后两组对照分别保留旧状态/新状态。该证据确认恢复算法缺口；未在 Windows 文件系统实测错误触发概率，也不等于掉电测试。
- 影响：只在备用分支与特定崩溃窗口发生，但重启静默表现为空库，违反恢复目标。备份可人工找回，因此不要描述成磁盘旧数据已永久擦除。与 S3-01 普通业务失败部分提交不同源。
- 建议：启动时识别未完成替换痕迹，校验候选文件后恢复或明确拒绝启动并说明恢复路径；不能无条件选择可能过期的备份覆盖已存在的新主文件。验收中断各时点、主文件有/无、多个备份、坏备份、恢复再次失败及真实 Windows。
- 证据：[进程中断恢复结果](证据/阶段5/进程中断恢复结果.json)，`atomic-crash.mjs` 与子进程脚本。

## S5-03：4 项编辑器 E2E 未跟随实现更新（P2，已证实）

- 定位：[v4-07-editor.spec.ts](../../apps/web-v4/e2e/v4-07-editor.spec.ts) 第 418、541、766、882 行，以及第 980 行附近 mock 路由。
- 两项图片断言：仍要求图片菜单禁用或名为“图片（待附件适配）”；当前 [EditorFormatMenu.tsx](../../apps/web-v4/src/features/editor/EditorFormatMenu.tsx)、[EditorContextMenu.tsx](../../apps/web-v4/src/features/editor/EditorContextMenu.tsx) 已提供可用图片上传，相关单元测试和第四阶段实际上传也通过。
- 两项检查器/长文断言：页面 [NoteEditorView.tsx](../../apps/web-v4/src/features/editor/NoteEditorView.tsx) 第 275～287 行加载真实关联 API；原 mock 没有处理 `/notes/note-1/links`，返回默认空数组，使要点击的关联笔记消失。初始本地关系短暂可见不能证明异步接口已模拟。
- 实际：完整 48 项运行中这 4 项失败；审查目录副本只更新图片断言并补上关联返回后，4 项全部通过。副本用于归因，未修改原测试，也不计入原完整套件通过数。
- 影响：完整浏览器回归持续报错，长文恢复和切换保存的后续断言无法完成；属于测试有效性问题，不将其误报为 4 个产品交互故障。关联 N-29、Q-08。
- 建议：同步原测试、接口契约 fixture 和当前实现；保留图片上传/关联数据的真实 API 集成样本。修正后重跑原完整套件，不只关闭失败断言。
- 证据：`e2e-result.json`、`diagnostic-result.json`、[诊断日志](证据/阶段5/diagnostic.log)及 `diagnostic-e2e/editor-diagnostic.spec.ts`。另一个表格首次失败单独记录为不稳定结果，不并入这 4 项。
