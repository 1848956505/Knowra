## 4. 验证入口与执行顺序

下表来自本次实际读取的根/workspace `package.json` 和测试配置；所有命令尚未执行。先审 runner、fixture 与存储配置，确保不触及真实数据后，再运行行为验证。

| 命令 | 已确认的配置组成 | 执行注意 |
| --- | --- | --- |
| `npm run check:web:v4` | V4 typecheck → boundaries → test；含 web-core 预构建 | 已包含 V4 Vitest 和服务器 node:test，不再同基线重复 `test:web` |
| `npm run build:web` | web-core 预构建 → V4 tsc → Vite build | 与 typecheck 有重叠，但生产构建产物需独立验证；写入 dist |
| `npm run test:api` | `node apps/api/test/run-tests.js` | 必须核验注册与执行数，不能直接 import 测试文件代替运行 |
| `npm run test:web-core` | web-core Vitest | 核验共用契约及 workspace 行为 |
| `npm run test:web:legacy` | web-core 预构建 → V3 自定义 runner | 回归源码契约，不启动 V3 产品 |
| `npm run test:scripts` | `node --test scripts/test/*.test.js` | 先确认部署/迁移测试使用隔离 fixture |
| `npm run test:e2e -w @study-accelerator/web-v4` | `playwright test`，Chromium 项目 | 显式提供隔离运行服务实际 `V4_BASE_URL`；现有配置没有自动 webServer 字段 |
| `npm run prisma:validate` | Prisma schema 校验 | 先检查本地 CLI 可用性；不据校验通过推断真实迁移可用 |
| `npm run prisma:generate` | Prisma 客户端生成 | 在隔离验证环境按需执行；是生成动作，不是数据库集成测试 |
| `npm run prisma:migrate:deploy` | 应用数据库迁移 | 仅隔离数据库；先确认连接目标与数据可丢弃，绝不使用生产连接 |
| `npm run audit:prod` | npm audit，排除 dev/optional，high 门槛 | 只是当前生产门禁；全面审查另外检查开发、构建、PostgreSQL 依赖的适用风险 |
| `npm run check:attachments` / `npm run migrate:postgres` | 附件检查、JSON→PostgreSQL 工具入口 | 参数与副作用尚未审查，不能直接按默认路径运行；先读脚本并指向隔离数据 |

建议第五阶段组合：`check:web:v4` + `build:web` + `test:api` + `test:web-core` + `test:web:legacy` + `test:scripts`，再补 E2E、数据库、安全和性能专项。`npm test` 已包含五套测试，若选择它作为统一入口，则不要再把上述同一批单套测试重复运行。失败修正、基线变化或新增风险时可针对性重跑。

配置中发现现有 E2E 默认 URL 为固定端口，实际执行必须由运行时发现的隔离端口覆盖；这里登记的是执行前提，不把默认值直接判为缺陷。
