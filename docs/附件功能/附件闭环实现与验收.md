## 用户流程与保留边界

附件面板支持上传、插入、重命名、图片受控预览、下载、核验、原文件恢复及删除依赖检查。`ready` 可正常打开和插入；`missing` / `corrupt` 提示异常并提供核验和原文件恢复；`pending` / `failed` 提示未完成；未知状态不视为可用。没有可信原 SHA-256 的记录可核验但不能覆盖原 ID，需重新上传成新附件。

恢复严格比较可信原 SHA-256 和原大小，不更换 ID、不改写正文链接或历史证据。新上传上限 5 MiB，恢复兼容既有同步附件的 6 MiB；恢复接口及 V4 生产代理的该路由 JSON 请求单独限制为 9 MiB，其他路由保持既有上限；生产代理已验证 6 MiB 原文件的 Base64 加 JSON 包装可完整转发。错误原文件、超限和并发身份变化均失败。

删除先打开权威预检；加载失败、只读、有引用时不能确认。执行前等待正文保存，并检查最新草稿；服务端在可靠提交边界重新扫描依赖。移除当前正文链接后，历史版本仍可能阻止删除，不自动清理历史记录。

桌面删除返回 `retained-local` 并保留本机文件。本轮未增加附件回收站、本机副本物理清理、全端内容清除、图片编辑或表格增强。

## HTTP 与共享客户端契约

成功为 `{ data: ... }`，失败为 `{ error: { code, message } }`。内容响应保留安全 MIME、Content-Disposition 和 nosniff 规则。

| 接口 | 返回/约束 |
| --- | --- |
| `GET /api/storage/attachments/:id/deletion-preflight` | `asset`、`decision`、`references`、`coverage`；引用增加名称、可用 noteId 与 knowledgeItemId；可打开活动笔记及知识，历史对象保留只读说明。 |
| `POST /api/storage/attachments/:id/verify` | 实际核验后的原附件记录；文件缺失/损坏返回对应状态。读取/持久化操作失败返回错误。 |
| `POST /api/storage/attachments/:id/restore` | 请求 `{ contentBase64 }`；成功返回同 ID 原附件记录。 |
| `GET /api/storage/attachments/cleanup` | `{ items, pending }`，仅已提交删除且未完成的任务；不暴露磁盘路径。 |
| `POST /api/storage/attachments/cleanup/retry` | `{ completed, pending }`；元数据尚存在的删除意图保留且跳过，不计入已提交删除的待清理数量。 |
| `DELETE /api/storage/attachments/:id` | 原附件字段与 `cleanup`：`complete` / `pending-retry` / `retained-local`。 |

`complete` 只代表当前实例的受管理文件清理成功；`pending-retry` 表示记录已删除，清理任务可在重启后查询/重试；`retained-local` 表示桌面本机副本按既有策略保留。共享客户端保留删除结果，不转换成 void。

主要错误：`ATTACHMENT_RESTORE_MISMATCH`（原文件不匹配，422）、`ATTACHMENT_RESTORE_UNVERIFIABLE`（缺可信原哈希，422）、`ATTACHMENT_TOO_LARGE`（超限，413）、`ATTACHMENT_CHANGED`（准备后身份变化，409）、`ATTACHMENT_REFERENCED`（保留引用，409）。已删除 ID 的新恢复请求返回不存在，不复活记录。

## 引用、状态与故障恢复

`packages/shared/src/attachments.js` 按真实 `/api/storage/attachments/:id/content` 路径识别，ID 单次解码；百分号编码不能漏检，hash 的 `attachment=` 不覆盖路径 ID，异常编码不抛异常。同时递归扫描结构化 attachmentId、附件 sourceType/sourceId 以及持久化文本。

JSON、SQLite 和 PostgreSQL 预检覆盖当前/其他笔记、回收站、版本、标注修订、分析范围和知识/题目来源等持久业务集合。备份、离线设备和运行任务明确为 unverified。桌面运行层改用同一全量依赖规则。

内容读取定位后又消失时记录 missing；大小/哈希异常记录 corrupt 并清空有效核验时间。显式核验绕开旧 corrupt 状态，正确原文件回到 ready。可信原哈希和大小不得被异常文件的实测值覆盖；健康读取不反复刷新 verifiedAt。

恢复先在受管理上传目录创建临时文件、原副本备份和恢复意图，再原子替换文件、提交元数据、清理临时材料。写文件或提交元数据失败回滚，不能安全回滚的材料保留；启动恢复只继续身份、可信原哈希和大小仍匹配的操作，删除/改名后不复活或覆盖新路径。PostgreSQL 文件 IO 在数据库事务外执行，元数据事务内再次核对身份。清理先落意图，业务删除提交后才移除文件，失败保持持久重试任务。

健康状态不作为用户内容差异上传；远端合并同 ID/哈希/大小/文件名时保留本机状态、核验时间和路径。新远端文件沿用现有传输哈希验证后发布可用记录。云端同哈希修复机制继续保留，没有新增定时全量文件扫描。

## V4 与桌面访问

面板与正文链接（含中键点击）通过同一访问层。图片使用 Blob 受控预览，其他文件通过下载。桌面 IPC 只接受附件 ID；主进程验证主窗口/主 frame，向固定本地内容路径发送 APP 当前 Electron 会话和当前资料集，拒绝重定向，限制内容大小，原生另存为并原子保存。资料目录及其符号链接别名不能被另存覆盖；用户主动点击打开后，仅使用主进程生成的临时保存令牌。

切换笔记后，旧附件请求完成不能写入新笔记列表；当前面板按 noteId 重建；上传慢请求切换笔记的组件回归已通过。只读模式禁止核验/恢复/重命名/确认删除等写入，仍可读取预检。删除失败刷新依赖后保留操作错误；删除已提交而清理状态查询失败，不误报删除本身失败。
