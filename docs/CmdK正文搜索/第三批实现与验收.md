# 第三批 Cmd/Ctrl+K 正文搜索实现与验收

本批从 `3811447f5f2243278fa7de823b3d359ff5e7e13c` 的独立工作树开始，模型固定为 GPT-6.1 Sol Max。仅接入当前空间的字面子串正文搜索，版本仍为 `2.27.2`。工程变更日志、结构导航和领域规范由父线程统一维护。

## 用户行为

- Cmd/Ctrl+K 可搜索资料标题与完整正文，包括 240 字工作区摘要之后的中文内容。
- 继续保留本地标题、标签、返回主页、方向键、Enter、清空、关闭和已有资料跳转路径。
- 输入使用 180ms 防抖；查询、空间、打开状态或 IME 组合状态变化时立即隔离旧结果。加载或失败时 Enter 不跳转旧命中。
- 中文 IME 组合期间不发正文请求、不抢 Enter；结束后只请求最终输入，并保护 `keyCode=229` 的确认键。
- 正文服务失败明确显示错误；正常空结果显示无匹配，不将 HTTP 错误降格为空查询成功。
- 有界正文片段换行显示，保证关键词不会被旧单行省略样式截掉；浏览器同时核验桌面与 390px 的关键词可见边界。

## 接口与隔离

沿用 `GET /api/knowledge/search/notes`，增加 `result=command` 投影：`id/title/folderId/snippet`。共享 API 的 `searchCommandNotes` 是可选能力，由 store 绑定当前空间；旧宿主与已有测试 stub 可省略该能力。

命令查询要求非空、最长 200 字符的 `spaceId` 和最长 200 字符的查询。服务端按注入的 owner 读取空间并校验 `space.userId`，拒绝客户端 `ownerId/userId` 覆盖；无空间或跨 owner 返回相应错误。服务端不因客户端声明了一个空间 ID 就信任其访问范围。

结果默认 30 条、最多 30 条；片段含省略号最多 220 个 UTF-16 单元。命令分支忽略回收站筛选并强制排除 deleted，还复核每条 note 的空间。片段定位保留原 `toLowerCase()` 子串语义，并用常量空间映射扩长的大小写偏移回原文本；不切开 emoji 代理对。renderer 的搜索响应不包含 Markdown 或完整 plainText。

同步 JSON/SQLite 和异步 PostgreSQL 服务使用相同投影规则。原 `result=ids` 与全 note 查询保持兼容；笔记索引的 `searchNoteIds` 继续携带 `includeDeleted=true`。未引入新搜索引擎、SQL 迁移、AI 检索或知识训练功能。

## 有效缺口证据

实现前实际运行了注册的定向 API runner 和 UI 测试：

- 原 SearchCommand 的 loading 列表没有 DOM option，Enter 仍调用旧 `onSelect` 一次；专门回归失败。
- 原 JSON/SQLite HTTP 的 `result=command` 返回 rawMarkdown、plainText 等完整 note 字段，窄 DTO 断言失败。
- 原跨 owner 命令请求返回 200；期望 404 的真实 HTTP 断言失败。

第一次 HTTP 测试因沙箱禁止回环 listen 得到 EPERM，不计作业务 red。自动审批随后允许只用临时合成根和 127.0.0.1 随机端口的定向测试，取得上述有效失败，再完成 green。

## 固定 5ad 审查发现的 P2 与修复

独立 Max 审查在 `5ad5626b9db35c5b2bebea8c49a416d74d28413d` 发现：页面摘要载入之后新增的有效服务端笔记可被正文搜索命中，但 Enter 只改变 URL。原 `selectNote` 因本地没有该 ID 而置空；`loadNoteContent` 也因笔记不存在直接返回，页面显示“未找到这篇笔记”。实现线程用原 `CmdK-5ad-Max-remote-opening.test.tsx` 与原配置复跑，实际得到 1/1 业务失败：`notes=[]`、`selectedNoteId=null`、工作区加载一次、`getNote` 零次。

修复增加专用 `loadCommandNote`：未知 ID 先通过已有 API 获取完整详情，严格校验 ID、空间、deleted、标题及 Markdown，使用现有归一化与缓存助手的显式 `insertMissing` 模式加入 store。载入返回对应工作区快照回执；选择前再次核对回执、空间、数据模式、载入状态、代际和笔记身份。已有摘要继续使用编辑路由的 `loadNoteContent`，已载正文、草稿和保存状态保留原路径。

选择请求绑定实际输入、空间、打开/IME 状态、搜索结果和选择序号，不绑定 App 的 inline callback 对象身份。关闭、改输入、换空间、同空间新快照、其他导航或后续选择会隔离旧详情及旧错误。Dialog 在详情载入时保持打开并显示状态，404/详情不符/获取失败显示可重试错误；已有导航 Guard 在选择前生效。

额外回归实际发现并修复“详情完成到选择之间工作区快照被替换”的间隙：补回执检查前测试因仍导航一次而失败，补后通过。有效 red 原始日志为 ignored `dist/command-search-evidence/p2/independent-red.log` 与 `selection-snapshot-red.log`；原独立复现用例未修改断言，最终 1/1 通过，日志为 `independent-final-green.log`。
