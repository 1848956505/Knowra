# App 功能补齐：用户验收清单

本轮目标是让 App 完成现有知识与人工训练资产的操作、持久化和同步；Web 用于测试。先以合成资料验收，部署生产和替换正在使用的 Mac App 另行协调。请以交付回执的准确 main、构建标识和 CI 为版本依据，不能把云端构建当成已安装。

## 安装后的验收顺序

请使用一次性合成笔记与资产。永久清理测试只使用这些合成资产，不能用真实学习资料。

| 验收项 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 构建身份 | 打开 App 核对版本和构建提交 | 与交付回执一致；本轮未自动替换旧 App |
| 知识创建与审阅 | 创建手工知识，编辑陈述，再明确确认；关闭 App 后重新打开 | 修改与审核状态保留；过期版本拒绝保存并保留输入 |
| 知识回收／恢复 | 将知识移入回收站，重启，再明确恢复 | 原件与来源保留；原归档属性保持，失效来源提示待修订；下游目标／题目不会自动重新确认 |
| 来源重新采用 | 撤回一条来源，回收／恢复知识，再重新采用来源并人工核对 | 来源状态准确；需要审阅的知识和下游资产仍需明确确认 |
| 人工学习目标 | 在知识详情或训练工作台创建目标、填写动作／层级／可评测描述，再逐项审阅确认 | 保存候选和确认分开；父知识或目标被另一端修改时保留输入、要求重新核对 |
| 配置与考点 | 新建考试配置，绑定目标创建考点，确认后再修改父目标 | 严格执行新确认门槛；既有考点状态维持现有 Web 规则，不新增自动降级规则 |
| 题目及关联 | 创建／编辑题干、答案、目标关系和来源，关闭并重开 | 题目版本与关系保留；存活关系保持身份，解除后重新关联使用新关系 ID |
| 训练生命周期 | 回收目标／配置／考点／题目，再恢复、核对并重新确认 | 最终状态及明确操作都能同步；后续重新确认不会被临时回收批覆盖 |
| 两设备同步 | App 编辑后同步，在另一测试端回读；另一端修改后再刷新 App | 六训练集合及知识来源一起收敛，实际同步状态与资料一致 |
| 删除与旧编辑冲突 | 测试端删除合成知识／训练资产，离线 App 继续旧编辑再同步 | 显示三份对照；旧编辑不能隐式恢复回收站或已永久删除的 ID；未采用内容保留恢复记录 |
| 联网永久清理 | 完成同步，在回收站对无引用的手工资产预检并确认 | 仅五类手工资产走云端权威清理；收到真实删除事实后才显示确认结果 |
| 引用阻塞 | 给合成知识保留关联目标或其他实际引用，再预检清理 | 显示阻塞原因并可核对引用；不能绕过预检或因 AI 开关关闭而跳过任务历史核查 |
| 离线清理 | 断开云端后尝试预检／执行 | 明确提示连接要求，原件仍在；本地不会先物理删除再上传 |
| 清理期间编辑 | 发起合成资产清理时，在另一测试窗口恢复／编辑该资产 | 云端删除事实与本地新修改分别显示；本地修改保留为冲突／恢复资料，重启后仍可回读 |
| 旧端兼容 | 新 App 连旧测试服务，或旧测试 App 连新服务 | 提示配套更新，原件和未确认请求保留；不能以改写旧请求哈希绕过门禁 |

清理成功只表示当前权威资料集确认删除。离线设备、独立备份和保护备份按各自同步／保留规则处理，不能宣称所有副本已消失。丢响应、游标过期和世代改变的细节由自动化合成验收覆盖，用户界面应保留“结果待核对”，不得假报成功或自动重发清理。

## 本轮仍未覆盖的能力

- 正式 P3 provider、worker、预算准备、产品入口／UI 开放及剩余 AI 元数据同步仍需按冻结 docs 分批实现；本轮不调用真实或付费 AI。
- AI 出题与独立审核、正式组卷快照、作答恢复／交卷、评分与实际得分／覆盖报告属于后续批次，不能用人工题目库补齐冒充完成。
- “同一生成向导内补齐知识／目标审阅”“多选必须完全匹配才得分”“先展示实际得分／覆盖、不判掌握等级”已是确认规则，相关后续实现仍须遵守；60／80 等阈值未采用。
- 复习间隔与每日题量以后确定；不影响本轮已有人工资产操作。
- 前序日常五项已有实现仍需平台／实机验收收尾，包括外盘独立备份、退出合同、真实 AI 外部准备等；本轮不重复宣称这些外部验收已完成。
- Linux 发布包的生成 Prisma 依赖完整性问题另行登记；产物生成不等于部署验收通过。
- 原生 Mac／Windows 实机、生产部署与用户正在使用 App 的替换尚未由本轮云端执行。同步新增必需能力要求 App 与服务配套更新，不支持任意旧二进制共同读写带新私有队列的资料库。

工程与自动化证据见[桌面资产补齐：实施与验收](桌面资产补齐-实施与验收.md)。
