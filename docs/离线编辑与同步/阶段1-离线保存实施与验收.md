# 阶段 1：离线保存实施与验收

> 后续进展：笔记同步与冲突删除处理已在 [阶段 2/3](阶段2与阶段3-同步冲突实施与验收.md) 实施；下文记录阶段 1 交付时点。

> 日期：2026-09-10。本轮完成总方案中的阶段 0 与阶段 1；不包含阶段 2 的云端增量传输，也不包含 Mac 安装包。

## 1. 已实现行为

- 新增独立本地运行服务，监听动态分配的回环端口，提供现有 V4 界面与本地业务 API。
- 应用数据与安装目录分离，默认写入用户应用数据目录，也可通过 `--data-dir` 指定独立资料库。
- 本地正文与业务副作用、修订及待同步队列通过 SQLite 同一事务保存。
- 正常重启与强制终止后恢复已提交内容，提交失败恢复内存与数据库基线，保留编辑器草稿。
- 使用现有笔记编辑器和自动保存接口；输入尚未落盘时显示“保存中”，事务确认后显示“已保存到本机”。
- 数据模式明确显示“本地资料 · 云端同步未启用”，不会将本机提交误报为云端已同步。
- 普通网页仍使用原在线保存与只读缓存保护；本地模式没有通过放开缓存写入实现离线编辑。
- 本地缓存按 datasetId 分隔；持久数据在 SQLite，不依赖 localStorage 或 sessionStorage 恢复。
- 支持 JSON 完整快照迁移至新目录，支持含 SQLite 队列和附件文件的校验备份及恢复。

阶段 1 开放资料基础操作，包括目录、标签和笔记的现有本地事务行为。附件上传、标注写入、知识及训练写入、永久删除和整库在线导入由本地服务拒绝；图片和标注相关编辑入口同步禁用。已迁移附件可以读取、下载，已有标注与历史版本可阅读。后续按原方案阶段 3/4 逐项开放。

## 2. 启动与数据目录

仓库根目录执行：

```bash
npm run build:web
npm run start:desktop
```

打开命令输出的本次启动入口。本轮提供本地运行基础，仍需浏览器窗口；尚未生成 `.app` 或 `.dmg`。

默认数据目录：

| 系统 | 路径 |
| --- | --- |
| macOS | `~/Library/Application Support/Knowra/offline` |
| Windows | `%LOCALAPPDATA%/Knowra/offline` |
| Linux | `$XDG_DATA_HOME/knowra/offline`，未设置时为 `~/.local/share/knowra/offline` |

开发时建议显式指定新的隔离目录：

```bash
npm run start:desktop -- --data-dir /absolute/path/to/knowra-local
```

运行服务不自动读取、上传或覆盖现有云端/仓库资料库。多个窗口使用同一个运行服务；相同资料目录不允许第二个服务实例同时打开。应用异常退出后检查原进程存活状态，恢复过期实例锁；无法确认锁有效性时停止启动。

本地入口只接受本次随机会话，校验 Host、Origin 和跨站请求，凭据通过 HttpOnly、SameSite Cookie 保存。入口 URL 不应分享给其他人。该机制只用于本机服务隔离，不替代云端身份认证。

## 3. 迁移与备份

### 原 JSON 基线导出

默认目录布局下可只读生成完整快照，`--output` 必须是新文件：

```bash
node apps/desktop-runtime/src/export-baseline.mjs --source storage/data/knowledge-base.json --storage-root . --output storage/exports/offline-baseline-new.json
```

### 导入新本地资料库

目标目录必须尚不存在；输入为包含附件文件的 Knowra 整库快照，无附件的旧快照也可以迁移：

```bash
npm run start:desktop -- --data-dir /absolute/path/to/new-local-data --import-json /absolute/path/to/snapshot.json
```

先在临时目录创建数据库和附件，完成领域与附件校验后再发布新目录。任何步骤失败均不覆盖原快照，不把半成品作为可用资料库。导入是独立本地副本，不代表已经与云端建立共同基线。

### 本地备份恢复

已认证本地会话可调用 `POST /api/local-runtime/backup`，返回新备份目录。当前阶段未增加独立备份管理页面；程序接口为 `createRuntimeBackup(store, dataDirectory)`，供后续桌面菜单接入。

备份包含 `local.sqlite`、已有 uploads 和 SHA-256 清单，保留待同步队列。恢复命令：

```bash
npm run start:desktop -- --data-dir /absolute/path/to/new-restored-data --restore-from /absolute/path/to/backup-directory
```

恢复前验证清单和文件字节，拒绝覆盖已有目录。恢复后首次连接云端仍须遵循阶段 2 的数据集绑定规则。

## 4. 模块职责

| 文件 | 职责 |
| --- | --- |
| `apps/desktop-runtime/src/main.mjs` | 本地启动、参数、信号退出与未来桌面进程就绪通知 |
| `runtime-server.mjs` | 回环服务、会话、运行模式注入与业务 API 装配 |
| `runtime-policy.mjs` | 本轮开放操作边界，未知写入口默认拒绝 |
| `data-directory.mjs` | 跨平台资料目录与单实例保护 |
| `sqlite-schema.mjs` | 本地版本初始化，未知/未来版本拒绝降级 |
| `sqlite-data-store.mjs` | 事务、业务实体、修订、持久队列、回滚、备份接口 |
| `local-change-set.mjs` | 领域差异与实体依赖收集，无 HTTP 重放 |
| `snapshot-migration.mjs` / `export-baseline.mjs` | JSON 只读基线导出及新库迁移 |
| `backup.mjs` | 数据库和附件备份、完整性清单及新目录恢复 |
| `apps/web-v4/src/app/runtimeConfig.ts` | 接收受控本地运行配置，隔离缓存键 |
| V4 store、状态栏及编辑器适配 | 本地/云端保存文案分离、未落盘状态、后续阶段入口限制 |

普通业务模块保持小文件分工，没有引入 V3 依赖或将数据库代码放进 React store。

## 6. 交付边界与下一阶段

“已保存”只承诺已提交到本地数据库的内容。尚在输入法、编辑器内存或防抖队列中的按键不属于落盘成功；页面关闭前保留已有未保存提示，本地服务正常退出会等待已经接收的请求完成。桌面窗口的关闭握手在安装包阶段实现，不能据此宣称已经具备原生窗口退出保护。

本地库 schema 1 初始化与旧 JSON 快照迁移已经实现。未来 schema 升级必须先增加迁移和升级前备份，不允许直接修改 `user_version` 绕过检查。

下一步进入阶段 2：云端修订与日志、幂等结果、快照与增量拉取，以及已绑定数据集的正文上传。当前 outbox 没有发送器，不会产生云端副作用；阶段 2 不得把空 baseRevision 或导入快照直接解释为可以覆盖远端。
