# 数据保护复核与知识流程第一步

## 交付范围

前两步沿用并复核 2.22.0 的实际实现：桌面能力提前说明、历史摘要分页/差异/恢复/另存、本机备份检查与恢复、同步冲突可视化。没有降低自动保存频率，也没有删除不可变历史版本。

本轮补上重复恢复后的草稿保留：原备份携带的草稿与当前根目录草稿分别归档，后续备份及救援导出继续保留；同键不同正文不覆盖。完整性检查与草稿导出包含这些归档。

知识流程第一步：

1. 知识库手动创建候选，或编辑器「标注 → 更多操作 → 创建知识候选」。来源创建前完成正文保存并复核范围。
2. 填写标题、核心陈述、个人解释和类型；来源摘录由服务端读取，提交时检查标注版本/修订。
3. 核对详情与来源，人工确认；支持编辑、归档和恢复为候选。修改已确认正文会转为待修订。
4. 来源摘录保留并可打开原笔记；笔记变化导致来源失效时，正式知识重新进入审核状态。

## 保存边界

- 创建候选及证据在同一事务完成。客户端固定候选 ID，相同请求重试可找回已创建结果，避免丢响应后生成重复条目。
- 编辑、确认、归档与恢复携带时间基线；旧页面不得静默覆盖新内容。失败不清空表单。
- 未保存的知识表单关闭需确认；导航/退出保护与笔记自动保存分开，知识操作失败不覆盖正文保存状态。
- 当前知识沿用后端单用户全局资产模型，不宣称空间级隔离。

## 明确保留的限制

- 桌面可查看从云端同步来的知识；知识创建和修改尚不在离线写入同步协议内，UI 与 store 都阻止写入。网页版支持这一轮完整人工流程。
- AI 生成候选、学习目标编辑、试题和学习执行仍属后续工作。本轮没有请求第三方模型。
- 历史快照仍无自动物理淘汰。列表归组不等于释放空间；引用安全清理需要独立方案，避免破坏标注、证据、分析范围、试题及未确认同步记录。
- 不在真实资料库执行恢复、永久删除、冲突覆盖或知识验收写入；页面验收使用临时独立数据。
