# 资产生命周期阶段 4：空间测量、留存决策与验收

> 日期：2026-09-24。依据[资产生命周期规范 v1.0](../Knowra_资产生命周期规范_v1.0.md) §9.4、§10.2～10.4 与[差距与分步实施方案](资产生命周期差距与实施方案.md) §4 阶段 4。本阶段先建立可重复的只读测量并以当前实际数据确定清理优先级。测量本身不授权删除，未启用自动到期清理。

## 1. 交付

- 新增 `npm run measure:assets -- --driver=local-json|sqlite|postgres`。只读统计正文、笔记版本、来源与快照、附件、检索索引、临时任务、同步日志、备份和导出。输出各集合数量、UTF-8 逻辑内容量、文件体积；SQLite 报告表页、空闲页和待同步队列；PostgreSQL 报告关系与索引页占用。结果不包含标题、正文、对象 ID 或数据库连接串。
- 桌面“本机备份与恢复”列表显示每份备份及清单合计大小，明确当前**不会自动到期清理**。旧清单缺少用途字段时显示“历史备份”，不猜测为手动备份；清单异常仍须检查，不冒充真实体积。知识与训练回收站显示“保留至手动清理”，不暗示 30 天后会自动消失。
- JSON、SQLite、PostgreSQL 三种驱动均已运行统计工具。PostgreSQL 使用本次创建并完成全部 10 个迁移的空测试库，只验证统计可运行；**不将空库数字用于实际容量决策**。

示例命令（实际目录可用对应参数替换）：

```bash
npm run measure:assets -- --driver=local-json --storage-root=/path/to/knowra
npm run measure:assets -- --driver=sqlite --source=/path/to/offline/local.sqlite
DATABASE_URL=postgresql://… npm run measure:assets -- --driver=postgres --storage-root=/path/to/knowra
```

可用 `--uploads`、`--temp`、`--exports`、`--backups` 指定受管理目录，`--output` 写入新的 JSON 报告文件。脚本不跟随符号链接；`--output` 拒绝覆盖旧报告。重复运行同一范围，才能比较真实增长。数据库页占用、文件体积与逻辑内容量口径不同，不能相加推断“删除后立即释放”的空间。

## 3. 留存与 GC 决策

1. **优先处理可见性与恢复能力。** 备份约 97 MiB，是本机最大的独立保留范围。本阶段先展示大小和不自动过期的真实状态；下一次设计备份保留配置时，应先给出逐份完整性、待同步修改、恢复草稿和恢复前保护用途，再提供受控手动释放。当前不批量删除任何备份。
2. **版本裁剪先补语义再执行。** 桌面单篇 527 个版本提示值得研究生成频率，但 4.20 MiB 正文小于备份与同步恢复占用。现有阶段 2 预览明确缺少用户保留点元数据；未建模保留点、正式引用与可恢复性之前，不配置自动版本裁剪，也不把旧归档视为到期授权。
3. **同步恢复与墓碑独立保留。** 21 项待同步修改仍未完成；没有设备安全水位、旧端重建基线及导入保护的联合验收。`sync_recovery`、`sync_base`、墓碑和恢复副本均不按固定天数清理。若后续提供显式释放恢复记录，须先支持导出、预检与结果记录。
4. **回收站自动到期清理保持关闭。** 30 天只是规范建议的恢复窗口，不是已启用的删除规则。现阶段没有跨资产任务引用、离线设备及备份边界均安全的自动批量清理证明；手动受控清理仍使用前几阶段的逐项预检。
5. **缓存与临时 GC 暂不引入新写路径。** 当前受管理临时任务目录为空，也未找到独立持久检索索引。没有可确认的高收益、无主派生数据批次。日后出现候选时，再做只读预览、小批量执行、引用复核、失败重试及结果记录；PostgreSQL 不把业务删除绑定 `VACUUM FULL`。

这是一份基于单次容量快照和近 7／30 天版本生成时间的排序，不是长期增长率证明。后续应在相同范围按周重复只读测量，比较备份、版本、恢复记录和待同步队列变化，再讨论自动策略。

## 4. 验收与边界

- `npm run test:scripts`：25 项通过，包含 JSON、SQLite 只读统计、符号链接跳过、备份用途与输出不含内容的测试。
- `npm run test:desktop`：75 项中 71 项通过、4 项需外部 PostgreSQL 变量而跳过；新增测试覆盖旧清单缺少用途仍可检查、列表准确标示为“历史备份”。`npm run check:web:v4`：类型、边界、361 项 Vitest 与 4 项服务器测试通过；`npm run build:web` 成功。
- PostgreSQL 17 隔离测试库执行全部 10 个 migration 后，统计命令只读成功。实际 PostgreSQL 生产资料未测量，不能由本机 JSON／SQLite 体积推断其占用。
- 本阶段没有执行用户资料、版本、备份、同步日志或墓碑的删除；未启用后台定时清理。统计不是磁盘安全擦除证明，也不涵盖用户另存的导出和第三方副本。
