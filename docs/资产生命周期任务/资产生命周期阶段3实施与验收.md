# 资产生命周期阶段 3：训练资产实施与验收

> 日期：2026-09-24。依据[资产生命周期规范 v1.0](../Knowra_资产生命周期规范_v1.0.md) §6、§13 及[差距与分步实施方案](资产生命周期差距与实施方案.md) §4 阶段 3。本报告描述已存在的训练模型和 V4 首批训练管理入口；规范明确属于未来实体的试卷与作答历史另列接入门槛，不把尚未发生的历史独立化说成已验收。

## 1. 已交付范围

| 资产 | 入口与状态 | 清理边界 |
| --- | --- | --- |
| LearningObjective | 训练页可创建、编辑、确认、归档、移入回收站、恢复；回收后不再参加新题目绑定，关联正式题降为候选，来源标为待核。恢复后原归档状态保留，原正式目标回到候选，须重新确认。 | 预检 ExamFocus、QuestionObjective、QuestionSource 和已保存范围引用。任何未处理引用均阻止永久清理。 |
| ExamProfile | 训练页可创建、编辑、归档、回收、恢复。删除配置不连带删除考点或目标。 | 存在任何 ExamFocus，包括已回收但尚未清理的考点，都阻止配置清理；须先处理考点。 |
| ExamFocus | 训练页可创建、编辑、确认、归档、回收、恢复。确认时重新检查配置及目标。 | 当前模型无指向考点的持久下游关系；仍检查已保存范围中的身份引用。清理不删除配置或目标。 |
| Question | 训练页可创建、编辑、校验、确认、归档、回收、恢复。回收后普通题库列表不再使用；恢复前检查关联学习目标是否仍存在，原候选／正式题退回草稿以待重新校验。 | 预检共享历史引用；清理仅删除原题及专属 QuestionObjective、QuestionSource 关系，不影响目标、知识点或来源资产。没有 Exam 模型时不构造虚假的历史快照。 |

四类资产以独立 `deletedAt` 表示回收站，原 `reviewStatus`／`archivedAt` 继续表示审核和归档。普通列表默认隐藏回收站，`includeDeleted=true` 才能管理。删除、恢复和清理均在本地原子事务或 PostgreSQL `Serializable` 事务中执行。清理前预检和执行时复核 `updatedAt`；同毫秒变更也产生递增时间基线。JSON 与 PostgreSQL 保留最小墓碑，重复清理返回 `already-purged`，旧备份及迟到创建不能复用已清理 ID。

V4 试题库已从占位入口接通，提供四类资产列表、使用中／已归档／回收站筛选、创建编辑和生命周期操作。清理对话框列出具体引用及离线设备／备份边界，阻断时不允许确认。桌面本地模式可以查看云端下行训练资产；由于训练集合尚未获得上行 capability，页面禁用写入。网页端可写入。这样不会让本地操作形成无法上传的“已保存”错觉。

API 新增四类资产统一的 `purge-preview`、`trash`、`restore-deleted`、`purge` 动作，并为考点补根列表／创建入口。共享 `WorkspaceApi`、JSON／PostgreSQL 领域服务、Prisma migration 9、V4 页面与本地数据校验同步更新。组织资产的已有归档 `restore` 与回收站恢复 `restore-deleted` 保持两个动作。

## 2. 规范用例与未来实体门槛

| 用例 | 当前结论 |
| --- | --- |
| LC-13 | 草稿题也先回收并预检；题目专属目标和来源关系由同一事务清理，已保存范围引用阻断。当前没有其他草稿或运行任务指向题目的模型，未来新增时必须加入预检。 |
| LC-14 | **未完成历史试卷验收。** 当前没有 Exam／ExamQuestionSnapshot／Attempt 模型，故不能声称“删除题库原题后历史试卷不变”。正式试卷接入前，必须先实现题干、选项、答案、评分规则、分值与附件的独立完整快照，并以历史引用测试后才允许清理已入卷原题。 |
| LC-15 | 删除目标会使关联正式题退出新组卷可用状态，已有题目仍保留；目标永久清理被尚存关系阻断。 |
| LC-16 | 删除配置不隐式删除 Focus；必需的 `examProfileId` 引用保留并阻断配置永久清理，用户可显式分别清理考点。 |
| LC-17～18 | **尚未开始。** Attempt、Response、GradeResult、LearningEvidence、MasteryState 当前均无持久模型或 V4 入口。接入时必须以整次 Attempt 为默认删除单元，暂停／撤回证据贡献，按剩余证据重算掌握度；恢复时复核依赖并避免重复累计，单独撤回的贡献不得复活。 |
| KnowledgeRelation／KnowledgeTopic／ExamBlueprint | 尚无持久模型。关系删除只删除关系、不删除两端；蓝图删除不改历史试卷，均在接入时按规范 §6～7 建模与验收。 |

以上未完成项不开放相应试卷、训练记录、掌握度或蓝图按钮，也不放宽外键来模拟成功。当前题库清理的安全前提是数据库中尚不存在正式试卷／作答历史；将来新增这些表时，须在同一变更中扩展预检并先运行快照迁移与历史测试。

## 3. 验证记录

- `npm run test:api`：285 项通过，新增回收、归档分离、关联降级、配置不级联、预检版本、专属关系清理、JSON 墓碑与 HTTP 契约测试。
- `npx prisma validate`、`npx prisma generate` 和**全新隔离 PostgreSQL 17 临时库**执行 10 个迁移，均成功；阶段 3 真实数据库用例覆盖四类资产、事务清理、重复请求与墓碑。
- `npm run test:desktop`：补充 SQLite 设备云端下行题目回收与清理测试后，在全新隔离 PostgreSQL 测试库中 74 项全部通过。复用旧测试库时曾有 1 项文件夹同步用例受残留数据影响失败，因此最终验收使用新建数据库及全量迁移。训练写入未加入桌面上行集合。
- `npm run test:web-core`：22 项通过，包含训练 API 路径与清理时间基线；`npm run check:web:v4`：类型、边界、360 项 Vitest 及 4 项服务器测试通过；`npm run build:web` 成功。
- Playwright Chromium：阶段 3 训练页 2 项真实页面状态测试通过，验证题目回收、回收站入口、被引清理禁用状态及跳转关联题目。

## 4. 下一接入门槛

正式试卷、题目历史快照、作答与掌握度属于后续训练业务实现。其模型、迁移、API、V4 页面和双端同步必须一次形成规范 §6 的完整删除／恢复语义；尤其不能先建立指向原题的历史外键，再开放题库原题清理。启用桌面训练写入前，须新增训练集合 capability、引用校验、冲突及墓碑回放测试。整机数据库与墓碑同时回滚后的外部删除事实核对仍沿用阶段 2 的灾难恢复限制。
