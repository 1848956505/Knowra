# 资产生命周期阶段 0：语义、引用与安全基线

> 2026-09-23。依据：[资产生命周期规范 v1.0](../Knowra_资产生命周期规范_v1.0.md) §1、§4、§8、§9 与[差距与分步实施方案](资产生命周期差距与实施方案.md)阶段 0。本文区分**已实施的保护**与**后续协议草案**；没有启用新的知识点、标注或其他资产的永久删除入口。

## 1. 状态转换表（目标语义）

业务审核、归档、删除、来源适用性、技术健康、同步进度分别记录。只有“删除”使对象进入回收站；归档资产也可以申请删除，恢复后仍归档。旧数据不按新含义批量改写。

| 当前状态 | 操作 | 目标状态 | 执行前必须检查 |
| --- | --- | --- | --- |
| 在用或已归档 | 归档／解除归档 | 原删除状态不变 | 审核与正式使用资格；不得把解除归档当恢复 |
| 在用或已归档 | 移入回收站 | 保存删除前状态，设删除事件及删除时间 | 所属权、预期版本、关联关系、在用任务、同步能力 |
| 回收站 | 恢复 | 清除删除标记，恢复原归档属性 | 恢复材料、父容器与来源、锚点、版本冲突 |
| 回收站 | 永久清理 | 先保留最小删除事实，再清主体和专属数据 | 全部保留引用、历史包独立性、共享资源、任务、同步水位；提交前重查 |
| 已永久清理 | 重放旧创建／编辑／恢复 | 拒绝旧 ID | 最小墓碑与权威序号；受控导入另发新身份 |
| 任何业务状态 | 撤回来源适用性／健康重算 | 只更新各自维度 | 不得借健康重算重新采用已撤回来源 |

当前 `Note.deletedAt` 已承载回收站；`KnowledgeItem.deletedAt` 仅有字段，没有完整删除操作；`ContentAnnotation.lifecycleStatus='archived'` 和 `deletedAt` 在旧取消重点流程中同时写入。它们均**不代表**上述目标转换已落地。当前 `reviewStatus='archived'`、`AnnotationExclusion.status='archived'` 保持原语义。

## 2. 引用分类与处置表

| 类型 | 当前实例 | 清理前处置 |
| --- | --- | --- |
| 专属附属 | 标注修订、经预检证明无其他用途的笔记版本或附件、知识点专属辅助记录 | 确认没有独立历史用途后才随主体清理 |
| 独立业务引用 | `KnowledgeEvidence → KnowledgeItem / NoteVersion`、`QuestionSource → NoteVersion`、`LearningObjective → KnowledgeItem` | 不默认级联；撤回、重新绑定或明确组合删除 |
| 历史引用 | `NoteVersion`、`AnalysisScopeSnapshot`、将来试卷与作答快照 | 独立历史包完整、可展示且不再依赖原对象，或明确清理该历史 |
| 共享引用 | 多个来源共享 `NoteVersion`；正文、回收站和历史版本共用附件 | 直到所有保留用途解除才能删除本体 |
| 派生引用 | 检索索引、AI 输入输出、缓存 | 先停止使用，再由可重试任务清理或重建 |

运行中任务、待处理同步、恢复点、备份单列为**保留边界**，不因当前业务表没有外键就推断为无引用。PostgreSQL 的 `KnowledgeEvidence.knowledgeItemId`、`LearningObjective.knowledgeItemId` 等 `Restrict` 关系及 `QuestionSource` 的多态 `sourceId` 均需要业务预检；数据库级联不能代替决定。

## 3. 逐实体字段与依赖清单

依据 `prisma/schema.prisma`、JSON schema v5、领域实体与服务；“待补”表示后续阶段的合同，不表示本阶段偷偷迁移。

| 资产 | 当前生命周期字段／删除方式 | 主要依赖与待补 |
| --- | --- | --- |
| `KnowledgeSpace` | 无删除字段，仅默认空间创建／读取 | 子文件夹、笔记、标签、标注、范围；阶段 2 才做迁移或组合删除 |
| `Folder` | 无删除字段，当前直接删子树 | 子文件夹、笔记目录关系；阶段 1 补预览、移动、恢复包 |
| `Tag`／`TagGroup` | 无删除字段；普通标签删除／合并，空组可删，内置受保护 | `NoteTag`、分组标签；保留轻量撤销和删除事实，内置对象不开放删除 |
| `Note` | `deletedAt`、领域 `deleted`；回收站／恢复／受限永久删除 | `NoteVersion`、标注、附件、证据、题目来源、分析快照；已有三类正式引用阻断保留 |
| `NoteVersion` | 不可变，无独立删除字段；随可清理的笔记移除 | 标注、证据、题目来源、分析快照；受控裁剪需独立预览 |
| `Attachment` | `status` 为文件完整性，不是删除状态；现有直接删除 | 正文、回收站、版本及其他保留业务记录；本阶段增加权威预检与阻断 |
| `ContentAnnotation` | `lifecycleStatus`、`anchorStatus`、`deletedAt`；旧取消重点写归档 | 版本、修订、排除项、证据；阶段 1 区分撤销／回收站与旧归档 |
| `AnnotationExclusion`／`AnnotationRevision` | 前者 `status` 含 archived；后者不可变 | 附属于标注与版本；按父资产历史处理 |
| `AnalysisScopeSnapshot` | 不可变，无删除字段 | 版本、选区、任务输入；阶段 1 增管理／回收站，阶段 2 清理 |
| `KnowledgeItem` | `reviewStatus` 含 archived，`deletedAt` 仅有字段 | 证据、学习目标、题目来源；阶段 1 新增独立回收站状态 |
| `KnowledgeEvidence` | `status` 兼技术健康与用户撤回，摘录保留 | 知识点、笔记、版本、标注；阶段 1 拆适用性与健康 |
| `LearningObjective` | `reviewStatus` 含 archived，无删除字段 | 知识点、题目目标；随训练工作域实现回收站 |
| `ExamProfile`／`ExamFocus` | `reviewStatus` 含 archived，无删除字段 | 考试配置与目标；随训练工作域实现 |
| `Question`／`QuestionObjective`／`QuestionSource` | 题目 `reviewStatus` 含 archived，无删除字段 | 目标、来源及未来试卷历史；正式历史包完成前不清原题 |
| `SyncJournal` | `revisions`、`changes`、`receipts`、`snapshots`；非业务资产 | 已记录 `value=null` 和序号，但尚无独立生命周期操作与最小墓碑 |

尚未建立完整持久实体的知识关系、主题、蓝图、试卷、作答、评分、学习证据、掌握度，以及 AI／索引任务，按规范在各自上线时补入引用图。本阶段不对它们宣称已经安全清理。

## 4. 已实施的只读附件预检与保护

`GET /api/storage/attachments/:id/deletion-preflight` 返回当前服务端已持久化资产中的引用；不存在的附件返回 404。结果形状：

```json
{
  "asset": { "type": "attachment", "id": "attachment-…" },
  "operation": "delete-unreferenced-file",
  "decision": "requires-dependency-action",
  "references": [{ "category": "history", "collection": "noteVersions", "id": "version-…", "reasonCode": "ATTACHMENT_REFERENCED" }],
  "reasonCodes": ["ATTACHMENT_REFERENCED"],
  "coverage": { "persistedCurrentAndHistory": true, "offlineDevices": "unverified", "backups": "unverified", "runningTasks": "unverified" }
}
```

`decision` 目前只可能是 `requires-dependency-action` 或 `can-purge-no-history`。后者只说明**本服务端已持久化业务记录**没有可识别的附件 URL／结构化附件 ID 引用，不是多端内容清除的保证。扫描包含在用、回收站、历史版本、分析快照及现有其他业务集合；回收站笔记仍归入共享引用，并额外标记 `retention=recycle-bin`。结果返回资产 ID 和原因，不返回正文摘录。预览不授权执行；直接删除和同步批次在写入前重新扫描。永久删除笔记／清空回收站的附带附件清理也检查删除范围外的引用。PostgreSQL 的引用复核与业务元数据删除在同一事务和现有写入锁下完成，文件清理在提交后。JSON 删除在同步写入前复核，失败时保留元数据和文件。

目前文件清理重试只在进程内调度，没有可靠持久任务；离线设备、备份和进程外运行任务也未纳入全局授权。因此此接口是阶段 0 的**安全基线**，不能作为阶段 2 的通用永久清理承诺。用户需先移除列出的引用；历史版本不因页面取消引用而自动丢弃。

## 5. 统一预检／执行结果契约草案（尚未开放）

通用预检请求：`assetType`、`assetId`、`operation=trash|restore|purge|retract|prune-history`、`expectedVersion`、可选组合范围。预检返回对象状态、归属、引用清单（类型、对象 ID、阻断原因、可执行处置）、保留历史包、共享文件、运行任务、同步能力与检查基线。判定枚举固定为：`can-trash`、`can-purge-no-history`、`can-purge-retain-history`、`requires-dependency-action`、`unsupported-safe-handling`。附件现有两值是其受限子集。

执行请求再携带 `operationId` 幂等键、预检基线与预期版本；领域服务在提交前重新计算。结果分别报告 `businessRecord`、`retainedHistory`、`filesAndIndexes`、`offlineDevices`、`backups` 的 `complete|pending|blocked|not-applicable`，并提供可重试任务 ID。HTTP 成功只代表对应权威提交完成，不暗示所有副本已清除。阶段 0 **未实现**通用执行请求、删除包、可靠清理任务或该完整结果体。

## 6. 入口盘点与兼容规则

| 入口 | 当前路径与阶段 0 结论 |
| --- | --- |
| Web／桌面 UI | V4 `EditorAttachmentPanel` 只检查当前正文；权威检查已下沉 API。桌面常驻服务与 Web 均走同源 `/api/*`；没有新增清理按钮。 |
| JSON API | `storage-routes → knowledge-base-snapshot-service → local-attachment-store → local-attachment-deletion`；直接删除和笔记清理的附件引用阻断已接入。笔记原有领域阻断未放宽。 |
| PostgreSQL API | `storage-routes → postgres-snapshot-service → postgres-attachment-store`；直接删除及笔记清理事务内引用复核，业务记录提交后再做文件 IO。 |
| 批量同步 | `pushBatch → prepareBatchState` 对附件 `value=null` 使用同一引用扫描；知识对象的无语义 `null` 和 `deletedAt` 更改仍被拒绝。 |
| 旧笔记同步 | 协议 v1 `push` 使用预期修订、操作 ID；当前只能表达既有笔记软删除语义，不可当通用删除操作。 |
| 导入／备份 | JSON 和 PostgreSQL 导入可替换整份资料，现有快照版本 v1／schema v5；恢复旧快照与未来墓碑的冲突处理尚未实现。上线新删除协议前须加基线／新身份门禁。 |

迁移原则：旧 `archived` 不转 `deleted`；旧 `deletedAt` 按各实体当前实际语义解释，不跨实体推断。下一阶段新增删除字段、删除包和适用性字段时，先只读盘点与备份，新增字段须可从旧记录确定默认值且不改变归档状态；PostgreSQL 与 JSON 同步迁移，导入旧快照须经版本门禁。旧客户端不理解新状态时限制其**相关写入**，不能只靠 UI 隐藏操作；阶段 0 没有引入新状态，现有协议与能力声明暂不升级。

同步操作协议建议使用 `{ protocolVersion, capability, deviceId, operationId, datasetEpoch, assetType, assetId, action, expectedRevision, scope }`。服务端按权威序号检查并保存幂等回执；`trash`／`restore`／`purge` 使用领域服务而非直接写 `deletedAt` 或 `value=null`。永久清理先提交仅含资产类型、ID、所属同步域、事件 ID、权威序号与必要时间的墓碑；旧 ID 写回、过期删除重放和旧备份导入必须被拒绝。同步设备安全水位与墓碑压缩留待阶段 2／4。

## 7. 阶段 0 验收与剩余边界

- API 自定义 runner 覆盖附件只读预检、JSON 文件与元数据保护、PostgreSQL 事务内复核、笔记清理时的共享引用阻断、同步批次阻断，以及笔记知识证据／题目来源／分析快照的原有保护。
- 无新生命周期字段或数据库迁移；未改变既有归档与知识审核状态。
- 实际 PostgreSQL 数据库、多设备离线回写、旧备份恢复、运行中任务、可靠文件重试、通用删除结果仍需在对应阶段验收。在这些边界关闭前，不开放其他资产的永久清理。
