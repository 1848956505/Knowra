# 资产生命周期阶段 1：实施与验收

> 日期：2026-09-23。以[资产生命周期规范 v1.0](../Knowra_资产生命周期规范_v1.0.md)为语义基准，按[差距与分步实施方案](资产生命周期差距与实施方案.md) §4 阶段 1 实施，并继承[阶段 0 安全基线](资产生命周期阶段0基线.md)。本文件记录**本次实际实现与验证的边界**，不把回收站操作称作永久清除。

## 1. 本阶段交付

| 资产 | 现在的操作与约束 | 数据与页面入口 |
| --- | --- | --- |
| 笔记与子标注 | 笔记移入回收站时记录子标注 ID、生命周期状态及修订；恢复父笔记不复活之前独立删除的标注。取消重点写为 `deleted`，旧 `archived` 仍保留旧义；10 秒内可撤销。恢复标注重新解析正文锚点。可复核来源保留历史摘录并提示“原标注已移除”；删除来源笔记则暂停其证据的正常使用。 | `Note.deletionPackage`、`ContentAnnotation.lifecycleStatus/deletedAt`；编辑器检查器的取消与撤销、知识来源历史提示。 |
| 知识来源 | `status` 只表示技术健康，`applicabilityStatus=active|withdrawn|needsReview` 表示是否采用。撤回不改写历史摘录或技术健康；重新采用需重新校验。旧 `invalid` 来源按 `needsReview` 保守导入。 | 来源服务、JSON 与 PostgreSQL、知识详情中的撤回／重新采用。 |
| 知识点 | 任意审核或归档状态可移入回收站；`deletedAt` 独立于 `reviewStatus`。默认列表、确认和新来源写入排除回收站对象；恢复保留原归档属性并重查证据。正式学习目标、题目随上游失效退出正式使用，原对象与历史来源不级联删除。回收站详情仍可读历史来源。 | 知识服务与 HTTP、知识库状态筛选和详情。 |
| 已保存分析范围 | 提供列表、移入回收站、恢复和修订冲突检查；已保存片段与版本引用不因回收站动作修改。AI 页签可管理在用与回收站记录。 | `AnalysisScopeSnapshot.updatedAt/deletedAt/mode`、范围 API、编辑器 AI 页签。 |
| 文件夹 | 删除时明确选择“保留笔记并移至目标目录”或“文件夹与其笔记一同回收”；两者均记录删除包。组合恢复只处理本次包内的笔记，先前独立删除的笔记仍在回收站。 | `Folder.deletedAt/deletionPackage`、`Note.folderDeletionPackageId`；笔记侧栏确认与文件夹回收站。 |
| 普通标签 | 现有删除或合并仍只移除标签及其适用关系，不删笔记。确认后提供 10 秒撤销窗口，窗口结束才提交；同步保留删除事实，旧设备不能按旧 ID 复活标签。 | 标签管理页、同步修订日志。内置标签仍受保护。 |

新增生命周期操作均接入 JSON、PostgreSQL、桌面 SQLite 同步及 V4 共享 API。同步批次要求显式的 `trash`／`restore`／`withdraw`／`readopt` 操作标记并校验数据不变量；旧格式的笔记删除缺少子标注状态包时被拒绝。服务端通告 `asset-lifecycle-v1` 能力；未理解新操作的客户端必须升级后再提交相应变更。

## 2. 迁移与历史兼容

- PostgreSQL 迁移 `prisma/migrations/8_evidence_applicability/migration.sql` 新增来源适用性、范围管理字段、文件夹删除包与笔记删除包字段。旧 `KnowledgeEvidence.status=invalid` 标为适用性待核对；旧范围默认 `mode=marked`、`updatedAt=createdAt`、`deletedAt=NULL`。JSON 导入使用同样的保守默认值。
- 旧 `ContentAnnotation.lifecycleStatus=archived` 不批量改成 `deleted`；旧笔记和知识点也不因其他资产状态被追溯删除。已有 `NoteVersion`、Evidence 摘录及来源 ID 仍保留。
- PostgreSQL 同步写盘表补入 `AnalysisScopeSnapshot`，并让备份导出包含已回收的范围。否则范围可能在客户端显示“同步完成”却未入库；真实数据库测试已覆盖创建、回收、恢复。
- 本阶段没有放宽笔记、版本、附件、知识点和范围的永久清理门禁；不会自动清理旧归档、运行时预览或保留历史。

## 3. 规范用例对应结果

| 用例 | 结果与证据 |
| --- | --- |
| LC-01、02、12 | 知识点默认查询排除回收站；已归档对象恢复仍归档；有正式学习目标时其身份与关系保留，但退出正式使用。API 与两设备同步测试。 |
| LC-03、04、05、08、09 | 取消重点独立可恢复，父笔记恢复不覆盖子标注原状态；锚点恢复重新解析。已固定版本的证据可独立复核；缺少可复核版本的来源不被新建或确认门禁放行。API、V4 与浏览器页面回归。 |
| LC-06、07 | 来源撤回与健康分列；后台重算不自动重新采用。来源笔记删除后证据失效、知识降为待修订，保留历史摘录。API、两设备及真实 PostgreSQL 回归。 |
| LC-11 | 已保存分析范围可列出、回收、恢复，内容不变；独立保存的知识和题目不级联删除。当前代码尚无“运行中的分析任务引用此快照”的持久任务实体，因此未声称完成任务占用场景的端到端验收；在引入该实体前不开放范围永久清理。 |
| LC-19 | 普通标签删除或合并只改变标签关系；旧设备回写不复活标签。文件夹组合删除有显式范围与恢复包。V4 撤销窗口与桌面同步测试。 |
| LC-35 | 临时真实 PostgreSQL 数据库应用 0～8 全部迁移，通过范围、来源、知识点、文件夹的创建、回收／撤回、恢复与两设备 HTTP 同步测试；JSON／SQLite 路径通过完整回归。 |
| LC-36 | 同步服务拒绝缺失生命周期动作、旧笔记删除包、篡改 Evidence 摘录及不满足正式来源条件的客户端批次。HTTP owner 由服务端固定；现有系统本身没有身份认证，外网部署仍按仓库要求由 Nginx Basic Auth 保护。 |

## 4. 验证记录

- `npm run test:api`：273 项通过；含阶段 1 删除包、来源适用性、知识／目标依赖、标注恢复定位、范围与文件夹测试。
- `npm run test:desktop`：本地 JSON／SQLite 与真实 HTTP 双设备回归通过；默认运行跳过需要数据库环境的 PostgreSQL 用例。
- 临时 PostgreSQL 17：`prisma migrate deploy` 全部 9 个迁移通过；`prisma generate`、`prisma validate` 通过；设置 `KNOWRA_SYNC_TEST_DATABASE_URL` 与写入门禁后，`entity-sync.test.mjs` 的真实 PostgreSQL 用例通过。数据库位于独立 `/tmp` 测试实例，未使用用户资料库。
- `npm run check:web:v4`：类型、边界与 V4 的 359 项测试通过；标注撤销、知识回收站历史来源、原标注移除提示、分析范围管理、标签撤销均有组件回归。`npm run build:web`、`npm run test:web-core` 通过。
- Playwright Chromium：`标注渐进披露：正文三种创建入口与紧凑检查器` 与 `阶段1 知识点回收站保留来源历史并可恢复` 两项真实页面用例通过，覆盖取消重点后高亮消失、撤销入口，以及知识回收站详情和恢复。未将这两项结果称为全量 E2E 通过。

## 5. 尚未开放的边界与下一阶段

阶段 1 的回收站和操作级撤销可以使用；受控永久删除、可靠清理任务、最小墓碑、旧备份防复活、运行中 AI 任务占用处置和自动保留期清理仍属后续阶段。保留引用的笔记版本、附件、Evidence 或已保存范围不能因为进入回收站就物理清除。阶段 2 应先落实统一预检／执行结果、依赖处置与真实数据库并发回归，再分别开启安全的永久清理入口。
