# 资产生命周期阶段 2：受控清理与空间管理实施验收

> 日期：2026-09-23。依据[资产生命周期规范 v1.0](../Knowra_资产生命周期规范_v1.0.md)及[差距与分步实施方案](资产生命周期差距与实施方案.md) §4 阶段 2，继承[阶段 1 验收](资产生命周期阶段1实施与验收.md)。本阶段只开放能够由现有引用图证明安全的清理路径；预览无法证明安全时继续阻断。

## 1. 已交付的操作

| 范围 | 实施结果 | 权威边界 |
| --- | --- | --- |
| 知识点 | 回收站中增加“永久删除…”预检和确认；按真实引用而非审核状态决定。无依赖时删除主体及专属 Evidence；LearningObjective、QuestionSource、已保存范围引用会阻断，执行事务内再次预检和核对 `updatedAt`。重复提交依据持久墓碑返回 `already-purged`，不会再删除其他对象。 | JSON 与 PostgreSQL 共用预检规则；保留来源笔记、标注及其他全局对象。迟到的创建请求不能复用已清理的知识点或 Evidence ID。桌面端不开放离线永久清理。 |
| 笔记版本 | 版本面板提供逐版本只读裁剪预览，列出当前内容、正式来源、题目来源、标注、排除项和已保存范围的引用。 | 尚无可证明的保留点元数据，全部标记为不可立即裁剪；没有新增物理删除接口。已有笔记永久删除保护继续生效。 |
| 附件 | 删除前权威扫描当前、回收站与历史业务记录；有引用时拒绝。删除任务先在受管目录持久化，主体提交后执行文件清理；失败返回 `pending-retry`，服务启动和维护接口可重试。笔记永久清理、清空回收站也报告各附件清理结果。 | PostgreSQL 的任务准备位于数据库事务外，事务内重新核对附件集合、路径和引用；事务失败时任务因元数据仍存在而不误删文件。文件清理失败不使已清理主体复活。 |
| 同步与导入 | 修订日志新增不含正文的最小墓碑；旧格式日志可从“有修订而无主体”重建删除事实。JSON 与 PostgreSQL 导入旧快照时检测已清理 ID，拒绝复活，并在安全导入后的新世代保留墓碑。 | 旧设备提交已清理 ID 仍被同步修订门禁拒绝；保留离线副本与备份的实际状态，在结果中写为待同步／按保留策略处理，不宣称全端清除。 |
| 知识空间 | 笔记库新增“空间管理”：创建、切换、迁移预览／确认、空空间删除预览／确认。整包迁移目录、笔记、标签／自建分组、标注和已保存分析范围，包含回收站对象；目标必须为空，跨空间笔记链接与范围版本引用受阻断，确认时比对内容哈希。 | 默认空间外壳不删除，但可迁移其自有内容；自建空间仅在全部空间内对象处理完后可删除。知识点与训练对象为全局资产，不随空间迁移或删除。桌面端可查看／切换，创建与不可逆操作仅网页版开放。 |

V4 入口分别位于知识库回收站详情、编辑器版本历史与笔记库标题栏的“空间管理”。空间页明确列出迁移范围和全局资产边界。新 API 包括知识点清理预检／执行、笔记版本清理预览、附件清理重试及空间创建／删除预检／迁移。删除事实与业务变更在同一 JSON 原子写入或 PostgreSQL 事务中提交；文件操作与数据库事务分开。

## 2. 规范用例和阻断边界

| 用例 | 本阶段结果 |
| --- | --- |
| LC-10、12、26 | 知识点预检列出关联目标、题目来源及范围；预览后新增引用或主体更新会阻断事务。版本预览逐项列出被引证据；被引版本不裁剪。正式目标没有可用的重新绑定／历史独立化管理页时，知识点永久清理继续阻断。 |
| LC-20、27、28 | 附件有任何保留引用时不删除；无引用时元数据删除与待清理任务分阶段完成。模拟文件失败后任务仍在，重试完成；正常读取入口因元数据已消失而不可用。真实进程在事务提交与文件清理之间被强杀后的自动重试尚未做端到端故障注入。 |
| LC-21 | 非空空间先整包迁入空目标；默认外壳保留，自建空容器才能删除。**没有开放非空空间直接组合删除／恢复**，因此该用例中的组合恢复路径不适用当前入口。迁移保留回收站资产原状态。 |
| LC-22～25、29、30 | 同步修订、墓碑及旧备份导入阻止旧 ID 复活；知识点重复清理返回墓碑结果且同步头不增加；迟到的知识创建请求被拒绝。游标过期仍要求重建基线。没有持久 AI 任务实体；未来增加任务时须接入同一清理门禁。 |
| LC-33、34 | 界面和 API 结果说明离线设备与备份仍需处理。应用内恢复旧快照会对照当前墓碑拒绝复活。若**整个主机或数据库连同墓碑一起回滚**，当前服务无法凭被回滚的数据自行知道后续删除事实；对外开放前必须从独立保留的删除事实核对、清理冲突 ID 并重置同步世代。该灾难恢复场景没有自动化闭环，不能宣称已完成 LC-34。 |
| LC-35、36 | JSON、SQLite 同步及真实 PostgreSQL 对安全子集作一致性回归；服务端 owner 边界和显式生命周期动作门禁沿用阶段 1。HTTP 知识空间 owner 由服务端决定。 |

以下对象仍受保护：有正式引用的知识点；缺少保留点证明的笔记历史版本；有业务或历史引用的附件；有潜在 Evidence／任务引用的标注及已保存分析范围；非空且未迁移的空间。当前训练页尚无处理 LearningObjective、QuestionSource 的完整操作入口，不以不可逆级联删除绕过它们。没有启用 30 天自动清理，也不追溯清理旧归档。

## 3. 验证记录

- `npm run test:api`：280 项通过。覆盖知识点清理引用复核、重复提交、迟到创建拦截、JSON 墓碑导入、文件清理失败重试、版本预览和空间迁移基线。
- `npm run test:desktop`：在**全新临时 PostgreSQL 17 测试数据库**应用 9 个迁移后，72 项全部通过，包括真实数据库的空间迁移／空容器删除、知识点清理及旧备份拦截、附件及笔记附属文件清理，以及旧设备回写阻断。默认无数据库环境时 PostgreSQL 用例按测试门禁跳过。
- `npm run check:web:v4`：类型、架构边界、359 项 Vitest 与 4 项服务器测试通过；`npm run build:web`、`npm run test:web-core`（21 项）通过。
- Playwright Chromium：阶段 2 的 2 项页面用例通过，覆盖空间默认外壳保护、迁移预览，以及知识点永久删除的范围说明与确认。它们是受影响页面回归，不代表全量 E2E 通过。
- 一次将多个 PostgreSQL 用例复用同一临时库时，旧测试的清理代码只删笔记、留下引用该笔记版本的分析范围，造成随后备份校验失败。已修复测试清理顺序；全新临时库的完整桌面套件通过。不要将该测试污染解释为生产数据迁移成功。

## 4. 后续约束

训练域的目标与题目管理、独立历史包、持久任务占用和整机灾难恢复的外部删除事实来源仍需单独设计与验收。当前对这些情况保持预检阻断；不得通过放宽外键或仅隐藏 UI 来使永久删除“成功”。未来若开放笔记版本、标注、范围或非空空间组合清理，应补相应引用处置、幂等结果、故障注入与两端恢复测试后再开启入口。
