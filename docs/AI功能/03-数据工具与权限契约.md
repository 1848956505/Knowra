# 数据、工具与权限契约

状态：领域说明草案；P0 已冻结[运行对象/范围/工具 v1 schema](p0/AI-00-03-契约与迁移冻结.md)。以下新增对象、字段、工具及路由仍不是现有 API 承诺；P1 需实现运行时校验、持久化与执行。

## 1. 数据对象

| 对象 | 最小信息 | 保存与边界 |
| --- | --- | --- |
| `AIProviderProfile` | ID、协议/端点、模型/能力、credentialRef、预算策略、配置版本 | 执行端设置；不保存明文 key，不随业务同步 |
| `AIConversation` / `AIMessage` | 会话、资料集/空间、消息、来源引用、关联任务、创建时间 | 首期执行端保存；不默认跨端同步；对话不是授权凭据 |
| `AIGrant` | actor、入口、允许的范围/工具/动作类别、限制、有效期、撤销时间 | 由受信用户操作产生；模型不可填写或扩大 |
| `AIJob` | requestId、jobId、parentJobId、kind、owner/资料集/空间、输入快照引用、inputHash、幂等键、status/phase、attemptId、模型/提示词/schema 版本、结果、用量、错误 | 持久任务与恢复依据；执行端独占运行 |
| `AIJobAttempt` | jobId、执行次数、租约 generation、开始/结束、providerRequestId、交付不确定标识 | 网络重试不覆盖先前调用及用量 |
| `AIAction` | actionId、jobId、grantId、operationId、计划内容、基线、planHash、审核凭据、status、真实提交结果 | 对业务变更单独建账，模型输出不等于执行 |
| `AIArtifactProvenance` | artifactId、产物类型、原 job/request、provider/model、输入/输出哈希、schema/prompt、来源版本/范围 | 与正式产物关联的最小可追溯信息；同步设计不能依赖远端可访问原任务 |
| `AIUsageRecord` | attemptId、token/其他计量、预估/实际费用、币种、计价版本、unknown 标记 | 服务端计算，不采用模型自报消耗 |
| `AIEvaluationRun` | 样本集版本、模型/提示词/检索版本、结果、评分人或规则、阈值 | 开发评测记录，禁止混入正式用户学习证据 |

ID 和 owner 来自服务端。外部请求中的 owner、审核状态、数据库集合名、createdBy 和任意目标 URL 不透传。用户发送的是对象引用，服务端必须重新加载并核对权限、范围和生命周期。

### 1.1 存储改造清单

- JSON：schema 默认值、兼容导入/导出、引用验证、原子事务和任务恢复；旧快照无 AI 集合可正常打开。
- SQLite：升级 schema 与同一事务内的动作 ledger、业务写入、必要同步 outbox；备份/恢复包含运行记录并重置失效租约。
- PostgreSQL：增量 migration、唯一约束、索引、repository/mapper/snapshot 覆盖；原子领取和提交，禁止网络 IO 进入事务。
- 引用：新增 provenance、任务引用和未来试卷快照后同步更新版本裁剪、附件/对象清理预检和资料集迁移规则。
- 同步：AI 会话/任务不进首期业务同步集合；产物和必要 provenance 使用显式版本化能力。旧端不能静默丢掉其无法理解的来源字段。
- 恢复：恢复备份后不自动重放历史写入或远程请求。仍有任务的资料集重新获得执行 epoch，旧进程提交被拒绝。

## 2. 范围与来源契约

### 2.1 权威范围

`ContextManifest` 建议包含：资料集 ID、spaceId、scope kind、允许对象 ID、所读版本、排除项、仅阅读上下文、实际发送字数/token 估计、附件列表、快照哈希和生成时间。

支持 `selection`、`heading`、`note`、明确多选集合、`folder`、`knowledgeItems`；全库操作需单独范围。目录范围在任务创建时展开为固定 ID 集合，后续目录中新增笔记不自动纳入本次授权和输入。

授予某目录读取权限不等于允许将目录外的候选检索摘要发送模型。搜索、计数、标题、引用和正文均先过滤权限；不能先把全库结果给模型，再让它自行忽略。

### 2.2 引用

笔记引用绑定 `noteId + noteVersionId + contentHash + start/end + quote`，偏移沿用 JavaScript UTF-16 左闭右开语义。模型只可引用输入中的 sourceId，服务端映射正式 ID 并核验摘录。

知识、目标、题目引用还需保存当时的版本/不可变快照及来源链。当前知识/目标并非都有完整版本表，P3/P4 应增加受控 snapshot 或 revision 能力，不能把 `updatedAt` 当作可还原的历史正文。

对话消息、用户直接输入、草稿快照与外部资料均有独立 source kind。未核实的 AI 解释不能被记录为已保存笔记引用。图片/PDF 的页码和音频时间段采用独立定位类型，不套用虚假的文本偏移。

### 2.3 现有知识提炼 v1

继续复用 [原契约](../知识库与试题模块/基础/AI知识提炼接入契约与验收.md) 和 [实现](../../apps/api/src/modules/knowledge/application/knowledge-extraction-contract.js)：

- 使用已保存范围和不可变版本；最多 128 片段、120,000 UTF-16 单元；不是模型 token 上限。
- 最多 40 候选、每条 1–8 引文，整体 JSON 最多 256,000 UTF-8 字节。
- 严格字段白名单；结果经校验形成 `candidateInput`，强制 `candidate` / `sourceMode: ai`。
- `contextSegments` 不发送；扩展输入/输出使用新版本，不默默改变现有证据边界。
- 所有候选、证据、provenance、任务结果同一事务提交；任一失败整体回滚。
- 输入来源已删除或权限/空间变化拒绝入库。仅正文更新时保留旧版本来源、标为待核对，不假装来自最新原文。

## 3. 任务状态与取消

保留领域草案已有状态并作受控扩展：

```text
pending → running → succeeded
pending / running → failed
failed → retrying → running → succeeded / failed
pending / running / retrying → cancelling → cancelled
```

`cancelling` / `cancelled` 为本方案拟新增状态；落地需升级相应 schema、客户端和原提炼文档。`phase` 独立记录 preparing、retrieving、generating、validating、committing，不用它替代权威状态。

- 只读问答：succeeded = 最终回答/引用已验证并保存。
- 提炼任务：succeeded = 输出、全部候选及证据已原子落库；知识仍未正式确认。
- 写入方案生成：succeeded = 已保存可审阅方案，不能显示“修改已完成”；动作状态独立。
- 题目生成：succeeded = 已保存符合该阶段契约的题目草稿/候选及来源；不表示已正式确认或发布试卷。

关闭面板不等于取消；取消是显式请求。提交前事务复核取消标记、租约及授权。若业务提交已经先完成，取消响应返回“已提交，无法取消”，可以另走撤销流程。外部调用可能已收费，取消不能承诺退费。

## 4. 动作与幂等

### 4.1 状态

```text
planned → awaitingApproval → authorized → applying → applied
planned → authorized → applying → applied       （已获明确指令的新建/追加）
planned / awaitingApproval → rejected / cancelled / expired
authorized / applying → conflicted / failed
```

网络超时不直接判定写入失败：若已进入 applying，查询唯一操作回执和事务状态再判断。不能在“可能已成功”时重建另一个 action 盲目再写。

### 4.2 两层幂等

| 层 | 唯一边界 | 规则 |
| --- | --- | --- |
| 模型任务 | owner + dataset + space + kind + idempotencyKey | 同键同输入复用；同键不同 inputHash 返回 409；明确重新生成使用新 key |
| 业务动作 | owner + dataset + operationId | 同一操作只提交一次；同 operationId 不同 planHash 拒绝；响应丢失后返回原回执 |

`inputHash` 包含实际快照、用户请求、模型配置版本、prompt/schema、相关参数和授权范围版本。`planHash` 包含操作类型、目标 ID、变更内容和每个目标基线。哈希由服务端生成，不能信任客户端声明。

重试模型可能生成不同结果。第一次已被接纳的 outputHash 不允许被另一个迟到响应覆盖；尝试次数、租约与终态决定哪一次有提交权。

### 4.3 写入协议

1. 服务端取得当前权限和真实对象，形成基线。新建预先分配固定目标 ID；追加/改写记录版本与正文哈希。
2. 模型提出允许字段的建议，schema/业务校验后生成计划。
3. 改写/批量操作在可信 UI 展示差异、目标、数量及来源影响，确认凭据绑定 planHash、目标基线、actor 和有效期。
4. 提交事务内复核 grant、资料集 epoch、生命周期、目标范围及所有基线，然后执行现有领域服务。
5. 在同一原子提交中保存业务变更、版本/关联维护、动作结果及必要 outbox。完成后向模型返回真实 ID 和状态。
6. 版本不匹配返回冲突，保留建议供重做预览；不得自动取得最新版本并原样覆盖。

正文复用 `expectedUpdatedAt`，同时检查 plan 所绑定的 contentHash。对没有足够并发语义的元数据/训练操作新增 CAS，并在事务内实现；仅在 HTTP 读取时比较不足以阻止竞争。

追加也属于有基线的写入。当前没有专门的追加服务，AI wrapper 需先读取并验证锚点，再基于当前基线调用 update。局部修改使用确定的片段/范围与原文核对，重复片段需定位消歧；禁止全文模糊 replace。

批量写入不能直接把现有多次单项调用当作原子操作。首版最多 20 个对象的一组计划应整体预检、整体事务提交；跨资料集计划拆成明确的多个动作，不承诺跨库事务。更大任务按用户可见分组执行，已完成组不因后续取消自动回退。

### 4.4 撤销

正文依赖修改前版本，元数据依赖 before image。撤销是基于当前状态的新动作，带版本复核；若此后用户又编辑，不允许直接回滚覆盖。新建笔记可提出移入回收站，不能自动永久删除。批量撤销同样展示影响和冲突，不承诺永远一键撤销。

## 5. 权限矩阵

用户已确认的 D03：授权范围内可读取；明确要求的新建/追加可直接执行；改写、批量管理先预览。

| 行为 | 默认策略 | 实施约束 |
| --- | --- | --- |
| 搜索/读取授权范围 | 允许，无需逐步确认 | 每次读重新检查 grant；默认排除回收站，归档是否纳入显式可见 |
| 超出目录/空间或读取额外附件 | 申请扩展范围 | 模型不能靠换 ID 绕过 |
| 明确要求的新建、追加 | 可直接执行 | 用户指令有目标/位置与动作意图；目标歧义需消歧；既有草稿冲突需处理 |
| 单篇改写/替换 | 预览后执行 | 差异绑定确切版本，批准后变更则失效 |
| 改名/移动/标签，尤其批量 | 默认计划预览 | 单项也可使用同一预览；不推断“整理一下”授权全库管理 |
| 启动提炼并保存候选 | 显式发起后可保存候选 | 不得升级为 confirmed |
| 知识/目标/题目正式确认 | 领域审核 UI 的人工动作 | 不向自主工具循环开放无条件确认权限 |
| 移入回收站/合并拆分 | 预览影响后人工确认 | 复用引用预检，不隐式删除关联独立资产 |
| 永久清理/备份恢复/空间迁移 | 首期 AI 工具禁用 | 引导到已有受控管理界面 |
| AI 批改采纳 | 明确接受报告，警告项单独复核 | 先暂定结果，再形成证据 |
| 修改掌握度/历史成绩 | 禁止通用 AI 写工具 | 成绩走可追溯重评；掌握度由证据规则重算 |

模型输出 `authorized: true` 没有效力。服务端的用户命令记录/可信 UI 创建 request-bound grant；模型只在其范围内填参数。普通只读对话没有自动写 grant，无法确定是否含明确写意图时先生成方案。

端侧现有只读保护优先于 AI grant。加载失败、恢复模式、同步冲突隔离或当前模块不支持写入时，AI 只能提供草稿或说明。

## 7. 对外 API 草案

统一命名空间拟为 `/api/ai/*`，经同源代理。接口仍返回项目标准封装；以下路径不代表已实现。

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/ai/capabilities` | 返回已配置能力、端侧限制和原因，不泄漏凭据 |
| `POST /api/ai/conversations` | 创建绑定资料集/空间的会话 |
| `POST /api/ai/conversations/:id/messages` | 校验用户请求，创建/复用 AIJob，返回 202 与 jobId |
| `GET /api/ai/conversations/:id/messages` | 分页恢复会话和关联结果 |
| `POST /api/ai/jobs` | 发起类型化提炼/出题等任务，包含幂等键和对象引用 |
| `GET /api/ai/jobs` / `GET /api/ai/jobs/:id` | 任务列表、终态与结果 |
| `GET /api/ai/jobs/:id/events` | 版本化 SSE 事件与恢复游标 |
| `POST /api/ai/jobs/:id/cancel` / `retry` | 显式取消或受控重试，均校验授权 |
| `GET /api/ai/actions/:id` | 获取计划、基线和当前执行结果 |
| `POST /api/ai/actions/:id/approve` / `reject` | 可信用户流程确认或拒绝；approve 携带 planHash 和交互凭据 |
| `POST /api/ai/actions/:id/apply` | 内部执行或已获确认的受控提交，不接受模型伪造审核 |
| `POST /api/ai/actions/:id/undo-preview` | 构建新的撤销计划，提交仍走审核规则 |
| `GET /api/ai/usage` | 配额、预估和实际用量及未知项 |

配置 API 独立限制为受信设置操作。`retry`、`reject` 等缩写路径均挂在同一个 `:id` 下，不是根路径。

关键错误码建议：`AI_NOT_CONFIGURED`、`AI_CAPABILITY_UNAVAILABLE`、`AI_SCOPE_FORBIDDEN`、`AI_INPUT_TOO_LARGE`、`AI_BUDGET_EXCEEDED`、`AI_IDEMPOTENCY_CONFLICT`、`AI_ACTION_APPROVAL_REQUIRED`、`AI_ACTION_CONFLICT`、`AI_SOURCE_UNAVAILABLE`、`AI_OUTPUT_INVALID`、`AI_PROVIDER_TIMEOUT`、`AI_CANCELLED`。映射明确 HTTP 状态并给出可恢复动作；不在错误消息里泄漏原文或 key。

## 8. 保留、删除与隐私

- 输入优先引用已有不可变版本，避免每次复制全篇；临时快照仅保存复现与审核所需内容。
- 正式产物引用的 provenance、证据和快照按资产生命周期保护，不能随聊天清理被级联删除；删除聊天与删除业务产物是不同操作。
- 未保存且已结束任务的临时数据可提供短期保留建议，例如 7 天，但首次启用需确认；未启用自动清理时明确“保留至手动清理”，不默认改变原项目 GC 政策。
- 运行中任务在删除来源时被取消或阻止提交；迟到输出不得复活已清理 ID。任务恢复同样复查墓碑。
- 用户清除内容时盘点会话、任务输入输出、证据摘录、索引、缓存和受控备份；源文删除不自动删除语义相似的独立笔记。
- 本地清理不等于供应商已删除副本。远程保留期限与训练使用规则按实际选定供应商核对和展示，不承诺“零留存”。
- 审计日志默认只存元数据；临时诊断全文需显式开启并有期限，日志导出脱敏。
- 数据备份恢复不恢复已撤销凭据或重新授予过期 grant；grant 中引用旧资料集 epoch 的写入失效。
