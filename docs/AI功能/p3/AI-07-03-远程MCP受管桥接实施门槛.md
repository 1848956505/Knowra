# AI-07-03 远程 MCP 受管桥接：实施门槛与验收计划

状态：受管桥接内核候选已实现并做合成测试；完整远程接入未实现、未启用。基线：`037b70f4826d245949c26bc0e7ad1bde5d6307b7`（本地 MCP 向导与任务工作区 V1 合并后）。本批提供默认关闭、未接入生产宿主的只读内核，不新增监听器、后台进程、授权记录或凭据，也不改变现有 stdio。

## 1. 决策摘要

资料仍由用户本机提供。拟采用“远程 MCP 接入服务 → 受管转发 → 在线桌面运行端 → 现有统一 gate”的路径；桌面主动建立经过认证的连接，不直接公开桌面 API 或本机 socket。转发服务只承担受控请求路由，不持有资料库副本。

当前不应把内存队列或假身份校验器包装成“远程 MCP 已可用”。缺少远程身份验证、设备注册与撤销、用户确认的远程授权绑定及其持久生命周期，仍无法把真实外部调用安全地绑定到现有 gate。本批只做可注入受信绑定端口的内核；合成测试签发不透明句柄，并真正经过现有配对、gate、任务服务和 SQLite，不把替身当成生产认证。

实际价值：已验证两个任务只读工具的真实授权执行链与有界请求生命周期，下一批可替换受信宿主适配器而不绕过原权限；产品说明仍明确区分“本地已可用”和“远程待实现”。

仍不可远程使用：工具发现、笔记/知识读取、任务工作区读取、图片读取、任务协写、领取/续租/提交任务，以及任何其他 MCP 工具。不存在可提供给远程客户端的 URL；不得承诺支持所有客户端。

| 已实现模块 | 可复用能力 | 不能直接推导出的能力 |

## 3. 信任边界与最小数据流

1. 远程 MCP 接入服务验证请求令牌：限定受信 issuer、目标 resource/audience、有效期、client 与 scope，完成正式协议所需的授权发现与拒绝响应。不接受任意自声明身份，不向下游透传其他受众的 token。
2. 设备注册服务确认已授权用户与真实设备，维护可撤销设备绑定；桌面使用单独、可轮换的设备凭据连接。具体身份提供方、凭据保存和运营方案待确认，不自制密码系统或密码学协议。
3. 用户在桌面明确确认特定远程客户端、转发服务、资料范围和能力。远程授权应独立记录；既有本地配对不得静默升级。
4. 受信设备通道把验证后的主体绑定与请求交给桌面桥。网络请求体中的 userId、deviceId、grantId 只能是待比对的选择器，不能成为认证依据。
5. 桌面根据受信绑定服务查出当前授权、资料集与修订；以仅进程内可持有的能力句柄进入 gate。句柄不能通过 JSON 反序列化获得，不能以本地 token 换取网络授权。
6. 仍由现有 gate 和业务服务生成可信上下文、检查权限、执行工具、复核输出；桥不直接读数据库，不创建第二套放行逻辑。桌面最后输出前和 relay 最后发送前再次复核，防止 gate 返回后排队期间授权已变化。

必须分开三个身份：远程用户/客户端身份、在线设备身份、本地数据授权。相同 grantId 或相同字符串形式的 subject 不构成三者的绑定证明。身份唯一性至少含 issuer 与 subject，不能按展示名称或邮箱直接绑定。

撤销需要明确线性化检查点与传播策略：桌面本地授权撤销在其权威检查点生效，relay 远程授权撤销在其权威检查点生效；两端各自最终发送前检查当前有效性。若不能确认绑定/撤销状态（例如通道断联），失败关闭，不使用旧缓存继续放行。已发送字节无法收回，不承诺跨节点墙钟同一瞬间撤销即全网零延迟；R1/R3 必须明确撤销确认回执何时可向用户显示“已生效”。

转发节点可见工具参数与结果的具体范围需在正式方案中说明；TLS 不意味着转发服务看不到正文。本批不承诺端到端加密，不自行设计加密协议。即使不持久化正文，也必须把该服务作为数据接收方明确告知用户。

## 4. 接口边界（不是公共远程 API）

以下区分已实现的宿主内核与未来适配器；都不是新增公共协议：

- `RemoteIdentityVerifier`：由受信宿主装配，对真实认证证据产生不透明已验证主体；失败不产生主体。不允许部署环境使用测试替身。
- `DeviceBindingRegistry`：将已验证主体、client、device、grant、grantRevision、datasetEpoch 绑定，并提供同步最终有效性检查或等效不可竞态的出口保证。撤销后不继续依赖长寿命缓存。
- `remote-read-bridge.mjs`（已实现的单连接内核）：接收已验证通道对象与严格请求信封，做字节限额、队列、deadline、取消和重复检查；不能自行决定数据授权。
- `remote-binding-port.mjs` 与 gate 的 `callRemoteRead` 宿主专用入口（已实现）：受信端口提交不透明授权句柄，gate 内部取得当前记录，复用本地 gate 的业务路径。不能公开 `callAs(row)`、接受任意 ctx，也不能读出配对文件中的 knp1 作为远程通道凭据。
- `RemoteRelayTransport`：仅在真实 verifier、设备注册、授权存储、撤销传播、受信 gate 端口均配置且用户明确开启时可装配；缺一则拒绝启动。模块导入和桌面启动都不得自动联网。

外部信封拟包含：协议内部版本、requestId、目标 deviceId/grantId、预期 grantRevision/datasetEpoch、deadline、固定方法、tool、input。仅允许声明字段，按最终编码字节限制请求；严禁 token URL、任意目标 URL/路径、客户端 ctx/owner/权限对象、任意反序列化代码或模块名。所有身份字段必须与通道和注册表匹配，不能信任信封本身。

本批可执行切片只允许 `task_documents_read` / `tasks_get`，两者必须提供 workspaceId。明确拒绝 list、普通笔记、写工具及图片。不能以工具名命名习惯或客户端声明 `readOnly` 判定；`tools/list` 和 `tools/call` 必须使用同一许可交集。写工具与图片另行解锁，不能随着本地工具表增加而自动远程可用。

## 5. 调度、取消与重试语义

- 入队前完成认证及大小/字段校验。本批限制单连接实例的队列长度、排队字节、并发、最大 deadline 和重放记录数量，结果复用任务出口字节上限；跨主体、设备与全局预算由未来连接管理器补齐，不能无限创建实例；超限拒绝，不静默无限缓存。
- deadline 由可信服务时钟钳制：客户端不能用远未来时间获得无限租期。入队、出队、gate 前、事务提交 guard、出站均检查；本地等待使用单调时间，明确跨主机时钟偏差预算。
- 状态最少区分 queued、running、completed、cancelled、expired、disconnected、revoked。状态属于特定绑定与连接代际，外部不能伪造完成或取消其他人的请求。
- 取消排队请求后不执行；取消运行请求后停止交付，并将取消传入业务 guard。仅 Promise.race 超时或 AbortSignal 不足以证明写入被取消。
- 断线清除待执行队列，拒绝迟到结果；不在重新连接后自动重放。运行中的只读工作即使底层不能立刻停止，也要占用并发直到实际结束，避免无限制造孤儿任务。
- 连接代际改变、设备/授权撤销、资料库恢复或切换，都使旧请求与旧结果失效；重新连接不复活旧 grant，不恢复旧正文缓存。
- requestId 用于传输重复检测，作用域包含主体、设备、grant 与连接代际。重复请求不能再次执行；内容不同的同 ID 必须报冲突。最小方案拒绝重放，不缓存正文。记录到达容量时拒绝新请求或轮换连接，不能通过提前淘汰记录允许旧请求重放。
- operationId 是业务命令的独立幂等键，沿用任务服务既有约束，不能由桥每次重试自动生成。未来写操作若结果丢失，应先对账或按相同 operationId 恢复；必须报告“结果未知”，不能报告“未执行”。不声称网络层实现 exactly-once。
- 协议层取消、连接断开、业务任务取消是不同操作。远程请求取消不能等同于撤销/取消用户任务；已有 MCP 没有的业务工具仍不得补出。

## 6. 最小实现切片与退出条件

### R0：设计核对（已完成）

文档与内核范围已经核对；不增加空 service、假 production verifier 或远程“可用”状态。

### R1：受信绑定与 gate 内部端口（合成实现已完成）

前置：确定身份/设备/grant 的生命周期、用户确认与撤销设计。以现有 gate 为唯一执行点，增加进程内不可伪造的授权端口及只读 allowlist；针对现有本地 token 入口做回归。仅内存合成数据测试，不联网。

退出条件：绑定校验失败、默认关闭、缺配置、撤销、epoch 变化、跨主体/设备/grant、序列化伪造句柄全部拒绝；本地 stdio 不受影响。仅测试替身的通过不算真实认证完成。

### R2：有界只读调度与真实 gate 集成（单连接内核已完成）

前置：R1 审核通过。实现本节定义的信封、队列和出站复核，至少一条真实 gate 只读调用贯通；使用 in-process harness，无监听器，不绕过环境 socket 限制。

本批证据见第 10 节。队列、在途及重复记录都有单实例空间上限；取消/断线/迟到不得泄漏正文。gate 超时后底层工作未结束仍保留并发槽。R3 前仍须补全跨实例总预算、真实绑定签发/撤销确认与可信发送端，不可把本内核直接挂到公网。

### R3：真实认证、设备连接与指定客户端验收

前置：用户批准服务/域名、接收方、身份方案与凭据配置，安全审核和正式协议核对通过。真实适配器配置后仍默认关闭，由明确开启流程接入；先合成资料，后按用户选择范围验收。

退出条件：指定客户端完整授权/重连/撤销/升级流程有证据；云端错误、代理日志、监控与保留政策核查通过；桌面离线有明确失败，不把本地资料上传作回退。此时才可宣称该客户端的远程只读接入可用。

### R4：写操作与图片

独立评审。写入需取消/超时 guard 进入实际事务、业务回执对账、operationId 复用与冲突验证；图片需单独许可、精确文档版本、最终快照及更严格字节限制。不能由 R3 自动解锁。

## 7. 完整接入验收矩阵（内核子集已测，认证/网络/客户端仍待运行）

| 场景 | 必须建立的证据 |
| --- | --- |
| 未开启、缺 verifier/registry/relay、生产装配测试替身 | 无监听/联网/执行；明确拒绝，不能静默回退匿名 |
| 错 issuer/audience/resource、过期 token、跨 client | 不查数据、不入业务队列；拒绝细节不泄漏资料 |
| 伪造 subject/device/grant/revision/epoch/ctx | 不透明句柄不可通过 JSON 构造；与受信通道不匹配即拒绝 |
| 本地 knp1 误送云端、URL 含 token | 明确拒绝；不记录凭据；不交换为远程授权 |
| allowlist 未含的本地工具、新增工具、写工具、图片 | tools/list 不显示，直接 tools/call 也拒绝 |
| 全局 AI/外发开关关闭，独立知识许可关闭 | 包括排队与在途结果都被挡住；不得以旧清单绕过 |
| 排队满、总字节满、并发满、极长 deadline | 有界拒绝，资源可回收；不留下失控后台任务 |
| 排队取消、运行取消、到期、断线 | 排队不执行；迟到无正文；真实运行未结束前不释放并发槽 |
| requestId 重复、同 ID 不同内容、重放表满 | 不重复执行；不靠清空表使旧请求重新有效 |
| grant 撤销发生在工具执行中、gate 后、发送前 | 撤销已在相应权威检查点生效后，不再向下一跳发送正文；验证两端最后发送检查、传播确认和断联失败关闭；已发送字节不声称可收回 |
| 恢复资料库、切换资料集、连接代际改变、设备撤销 | 老请求/老句柄/老结果失效，重连不自动续权 |
| 任务写已提交但响应丢失（R4） | 相同 operationId 恢复同一回执；不再创建一次；不谎报取消成功 |
| 故障异常/日志注入/参数含敏感文本 | 只记录固定事件、受限错误码、计数与内部关联标识；无正文、参数、token、任意异常堆栈或 URL |
| 本地 stdio 与原配对回归 | 原输入/输出、撤销、知识权限、任务权限和幂等行为不变 |
| 指定真实客户端（R3） | 真实授权和当前协议协商证据；没有通过的客户端不列为支持 |

## 8. 用户醒后集中确认的最小清单

1. 第一位要接入的远程客户端及使用方式；首批是否同意只读，选择哪些资料范围。
2. 服务归属、域名与部署位置；转发服务/客户端哪些组织可接触请求和返回内容，是否接受相应数据外发与日志保留政策。
3. 采用的身份提供方与设备注册方案；是否授权创建服务账号、OAuth 配置及设备凭据。此类持久访问和敏感步骤在实际执行前按要求确认或交接，不因同意设计即视为授权。
4. 桌面在线要求与设备选择；首轮只用合成资料验收，后续真实资料另明确范围。
5. 预算/收费、域名或部署采购如有，另提供具体金额与承诺确认。本批没有这些费用或部署。

本批停在合成本地内核。R1/R2 未依赖部署商家或真实凭据；R3 才要求相应服务、接收方与持久访问授权。涉及真实数据或 R4 的授权另行确认。不夜间反复请求配置，不尝试替代账号或降级绕过认证。

## 9. 协议依据与兼容边界

2026-10-15 在线核对官方资料；以下引用不是仓库已经实现相应功能的声明。正式编码前应再次核对 Current 修订及选定 SDK 的实际支持范围。

- [官方版本说明](https://modelcontextprotocol.io/docs/2026-07-28/learn/versioning)：Current 为 `2026-07-28`；版本以每请求 `_meta` 声明，Streamable HTTP 另携带对应版本 header；`server/discover` 与不支持版本错误是新版发现/协商机制。不能拿旧版 initialize 成功作为新版通过证据。
- [官方传输总览](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)：Streamable HTTP 使用单端点 POST，响应是 JSON 或请求级 SSE；请求体元数据为准，头体不一致必须按绑定规范拒绝。HTTP 中断响应流与 stdio 的取消通知是不同传输表达，业务提交/回执仍需本方案的独立保护。
- [官方授权规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)：受保护 MCP 服务是 OAuth resource server；需要 Protected Resource Metadata 与授权服务器发现，客户端注册有多种路径，动态注册已被标为 deprecated，不能默认要求自建动态注册。身份提供方实现不由 MCP 规范替项目补齐。

协议侧公开入口与桌面内部桥接是两层。第 4 节信封不是替代 MCP JSON-RPC 的公共协议；若内部通道被定义为 MCP 自定义传输，也必须遵守官方消息方向、每请求元数据和取消规则。[正式版本兼容规则](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning) 与 [Streamable HTTP 绑定](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) 是后续实现入口；支持版本/客户端矩阵全部待验。远程公开端选定支持版本并单独验收；本机现有 SDK `1.32.1` 和 stdio 行为保持原样，不在本批升级。


## 10. 本批实现与可复核证据

- `remote-binding-port.mjs`：authority 默认 null；只接受宿主识别的不透明 handle，每次重新解析并比对 issuer/subject/client/device/grant/revision/dataset/epoch/sessionGeneration/pairing；独立 remoteConsent 与工具/工作区复核必须同步返回 true。没有生产签发器或本地 token 交换。
- `remote-read-bridge.mjs`：只收严格 JSON 字符串信封，默认关闭；单连接默认并发 1、排队 8、排队 128 KiB、单请求 16 KiB、累计 requestId 256、最长 deadline 15 秒。记录满即拒绝，不清掉旧记录放行重放；断线实例不可复活。无正文日志或结果重放缓存。
- `mcp-gate.mjs`：新增宿主专用入口，复用现有 taskExecutor/配对/全局开关/审计路径。远程失败不能降级进普通笔记工具；同步 guard、task assertCurrent、受信 deliver 在交接前复核。Promise 只返回完成状态，不返回正文。
- `task-executor.mjs`：额外提供无正文的真实执行完成信号。桥可立即向调用者报告取消/到期，但直到底层工作完成才释放并发槽，不用 Promise.race 制造无界孤儿任务。本地入口不传此信号，行为不变。
- `test/remote-read-bridge.test.mjs`：真实本地配对存储、任务服务与 SQLite，12 组内存/临时目录测试覆盖双只读工具、默认关闭/无 authority/JSON 仿造句柄、独立 consent、权限交集、禁用工具/字段、重复与冲突、容量限制、取消/排队截止/断线、底层超时槽、撤销/epoch/代际/全局开关、原 token 路径与错误脱敏。无监听、真实账号、付费模型或真实用户资料。

命令：`node --test apps/desktop-runtime/test/remote-read-bridge.test.mjs`（仓库根目录）。新增测试 12/12 通过；既有 mcp-gate、task-mcp、task-mcp-service、task-mcp-pairing、mcp-entity-inprocess、mcp-entity-output 六个文件合计 30/30 通过。单元测试通过不代表协议/认证/网络/客户端验收通过。附加尝试既有 mcp-adapter 测试时，7 项均在配对 fixture 返回空结果处失败，未进入 stdio 断言，原因未核验；本批不把该测试算通过，也不修改既有 fixture 来绕过环境限制。未运行完整桌面/UI/E2E。

生产 `index.mjs` 不导入桥、不传 authority；网页/手机仍不能连入，没有 OAuth server、HTTP endpoint、设备凭据或后台连接。deliver 仅表示同步交给当前受信接收端，不表示物理发送成功；不正确或恶意的宿主适配器不在内核可防御的网络威胁边界内，正式实现必须审核其同步/不缓存约定。
