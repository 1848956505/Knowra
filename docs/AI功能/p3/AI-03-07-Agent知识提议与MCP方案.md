## MCP 边界

- 只做本机 stdio，通过受保护配对配置绑定资料集与范围；不开放对外的回环或远程 HTTP MCP 服务。远程授权仍归 AI-07-03，认证完成前不公开。
- 默认只读；`knowledge_propose` 只能创建候选，需用户显式开启，且后置到 M5。不提供确认、删除、改写笔记、原始 SQL、任意文件/网络访问。
- 与内置 Agent 共用同一工具层，授权、引文校验、基线、幂等和审计只实现一次；owner、审核状态、目标集合等客户端参数一律不透传。
- 外部模型使用其自带订阅或密钥，费用不进知境预算账本，需有单次数量与调用频率上限；其读取的片段会发给该客户端所属厂商，`aiVisibility` 私有笔记仍不可读。

## MCP 设计

状态：2026-10-06 冻结；M1（运行端）与 M2（stdio 适配器与三个只读工具）已实现；设置页（M3）、真实客户端验收（M4）与 `knowledge_propose`（M5）尚未实现。决策见 [00 的 D20–D22](../00-总体方案与决策记录.md)。

### 形态

- Claude Code / Codex 等客户端以子进程方式启动 stdio 适配器（一个 Node 入口）。适配器**不读写数据库**，只把 MCP 的 `tools/list`、`tools/call` 转成对**运行中的知境运行端**（桌面本地运行端；网页版服务端后续再议）的本机请求，并把结果整理成 MCP 结构化内容。知境未运行时，适配器返回稳定错误码“知境未运行”，不尝试自行打开数据库。
- 运行端新增只接受“配对令牌”的入口（例如 `/api/mcp/*`），与现有基于启动 URL 的会话 cookie 分开：浏览器会话不能调用，配对令牌不能访问普通 API。入口只在上述本机 socket 上提供（不监听 TCP），每次调用都校验令牌、有效期、撤销状态和资料集。
- 运行端在数据目录（权限 0700）内创建**本机 Unix domain socket**（权限 0600，随运行端启动创建、正常退出删除），MCP 入口只在该 socket 上提供，不占用 TCP 端口，因此其他本机进程无法靠抢占旧端口冒充运行端。适配器启动时只接收一个参数：**配对文件**路径；配对文件由知境在创建配对时生成（权限 0600、位于用户配置目录），内含该配对的令牌、数据目录与 socket 路径。
- **发送令牌前先验证运行端身份**：适配器连接前检查 socket 路径的属主是当前用户且权限不宽于 0600、其所在目录属主正确；连接后先发随机 nonce，运行端须返回以“令牌验证值”（令牌的哈希，运行端本就保存）为密钥的 HMAC，适配器核对通过才发送令牌。崩溃遗留的旧 socket 文件无人监听，连接直接失败并提示“知境未运行”；他人伪造的 socket 既无法通过属主检查，也无法给出正确的 HMAC，令牌不会外发。Windows 的命名管道与权限语义不在本版范围。
- 令牌不写进客户端（Claude/Codex）的配置文件，客户端配置里只有命令和配对文件路径；令牌也不出现在命令行参数、环境变量、日志、错误信息或界面回显中。运行端只保存令牌哈希；撤销配对会删除配对文件。

### 授权模型

- 用户在设置里创建“外部 AI 客户端配对”：选择范围（一篇笔记、一个目录或整个知识空间）和有效期（默认 7 天），可随时撤销、可看到最近一次使用时间与调用次数。
- 一个配对对应一条**只读**访问授权，复用现有授权策略：范围、排除项、`aiVisibility` 私有笔记排除、资料集代际与撤销语义与内置助手完全一致；外部客户端不能创建、扩大或续期自己的授权。
- 创建时明确提示：被读取的片段会发给该客户端所属的厂商，费用不进知境预算；配对本身不代表允许创建候选。
- 令牌只存在于配对文件（0600）和运行端的哈希记录中，界面不显示；撤销或过期后立即拒绝，进行中的调用在下一次校验点终止。配对文件被他人复制等同于令牌泄露，所以文档与界面都提示妥善保管，并可随时撤销重建。

### 外发许可与清单

读取授权不等于外发许可。内置助手的外发许可、接收方与片段清单在模型请求链上校验；MCP 工具结果直接返回外部客户端，不经过那条链，所以在运行端的 MCP 入口单独做同等校验：

- **接收方语义**：外部客户端的模型厂商运行端无法确认，因此接收方定义为“该配对的外部客户端”，不套用只接受 DeepSeek 的内置契约；创建配对时用户明确确认“被读取的片段会发给该客户端所属的厂商”，该确认随配对记录保存，未确认不能创建。
- **逐调用复核**：每次工具调用在返回前重新校验配对状态（未撤销、未过期）、读取授权（范围、排除项、`aiVisibility`、资料集代际）和外发许可（配对确认仍有效，且运行端的 AI 总开关 `KNOWRA_AI_ENABLED` 与独立的紧急外发开关 `KNOWRA_AI_EGRESS_ENABLED`，即运行端的 `allowExternal`，均为开启）；任一不满足则不返回任何正文。
- **逐调用片段清单**：每次返回都记录“笔记 ID、版本、偏移范围、字节数”的清单（不含正文），用于审计与后续 M5 的已读约束；清单与实际返回内容由同一处生成，不允许工具实现绕过。
- **三个开关互不替代**：`allowExternal`（紧急停止外发）关闭时，即使 AI 开启、配对有效，三个只读工具也一律不返回资料，返回稳定错误码；“AI 提炼知识点”开关（`knowledgeProposals`）只控制内置 Agent 能否提议候选，与只读 MCP 无关，只在 M5 的 `knowledge_propose` 上额外生效。
- 实现上由 M1 提供统一的“外发出口”函数，M2 的三个工具只能经它返回结果；测试断言没有任何路径直接返回正文。

### 工具（首版）

| 工具 | 说明 | 版本 |
| --- | --- | --- |
| `notes_search` | 在授权范围内检索，返回带来源引用的片段 | M2 |
| `notes_read` | 按笔记 ID 与偏移读取授权范围内的片段（有上限） | M2 |
| `annotations_list` | 列出本篇的有效重点，分页，带来源引用 | M2 |
| `knowledge_propose` | 创建待审核候选；沿用 S2 的引文校验与 S3 的原子保存 | M5，需单独开启 |

- 工具输入输出与内置 Agent 的契约一致；客户端不能传入 owner、审核状态、授权或目标集合。错误码稳定（沿用 `AI_*`，另增“令牌无效/已撤销/已过期”“限流”“知境未运行”）。
- 内置 Agent 靠“本回合已读”约束引文；MCP 没有回合，`knowledge_propose`（M5）改为按**配对内已读片段记录**约束：只接受该配对在有效期内读到过的片段，且读取记录随原文版本校验。

### 限流与大小

外部模型不进知境预算，所以单独限制：每配对每分钟调用次数、每日调用次数、单次结果字节上限、`notes_read` 单次读取上限、并发数。超限返回稳定的限流错误并说明何时可重试，不静默截断。具体数值在 M1 用实测定，写入变更日志。

### 审计

运行端记录配对创建/撤销、每次调用的工具名、时间、结果状态与返回片段数，不记录笔记正文与令牌；用户可在设置里查看最近调用。

### M5 的额外工作

- 来源摘要新增执行方式（例如 `mcp`）与来源字段（配对 ID、客户端会话、调用 ID），不含对话内容；沿用 S3a 的做法更新契约、`web-core` 类型，并像 S3c 一样新增同步能力门禁，旧端在握手阶段被拒绝。
- 保存仍走核心操作账本，重复调用按幂等键返回同一结果；原文变化后来源显示待核对。

### SDK 与依赖

- 先试官方 MCP SDK（固定版本）。新增生产依赖会进入 `npm run audit:prod`（`--audit-level=high`）：有高危且无法在合理范围内升级时，退回手写最小 stdio 实现（`initialize`、`tools/list`、`tools/call` 三类请求加必要的通知），并在代码里标明所对照的协议版本。
- 协议版本以 M2 时核实的目标客户端支持为准，本方案不宣称某个版本是最新。

### M1 实现记录（2026-10-06）

代码在 `apps/desktop-runtime/src/mcp/`，仅桌面本地运行端；`startLocalRuntime` 装配，装配失败只让该入口不可用，不影响笔记。

- **与设计的两处差异**：① 配对文件与配对记录放在数据目录的 `mcp/`（目录 0700、文件 0600，不进备份、不参与同步），而不是单独的“用户配置目录”，这样同一目录同一把锁；② socket 默认是 `<数据目录>/mcp/runtime.sock`，路径超过 100 字节（macOS 上限 104）时改用按数据目录哈希确定的 `<tmp>/knowra-<uid>-<hash>/m.sock`（目录 0700 且校验属主），重启后路径不变，配对文件无需更新。
- **入口**：运行端在 socket 上提供 `POST /mcp/v1/handshake` 与 `POST /mcp/v1/call`；浏览器侧（会话 cookie 保护，另需请求头 `X-Knowra-MCP-Pairing: 1`）提供 `GET/POST /api/local-runtime/mcp/pairings`、`POST …/pairings/:id/revoke`、`GET …/audit`，响应只含配对文件路径，不含令牌。
- **令牌**：`knp1.<配对ID>.<32 字节随机>`；运行端存 SHA-256 哈希（即身份验证用的 verifier），比较用恒定时间。
- **身份验证**：适配器侧的 `client.mjs`（M2 的适配器直接复用）每次调用先检查配对文件（普通文件、当前用户、无组/他人权限）和 socket（socket、当前用户、无组/他人权限、目录同样），再发 nonce，运行端以 verifier 为密钥返回 HMAC，通过后才发令牌。运行端启动时在已持有数据目录锁的前提下清理旧 socket；非 socket 文件占用路径则拒绝启动。
- **授权**：创建配对时生成一条 `read: true, egress: false, recipients: []` 的访问策略（复用内置助手的范围、排除项、私密笔记、资料集代际与撤销规则）；外发许可记在配对上（创建必须 `egressConfirmed: true`）。每个配对有一条运行授权（工具集仅 `notes_search`/`notes_read`，预算 0），到期前 60 秒内续发。
- **统一外发出口**（`mcp-gate.mjs`）：工具只返回 `{ fragments: [{ noteId, title, start, end, text }], meta }`。出口逐条用 `verifyRead` 对照授权范围内笔记的**当前正文**，要求标题一致且 `text` 与 `content.slice(start, end)` 逐字相同，才生成响应与片段清单；`meta` 只允许数字与布尔值。工具无法返回授权外或改写过的内容。执行前后各复核一次配对状态、AI 总开关与 `allowExternal`，执行中撤销或关闭外发则不返回正文。
- **限流默认值**：每配对每分钟 30 次、每日 1000 次（按 UTC 日历日）、并发 2、单次响应 64 KiB（对最终发给客户端的消息生效：按“结果再序列化进文本内容”的二次转义大小加 256 字节封装预留计，所以转义、标题、偏移与信封开销都算在内）、单次最多 50 个片段、工具超时 15 秒；超限返回 `MCP_RATE_LIMITED`（含 `retryAfterSeconds`）或 `MCP_RESULT_TOO_LARGE`，不截断。实测出口加协议开销 p95 约 2.6–3.1 ms（含 60 KB 返回、60 万字节笔记），所以这些数值是为保护用户资料与客户端额度而设，不是容量上限，可在 M4 真实验收后调整。
- **过期与撤销清理**：配对过期或撤销后，含原始令牌的配对文件立即删除；运行端启动与列出配对时再清扫一次（含没有对应记录的孤儿文件），所以崩溃或重启后也不会残留。清扫只在配对记录**成功加载**后进行：记录文件不存在视为首次使用（空列表），而记录读取失败、JSON 损坏或结构无效时，整个配对能力停用（返回 `MCP_STORE_UNAVAILABLE`），不清扫、不写入、保留所有原文件；记录修复后下一次访问自动恢复，无需重启。
- **审计**：`mcp/audit.jsonl`（0600，超过 1 MiB 轮转一代），只记事件、配对 ID、工具名、状态、错误码、片段数、字节数与片段清单（笔记 ID、版本 ID、偏移、字节数）。
- **稳定错误码**：`MCP_TOKEN_INVALID`、`MCP_PAIRING_REVOKED`、`MCP_PAIRING_EXPIRED`、`MCP_AI_DISABLED`、`MCP_EGRESS_DISABLED`、`MCP_ACCESS_REVOKED`、`MCP_RATE_LIMITED`、`MCP_RESULT_TOO_LARGE`、`MCP_RESULT_INVALID`、`MCP_TOOL_UNKNOWN`、`MCP_REQUEST_INVALID`、`MCP_TIMEOUT`、`MCP_RUNTIME_UNAVAILABLE`、`MCP_RUNTIME_UNTRUSTED`、`MCP_PAIRING_FILE_MISSING`/`UNSAFE`。
- **尚未做**：网页版服务端不提供该入口；Windows 命名管道与权限未设计。

### M2 实现记录（2026-10-06）

- **SDK 决策（D22）**：先试官方 `@modelcontextprotocol/sdk`，固定 `1.32.1`（Node ≥ 18，当前最新稳定版），加在 `apps/desktop-runtime` 的 `dependencies`。核实结果：`npm run audit:prod`（`--audit-level=high`，含 `--omit=optional`）0 个漏洞，所以不退回手写。代价如实记录：新增约 75 个顶层生产依赖包（含 HTTP 传输用的 express、hono 等，本适配器不使用），`package-lock.json` 增加约 1000 行。SDK 只在 `mcp/stdio-server.mjs` 一个文件里使用，业务逻辑在与 SDK 无关的 `adapter-core.mjs`，将来若审计出现无法升级的高危，只需重写这一个文件为手写 stdio（约 100 行）。协议版本由 SDK 协商（当前支持 2024-10-07 至 2025-11-25）。
- **适配器**：`apps/desktop-runtime/src/mcp/adapter.mjs --pairing-file <路径>`，唯一参数是配对文件；不读写数据库、不含业务模块（测试静态检查其导入）；没有自己的工具表，`tools/list` 来自运行端的 `POST /mcp/v1/tools`（需通过身份验证与有效配对）；工具失败按 MCP 惯例返回 `isError` 结果，错误码与重试秒数写在文字里；stdout 只输出 JSON-RPC，stderr 不含令牌与正文；运行端重启后无需重启适配器，运行端未运行返回 `MCP_RUNTIME_UNAVAILABLE`。
- **三个只读工具**（`mcp/tools.mjs`，复用内置助手的检索、授权读取与重点列表实现，但只返回带偏移的片段）：
  - `notes_search(query, limit≤5)`：授权范围内的关键词检索（不含时间筛选与向量索引）；附加信息 `inspected`、`truncated`。
  - `notes_read(noteId, start?, end?)`：单次最多 1000 个 UTF-16 单位，不拆代理对；附加信息 `length`、`hasMore`。
  - `annotations_list(noteId, minImportance?, limit≤8, offset?)`：当前版本上仍有效的重点；片段附加字段 `importance`（枚举）、`truncated`（布尔）、`annotationId`（限定格式的标识符）；附加信息 `total`、`offset`、`hasMore`、`unavailableCount`。重点的备注、标题路径等自由文本不返回。
  - `notes_read` 读到末尾（含空笔记从 0 开始）返回空片段与 `length`、`hasMore: false`，不是参数错误；起点超过长度才报参数无效。
  - 所有参数由出口按工具公布的 `inputSchema` 统一严格校验（类型、枚举、范围、长度、必填、多余字段；`null`、数组、`"constructor"` 这类原型键都不会被当成有效值），公布的结构与实际接受的一致；客户端传入的 owner/授权/审核状态等多余字段一律被拒。新增错误码 `MCP_SOURCE_CHANGED`（读取期间笔记变化）、`MCP_TOOL_UNAVAILABLE`。
- **出口扩展**：工具可声明 `fragmentAttrs`（枚举、布尔值、限定格式的标识符三种），出口逐值校验，自由文本不能借此外发。
- **打包**：适配器目前以 `node apps/desktop-runtime/src/mcp/adapter.mjs` 运行，未并入 Mac 应用包；设置页提供的配置片段与应用内路径（通过 esbuild 打成单文件放进应用包）在 M3 处理。

## 风险

- 模型可能编造引文或偏移，必须以服务端逐字校验兜底，不信任模型回传的来源、状态或 ID。
- 引文校验只能证明引用存在，不能证明陈述被语义支持；人工审核仍是必经步骤。
- 放宽轮数后成本不稳定，靠检查点、预算与取消兜住；多笔记场景需单独评测。
- 现有提炼任务与新路径并存期间，界面须区分“Mock 提炼任务”和“Agent 提议”，不能把保存范围或提议显示为提炼成功。
