# AI-03-07 Agent 知识提议与 MCP 方案

状态：2026-10-05 规划，**尚未实现**。本文只记录方向、切片和验收，不读取凭据、不调用模型，也不代表任何功能已上线。

## 决策

| 项 | 决定 |
| --- | --- |
| 路线 | 知识由 Agent 通过受控工具读取笔记与重点后提议，不再把整篇范围打包交给一次性 API 调用。提炼任务（AI-03-01/02 的 Mock 执行路径）保留并冻结，不再接真实 provider |
| 产物状态 | AI 产出一律为 `candidate`（`sourceMode: ai`），由用户在知识候选区审核一次，确认前正式知识数量不变；不新增收件箱采纳这一道人工关口 |
| 数据外发 | 用户允许外发；范围仅限 Agent 通过工具实际读取的片段，仍遵守 `aiVisibility`、授权范围和每次外发清单（D04） |
| 费用 | 北京时间自然日硬预算目标由 10 元放宽为 20 元，知识提议任务单独放宽轮数/工具数上限；实现与核价调整归 S4 |
| MCP | 提前 AI-07-02：本机 stdio MCP adapter 与内置 Agent 共用同一工具层，不另写第二套校验 |

## 现状基础

- 笔记助手已有 Agent 循环（4 轮/6 工具）、检查点、预算预留与结算、取消，工具 `notes_search`、`notes_read` 与 4 个笔记写入提议工具。
- 提炼 v1 契约（`knowledge-extraction-contract.js`）的逐字引文校验、版本绑定与候选计划生成可复用；原子接纳服务（AI-03-02A）负责候选与证据同事务提交。
- 缺口：Agent 读不到重点（ContentAnnotation）；动作计划只认笔记类写入，没有知识候选的提议工具。

## MCP 边界

- 只做本机 stdio，通过受保护配对配置绑定资料集与范围；不开放回环或远程 HTTP。远程授权仍归 AI-07-03，认证完成前不公开。
- 默认只读；`knowledge_propose` 只能创建候选，需用户显式开启。不提供确认、删除、改写笔记、原始 SQL、任意文件/网络访问。
- 与内置 Agent 共用同一工具层，授权、引文校验、基线、幂等和审计只实现一次；owner、审核状态、目标集合等客户端参数一律不透传。
- 外部模型使用其自带订阅或密钥，费用不进知境预算账本，需有单次数量与调用频率上限；其读取的片段会发给该客户端所属厂商，`aiVisibility` 私有笔记仍不可读。

## 风险

- 模型可能编造引文或偏移，必须以服务端逐字校验兜底，不信任模型回传的来源、状态或 ID。
- 引文校验只能证明引用存在，不能证明陈述被语义支持；人工审核仍是必经步骤。
- 放宽轮数后成本不稳定，靠检查点、预算与取消兜住；多笔记场景需单独评测。
- 现有提炼任务与新路径并存期间，界面须区分“Mock 提炼任务”和“Agent 提议”，不能把保存范围或提议显示为提炼成功。
