# AI 预算与用量改造方案

状态：2026-10-08 与用户讨论并确认；B1–B5 已实现（决策 D24），B6 待做。新开对话接手时先读本文件和 [00-总体方案与决策记录](../00-总体方案与决策记录.md) 的 D05 / D23 / D24。

## 目标

1. 用户能看到知境自身的 API 消耗，以及（读得到的话）API 账户整体数据。
2. 用户自己决定是否设预算上限、设多少，而不是系统内置死。
3. 达到阈值只提醒，不一定关闭 AI 功能。

## 现状（改造前）

- 限额写死：每日 20 元（`budget-ledger.js` 的 `DAILY_LIMIT_MICROUNITS`）、单任务 2 元（`JOB_LIMIT_MICROUNITS`）。界面只有一句文字提示，没有任何用量展示。
- 预留→结算：发请求前按最坏情况预留，返回后按实际用量结算；结果未知的请求持续占额度。
- 两套互相独立的账本（D23）：Web 用云端预算权威（`/api/ai/budget/*`），Mac 用本机 `ai-budget.json`（`apps/desktop-runtime/src/local-budget-authority.mjs`）。多设备的每日额度各算各的。
- 价格表 `reviewed-price-profile.js` 用于 token → 钱的换算；原先过期即停止所有付费调用（B1 已改为只提示）。

## 三件事要拆开

| 概念 | 说明 |
| --- | --- |
| 计量 | 记录每次请求发生了什么，永远开启，不拦截任何请求 |
| 计价 | 把 token 换算成钱；价格表过期只提示，用户可覆盖单价 |
| 限额与提醒 | 用户可配置，可关闭、仅提醒或达到即停 |

## 能读到什么、读不到什么

- **知境自身消耗**：可全量记录——时间、模型、输入/输出 token、缓存命中 token（DeepSeek 响应带 `prompt_cache_hit_tokens`，可比现在“全按未命中价”更准）、估算费用、状态（成功/失败/结果未知）、所属对话。
- **账户余额**：`GET https://api.deepseek.com/user/balance`，返回 `is_available`、`balance_infos[]`（`currency` 为 CNY 或 USD，`total_balance`、`granted_balance`、`topped_up_balance`，金额为字符串）。官方文档未写鉴权要求，按现有 Key 以 Bearer 调用，**首次实现时须实测**。
- **平台累计消费、剩余额度**：DeepSeek 没有公开的用量或账单接口，无法直接读取。替代办法是定期保存余额快照，用差值推算“账户总消耗”（余额回升视为充值）。若同一 Key 在别处也使用，推算值会大于知境自身消耗，界面并排显示并标明“由余额变化推算”。

## 限额规则（B4）

| 规则 | 说明 |
| --- | --- |
| 每日上限 | 北京时间自然日 |
| 每月上限 | 新增 |
| 单次回合上限 | 取代现在的 2 元任务预留 |
| 账户余额下限 | 余额低于 X 元就停，依据真实余额，是跨设备唯一可靠的口径 |

每条规则三档：**关闭 / 仅提醒 / 达到即停**。只有“达到即停”才需要发请求前预留；其余两档只需结算后记账。选择“不设上限”需二次确认。

**默认值（已确认）**：保持现状——每日 20 元、单次 2 元，均为“达到即停”；用户可改成仅提醒或关闭。

**始终保留的技术护栏**（用户无法关闭）：Agent 单回合的轮数、工具次数、单次请求最坏费用上限，防止错误循环烧钱。

## 提醒（B5）

- 阈值默认 50% / 80% / 100%，可自定义；每个周期每个阈值只提醒一次。
- 渠道：界面内横幅 + Mac 系统通知。不做邮件和推送。导航里的“通知”入口目前标注“尚未上线”，通知中心可后置。
- 提醒内容给出操作：继续 / 提高上限 / 暂停 AI。
- “达到即停”被触发时，错误里要有“提高上限 / 本次放行”的出口，不能是死胡同。

## 其他设计点

- **价格表**：界面显示“价格核对于 XX 日”，超过 30 天提示“可能过期”；允许用户覆盖每百万 token 的输入（命中/未命中）与输出单价。档案缺失或数值无效仍拒绝调用。
- **结果未知的请求**：显示“N 次请求结果未知，按最坏情况占用 X 元”，允许对照余额后手动释放。
- **币种**：按币种分别显示（CNY / USD），不强行换算。
- **多设备**：沿用 D23，设置和账本属于各自的权威（本机或云端），界面写明“这是本机/云端的数据”。
- **隐私**：用量记录只含 ID、数字和状态，不含对话内容；余额请求只带 Key，不带任何笔记。
- **保留期**：用量明细保留 90 天，更早的只保留按月汇总。

## 实现时的注意事项

- 两套预算权威（云端 / 本机）都要实现同一接口；用量记录和限额设置放在各自权威旁边（云端设置存服务端，Mac 存本机文件，如 `ai-budget.json` 同目录）。
- 现有账本校验（`validateBudgetState`）要求日账本与预留记录严格一致，新增字段要保持向前兼容，旧账本升级时补空集合。
- 账本损坏或写盘失败时仍须拒绝付费调用（fail closed），这条不变。
- 助手状态里的 `budget.limitMicrounits` 目前被校验必须等于 20_000_000（`assistant-service.js` 的 `readiness`），改成可配置时要同步放宽这个校验和相关测试。
- V4 前端：用量面板放在设置页的模型连接区域附近（`ModelConnectionSettings.tsx`），按钮、表单控件复用 `components/ui/`。
- 请求总量上限（12KB）对字节敏感，新增请求内容要留意。
