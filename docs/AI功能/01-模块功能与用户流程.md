# 模块功能与用户流程

状态：v0.3 产品需求，2026-09-27；当前重点为对话式笔记 Agent，知识与正式训练为后续规划。实现状态见 [开发任务](04-分阶段开发任务.md)。

## 1. 统一助手体验

### 1.1 入口与上下文

AI 提供独立的助手主页面，采用会话列表、消息流与持续输入框，支持新会话、历史恢复、多轮追问和停止生成。它作为横向能力服务于 [四工作域](../知识库与试题模块/基础/模块规划.md)，不改变业务资产归属。选区操作、侧面板和模块按钮是补充入口。

- 全局助手：跨授权范围搜索、问答、继续会话、查看任务和操作记录。
- 笔记编辑器：解释选区、总结本节、整理表述、记录讨论、提炼知识。
- 笔记索引：针对已选笔记总结、建议目录/标签、查找重复内容。
- 知识库：提炼、比较、补充学习目标、发现来源问题。
- 训练：出题、组卷、按题提示、批改与复核。
- 学习档案：解释证据、建议复习、生成变式、形成学习总结。

助手简洁展示授权范围与运行位置，例如“本机 · 可检索学习笔记库”；每轮实际引用在回答中呈现，检索过程和发送明细可展开查看，费用与诊断不占据默认主界面。当前选区、整篇、目录和全库是不同范围，不因打开某页面自动授予全库读写权。切换知识空间/资料集后旧任务继续绑定原资料集；显示旧任务归属，不向新资料集写回。

会话可带入当前笔记的标题、ID、选区和版本，但正文是否发送遵守范围授权。选择“读取当前草稿”时展示未保存标识；这类内容只能产生草稿建议，不自动形成正式来源。

首次配置读取/外发范围后，用户直接提问，Agent 自行检索相关片段、必要时继续读取，再给出带来源回答；手选笔记和预览发送范围是可选限定方式，不是每次提问的前置步骤。没有相关资料时说明未找到，可给出明确区分的通用解释。

普通聊天与教学不要求调用笔记工具，也不要求引用。追问沿用会话语境，历史文本不是新的授权；再次读取仍核对当前权限和版本。长回答支持逐步显示，刷新或重新进入能恢复消息与任务实际状态。

### 1.2 结果形态

| 结果 | 示例 | 用户下一步 |
| --- | --- | --- |
| 通用对话/教学 | 聊天、讲概念、解释例子、讨论学习思路 | 继续追问，无需先选择笔记或提供来源 |
| 带来源回答 | “这几篇笔记对 LU 分解的条件有哪些表述？” | 打开引用、继续提问、另存笔记 |
| 内容草稿 | 一篇学习总结或改写段落 | 编辑、采用、另存或放弃 |
| 变更方案 | 5 篇笔记的改名/移动清单、正文差异 | 检查影响并执行；目标变化则重新预览 |
| 待审资产 | 知识候选、目标候选、题目草稿、暂定批改 | 在对应模块核对、确认或退回 |

任务进度、生成完成、保存成功、云端同步完成是不同反馈。最终消息必须给出真实产物链接、写入位置和同步状态；没有落库就只能说“已生成草稿”。

### 1.3 共用交互状态

未配置 → 可配置入口；网络不可用 → 保留手动功能；排队/运行 → 可取消；待确认 → 可预览；来源变化 → 比较版本；失败 → 原因及适用的重试；超额 → 调整范围或预算。

长任务可退出面板，回到任务记录继续查看。正文流式显示只用于预览，不边生成边覆盖笔记。重试复用原任务输入，选择“按最新内容重新生成”才建立新任务。

复用 V4 的 `Button`、表单、`SearchBox`、`Menu`、`Dialog` 和工作区面板。独立滚动，键盘可操作；运行状态通过可访问状态区播报。首期不开展全站视觉重构。

## 2. 笔记库：阅读、记录与整理

| ID | 功能 | 输入与输出 | 边界 | 阶段 |
| --- | --- | --- | --- | --- |
| N00 | 通用聊天与教学 | 问题与对话上下文 → 自然语言解释 | 不强制笔记引用；模型知识与用户资料依据区分 | P1 补齐 |
| N01 | 当前笔记/选区问答 | 所选文本 → 回答与来源片段 | 区分原文支持与模型解释，资料不足明说 | P1 |
| N02 | 跨笔记检索与比较 | 问题、授权库/目录 → 自动搜索、阅读、摘要、差异及引用 | 显示实际命中的笔记，不能声称看过全库 | P1 |
| N03 | 对话记成笔记 | 用户选定的讨论 → 标题、Markdown、目录建议 | 明确新建，保留生成来源；不把模型推测写成已核实事实 | P2 |
| N04 | 追加学习记录 | 指定笔记与记录 → 指定章节或末尾追加 | 有版本基线、幂等键；不重复追加 | P2 |
| N05 | 局部改写与校对 | 明确段落 → 差异预览 | 保留公式、代码、附件和标注语义；冲突不强行覆盖 | P2 |
| N06 | 改名、标签、移动 | 选定笔记 → 目标清单与理由 | 路径重名、跨空间限制由领域服务检查 | P2 |
| N07 | 重复笔记与合并建议 | 限定集合 → 重复/互补报告 | 首期仅建议，可生成合并新稿；不自动删除源笔记 | P7 |
| N08 | 图片/PDF/语音转记录 | 用户选择的附件 → 可编辑提取稿 | 记录页码/时间段与识别不确定项，不能假装已识别未读图片 | P7 |

“AI 记录笔记”首期指用户主动要求保存文本、讨论或整理稿。持续录音、屏幕监控、读取其他应用和后台自动日记不在默认授权内。

### 2.1 示例：将讨论追加到学习笔记

1. 用户说“把刚才关于选主元的结论追加到《LU 分解》”。
2. 按授权目录查找；存在同名笔记时由用户选定，不按标题猜测目标。
3. 读取保存版本，生成追加内容，检查当前编辑器是否有未保存草稿。
4. 根据权限策略执行或展示预览；若有草稿，先由用户保存，或把建议作为待合并内容，不能清掉草稿。
5. 在提交时检查版本，写入、版本/标注维护及动作回执一次提交。
6. 返回笔记链接与“已保存到本机，待同步”等实际状态。响应丢失时查询原动作，不重新追加。

### 2.2 草稿与范围

正式引用和知识提炼默认使用已保存内容。用户愿意分析草稿时，为任务生成不可变临时快照并标注 `draft`；该快照不得冒充 `NoteVersion`。若随后要入知识库，先保存笔记并重新绑定来源、验证引文和审核。

### 2.3 示例：不选笔记也能问

1. 用户已授权“学习笔记库”的读取和相关片段外发，输入“我之前对卷积与全连接层的区别记了什么？”
2. Agent 搜索相关笔记，读取命中片段；发现不足时，在预算内换关键词或继续读取。
3. 消息区展示简洁进度，回答引用具体来源；不要求用户逐篇挑选或逐次确认发送清单。
4. 用户追问“再举例讲清楚”，助手结合上文教学；用户说“记成新笔记”后转入 P2 的受控新建流程。

### 2.4 非正式聊天练习

用户可说“根据这些笔记考考我”，直接在聊天中生成问题、作答和获得反馈，不强制先建知识点。此类内容不会自动生成正式试卷、成绩、掌握度或学习证据。未来若提供采纳入口，必须重新经过对应领域流程。

## 3. 标注与知识库：从资料到可靠候选

### 3.1 提炼主流程

选择选区/重点/章节/笔记 → 预览实际包含、排除及遗漏内容 → 显式启动 → 展示进度 → 原文对照的候选列表 → 修改或确认 → 保存知识及来源。

标注只是入口之一。没有重点也可从选区或整篇提炼；不能把“已标重点”视为“已调用 AI”。

首接复用已有提炼 v1，输出标题、核心陈述、类型和逐字引文；任务结束时事务保存候选与来源。自动保存候选不等于正式确认，确认前正式知识数量不变。

已有契约不发送 `contextSegments`。需要额外阅读上下文时须另做 v2：区分可引用片段与仅供理解片段，预览发送清单，排除内容仍不得通过上下文绕回。不能直接扩充 v1 请求而保留原契约号。

### 3.2 知识能力目录

| ID | 能力 | 结果与规则 | 阶段 |
| --- | --- | --- | --- |
| K01 | 忠实提炼 | 候选 + 原文 + 来源状态；不填充不存在的结论 | P3 |
| K02 | 候选解释与目标建议 | 解释放独立建议；目标包含可观察动作、条件与要求 | P3 |
| K03 | 同义、互补与矛盾发现 | 分类别展示已有知识及依据，不自动合并/覆盖 | P3 |
| K04 | 增量提炼 | 展示新增、无变化、建议修订；忽略项在相同输入下不反复出现 | P3 |
| K05 | 来源变化辅助处理 | 定位差异、建议重绑或修订；旧证据保留，不能用相似位置冒充原引文 | P3 |
| K06 | 知识合并/拆分 | 展示目标、题目、来源和证据影响，用户确认迁移方案 | P7，先补领域服务 |
| K07 | 主题/关系建议 | 候选关系与理由，确认后进入正式关系数据 | P7 |
| K08 | 知识库问答 | 优先已确认知识，明确显示待修订及争议 | P3，语义检索增强在 P7 |

忠实提炼与扩展解释提供不同模式。扩展内容不能伪造原文引用；来自模型自身的补充标注“未外部核验”。首版正式提炼只支持有来源的 v1 候选，不通过伪造 `manual` 来源绕过校验。

## 4. 学习目标与考试考点

AI 根据知识提出“能够解释/计算/比较/证明什么”的候选，不以“掌握某章节”充当可评分目标。知识确认和目标确认可在同一面板完成，但各自保持独立状态。

- O01：为已确认知识补齐目标、认知层级和可观察完成标准（P3）。
- O02：发现重复、含糊或过大的目标，提出拆分建议（P3；正式拆分迁移依赖 P7）。
- O03：根据用户提供的大纲/历年题提出考试考点和权重建议（P4）。
- O04：比较目标覆盖与现有题库，列出尚无题目、来源待修订或仅有同类题的目标（P4）。

“用户设为重点”“大纲明确要求”“历年题支持”“AI 建议”必须分开。没有外部依据时不标成“官方必考”或“高频考点”。修改已确认目标后，沿用现有失效链路复核相关题目。

## 5. 试题库：生成与审核

### 5.1 正式流程与聊天练习的边界

正式卷子与日常测试在试题库专属页面运行：选择已整理/确认的知识及目标，配置范围、题型、数量和难度，点击“生成试卷/日常测试”，系统负责出题、校验、快照、作答、提交、批改、复核及报告。流程状态、失败续跑和答案权限由程序控制，不由聊天措辞或模型自由计划决定。

“先整理知识，再正式出题”为当前暂定前置；知识库与试题库完善后再冻结具体配置。对话练习遵守 2.4 节，不代替正式流程。一键发起不等于无条件发布、免质量检查或免批改复核。

### 5.2 题库资产生成与审核

选择已确认目标 → 指定题型/数量/难度 → 预览来源与范围 → 生成题目草稿 → 结构和质量检查 → 原文/目标对照审题 → 采用或确认入库。

题目输出包括题干、选项（适用时）、参考答案、评分细则、解析、目标映射及真实来源。AI 不能自由指定审核状态、正式 ID 或跨空间来源。

| ID | 能力 | 关键边界 | 阶段 |
| --- | --- | --- | --- |
| Q01 | 按目标生成题目 | 先支持现有题型，明确难度只是预估 | P4 |
| Q02 | 生成变式 | 保留考查目标，改变数值/情境；重新解题校验 | P4 |
| Q03 | 题目质量检查 | 可解性、条件完整、选项/答案、目标一致、评分、来源及重复 | P4 |
| Q04 | 答案与评分细则建议 | 用预先定义的得分点映射到目标，支持等价表达 | P4 |
| Q05 | 已有题目改写 | 生成修订预览；不改变历史试卷快照 | P4，历史快照在 P5 |
| Q06 | 题目导入与识别 | OCR/格式解析后人工核对，题目来源可追溯 | P7 |

结构校验由确定代码完成；生成后的语义检查使用独立检查步骤，但不能声称另一遍模型审查已证明答案正确。计算结果可接受受限的确定性计算器验证；任意用户代码执行与沙箱是后续独立项目，不随 AI 出题自动开放。

功能需求建议包含填空题，但当前领域枚举没有该类型。P4 的初始试用复用四种现有题型，P5 达标版补齐填空字段、输入和评分规则；不能只换 UI 标签冒充已支持。

## 6. 组卷与作答

E01 组卷：AI 建议蓝图，规则程序验证目标覆盖、题型、数量、总分及必须覆盖项。优先选已有合格题，缺口按用户偏好生成；无法满足时列出缺口供调整，不悄悄改条件。

E02 自测：默认只展示范围和卷面结构，隐藏答案。用户“使用本卷”是采用当次临时题，不等于全部确认为长期题库资产。答案曝光记录要跨助手、预览和答题入口统一。

E03 正式训练：先固定题干、答案、评分细则、目标映射与来源快照，再建立 Attempt。作答自动保存、失败保留草稿、重复提交幂等。答题服务不能把隐藏答案发给尚未获准查看的前端或助手工具。

E04 分级提示：练习可给线索、思路和答案；每次帮助记录级别。正式测试默认禁止答案工具，决定查看后该题记录辅助状态。不得把使用 AI 提示后的答对算作独立测验。

这一阶段依赖 ExamBlueprint、ExamQuestionSnapshot、Attempt、Response 等新的领域实现，不能仅用聊天记录拼接模拟正式训练。

## 7. 批改、学习档案与复习

G01 客观题先采用确定规则。主观题 AI 按锁定的评分细则给出逐得分点结果、引用、缺失项和不确定项，服务端检查分数范围及总和。

G02 无警告的 AI 结果可由用户一次性采纳；多解、来源冲突、条件不足和识别失败单独待复核。不能只看模型自报置信度。

G03 用户可提出异议、请求重评或人工修正；保存原判、修订与采纳关系。重评替换有效证据，不额外算一次训练。题目作废时调整有效分母和证据，保留原卷。

L01 学习档案用有效证据解释“哪些目标已测、哪些仍缺依据”。确定规则负责掌握状态计算，模型仅解释结果与建议行动。

L02 错题分析给出“可能的误区”候选，不凭一次错题贴永久标签。错误答案不能自动转化为正确知识。

L03 复习建议包含目标、理由、原文入口、动作、题量与日期。用户接受、改期、暂缓或取消；限制每日负担，相同目标去重。阅读完成只结束阅读任务，新的有效作答才能改变能力证据。

L04 按真实记录生成学习总结，可另存为笔记；总结本身不反向充当学习证据。

## 8. 检索、知识图谱与后台扩展

- 语义检索：在关键词不足时引入，按资料集/空间/版本过滤，返回实际引用；索引过期不得用旧摘要假装当前事实。
- 知识关系：AI 提议先修、对比、组成等关系，用户确认后保存；图谱只展示正式数据。图邻居不自动进入出题范围。
- 多模态：图片、PDF、录音分别建立提取、质量标记和原附件定位。手写公式、复杂图形和代码运行分别验收。
- 后台任务：用户明确订阅的定期整理、待复核提醒、复习安排可后置。每项规则限定范围、费用、频率和权限，支持暂停；不得借索引更新默默生成或改写资产。
- 外部 MCP：以搜索、阅读、创建和追加等共用工具开始，仍遵守 Knowra 范围授权、审核和动作回执。外部 AI 不能绕过正式知识确认和考试答案保护。

## 9. AI 失效时的用户体验

AI 关闭、未配置、超时、预算耗尽或局部页面失败时，只影响 AI 对话/生成/批改等能力。主外壳、笔记编辑与保存、普通搜索、已有知识/题目/试卷阅读及已有作答保存仍可使用；批改暂不可用不能丢失已提交答案。已保存 AI 产物可继续手动维护。AI 状态与重试入口留在相关局部，不用全屏错误阻断其他页面。

未来待办/打卡模块具备正式服务后，可以注册创建任务等工具；不能提前让 Agent 写入不存在的领域，也不因拥有工具而默认开始后台自动执行。
