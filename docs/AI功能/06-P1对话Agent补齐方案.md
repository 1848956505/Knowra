# P1 对话 Agent 补齐方案

状态：2026-09-27 新增设计；实施进度以 [04](04-分阶段开发任务.md) 为准。需求依据见 [00](00-总体方案与决策记录.md)，验收编号见 [05](05-验收评测与发布方案.md)。

## 1. 为什么需要补齐

旧规划虽提到“继续会话”和“授权范围内读取”，但后续 P0 外发决策、P1 固定输入契约和 UI 验收都偏向逐次选择笔记、预览清单、确认发送的单次问答。多轮消息、模型自主调用检索工具、一般聊天和插件故障隔离没有成为明确阶段出口。已有实现主要兑现了这个收窄后的范围，因此不能简单归因于开发没有理解一句“AI 助手”；需求文档和阶段验收需一起纠正。

单次问答的失败诊断与产品形态差距是两件事。修好输出格式、token 上限或供应商连接，并不会自动得到 Agent；换成聊天气泡而保留固定两条消息、空工具和强制选笔记流程，也不满足本方案。

## 2. 复用与差距

| 能力 | 旧 P1 基础 | 本轮目标与处理 |
| --- | --- | --- |
| 接入 | Gateway、凭据桥、兼容服务、Mock | 复用；分别实测普通文本、流式与工具调用，不从模型列表成功推导工具可用 |
| 运行 | 私有任务、取消、用量与预算、恢复 | 复用；补会话关联、工具结果回传及有界循环，预算覆盖所有轮次和重试 |
| 授权 | 固定任务范围、发送预览与确认 | 保留旧记录；新增持续库/目录读取与相关片段外发策略，逐请求服务端校验，无逐问确认 |
| 检索 | 固定范围的关键词召回、版本片段、引用校验 | 包装为模型可调用搜索/阅读工具，可补充检索；后续可替换混合/向量检索 |
| 交互 | 单次提问表单、最近任务、轮询详情 | 改为会话列表、消息流、持续输入、追问/停止/恢复；明细收进辅助面板 |
| 回答 | 资料问答的结构化结果与引用 | 通用聊天正常文本；资料结论有引用，混合解释区分依据；不强制所有回答含笔记来源 |
| 隔离 | 模块和任务基础不等于完整故障隔离 | 补可选装配、前端错误边界、隔离执行器、资源限额、私有存储失败处理及故障注入 |
| 写入 | 旧 P1 没有完整笔记写工具 | P2 接入创建/追加/改写/整理；AI 通过核心服务和原子回执执行 |

上述是范围对照，不是新增运行验收报告。旧 P1 报告的环境、样本、发布记录保持原意；未来每项补齐需新增可复现证据。

## 3. 补齐工作包

任务编号使用 `AI-01-Rxx`，不重编号旧任务，也不将旧验收倒签为新成果。

| 任务 | 具体交付 | 验收关联 |
| --- | --- | --- |
| AI-01-R01 | 可选插件装配、无 AI 能力实现、前端按需加载/错误边界、独立执行进程与受控业务桥；界定核心/私有存储及资源限额 | V45–V48、V53 |
| AI-01-R02 | v2 读取/外发策略、逐运行 grant、逐请求 manifest；权限撤销、历史内容外发复查与旧授权不扩权迁移 | V03、V06、V08、V43–V44 |
| AI-01-R03 | 会话/消息、工具 call/result、任务关联、序号/幂等、执行端恢复与历史 v1 只读回看 | V39、V41、V44 |
| AI-01-R04 | 有界 Agent 循环、普通聊天模式、搜索/阅读工具、补充检索、来源引用、取消与预算；模型工具能力实测 | V39–V43、V49 |
| AI-01-R05 | 对话主页面、首次范围设置、来源卡/可展开检索记录、停止/重试/恢复；按钮和上下文引用作为可选入口 | V39–V42、V45–V46 |
| AI-01-R06 | 可替换检索接口、关键词基线及召回样本、版本/权限过滤；定义后续 embedding 接入、异步索引和清理边界 | V40、V42–V43、V47 |
| AI-01-R07 | Web/桌面真实页面、各存储、真实模型小样本、隔离故障注入与预算回归；发布开关与回退记录 | V39–V49、V53；回归 V01–V25 受影响部分 |

R06 先建立接口与关键词基线，R04 才能完成检索接入；向量数据库不是该任务必需产物。R04 已接入最小关键词接口，召回样本和索引扩展仍由 R06 验收。R05 使用同一契约集成，R07 验收真实组合；各任务进度以 04 为准。

## 4. 主交付场景

1. **直接聊天**：新会话输入“解释梯度下降”，无笔记选择也可回答、举例、继续追问，不为凑引用调用笔记工具。
2. **问自己的资料**：已授权学习笔记库后输入“我记录过哪些防止过拟合的方法”，Agent 自动检索、阅读并引用片段，必要时补查，用户不逐次确认发送预览。
3. **承接追问**：“和我之前记的正则化有什么关系？”能承接指代，权限仍实时复核；刷新后消息与引用可恢复，不能把旧版本冒充现有正文。
4. **资料不足**：说明检索范围与未找到的内容，可提供区分明确的通用解释；达预算上限正常停止，不扩大权限或无限重试。
5. **AI 不可用**：关闭 AI 或让隔离进程卡死/退出，笔记新建、编辑、保存、普通搜索及同步仍可用。AI 中已保存的笔记仍可打开。
6. **随后 P2**：“将刚才讨论保存为新笔记”或“追加到某笔记”按明确指令执行；“重写这几篇笔记”先给差异和影响。目标歧义先消歧、草稿/版本冲突不覆盖。

## 5. 迁移与范围

- P0 `contracts/`、样本及验证脚本保留 v1，不在文档修订时顺手改变 schema/哈希。新字段和行为通过 v2 契约、增量迁移与兼容测试引入。
- 旧任务作为历史任务回看，不伪造不存在的会话/工具轨迹。新持续策略由用户建立，旧的选区授权不能自动变成全库读取或新供应商外发授权。
- 旧入口可短期作为诊断或显式指定范围的辅助入口；发布新主体验后不得仍让所有聊天绕回旧确认表单。
- 不扩展日预算；沿用 10 元/北京时间自然日、每任务最多预留 2 元及现有 P0 初始限额。调整工具轮数须重新评测，不靠提高预算掩盖循环问题。
- AI 插件拥有私有运行状态；核心领域拥有业务数据、来源与最小操作回执。正式产物不依赖插件存活。
- 当前不实现完整知识整理、关系图谱、正式试卷、批改和待办打卡；预留工具注册与固定工作流接口即可。向量检索按质量单独推进，MCP 不作为笔记 Agent 发布前置。

## 6. 完成判定

P1 补齐以多轮对话、授权范围内自动检索、真实引用、运行恢复与故障隔离为共同出口。只有表单换布局、一次真实回答成功、模型宣称支持工具或手动挑一篇笔记成功均不算完成。P2 的写入与管理另外验收，不把 P1 只读 Agent 说成完整读写 Agent。
