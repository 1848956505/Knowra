# 验收、评测与发布方案

状态：v0.3，2026-09-27 新增 Agent/故障隔离门槛。P0/P1 历史样本和验收仍按原范围记录；本次没有执行新产品验收，以下要求不是通过结果。

## 1. 分层验证

1. 纯契约：schema、偏移、引用、范围、状态机、计划哈希、预算和评分规则。
2. 应用服务：工具复用领域校验、CAS、幂等、批量事务、授权复核及来源生命周期。
3. 持久化：JSON、SQLite、真实 PostgreSQL 各自测试迁移、重启、回滚、并发和恢复。
4. HTTP/运行服务：实际响应封装、SSE 重连、桌面路由/会话、跨空间和答案访问控制。
5. V4 页面：任务状态、差异、审核、草稿、键盘操作及来源跳转；检查真实页面。
6. 模型质量：固定样本、人工对照、费用和延迟；mock 通过不等于真实模型合格。
7. 端到端：用户指令→生成→保存→重载回读→同步后目标端回读；不以“已完成”聊天文本为证据。

| ID | 场景 | 必须观察到的结果 |

| V05 | 大输入、排除段、emoji、公式、代码 | 不静默截断或回带排除内容，不切断代理对，遗漏明确 |

| V12 | 预览后用户编辑、目录变化或撤销权限 | 原批准不适用新计划，提交失败且保留建议 |
| V13 | 批量第 N 项失败 | 小批量事务整体回滚，动作状态不显示全成功 |

| V15 | 知识提炼伪造来源、错位引文、非法确认字段 | 整体拒绝；实际片段可定位，确认前正式知识数量不变 |
| V16 | 重跑、忽略项、个人解释、来源已改变 | 增量建议不覆盖个人编辑；旧来源标待核对，不伪装当前 |
| V17 | 未确认/归档/删除目标用于正式出题 | 被阻止并说明；模型不能偷扩出题范围 |
| V18 | 题干缺条件、错答案、多解、分值不符 | 隔离为待修复；机器检查不冒充人工确认 |
| V19 | 5 道题不能覆盖 20 个目标、总分冲突 | 显示缺口供调整，不宣称全面评估 |
| V20 | 双 worker、租约到期、恢复旧备份 | 一个合法 attempt 有提交权；旧 worker/epoch 被拒绝 |
| V21 | JSON/SQLite/PostgreSQL 写盘失败 | 原资产完整，任务与动作可诊断，恢复后不重复提交 |
| V22 | 日预算竞争、工具循环不停止 | 服务端限额生效，费用预留原子；不无限重试 |
| V23 | 日志/缓存/打包/导出检查 | 无密钥；默认无完整正文和模型响应，UI 只显示安全元数据 |
| V24 | 本地写入后同步暂停、旧云端能力不足 | 本机已保存与待同步区分；不把任务同步成另一次执行 |
| V25 | 桌面/Web 同改笔记，资料集切换 | 沿既有冲突恢复；旧任务不会写到新资料集 |
| V26 | 删除/永久清理/版本裁剪与运行中任务竞争 | 复查引用/墓碑，阻止迟到复活；保留必要历史并说明清理边界 |
| V27 | 正式试卷建立后修改题库/来源 | 当次题干、答案、分值、rubric 和来源快照稳定 |
| V28 | 答题中断、到时离线、重复交卷 | 草稿保留，原 Attempt 恢复；仅一个提交；失败不假称成功 |
| V29 | 自测时通过助手/搜索/MCP 问参考答案 | 未获准不返回；允许查看时写曝光事件，结果不算独立证据 |
| V30 | 临时题使用与长期题库确认 | 采用卷面不自动确认所有题目；长期入库另行审阅 |
| V31 | AI 批改分数越界、得分点不一致、不同解法 | 规则拒绝或转待复核；AI 自报高置信度不能绕过 |
| V32 | 综合题无法独立归因到多个目标 | 保留总分和综合说明，不虚构各目标精确得分 |
| V33 | 重评、人工改判、题目作废 | 修订可追溯；旧证据被替代/撤销，目标重算且不双计 |
| V34 | 未作答、提示后答对、自评、阅读完成 | 不伪装独立证据；状态说明与原始记录一致 |
| V35 | 重复复习建议、限额、改期和取消 | 同目标合并、日负担受限，不无限增加任务 |
| V36 | 索引滞后/删文/改权后检索 | 即时停止使用不适用条目；重建不复活已清理内容 |
| V37 | 外部 MCP 伪造 owner/approve/tool 参数 | 受同一授权和动作校验；远程无身份映射不准入 |
| V38 | OCR/转写遗漏或模糊原文 | 标识不确定项及实际处理范围，可回原附件核对 |

安全、数据完整性和审核不变量属于硬门槛；不能以平均通过率掩盖一次越权或数据丢失。

M1（2026-10-06）已用 `apps/desktop-runtime/test/mcp-pairing.test.mjs` 覆盖 V59、V60、V61、V64、V65 的运行端部分（含伪造/旧 socket、权限异常、执行中撤销与关闭外发）；M2 用 `mcp-adapter.test.mjs`（真实 stdio 子进程、官方 SDK 客户端）覆盖 V62 与 V60 中三个工具的越权/参数伪造场景；M3 用 `ExternalClientSettings.test.tsx`（组件）、`mcp-pairing.test.mjs`（概览接口）、`mcp-adapter.test.mjs`（打包后的单文件适配器）和一次真实运行端上的浏览器走查（创建 → 连接方式 → 真实 stdio 调用 → 撤销）覆盖 V59 的设置页部分；V63（真实 Claude Code、Codex）待 M4。

V39–V49、V53 为 P1-R/P2 相应准入；V54–V65 为 AI-03-07 准入（V58–V65 为 MCP）；V50–V52 是未来训练准入，不宣称当前实现。故障测试须注入真实边界（进程终止、超时、私有存储失败、模块加载失败），不能只 mock 返回 unavailable。记录同一环境 AI 开/关/故障时核心读写与同步的基线、p95 和最大阻塞；资源限额及允许退化阈值在 R01 冻结，未冻结/未测不能通过。

通用聊天可用性、资料引用正确率、正式结构化产物校验分别评估。通用聊天不纳入“必须有来源”分母；资料型回答的引用/权限检查不能放宽。流式体验、会话恢复和独立核心可用性必须真实页面验证，不能仅检查页面有输入框。

## 3. 模型评测集

首版已在 [P0 样本集](p0/AI-00-04-样本与门槛.md)准备 80 条有版本的合成质量样本和另 20 条对抗样本，后续逐阶段扩充。数量和质量阈值为工程门槛，不宣称有统计学充分性。

| 集合 | 建议数量 | 内容 |
| --- | --- | --- |
| 读取与引用 | 20 | 中文、多笔记对比、无答案、来源矛盾、公式/代码、排除内容 |
| 工具选择与写入计划 | 15 | 同名目标、明确追加、模糊整理、越范围、重复重试、无效参数 |
| 知识提炼 | 15 | 逐字引文、无可提炼内容、互补/冲突、代词缺上下文、增量 |
| 题目生成 | 15 | 不同题型、目标偏离、错误选项、欠缺条件、rubric 与来源 |
| 批改与证据 | 15 | 等价答案、错误参考答案、部分分、多目标、帮助曝光、改判 |

P1-R 另建版本化 Agent 场景集，覆盖无来源聊天、多轮指代、自动跨笔记检索、追加检索、无命中、权限撤销及旧授权迁移；故障注入集覆盖 V45–V49、V53。保留 P0 原样本和哈希，新样本单独记录版本，不用原 80+20 的通过结果替代新出口。

另建不少于 20 条授权/提示注入/生命周期对抗样本，不与上述质量平均分抵消。写入正确性主要依靠确定性测试；模型评测考查能否选对允许工具和提出恰当计划。

每条样本记录 fixture ID、输入范围、期望行为、禁止行为、人工参考及评分规则。开发集与保留集分开；不在提示词中包含验收答案。正式用户资料需要独立授权后才可入评测集。

## 4. 指标与建议门槛

| 指标 | 初始门槛/观察目标 | 解释 |
| --- | --- | --- |
| 越权读写/未审正式确认/丢失覆盖/重复业务写 | 固定验收集 0 次 | 硬门槛，不接受“偶发”作为正常行为 |
| 已展示精确引文的引用有效率 | 100% 通过代码校验 | 只证明引用存在，不证明语义支持 |
| 结构化任务有效输出率 | 保留集 ≥95%，不合格结果 100% 阻止落库 | 首次通过率与修复后通过率分别报告 |
| 带来源回答语义支持率 | 人工逐陈述评审 ≥95%，严重捏造 0 次 | 分母为需要来源支持的断言；模型补充单独标识 |
| 正确识别无答案/冲突 | 相关样本 ≥90% | 不能用全部拒答换取高引用正确率，同时统计可回答问题完成率 |
| 题目可用率 | 人工审阅 ≥90%，未解决重大缺陷不发布 | 统计可解、答案、目标、来源、评分细则；难度仅估计 |
| 主观评分误差 | 对照评分归一化平均绝对误差建议 ≤0.10 | 仅为试运行阈值；大偏差/争议项全部复核，报告分布而非只报均值 |
| 成本 | 每场景记录每次及每个采纳产物成本 | 包括失败、重试与未采纳结果，金额阈值在 P0 确认 |
| 延迟 | 记录首事件、首文本、完整结果的 p50/p95 | 初始体验目标：排队反馈 ≤1 秒；完整时延依模型基准设置 |

语言类指标由用户或明确指定的审阅者评审；二次模型判断只辅助筛查，不冒充独立人工验收。质量不足时降低开放范围，例如仅草稿模式、减少题型、要求逐题审核。

每次更换模型、提示词、schema、工具描述、检索/切片策略至少跑受影响保留集。小样本的 100% 只是该集通过，不表述为生产绝无错误。

## 5. 特殊故障与恢复试验

在任务创建、供应商已响应、业务事务提交前、提交后但响应前、同步发送后分别模拟中断。每次重启后检查：

- 业务对象数量与内容符合预期；无部分候选、孤立来源或重复追加。
- job/attempt/action 回执与真实持久状态一致，不依赖 UI 内存。
- lease、grant 和资料集 epoch 被重新核查；已撤销/已取消不会续写。
- unknown 调用费用不被清成 0；只恢复可确定的状态，必要时显示人工重试入口。
- 恢复草稿、旧版本、附件引用与同步队列保持可用。

桌面与 Web 同时编辑、旧客户端连接新版服务、旧云端接收新 provenance、资料集备份恢复均须独立覆盖。

## 7. 发布与回退

1. 迁移和备份恢复先在隔离资料集验证；能力开关默认关闭，部署新版不自动开始任务。
2. 先开启只读，再开放明确新建/追加，随后开放预览管理、提炼、出题和批改。
3. 每个场景独立开关、可用模型和预算。未支持同步/端侧写入时不显示可执行按钮。
4. 发布前核对旧客户端行为、提供商连通、数据库/桌面恢复和日志脱敏；保留停止任务/禁止新写的管理员入口。
5. 出现越权、丢失数据或审核绕过立即关闭受影响写入能力，保留队列和证据定位问题。只读能否继续按实际故障决定。
6. 回退优先关闭场景与切回已评测模型/提示词。数据库采用兼容性增量迁移，不直接降级 schema 或覆盖用户新数据；不兼容代码回退须先停 worker 并评估数据恢复。
7. 正式产物不会因关闭 AI 被删除；没有 AI 时仍能阅读、编辑、审核已有资产并查看历史。
