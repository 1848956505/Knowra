# AI-01-R04 有界对话 Agent 与工具循环

日期：2026-09-27。状态：后端本地实现与合成回归完成；`deepseek-flash` 合成工具调用和一轮端到端引用已实测。会话主页面、正式 Mac 包、真实 PostgreSQL、检索质量集及跨环境故障验收分别归 R05–R07。

## 交付

- `POST /api/ai/conversations/:id/messages` 的 `execute: true` 显式启动任务，提问最多 3800 个 UTF-16 单位；省略时仍可只落盘为 `staged`。`POST /:id/turns/:turnId/retry` 显式重试中断/失败任务，原取消入口中止在途请求。提交幂等键不因 `execute` 改变。
- 无 `requestedPolicyId` 的普通聊天直接使用文本模型请求，并保留安全的最近会话消息；不会读取笔记，也不会制造来源。带策略的任务每次领取后派生 R02 运行 grant；检索、阅读和每次模型发送都复核当前策略、笔记版本与逐请求 manifest。撤销、移动和来源变化按失败关闭。
- `notes_search` 提供可替换的只读关键词检索接口，最多检查 300 篇当前授权笔记，超出 20 万 UTF-16 单位的单篇暂跳过，返回至多 8 个命中；发生跳过或候选截断时把覆盖不足写入本次发送说明与清单。`notes_read` 限定单次 1000 个 UTF-16 单位。检索结果和阅读范围都生成版本、内容哈希、偏移和摘录哈希。模型工具调用及成功/失败结果写入 R03 轨迹；无效工具参数不会扩大读取范围。
- Agent 每轮最多 2 个工具调用，最多 4 轮、6 次工具调用、8 次模型尝试、10 分钟。已有来源但工具没有新增结果时，下一轮移除工具定义并要求回答；无命中最多补查一次。最终 JSON 引用必须能在本次实际发送的来源中逐字找到；无命中允许空引用，历史来源在追问时重新核验。
- 每次模型调用先写尝试记录和预算预留，再复核任务租约及 R02 manifest；已知用量按实结算，发送状态不确定保守占额。取消后拒收迟到答案；重启将过期租约转为中断，并将未结算尝试按未知费用恢复。JSON 私有状态由 v3 升为 v4，仅增加模型尝试集合；SQLite/PostgreSQL 的通用会话表无需改 DDL。

2026-09-27 使用**纯合成**提示词和临时合成笔记实测本机已配置的 `deepseek-flash`：工具能力探测返回 `finishReason=tool_calls` 和 `notes_search`；首次端到端样本暴露重复搜索，第二次暴露模型给阅读工具的过长范围，随后加入无新增来源时的最终回答约束与阅读范围裁剪。修复后端到端样本为 `succeeded`，2 次模型调用均有已知用量并结算，2 次 `notes_search`，最终引用 1 条。共计这些探测与调试调用的北京日权威预算账本显示支出 20,520 微元（0.02052 元）、悬挂预留 0；失败尝试也包含在支出内。没有发送用户笔记正文、密钥或原始模型回答至测试日志。

## 后续边界

R04 提供后端 Agent 契约和真实小样本，不等于完整 P1 发布。R05 需接入会话主页面及可见的执行/来源状态；R06 需建立召回样本、300 篇候选上限下的覆盖说明与索引替换边界；R07 需验证正式 Mac 包、真实 PostgreSQL、真实页面、预算并发和 R01 隔离故障门槛。目前 Agent 的授权/预算编排在受信宿主执行，供应商网络调用在隔离子进程；R07 须实测新 Agent 对核心 HTTP 延迟与故障隔离的影响。
