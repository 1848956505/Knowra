# AI-01-R06 授权检索接口与关键词基线

日期：2026-09-28。状态：本地实现、合成召回集及授权/版本/故障回归完成；真实 embedding、异步索引与跨环境模型质量验收尚未执行。

## 交付与运行边界

- Agent 的自动检索及 `notes_search` 共用 `createAuthorizedRetrieval`。默认运行方式为 R04 关键词扫描；将来只可通过受信装配传入 `retrievalCandidates.searchCandidates`，不能把候选源直接当作可外发正文。
- 候选源输入为查询、最多 32 个候选的请求上限、当前授权笔记的 `noteId`/`noteVersionId`/`contentHash` 清单及中止信号；输出仅含版本化笔记 ID、UTF-16 `start`/`end`、有限分数和 `truncated`。候选源可返回多个不同片段，但不能决定授权、正文、标题、引用或发送范围。
- 宿主先核对运行 grant，再将每个候选与授权清单比较，并重新调用 R02 `verifyRead` 检查当前目录成员、排除项、版本及内容哈希。实际摘录、标题和逐字引用哈希只从当前版本生成；不采用索引缓存的正文或引用。无效、旧版本、越权候选及空结果回退关键词。撤销 grant、资料集切换等授权错误直接失败，不能被回退掩盖。R02 发送清单仍在每次模型外发前再次核验。
- 候选源异常或超过 1500 ms 未响应时，中止候选请求并回退关键词；工具轨迹保存 `mode=keyword_fallback` 和原因，页面显示“索引无可用结果，已改用关键词检索”，模型请求说明关键词未命中不等于授权资料无答案。默认关键词模式记录为 `mode=keyword`。无索引装配时不增加额外索引服务依赖。
- 2026-09-28 的关键词基线最多对前 300 篇授权笔记做正文评分，单篇超过 20 万 UTF-16 单位跳过，命中片段至多 320 个单位、单次返回至多 8 条。该前 300 篇规则是历史实现，2026-10-02 的覆盖修复见下节。截断或超长跳过会标记覆盖受限；无法分词的查询仍先复核 grant。

## 2026-10-02 关键词覆盖补充

[覆盖修复与验收](../p2/授权关键词检索覆盖验收.md) 将“先截取任意前 300 篇”改为在授权范围和扫描预算内按查询预选，再稳定排序保留最多 300 篇匹配候选。默认扫描上限为 5,000 篇、标题与正文合计 4,000,000 个输入 UTF-16 单位，单篇正文上限仍为 200,000；最终返回上限与引用边界不变。第 301 篇的唯一标题或正文命中可进入结果，超出预算时仍必须报告覆盖受限，不能声称已检查完整授权范围。

候选和返回前继续复核当前授权、资料集 epoch、版本、正文哈希与引文；预选后正文突然超长时，在哈希和版本查询前拒绝。普通 R02 read 的默认大正文语义不变，每次模型发送仍执行逐请求来源与授权复核。`repository.list` 仍读取空间全量快照，这些预算不代表数据库分页、恒定内存、所有后续哈希的总量上限或跨客户端串行快照。

以下 2026-09-28 固定样本及其原始结果保留；覆盖修复的定向回归仍为关键词 top3 27/27、无命中 2/2、语义改写观察 1/3。新增规模覆盖不代表语义召回质量已通过，也没有接入 embedding 或向量库。三种存储与最终提交的验证边界以覆盖验收和 [PR31](https://github.com/1848956505/Knowra/pull/31) 为准。

## 后续 embedding / 索引 / 清理契约

1. embedding 仅作本地候选排序与片段定位；要接入外部 embedding 服务，必须另设接收方授权、逐次发送清单和预算门禁，不能复用当前 DeepSeek 回答授权暗中发送整库。R06 没有安装向量数据库，也没有生成或持久化 embedding。
2. 索引数据以资料集 ID/epoch、owner、知识空间、笔记 ID、版本 ID、内容哈希及片段偏移标识；异步消费笔记变更并可重建。笔记保存和普通搜索不得等待索引；索引落后或停机时关键词回退继续服务。
3. 删除、永久清理、授权收窄、目录移动及资料集恢复/切换先由 R02 当前状态即时拦截旧候选；索引任务随后删除或重建相关条目。索引是可丢弃缓存，旧队列和旧备份不能复活已删除正文，重建必须从当前有效笔记与版本出发。清理与并发时序的跨驱动验收留给 R07。
4. 检索质量扩展须继续维护版本化开发集与保留集，分别报告词面召回、语义改写召回、无答案误命中、跨笔记召回、截断率与授权失败数；模型引用的语义支持率仍需 R07 的人工逐陈述评审。
