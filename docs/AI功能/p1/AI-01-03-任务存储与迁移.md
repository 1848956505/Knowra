# AI-01-03：任务私有存储、迁移与恢复

日期：2026-09-26。状态：**三种驱动的代码与隔离验收完成；尚未部署到云端或打包 Mac 发布。** 云端继续使用 `local-json`，不因本任务启用 PostgreSQL。真实生成、Worker 和预算预留属于 AI-01-04，仍关闭。

## 实现

- [运行对象校验](../../../apps/api/src/modules/ai/record-contract.js)读取 P0 冻结的 v1 schema，拒绝未知字段，并复核来源偏移、范围哈希、授权时限和未知费用；[repository](../../../apps/api/src/modules/ai/record-repository.js)复核 owner／资料集／空间引用、上下文来源子集、任务幂等、状态转换、事件序号与 CAS。只接受安全事件摘要，不保存密钥、完整 prompt 或笔记正文。
- JSON：在原子业务文件中增加版本化的 `aiRuntime` 私有区，保存 scope、manifest、grant、job、attempt、usage 与事件。业务同步日志和普通快照导出不包含该区；原始运行数据备份包含它。业务导入会轮换 epoch，旧任务保留只读诊断但失去写入资格。
- SQLite：从 `user_version=3` 升到 4 前先 `VACUUM INTO` 保护备份，按 P0 DDL 建私有表并写入 `aiRuntimeEpoch`。新库直接建 v4；旧 v1/v2 沿既有路径依次升级。私有表不进入 `entities` 或 `sync_outbox`，AI 与业务记录可在同一 `BEGIN IMMEDIATE` 中提交。备份检查校验 AI 表外键和记录形状，恢复活动资料集时同时轮换 dataset ID 与 epoch。
- PostgreSQL：新增 [migration](../../../prisma/migrations/a_ai_runtime/migration.sql)、Prisma 模型与 owner 范围内的私有 repository。写入使用 `SERIALIZABLE` 事务、唯一键和序列化冲突重试；JSON 快照替换前保守轮换 epoch。当前云端机器仍运行 JSON，PostgreSQL 只在本机隔离 PostgreSQL 17 实例执行了真实迁移与并发测试。
- repository 仅供受信应用服务使用；本任务没有新增 AI 生成、任务创建或记录写入的 HTTP／IPC 路由，也没有外发笔记。P0 预留的 action 表尚不开放业务写入。

## 验收

| 范围 | 结果 |
| --- | --- |
| JSON | 重启后读取、失败写盘回滚、幂等键冲突、跨任务引用和未知字段拒绝、普通导出和同步日志隔离、导入后 epoch 失效通过。 |
| SQLite | v3→v4 保护备份、旧 v1/v2 升级、重启、业务与 AI 同事务提交／回滚、备份检查断裂外键、恢复后旧租约失效通过。 |
| PostgreSQL | 隔离 PostgreSQL 17 上按全部 Prisma migrations 顺序迁移成功；双 repository 并发同键只落一个 job、owner 隔离、用量／事件保存与 epoch 轮换通过。`pg_dump` 后恢复到另一隔离库，旧任务再次轮换 epoch 后不能写入。云端 PostgreSQL 未启用。 |
| 回归 | API 296/296；桌面 76 通过、4 项因未向该轮传入 PostgreSQL 测试库而跳过（此前已在隔离库跑通 80/80）；P0 冻结迁移校验、Prisma schema 校验、Web 生产构建、Mac 打包及桌面 E2E 通过。Mac 安装包未发布，部署前仍需按流程复验。 |
