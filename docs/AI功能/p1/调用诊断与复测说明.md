# P1 调用诊断与复测

> 适用范围（2026-09-27）：本文件记录原 P1 的实现与验收，文中的状态、日期和通过数不代表新版 Agent 已完成。范围问答基础继续复用；多轮对话、自动库检索、授权 v2 与插件故障隔离按 [补齐方案](../06-P1对话Agent补齐方案.md) 和 [任务表](../04-分阶段开发任务.md) 另行实施。旧发送预览流程仅作为显式指定范围/历史复测入口，不是普通聊天的必经步骤。

本文用于旧固定范围问答链路的定点诊断，不是新版主交互设计。对话 Agent 需求已确定，按 P1-R 补齐；基础调用故障修复与新体验建设分别验证。工程变更日志 2.27.1 已记录输出预算与结算修复，此处不据旧失败截图断言当前仍存在同一问题，本轮未复测运行环境。

## 记录范围

新任务在现有私有 AI 事件表中记录任务创建、请求核对、预算预留、发送、模型响应、回答校验、费用结算及最终状态。失败会记录阶段、稳定错误码、可用的 HTTP 状态，以及费用是已释放、已结算还是待核对。成功响应可记录供应商请求 ID、结束原因、输入/输出 token；页面的“调用详情”可在应用重启后查看这些摘要。

诊断不保存 API Key、笔记正文、问题正文、完整请求体、供应商错误正文或模型原始回答。请求体仅记录字节上界，来源仅记录片段数；未知用量继续占用预算预留额，不能当成实际消费。此前已经失败的任务没有这些事件，无法追溯旧调用的具体原因。

## 旧链路复测步骤

1. 更新云端与 Mac 应用后，确认 AI 助手显示已配置模型及可用预算。
2. 选一篇短笔记，输入问题，核对发送预览，再确认提问。
3. 在任务详情展开“调用详情”。如果失败，记录任务显示的错误码、失败阶段、HTTP 状态和预算状态；无需提供 API Key 或笔记内容。
4. 根据记录核对实际失败原因并验证修复；不能把旧链路跑通作为新版 Agent 已完成的证据。

新版复测必须另覆盖：无来源聊天、连续追问、授权库内自动检索、范围撤销、工具循环/预算和插件失效下核心保存。验收见 [05](../05-验收评测与发布方案.md) 的 V39–V49、V53。
