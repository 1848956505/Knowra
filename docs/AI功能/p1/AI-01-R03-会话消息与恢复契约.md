# AI-01-R03 会话消息与恢复契约

日期：2026-09-27。状态：v2 会话/消息/工具结果契约、三种私有存储路径及 HTTP 读写入口已实现；JSON、SQLite、HTTP 本地回归通过。PostgreSQL 迁移和条件测试已提交，真实数据库需要隔离测试库验证。模型工具循环与对话页面仍归 R04/R05。

## 交付范围

- `ai-conversation-v2.schema.json` 独立定义 `AIConversation`、`AIConversationTurn`、`AIConversationMessage`、`AIConversationToolCall`。每条记录绑定服务端 owner、资料集 ID/epoch 和空间；轮次的 `turnId` 同时是 `jobId`，用户与最终助手消息通过 ID 关联，工具请求和结果由稳定 `callId` 关联。
- 会话内轮次与消息分别使用连续递增的 `ordinal`、`sequence`；同一资料集/空间中的请求幂等键只生成一轮和一条用户消息，变更原请求内容返回冲突。创建会话可传稳定 `conversationId` 重试。前一轮处于待执行、运行或中断时，禁止提交下一轮。
- 内部执行接口按租约代数领取任务，工具调用与结果、阶段、最终消息都要求有效租约；取消或过期后拒绝迟到写入。到期运行任务转为 `interrupted`，不会自动重放模型请求。工具结果可绑定后续模型发送清单 ID，供 R04 复核历史来源。只有完整最终消息能使任务成为 `succeeded`；来源回答必须携带来源引用与发送清单 ID，流式片段不写成完成结果。
- JSON 私有状态 v1/v2→v3 只补空集合，不改写旧任务。SQLite v6→v7 先备份再增加独立会话表；PostgreSQL 使用 `d_ai_conversations` 迁移并在串行化事务中维护幂等与 owner 隔离。会话不进入业务同步和普通资料导出；桌面完整备份检查会话索引、正文和引用。资料恢复提升 epoch 后旧会话只可回看，不可继续提交或执行。
- `GET/POST /api/ai/conversations`、`GET /:id/messages`、`POST /:id/messages`、`GET /:id/turns/:turnId` 和 `POST /:id/turns/:turnId/cancel` 提供会话入口；写操作需要 `X-Knowra-AI-Conversation: 1`。服务端复核当前知识空间 owner。消息提交当前只产生 `staged` 任务，响应明确 `executionAvailable: false`，不调用模型。`GET /legacy-jobs` 与 `GET /legacy-jobs/:id` 从原 v1 私有任务读取历史结果、来源和诊断，始终只读，不合成 v2 会话或工具轨迹。
