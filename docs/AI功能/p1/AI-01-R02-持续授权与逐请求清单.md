# AI-01-R02 持续授权与逐请求清单

日期：2026-09-27。状态：v2 契约、三种私有存储路径与受信应用服务已实现；JSON、SQLite 和 HTTP 本地回归通过。PostgreSQL 增量迁移已提交，真实数据库验证需有隔离测试库；对话 Agent、模型工具循环及真实外发联调分别归 R03/R04/R07。

## 交付边界

- 新增独立 `ai-v2.schema.json`，定义 `AIAccessPolicy`、`AIRunGrant` 和 `AIRequestManifest`。策略绑定服务端 owner、资料集/epoch、空间、actor、范围、排除笔记、接收方、有效期和 revision。当前允许库、目录、固定笔记集合；附件固定不发送，接收方只开放 `deepseek`。策略最多一年，运行授权最多一小时、最多 2 元预算上限，只允许 `notes_search` / `notes_read`。策略可收窄或撤销；扩大范围、移除排除项、换接收方或延长有效期需要另建用户策略。
- `GET/POST /api/ai/access-policies` 与 `PATCH /api/ai/access-policies/:id` 是受信设置入口。服务端从当前运行 owner 取得 actor，不接受请求体覆盖；请求头沿用本项目设置操作的同源受信门槛。当前 HTTP owner 仍不是登录认证；公开部署继续受 Nginx Basic Auth 保护。会话和 Agent 页面在 R03/R05 接入后，才向用户展示首次范围设置与展开清单。
- 每次运行由策略派生只读 grant，绑定 policy ID/revision、会话、资料集 epoch、工具和费用上限。`listAuthorizedNotes` 在标题进入搜索候选前按当前空间、目录和排除项过滤；`verifyRead` 重新加载笔记与不可变版本。目录策略发现当前合法成员，固定集合不会变为目录授权。
- 每次模型请求由服务端生成不可变清单，含真实版本、UTF-16 区间、正文及摘录哈希、排除/遗漏、接收方、发送体哈希和保守输入上界。发送入口 `withAuthorizedRequest` 先复核 grant、策略修订、接收方、来源当前范围/版本和完整发送体。历史生成消息必须绑定原请求清单，全部历史来源重新复核；无法证明来源的历史消息停止发送。资料内容作为数据，不成为工具授权。
- v1 固定范围、已保存任务与引用保持原结构和语义。JSON 私有状态 v1→v2 只增空集合；SQLite v5→v6 先做保护备份并加私有表；PostgreSQL 使用 `c_ai_access_v2` 增量迁移。恢复换 epoch 后旧策略和 grant 只可历史读取，不会重新授权或重放请求。业务同步与普通资料导出不带这些私有记录；桌面完整备份包含并校验其记录与引用。

| --- | --- |

PostgreSQL 的 v2 测试使用 `KNOWRA_SYNC_TEST_DATABASE_URL` 在隔离库运行，未设置时不冒称实测。当前真实模型发送仍使用 v1 明确范围入口；R02 不表示持续策略已驱动对话 Agent，也不表示真实外发、跨端发布或浏览器设置 UI 已验收。历史工具结果当前拒绝重新发送，待 R03/R04 保存 call ID 与来源清单后才开放。R03/R04 应从本服务派生会话运行 grant，并且在每次工具读取与每次供应商发送前调用受控复核，不应只检查一次会话创建。R07 核对三种存储、恢复、正式 Mac 包及真实供应商行为。
