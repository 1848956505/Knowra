# AI 启动恢复与关闭竞态

本批修复旧 AI 恢复流程的资源生命周期，不开放 P3 正式提炼、真实供应商或新预算能力。

## 缺陷与关闭约定

基线 `f835961dad6f17bd10738a4ce907aaf2a837f8e9` 存在三个已复现路径：

- API 启动时按会话、Agent、旧任务执行恢复，但宿主关闭未等待完整链；恢复暂停后，关闭可先返回，后续继续访问持久化。
- 桌面并行启动恢复使用 `Promise.all`，一项先失败时，其他恢复仍可在 SQLite 关闭后读取。
- 桌面端口被占用而监听失败时，异常清理直接关闭 SQLite，尚未完成的启动恢复随后晚读。

前一项用真实 server／隔离 worker 与受控 repository 时序复现；后两项使用真实临时 SQLite 和回环 HTTP。它们证明恢复与关闭之间缺少等待，不证明历史 Prisma 引擎异常都由该竞态造成。

关闭流程先封住恢复准入，同时启动已有 Agent／worker 的关闭取消，并等待所有已登记恢复完成。恢复成功或失败均须排空；多个关闭调用者等待同一结果。已关闭后发起恢复在首次存储访问前拒绝。

API 通过显式 `server.closeAi()` 提供该等待，不改写 Node 原生 `server.close()` 的回调、事件或返回值。持久化 context 的 `close()` 等待对应 AI runtime，PostgreSQL 随后才断开。调用方仍负责先停止 HTTP 请求。桌面宿主在普通关闭、既有恢复换库与监听失败清理中先关闭服务，再关闭 SQLite 和释放目录锁。

## 验收入口

API 自定义测试必须调用每条记录的 `run()`；只导入文件不算运行：

```sh
node --input-type=module <<'JS'
import { aiRuntimeLifecycleTests } from './apps/api/test/ai-runtime-lifecycle.test.js';
for (const test of aiRuntimeLifecycleTests) {
  await test.run();
  console.log(`PASS ${test.name}`);
}
JS
```

PostgreSQL 条件回归注册在同一文件的 `aiRuntimeLifecyclePostgresTests`，随 `npm run test:api` 在隔离 schema 中运行。桌面定向入口如下，使用临时 SQLite 与合成 AI：

```sh
node --test --test-concurrency=1 apps/desktop-runtime/test/ai-runtime-lifecycle.test.mjs
```

2026-10-02 本地实际执行：API 定向 50 项通过，包含新增生命周期、隔离 worker、Agent、HTTP 与提炼入口契约；新增桌面生命周期 7 项通过，覆盖并发关闭、启动部分失败、监听失败、恢复换库／回滚及 configure 后迟到恢复。首轮回滚测试错误等待应跳过的替换库恢复，已改为暂停实际进入的旧库恢复，并断言替换库恢复零调用；未修改产品断言或增加超时。

`closeAi()` 只等待已进入的 AI 恢复；尚在网络阶段的 `sync.configure()` 仍由同步服务及 HTTP 宿主管理。其晚到结果不能再启动 AI 恢复，不把该边界称为等待整个同步配置。

本地依赖仅使用安装包自带的 Prisma 初始化占位以加载非 PostgreSQL 模块，没有可用原生引擎；真实 PostgreSQL 不计本地通过。固定提交独立审查、真实 PostgreSQL、候选 CI、合并后的精确 main CI 与发布包身份均须以对应 PR 的实际记录为准。

## 保留边界

- 不改恢复时的预算未知用量处理，不重放模型调用，不引入新的系统信号退出框架。
- 不改变 AI 默认关闭、可选故障保留核心服务、提炼能力拒绝及 Node 监听行为。
- 产物最小来源同步、来源保留与恢复预检、正式桌面资料集准入仍是后续切片；本批只完成相关只读评估。
- 所有新增测试只用合成数据与 Mock；未访问真实笔记或 AI 凭据，未调用付费服务，未部署 ECS 或操作 Mac。
