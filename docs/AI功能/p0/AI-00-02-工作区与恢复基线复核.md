## 4. 保存、同步与恢复基线

1. **JSON**：[文件存储](../../../apps/api/src/infrastructure/file-data-store.js)校验持久状态、同步日记与引用，`runTransaction()` 失败恢复内存状态；[原子文件替换](../../../apps/api/src/infrastructure/atomic-json-file.js)写临时文件并同步后替换目标。已有中断替换痕迹时会停止创建空库。它不为多个无协调进程写同一 JSON 文件提供安全保证。
2. **SQLite**：[本地存储](../../../apps/desktop-runtime/src/sqlite-data-store.mjs)将实体、不可变版本和 outbox 放在同一事务，启用 WAL/`synchronous=FULL`；既有空数据库或未来 schema 受保护，不自动清空。资料目录有[单实例锁](../../../apps/desktop-runtime/src/data-directory.mjs)。
3. **草稿与冲突**：[编辑器自动保存](../../../apps/web-v4/src/features/editor/useNoteAutosave.ts)按资料集/笔记保留草稿和远端基线；冲突后暂停自动覆盖，恢复草稿仍可读取。AI 写入不能只检查服务端版本，还须识别当前未保存草稿。
4. **桌面备份/恢复**：[备份](../../../apps/desktop-runtime/src/backup.mjs)纳入 SQLite、附件及正文/知识草稿，清单用 SHA-256 校验；检查时还做 SQLite 完整性、实体引用和附件校验。[恢复](../../../apps/desktop-runtime/src/restore-directory.mjs)在新目录准备，并原子切换活动资料集；[本地 HTTP](../../../apps/desktop-runtime/src/runtime-server.mjs)先等待写请求、创建恢复前保护备份，随后隔离旧窗口并暂停同步。救援导出另见[实现](../../../apps/desktop-runtime/src/recovery-export.mjs)。
5. **同步**：[服务端协议](../../../apps/api/src/modules/sync/service.js)使用资料集 epoch、版本基线、操作 ID 和回执；[桌面同步](../../../apps/desktop-runtime/src/sync-engine.mjs)保留待传、冲突及认证错误状态。AI 任务、凭据和完整对话尚无同步 schema，不应借业务 outbox 重放远程模型调用。

本轮 `npm run test:desktop` 覆盖了备份清单损坏拒绝恢复、恢复前保护备份、草稿保留、写盘失败回滚、进程崩溃前后提交、丢响应重试、同步冲突及旧云端能力不足时待传保留等隔离样本。它证明这些自动化样本通过，不等于所有用户备份均已校验，也不等于当前云端可登录或真实 PostgreSQL 已通过。

本机最新可见手动备份创建于 `2026-09-20T17:17:46.510Z`，本轮只读检查返回 `valid=true`：17 个文件、33,899,186 字节、28 篇笔记、15 个附件、1 项当时待同步操作、0 份备份内恢复草稿。这个结果确认**该份历史备份**的清单、数据库和附件校验通过；待同步计数只属于备份创建时刻，不是当前队列状态。未做从该备份恢复、恢复后页面回读或云端比对。

## 5. 供 AI-00-03/P1 使用的约束与待验项

1. 先冻结 AIJob/AIAction/Grant/Provenance 的执行端归属和资料集 epoch。恢复、切换资料集或撤销授权时，旧任务必须失去提交权。
2. JSON 仅在受控单写拓扑执行任务；若生产增加 API 实例/worker，先实现跨进程原子领取或改用 PostgreSQL。检查真实部署进程数和驱动后再宣称满足条件。
3. Web 的 `/api/*` 代理目前缓冲完整响应。P1 的 SSE 要新增流式透传及重连测试，或明确选择轮询。
4. 桌面训练资产不可由 AI 写工具越过路由限制；先补领域写入和同步能力。新增 AI provenance 与正式产物同步需升级实体 schema/能力协商。
5. 发布前分别验收 JSON、SQLite、真实 PostgreSQL 的任务重启、取消/迟到响应、重复写和恢复；还需云端重新登录、旧云端能力、实际桌面与 Web 页面、用户备份只读检查。未验收项保持未验收状态。
