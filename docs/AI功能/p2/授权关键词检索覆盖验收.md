# 授权关键词检索覆盖验收

日期：2026-10-02。范围：已授权日常第 5 项的 P2 检索覆盖修复。基线提交：`3811447f5f2243278fa7de823b3d359ff5e7e13c`；实现版本以本记录所属提交为准。关键词评分、授权和外发范围沿用 R02/R06；本次没有 embedding、向量库或外部检索引擎。

## 问题与结果

旧实现先对全部授权笔记逐份读取当前版本，再只对列表前 300 篇评分。JSON 和 SQLite 各创建 301 篇合成笔记，唯一标题或正文命中位于第 301 篇：4 条正式断言在旧实现下均失败，实际 `hits=[]`。相关笔记没有被排除、删除或移出授权范围。

新实现先在当前授权范围内按查询预选，再在扫描预算内按原分数与笔记 ID 稳定排序保留最多 300 个匹配候选。上述 4 条断言转绿；301 篇全部匹配时，位于列表末尾的更高分来源也能进入结果，同时明确报告候选覆盖受限。目录授权同样覆盖第 301 篇唯一正文命中。

追加的 KW21 在首个实现提交 `d98735ce4a6a715c5890a6ae9526fea81d59b379` 上复现预选后正文增长到 200,001 单位仍触发版本查询：红测的读取断言失败。修复后先检查当前正文长度再哈希/查询版本，该回归转绿。

## 实现和安全边界

- `access-service.js` 的 `findAuthorizedSearchCandidates` 复用现有 `noteRepository.list({ spaceId })`，在正文评分函数执行前过滤当前 owner/空间、固定集合、目录成员、排除项和删除状态；扫描和候选版本加载前后复核 grant、策略修订及资料集 epoch。该接口只供受信宿主调用，模型没有评分函数或预算设置入口。
- 预选只使用当前 `rawMarkdown`。R02 的权威当前版本本来就是按 `hash(rawMarkdown)` 查找不可变版本，并校验版本正文的实际哈希；因此不会把 `plainText` 或历史版本中的匹配当成当前来源。正文预选与最终评分都逐 Unicode 码点执行 NFKC/小写转换，标题仍执行整串归一化，保留原基线对组合符号的行为。
- 仅对排序后保留的匹配候选加载当前版本。关键词服务再经 `verifyRead` 核查当前范围、笔记身份、标题、版本 ID 与内容哈希后实际评分；返回前重新验证命中的版本、UTF-16 边界、原文切片与 `quoteHash`，最后再次复核 grant。扫描或返回前复核观察到的撤销、收窄、epoch/owner 变化、来源删除/移动或已匹配来源变化会报错，不返回先前命中。供应商外发仍必须走 R02 的逐请求清单复核。
- `verifyRead` 另提供受信内部可选的 `maxContentChars`。默认 `null`/省略维持普通 R02 read 的大正文语义；关键词调用传单篇上限，在当前授权复核之后、正文哈希和版本查询之前检查当前 Markdown 长度，并在已读版本正文哈希前检查其长度。预算参数要求正安全整数，没有新增模型工具参数。预选后正文突增的来源会 fail closed，不绕过单篇上限做超大正文哈希。
- 原标题每词 5 分、正文每词 2 分、同分按笔记 ID 排序的规则不变；原文片段与代理对边界处理保留。空正文不能形成引用，不占用匹配候选额度。
- 现有 `hits`/`inspected`/`truncated` 字段兼容。附加的 `coverage` 仅供检索宿主核查；Agent 继续投影原有工具结果字段，HTTP/tool schema 和 UI 均未扩展。给模型的截断说明改为“检索受到本次处理上限限制，不得声称已检查完整授权范围。”

## 预算与计数语义

| 项目 | 默认值与含义 |
| --- | --- |
| `maxScanNotes` | 5,000 篇授权笔记；访问超长笔记并跳过也占一次。未授权笔记不占正文扫描计数。 |
| `maxScanChars` | 标题 + 当前 Markdown 共 4,000,000 个输入 UTF-16 单位。整篇所需字符超过剩余预算时停止，不局部扫描正文。 |
| `maxNoteChars` | 单篇正文最多 200,000 个 UTF-16 单位；超过时跳过并继续寻找后续笔记。 |
| `maxCandidates` | 最多 300 篇匹配候选加载当前版本并最终评分；池满后继续在扫描预算内排序，后续高分/同分较小 ID 可替换候选。 |
| `limit` | 沿用单次最多返回 8 条。正常 top-k 排名丢弃其余命中不单独表示扫描覆盖受限。 |
| `inspected` | 本次进入当前版本验证与最终评分的候选篇数，至多 `maxCandidates`；不表示已检查全授权范围。 |
| `coverage.scannedNotes` | 已纳入扫描工作的授权笔记篇数，含超长跳过；因剩余字符不足而未扫描的当前笔记不计入。 |
| `coverage.scannedChars` | 预选实际归一化的标题 + Markdown 输入 UTF-16 单位数；不是归一化展开后的长度，也不把后续哈希/版本复核重复读取当成首次扫描。 |
| `coverage.matchedNotes` / `skippedOversize` | 扫描预算内具备可引用正文的匹配篇数 / 超长跳过篇数。 |
| `coverage.limitedBy` | `notes`、`chars`、`candidates`、`oversize` 中实际发生的限制；任一限制使 `truncated=true`。 |

这些预算限制正文归一化、候选版本查询和评分工作。4,000,000 是预选输入字符预算，不是后续所有哈希总量的上限；当前候选与最终命中复核还分别受候选篇数、单篇正文长度和返回条数限制。现有 repository 的 `list` 仍读取当前空间的全量快照，JSON/SQLite 仍使用现有内存列表排序，PostgreSQL 仍执行现有异步列表查询；本次没有实现数据库分页、数据库全文检索或恒定内存的全库读取。预算以外仍可能漏掉来源，`truncated=true` 时空命中不能解释为授权范围没有答案。读取和末次复核之间也不构成跨 PostgreSQL 客户端的可串行化快照；每次模型发送必须继续复核当前来源和授权。
