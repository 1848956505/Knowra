# AI-02-02 核心原子回执基础

日期：2026-10-01。范围仅为核心提交原语与恢复，不代表 AIAction、写授权或用户写入闭环已完成。

## 交付

`apps/api/src/infrastructure/core-operation-contract.js` / `core-operation-store.js` 不依赖 AI 模块。操作以 owner + dataset + operationId 唯一，绑定服务端固定的 planHash、actor、space、request、epoch 与工具类型；重复请求回读原 applied 回执，同键不同计划或身份返回 409。epoch 不进入唯一键，避免恢复后换 epoch 再提交同一操作。

内部 `commit(input, operation)` 在原子事务内先查询回执，再执行宿主提供的领域提交函数，再写最小回执。它不提供权限：宿主还须在提交函数内检查当前 grant、epoch、草稿、全部目标基线及生命周期。没有 HTTP 写入口或 Agent 注册，模型无法直接调用；不能把传入 planHash 当成已经校验了计划。

回执保留目标 ID、前后不可变版本 ID、正文哈希和撤销所需元数据 before image，不复制正文或供应商凭据。结果明确为 `localCommitted`，没有宣称云端已同步。现有领域服务维护版本/标注/派生来源，现有 JSON journal、SQLite outbox、PostgreSQL journal 与业务和回执同事务。

## 存储与恢复

- JSON 使用独立 `coreOperations` v1 顶层字段，原子替换时保存，失败时连同内存业务/AI/journal 回滚。损坏或未来版本保留原文，只关闭本操作入口，普通核心编辑继续可用；不得把未知回执当作未提交。
- SQLite 使用独立 `coreOperationsVersion` metadata 和 `core_operation_receipts`，增量建表前保存 0600 完整数据库备份；不复用可选 AI 的 `user_version`，无 AI 外键。完整备份检查回执哈希与索引身份，并恢复原回执。旧备份未带该扩展仍可读；重新打开时才升级。损坏回执关闭操作入口，保留坏表及普通核心编辑。
- PostgreSQL 增量迁移 `f_core_operation_receipts` 建立同名核心表，无 AI 私有外键。装配使用核心同步事务代理与既有全局事务锁，已有和首次操作都串行检查；两个实例不会因尚无回执行而重复写入。无需在事务内发送网络/附件 IO。
- 普通业务快照导出继续不包含回执/授权。原库业务导入保留回执并沿用既有 epoch 轮换，旧授权不能恢复；完整 SQLite/数据库备份保留回执。此批未新增跨端回执同步协议，不能声称在另一个新资料集恢复后已具备相同动作恢复能力。
