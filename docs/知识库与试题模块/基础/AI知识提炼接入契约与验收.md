# AI 知识提炼接入契约与验收

状态：2026-09-21 完成提供商无关的输入准备、结果校验和离线验收。**尚未接入模型，界面仍显示提炼不可用。** 本次没有读取密钥、选择模型、发送资料或增加外部请求。

## 已完成的接入基础

- `apps/api/src/modules/knowledge/application/knowledge-extraction-contract.js`：`prepareKnowledgeExtraction` 从服务端保存的分析快照和不可变笔记版本生成稳定请求；`validateKnowledgeExtractionResult` 严格校验模型结果并返回候选创建计划。均为纯函数，不写数据库、不调用提供商。
- `KNOWLEDGE_EXTRACTION_OUTPUT_SCHEMA`：供后续提供商适配器使用的 JSON Schema。即使提供商支持结构化输出，仍必须通过服务端校验。
- `apps/api/test/fixtures/knowledge-extraction.fixture.js`：使用真实范围服务构建的内存验收资料，包括被排除段落、中文和 emoji。
- API 自定义 runner 已注册契约测试。执行 `npm run test:api`，无需配置任何模型服务。

## 输入与权限边界

调用方必须从服务端按当前 owner/知识空间权限读取已经保存的 `AnalysisScope`，然后加载其绑定的 `NoteVersion`。不能采用浏览器或模型提交的来源表，不能只检查一个客户端自报的快照 ID。

准备函数检查版本 ID、笔记 ID、版本正文哈希、原文切片及标注修订记录是否一致。请求只包含快照中的 `segments`；局部排除已在范围服务扣除，`contextSegments` 不作为可引用来源发送。遗漏项继续由界面如实展示，不把图片无法读取解释为已经识别图片。

返回结构：

```text
contractVersion = 1
requestId       = 根据输入和幂等键生成的稳定 ID
scopeId / spaceId / inputHash
sources[]       = sourceId / noteId / noteVersionId / contentHash
                  start / end / markdown / annotationRevisions
```

`start/end` 为 JavaScript UTF-16 偏移，采用左闭右开区间；不能切断 emoji 代理对。单次上限为 128 个片段、120,000 个 UTF-16 单元。它们是应用层的输入限制，不代表某一模型的 token 上限。后续适配器必须按所选模型计算预算；超过限制应提示用户缩小范围，不能静默截断后声称分析了全部资料。

## 模型输出与来源绑定

模型只返回以下字段：

```json
{
  "contractVersion": 1,
  "requestId": "原样回传当前请求 ID",
  "candidates": [{
    "title": "数据增强",
    "canonicalStatement": "数据增强通过变换样本增加训练变化。",
    "knowledgeType": "concept",
    "citations": [{
      "sourceId": "输入中已有的来源 ID",
      "start": 0,
      "end": 17,
      "quote": "数据增强通过变换样本增加训练变化。"
    }]
  }]
}
```

示例中的偏移是相对于所引片段的 `markdown`，接入时必须使用实际输入中的 ID 和位置。无可提炼内容可以返回空候选列表；不能为了凑数产生无来源知识。

校验要求：

1. 根对象、候选、引文全部采用严格字段白名单。模型不能指定 `reviewStatus`、知识 ID、证据记录或用户解释。
2. 每个候选必须有标题、核心陈述、已支持的知识类型，以及 1–8 个不重复引文；引文必须逐字匹配所选片段的指定位置。
3. 输出最多 40 个候选；标题上限 200、陈述/引文各 8,000 个 UTF-16 单元；整体 JSON 最多 256,000 个 UTF-8 字节。错误或超限整体拒绝，不采纳部分结果。
4. 来源 ID、笔记 ID、版本 ID、正文哈希、绝对偏移和标注修订号由服务端映射。历史片段以 `noteVersion` 证据创建，避免当前标注已移动后替换历史引文。标注修订和精确偏移另保存在计划的 `provenance` 中，后续须随 AI 任务记录持久化。
5. 返回的每个计划强制 `reviewStatus: candidate`、`sourceMode: ai`，`candidateInput` 可交给已有候选服务。准备和校验自身不创建知识，不执行确认。

结构及逐字引用校验只能证明引用确实存在，**不能证明生成陈述在语义上受引用支持**。人工核对与确认是必经步骤；资料中的命令、网页指令、角色声明均视为待分析文本，不应被适配器当成系统指令或工具授权。

## 下一轮实际接入顺序

1. 确认提供商、模型、密钥来源、数据发送范围和预算后，再实现服务端适配器。密钥只在服务端读取，禁止进入前端包或同步数据。
2. 增加持久化 AI 任务：保存请求 ID、范围 ID、输入哈希、契约版本及状态；采用 `pending → running → succeeded`，失败进入 `failed`，用户重试进入 `retrying`。任务状态和已验证结果应能在进程重启后恢复。
3. 幂等记录以 owner/知识空间、幂等键和输入哈希绑定。同一键但不同输入应返回冲突；相同请求应复用已有任务及已验证结果。模型重新生成可能返回不同正文，不能只因候选 ID 稳定就覆盖第一次结果。
4. 外部调用在数据库事务之外完成。设置超时、取消、限流及有上限的重试；取消或过期任务的迟到结果不得写入。记录提供商用量与可诊断错误，默认日志不输出全文、密钥或完整模型响应。
5. 完整校验后，在一次本地事务或 PostgreSQL 事务内保存任务结果、全部候选及证据；用 `requestId + outputHash` 防重复提交。任何候选失败则整体回滚，不留下部分成功或孤立来源。
6. 入库时仍使用现有领域校验；若原文在分析期间已修改，旧版本来源应显示待核对，不能自动切换到新版本或自动确认。若来源已被删除、权限变化或空间不匹配，拒绝入库并保留可诊断任务失败状态。
7. 最后开放界面：范围预览 → 明确提交 → 进度/取消 → 候选审核与原文对照 → 用户确认。服务未配置、离线不可调用或超额时保持明确的不可用状态，不能把“保存范围”显示为“提炼成功”。

## 验收门槛

当前自动验收已覆盖：所选范围与排除项、旧快照与版本校验、稳定请求/候选 ID、非法审核字段、伪造/错位/重复引文、UTF-16 边界、空结果、畸形 JSON、数量与大小限制，以及结果兼容候选创建服务和原文变化后的待核对状态。

后续开启 AI 前还必须补齐：模拟超时/取消/限流/重试、任务重启恢复、同键异输入冲突、同任务不同输出竞争、写入中断回滚、跨空间或已删除来源拒绝，以及用户确认前正式知识数量保持不变。使用模拟适配器先验收，再在明确授权和小范围资料上进行真实提供商验收。
