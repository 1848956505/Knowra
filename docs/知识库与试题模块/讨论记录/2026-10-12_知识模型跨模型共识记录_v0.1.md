> **日期：** 2026-10-12  
> **状态：** 初步稳定共识 / 仍有待裁决事项  
> **来源：** [GPT-6 独立审查](./2026-10-12_知识模型独立审查_GPT-6.md)、[Claude 交叉评议](./2026-10-12_知识模型交叉评议_Claude.md)；对照 [现有领域冻结稿](../基础/Knowra%20知识与考卷系统领域冻结稿.md) 与 Prisma schema。  
> **适用边界：** 本文件记录“双方确实接受了什么”，不替用户进行产品裁决。新提案的实现方式与现有模型的兼容问题依然开放。

## 0. 一个重要进展：两条原分歧已撤回

Claude 在交叉评议中明确**收回**此前两条主张：

1. **“掌握度只挂在命题上”**：改为认可由可观察、可评测的 **LearningObjective（学习目标）** 承载评估对象，由作答等学习证据支持评估，再聚合到概念视图。
2. **“知识内容本质上都是命题”**：认可程序性知识（例如矩阵乘法、动态规划的操作过程）不能自然约化为一组真假陈述，必须允许合理的表达方式。

两者与 GPT-6 的主要反对意见已经消除。**撤回旧主张不等于新模型已经获用户批准。**

## 1. 双方达成的稳定原则

### 1.1 知识概念、笔记、知识内容各自独立

- **Concept（概念）应拥有稳定身份。** 例如“矩阵”“向量”“自动微分”可以独立存在，不必由某篇笔记创建。
- **Note（笔记）是来源与思考记录，不等于概念本身。** 一个概念可以关联多篇笔记，一篇笔记可以支持多个概念或知识内容。
- **Proposition（命题）值得作为独立可管理的知识陈述。** 能被引用、核查、修订、关联，且不等同于概念名称或问题标题。
- **Proposition 不是一切知识的唯一最小单元。** 必须容纳计算步骤、算法过程、使用方法等程序性知识；这些内容最终如何映射到底层对象，尚未定论。
- 概念身份的判别依据是**语义独立性与稳定含义**，而非某个词出现过几次。引用次数可以帮助选择何时建议、突出或展示它，但不能定义其本体身份。
- 正式名称、别名是不同的概念管理需求；**别名去重不能代替同名异义消歧**。不同语境下的“张量”“秩”等不能只因名称相似而自动合并。

### 1.2 知识库、训练与学习评估明确分工

- 知识库负责知识身份、内容、关系与可评测学习目标的管理；题目、试卷、作答、批改归训练/试题职责。
- **学习目标应当具体、可观察、可评测。** “理解矩阵乘法”不足以唯一评估，“能按规则完成矩阵乘法计算”更可测。
- 掌握程度不是“命题是否为真”，也不是“用户是否点了确认”。它是**特定用户对特定学习目标、根据学习证据形成的估计**。
- **LearningObjective → LearningEvidence → MasteryState** 是现有领域冻结稿已经提出的正确主线，应优先继承、核实实际实现范围，而不是另起平行的一套掌握度模型。
- 从多个目标聚合到概念层的状态只是一种**派生视图**；必须能显示“未评估”“证据不足”，不能把缺少测试数据误报成能力薄弱。
- **记忆可提取性、理解、实际应用能力不可混为一谈。** FSRS 可以作为复习调度的研究参考，不应直接用其记忆概率充当综合掌握度。

### 1.3 人工确认、知识可靠性与个人掌握是三个不同维度

- AI 提炼、自动关联与 AI 补充先产生**候选/草稿**，不因生成成功就进入已经确认的正式知识集合。
- 用户采用/确认一条陈述，不等于该陈述客观正确；陈述有来源，不等于来源可靠；陈述正确，也不等于用户已经掌握。
- 应能保留并明确标识待核查、错误或存在语境限制的知识陈述，方便纠错而非悄悄替换用户原话。
- **知识来源（KnowledgeEvidence / Provenance）** 与 **学习表现证据（LearningEvidence）** 是两类语义不同的证据，不应混用。
- 命题宜表达一项相对明确、可独立理解、在规定条件与语境下可讨论或核查的陈述；**可判真伪 ≠ 必须为真**。
- 溯源尽可能精确到具体陈述或方法，而不只停留在“整个概念来自哪篇笔记”。

### 1.4 关系与图谱：知识结构和视觉呈现分离

- 概念之间可以有分类、部分/整体、应用、关联等关系；关系的含义应明确，不能用一个泛化“相关”代替所有语义。
- **一条知识陈述可能同时涉及多个概念。** 不应强迫每条陈述都成为两个点之间的一条边。
- 少量核心关系类型可先行，但不宜永远封闭；结构性的 **isA（是一种）** 与 **partOf（组成部分）** 不能混用。
- 学习前置条件应与本体/分类关系区别；是否依赖前置知识可能受到学习目标与深度的影响。
- 圆点表示概念、方块表示命题，是一个值得测试的**视觉设计约定**，不是底层强制的数据存储形式。
- **图谱是正式知识的投影，不是另一套独立真源。** 同一命题在图上、详情页和笔记引用中出现时，不应形成多份各自修改的知识副本。
- 相邻节点弱化但仍可辨认、局部展开、避免大图过载等属于值得验证的交互假设；目前**不是冻结 UI**。

### 1.5 AI 的角色与创建门槛

- 默认 AI 帮助从笔记提炼知识，手工新建和“用户先写、AI 补漏”也应存在。
- AI 应**优先识别并链接已有概念和别名**，避免把“矩阵和向量如何相乘？”直接当成独立概念标题。
- 对新建概念保持审慎：概念语义独立性是基本要求；AI 提议新概念应保持候选态，避免未经确认即充斥正式图谱。
- 用户手动创建独立概念无需等待多次引用。
- AI 的产出规模和确认负担应受控制：不能为了语义完备，就要求用户每次审查大量无价值的细小对象。
- 当下先不写代码，**用小规模真实学习内容进行手工建模与当前 AI 提炼的基线对比**。

## 2. 与现有仓库的关系：已实现、已设计、待验证要分清

以本次阅读的 main 分支 Prisma schema 和领域冻结稿为依据：

| 领域职责 | 当前依据与状态 | 本次共识的含义 |
| --- | --- | --- |
| **KnowledgeItem**（标题、canonicalStatement、knowledgeType 等） | Prisma 中已有模型；现有内容类型包含 concept / process / algorithm 等 | 与“纯概念身份”不同，不能直接将其整体改名为 Concept |
| **LearningObjective** | Prisma 中已有模型，当前以 knowledgeItemId 关联 | 优先保留这条可评测能力主线 |
| **KnowledgeEvidence、KnowledgeArtifactProvenance** | Prisma 中已有模型 | 新概念或新的内容关联需研究如何延续溯源 |
| **LearningEvidence、MasteryState、KnowledgeRelation** | 已写入领域冻结稿；本次 main 分支 Prisma schema 未见同名模型 | 不应将“领域稿设计了”误写为“所有存储与能力都已经实现” |
| **Concept（独立概念身份层）** | 在本次检视的 Prisma schema 中未见独立模型 | 需要研究如何与现有 KnowledgeItem 建立桥接，未批准新增表或迁移 |

**明确的产品/领域边界：** 用户与模型可以赞成“知识库展示掌握情况”，但按照现有冻结稿，学习证据与掌握评估归 **Learning Module**；知识库展示其派生结果。这不是要求把 MasteryState 字段塞进 Concept。

## 3. 这次尚未达成完整共识的事项

下列事项**不得**写入“已批准设计”：

| 议题 | 共同认可的方向 | 尚未裁定的部分 |
| --- | --- | --- |
| **最小桥接方式** | 应解决独立 Concept 身份与现有 KnowledgeItem 的衔接 | “只新增 Concept 一层”是否就足够；关联、关系、来源的结构如何处理 |
| **命题与方法的落地对象** | 含义应区分，方法不能强行变真假陈述 | 是否共用 KnowledgeItem + knowledgeType；何时需要更丰富结构 |
| **概念与内容粒度** | 不能只看引用次数 | AI 提议阈值、候选展示、合并建议、图谱噪声门槛 |
| **关系事实的唯一真源** | 关系能具有可核查内容，支持多概念参与 | KnowledgeRelation 与独立命题如何避免重复表述和互相矛盾 |
| **关系类型清单** | isA 与 partOf 必须有语义区分 | 是否及何时新增 isA；prerequisiteOf 连接概念还是学习目标 |
| **真实性/审阅状态** | 人工确认不等于事实核验 | reviewStatus 是否拆维度、使用哪些名称、错误认识如何保留 |
| **AI 提炼工作流** | 保留来源、优先匹配已有概念、降低误合并 | 初版仅提概念，还是同时输出少量命题/方法候选 |
| **已有数据升级** | 不应破坏既有学习目标、证据、来源和题目引用 | 如何映射旧 KnowledgeItem、是否手工审核、如何回滚 |

## 4. 建议的共同验证实验

取《动手学深度学习》第二章中的**张量、向量、矩阵、矩阵乘法、链式法则、自动微分**，连同下列共九类测试：

| 用例 | 要识别的失败 |
| --- | --- |
| 1. 张量的定义 | “数学张量”与“DL 多维数组”的语境混淆 |
| 2. 矩阵乘法的步骤与性质 | 方法被错误拆成单纯真假陈述 |
| 3. 向量与张量的联系 | 概念关系缺限定条件、语义不准确 |
| 4. 自动微分与链式法则 | 多概念命题无法自然表达 |
| 5. 错误数学认识 | 用户确认被误当作知识已经核实 |
| 6. 会背规则但不会求导 | 命题记忆与操作能力被混为一个掌握度 |
| 7. 同名异义 | 同名不同含义被自动错误合并 |
| 8. 当前提炼回归 | “问题型知识点”能否变为概念 + 内容/方法 + 学习目标 |
| 9. 当前 AI 提炼基线对照 | 新流程是否真的更有用，而不只是结构变复杂 |

每个样例记录：候选概念、陈述/方法、涉及概念、来源、学习目标、歧义/不确定性、用户需要确认的操作次数，以及错误合并/重复创建情况。**反例比漂亮的图更重要。**

## 5. 本记录的使用规则

1. 后续模型可直接引用本共识文档，但请保留“**跨模型共同意见 / 非用户审批**”这一状态。
2. 新模型如有异议，指出具体小节、给出反例，写入独立评议，不直接抹去既有记录。
3. 只有用户确认的决策才能进入正式领域冻结稿或实施任务。
4. 在模型、字段、UI 语义尚不清晰前，不以本稿启动数据库迁移、代码重构、数据回填或大规模 AI 操作。
5. 合并多个模型的共识不是正确性的科学证明；以可核查资料、样例反证和用户裁决为准。

**一句话共识：概念是稳定身份，命题是可核查的陈述，方法承载操作过程，学习目标承载可评测能力；笔记及来源提供证据，知识图谱提供探索视图。现有系统应优先演进而不是推倒重来。**
