# 知境知识边界实验：GPT-6 独立复核与第三轮针对性再验证

> 日期：2026-10-16  
> 性质：多模型共享实验审查，**不是正式领域冻结、schema 迁移或自动确认知识的授权**。  
> 依据：[实验脚本](../../../scripts/experiments/knowledge-hardcases/README.md)、[Actions #38903414094](https://github.com/1848956505/Knowra/actions/runs/38903414094) 的公开合成报告；同时参照 [Claude 第二轮结果](./2026-10-16_Concept融合实验第二轮结果_Claude.md)。

## 一、用户本轮确认的方向

1. **“矩阵加法”“逐元素乘法”可以独立成为 Concept，而它们的定义仍可作为相关 KnowledgeItem。** 这不是二选一。是否需要为某个对象建独立节点，主要取决于其概念身份与复用价值，而不是模型把句子标成 fact 还是 definition。
2. **AI 允许主动补充没有对应个人笔记的知识。** 用户说的“来源可以为空”指**笔记出处**可以为空；仍须标明它属于 AI 补充或手动创建、处于什么审核状态。不能自动把无笔记来源解释成“已被证实”。
3. 用户明确允许继续使用 GitHub Repository Secret `DEEPSEEK` 跑受限合成实验，**不是允许读取真实私人笔记或将密钥输出到日志**。

## 二、对现有压力实验的独立复核

该轮真正完成了 10/10 次 DeepSeek API 请求，但只有 **8/10 条模型提议通过实验结构校验**；“API 成功”与“提议可被采纳”不能混为一谈。

| 用例 | 观察 | 我的判断 |
| --- | --- | --- |
| H01（三个概念） | 一条矩阵×向量结论正确关联矩阵、向量、矩阵乘法三种身份 | 对多 Concept 关联的正面证据 |
| H03（错误交换律） | 原话保留，标记 disputed，冲突指向已确认的 K_NONCOMM | 方向正确；尚不是事实核验能力 |
| H05（无笔记 AI 补充） | 生成乘积元素公式，`sourceMode=ai`、`quote=null`、`candidate` | **直接支持用户确认的来源可为空** |
| H08（矩阵加法定义） | 关联独立 C_ADD 及 C_MATRIX，内容为 definition | 与“概念身份和定义条目共存”一致 |
| H02（链式法则复用） | 找到了正确 K_CHAIN 和 Concept IDs，却输出 `reviewStatus=confirmed` 而被拒绝 | **定位正确，犯了把旧条目已确认状态复制给本轮候选的协议错误** |
| H04（非交换性复用） | 正确选择 K_NONCOMM，却同样输出 confirmed，同时为现有条目多加一个 C_MATRIX | **语义复用方向对，审核状态与旧条目关系集合越权修改** |
| H06/H09/H10 | 返回合理的附加概念（如 C_VECTOR / C_TENSOR），但人工评分对允许集合比较严格 | 这不自动等于“挂错”，应独立考察主关联、辅助关联和概念参与角色 |

**不能把 5/10 的概念集合分数直接说成 DeepSeek 有五次严重错误。** 在 H06 这样的定义中额外关联“向量”不一定没有根据。评分规则有价值，但需要区分“真正错误合并”与“合理但可省略的次级概念关联”。

### 一个真正需要补上的风险：来源与 AI 纠错混写

H10 模型的 `statement` 同时保存了：
- 原笔记的错误声称 `x.require_grad_(True)`；
- 模型自己补充的对照知识 `x.requires_grad_(True)` 与疑似拼写错误判断。

第二部分**不是原笔记中的内容**。如果整个 KnowledgeItem 标成 `sourceMode=note` 并只给一条原文引用，就会让 AI 的批注悄悄进入“笔记原意”字段。这是比“能不能找到 quote”更深的溯源风险。

建议研究中暂将“原话对应的 statement”和“AI 批注/纠错建议”分开表示，不要求此时立即新增正式表。用户允许 AI 补充**不意味着允许它冒充用户原话**。

## 三、下一轮只验证尚未解决的部分

以前 H02/H04 的失败都指向清晰的协议歧义，而不是模型完全无法识别已有知识。下一轮不必重复 24 次已通过的简单分类；应使用修订后的**通用提示词**再验证：

- 明确：`existingItem.reviewStatus=confirmed` 是已保存知识的状态，**新提议永远是 candidate 或 disputed**；即使复用已经确认的知识，也不继承 confirmed。
- 明确：复用时必须保持**已有 KnowledgeItem 的 Concept ID 集合完全不变**，新笔记顺带提及的其它概念不可偷偷写回旧条目。
- 明确：笔记原话中的错误须保留；AI 校正意见可以放在解释/审查理由，但不能悄悄混进被标记为笔记原话的 statement。
- 保留 H03 的错误冲突、H05 的无笔记 AI 补充，确保修一个问题不破坏另外两个已通过的行为。
- 再增加两条**未见过的同义复用语句**，防止只对 H02/H04 过拟合。

本次做**七条固定公开合成情形、七次 DeepSeek 调用、无自动重试**；仅研究性内存存储，测试报告保存七天。不更改知境的生产知识提炼、正式 KnowledgeItem、数据库、同步、RAG 或 AI 权限系统。

## 四、后续产品讨论

1. 可以承认“来源笔记为空”是一等合法情况，但需要来源模式及审核流程。
2. 概念/命题多对多本质有意义；若未来需解释参与角色，可以再逐步添加关系角色，不宜现在强制一切都是边。
3. **现有旧条目事实与新候选审核状态是两件事**；合并来源不等于确认新内容或修改旧内容。
4. AI 的纠错建议本身可以很有价值，但必须单独标注为建议，不能破坏用户笔记所表达的历史认识。
5. 本轮若结构检验全部通过，也只能说明该受控契约/合成语料下可行，**不构成真实用户笔记的泛化准确率**。

实验能验证的东西越清楚，后续才越能避免在知境核心知识模型上盲目重构。
