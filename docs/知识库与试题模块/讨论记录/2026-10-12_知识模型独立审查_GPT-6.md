## 0. 供其他模型阅读的背景与注意事项

知境（Knowra）正在探索一套以个人知识成长为目标的知识系统。当前讨论希望将“AI 从笔记总结知识点”升级为“识别独立知识概念、积累具体知识、建立语义网络，并最终服务于学习与复习”。

用户和 Claude 讨论形成的提案包括：

- 知识库与试题库作为独立模块；知识库管理知识网、知识点与掌握度呈现，试题库负责出题、作答与训练证据。
- 知识点是独立对象，与笔记形成多对多来源关系；支持脱离笔记新建。
- 图谱中使用圆点表示概念（矩阵、张量等），方块表示命题；方块可附着于概念或关系，且允许关联多个概念。
- 概念与命题的初步区分：能判断对错的是命题，不能的是概念。
- AI 提炼默认产生待确认草稿；需区分笔记来源与 AI 补充来源。
- 拟将掌握度挂在命题上，再聚合为概念状态，并考虑时间衰减（参考 FSRS）。
- 拟将定义、性质视为命题，将题目留在试题库；以“引用多次后晋升”控制概念粒度。
- 希望借鉴 Novak 概念图、SKOS、Wikibase、知识追踪等研究，不照搬完整 schema。
- 下一步不写代码，先从《动手学深度学习》第二章选择少量概念手工搭建知识网。

**阅读本稿时尤其注意：本稿是在评议上述提案，不是要求覆盖或替换仓库已存在的领域设计。**

## 1. 总体结论

**赞成当前提案的总体方向，但不赞成现在就将“命题”定为整个系统唯一的最小单元，也不赞成将命题掌握度直接等同于知识掌握度。**

目前“概念 + 命题”的方案很适合表达“知道什么”，但还不够充分地表达“会做什么”。对同时面向个人知识管理、学习理解和智能练习的知境，这个区别不可忽略。

本轮将关键设计主张归为：

- **8 项基本赞成**：可作为继续讨论的基础；
- **5 项有条件赞成**：方向可取，定义或适用范围需要修订；
- **3 项明确不同意**：应避免直接写入定稿。

这是定性的设计审查，不是实验证据、学术统计或模型投票结果。

## 2. 基本赞成的八项共识

| 设计主张 | 立场 | 原因 |
| --- | --- | --- |
| 知识库与试题库职责分离 | 赞成 | 防止知识体系被具体出题流程绑架；允许跨模块反馈 |
| 概念独立于笔记 | 赞成 | 笔记是知识来源，概念应拥有稳定身份 |
| 概念与笔记多对多 | 赞成 | 一份笔记涉及多个概念；一个概念可由多份资料支持 |
| 概念别名机制 | 赞成 | 避免 GD、Gradient Descent、梯度下降重复建点；仍需同名消歧 |
| 区分用户笔记与 AI 补充来源 | 赞成 | 有利于溯源、纠错、信任与后续增量更新 |
| 命题可作为独立知识对象 | 赞成 | 命题可以复用、引用、核查、关联和修订 |
| 一条命题能关联多个概念 | 赞成 | 关系并非都能简化为两概念间的单一连线 |
| AI 提炼结果保留待确认阶段 | 赞成 | AI 可以建议，但不应直接替用户确定知识真伪 |

**核心共识：概念（Concept）和命题（Proposition）应具有不同的身份，命题应可以独立管理。**

Novak 概念图所区分的“概念、连接词、命题”与此相符；但它不能证明所有知识都应转成命题。

## 3. 五项有条件赞成的主张

### 3.1 圆点代表概念、方块代表命题

可以作为直观且值得测试的 UI 语言，但不应成为底层知识定义。

- **概念是一种知识对象，圆点是一种显示方式。**
- **命题是一种知识对象，方块是一种显示方式。**
- 同一命题可在局部网络显示为方块，也可作为概念详情中的某项性质展示，而不复制成第二份数据。
- 支持方块关联多个概念；针对多元关系，需测试是否采用“命题为独立对象 + 参与者关系”，而不是强制将每条命题压入一条边。
- 选中概念时，相邻概念可以保留可辨识的弱化状态；该交互方案仍需在桌面与手机分别验证。

### 3.2 学习问题归试题库，但知识库不能不了解能力目标

同意题目、试卷、作答属于试题库/训练模块。不同意知识库只需要记录“某题考查哪几条命题”。

例如“计算两个矩阵的乘积”需要了解矩阵乘法规则，还需要执行计算。知晓命题与能够操作不是一回事。

建议沿用并进一步审查仓库已经存在的 **LearningObjective（可评测学习目标）**：知识库负责表达“需要会什么”，试题库负责提供“如何测”和实际表现证据；不必现在确定跨模块回写接口。

### 3.3 AI 一键提炼为默认、草稿待确认

默认由 AI 提炼适合整理已有笔记；主动学习和总结时，“用户先写、AI 补漏”也有价值。不宜认为一个流程对所有场景最优。

AI 生成的概念、命题、关系首先处于待确认状态。即使用户确认一条命题的内容正确，也**不代表用户已经掌握该知识**。

需区分：

1. 内容是否被用户确认；
2. 陈述是否有充分证据支持；
3. 用户是否理解或能够运用。

### 3.4 命题判定三标准需要修订

用户与 Claude 提出的原标准是：“只说一件事、脱离笔记能读懂、能判断对错”。

赞成其精神，建议表述为：

> 命题表达一个明确、可独立理解、并在规定语境与条件下能够被讨论或核查的陈述。

原因：

- 可判真假不意味着其内容为真。错误命题也可能值得保留，以便纠错。
- 部分命题必须附带领域语境、定义、前提、量词、例外及适用条件。
- 例如“梯度下降可以找到全局最优解”不能脱离目标函数性质等条件直接作为通用定理。
- 对存疑、争议、错误或已证伪的命题，系统应保留状态与溯源，而不是只允许“正确命题”进入知识库。

### 3.5 关系类型使用少量核心集合，但不要永远封闭

可以先有少量类型，如 **是一种 / 组成部分 / 前置依赖 / 使用或应用 / 对比 / 一般相关**。

但需注意：

- “是一种”“是一部分”“学习前置条件”语义完全不同。
- “学习前置条件”可能与学习目标有关，不一定是无条件的事实。例如只使用自动微分 API，不必先会完整证明链式法则。
- SKOS 的 broader、narrower、related 可用于概念组织，但不能直接代替领域中的严格逻辑关系或学习前置关系。
- 建议“有限核心类型 + 受控扩展 + 必要时附条件和解释”，具体列表留待样例检验后决定。

## 4. 三项明确不同意的主张

### 4.1 不同意：“掌握度只能挂在命题上”

“无法直接测一个宽泛的矩阵概念”这一观察是合理的，但结论不能推出“只能测命题”。

学习者既有**命题性知识**，也有**操作、应用与策略性能力**。

例子：围绕“矩阵乘法”

| 知道什么（命题性知识） | 能做什么（技能/目标） |
| --- | --- |
| 矩阵乘法一般不满足交换律 | 判断给定矩阵能否相乘 |
| 矩阵乘法满足结合律 | 正确计算具体矩阵乘积 |
| 矩阵乘法要求维度匹配 | 将运算用于问题求解 |

学习者可能会背性质但不会计算，也可能会计算但解释不清原理。把这些现象全都压到“记住几条命题”会丢失信息。

**建议：掌握度应基于可观察、可考核的知识或能力目标估计。命题可以对应某些学习目标，但不是唯一目标类型。**

概念级的展示状态可以聚合相关目标的证据，同时保留“未评估”“证据不足”而不是默认低掌握。评价还应考虑试题难度、是否查看答案、是否使用提示以及证据能否归因到具体目标。

此观点与仓库已有的 **LearningObjective → LearningEvidence → MasteryState** 领域链路相容，应明确继承既有合理设计，而不是为新的“命题中心论”删掉它。

#### FSRS 的使用边界

赞成现在就研究知识追踪，但**反对直接用 FSRS 的记忆可提取性（retrievability）数值充当对某条命题或概念的综合掌握百分比**。

FSRS 面向基于复习历史的记忆调度。记忆提取风险、理解程度、实际应用能力是相关但不等同的概念。

例如，一周未复习链式法则公式不必然等于一周后不能进行复合函数求导。

建议概念上分离：能力评估、证据充分度、复习到期/遗忘风险。是否采用具体 FSRS 参数应在真实数据与产品场景验证后再决定。

### 4.2 不同意：“所有知识内容本质上都是命题”

定义、性质、规律可以有命题表示；但还有 **程序性知识（Procedural Knowledge）**，它可能包含步骤、条件分支、算法过程和中间结构。

例如：

- 命题：“链式法则适用于复合函数的求导。”
- 方法：“如何逐步使用链式法则求导。”
- 动态规划方法涉及识别状态、定义转移、处理边界、选择计算顺序；这些不能仅靠一堆彼此分离的真假句自然表达。

**建议：允许“方法/过程（Procedure）”拥有自己的内容结构，而不强迫所有内容变成命题。**

方法仍可以关联命题，例如适用条件、正确性依据或计算规则。定义、例子、图示、推导也可以组织成可阅读视图。

“不要重复保存相同知识”非常正确，但避免冗余应靠源内容复用与视图组织，并非靠取消知识内容中所有非命题类型。

### 4.3 不同意：“某内容被引用两三次才晋升为概念节点”

引用次数可以决定关注优先级，不应决定本体身份。

反例：

- “自动微分”只出现一次，也有明确且稳定的概念身份。
- “矩阵的形状为 3×4”重复出现很多次，也不意味着“形状为 3×4”应成为独立概念。

**建议：用语义独立性判断概念资格，用引用频次、关联范围与用户需求判断何时推荐、突出或展开。**

允许首次出现即创建独立概念，同时不要求所有可建节点立即在可视化网络中出现。

## 5. 提议检验的替代模型

不建议现阶段把“概念 + 命题”宣布为能表示全部知识的最终模型。

一个更有弹性的候选模型为：

| 对象 | 主要回答 | 示例 | 是否必须成为图上的节点 |
| --- | --- | --- | --- |
| **Concept（概念）** | 这是什么？ | 矩阵、张量、自动微分 | 常作为圆点 |
| **Proposition（命题）** | 关于它知道什么？ | 矩阵乘法一般不满足交换律 | 可显示为方块，也可只作为详情内容 |
| **Procedure（方法/过程）** | 如何完成操作？ | 矩阵乘法的计算步骤 | 不必是主图节点 |
| **LearningObjective（学习目标）** | 学习者需要理解或能够做什么？ | 能独立计算矩阵乘积 | 更适合作为目标与评估对象 |
| **Evidence / Source（来源/证据）** | 这条知识根据什么建立？ | 笔记摘录、教材、AI 建议 | 通常附着于陈述/方法并可追溯 |

**这不是提议立刻新增五张表。** 它们首先是不同的语义职责。究竟需要几个独立领域对象，应通过例子以及与现有模型的兼容性检验来决定。

在 UI 中可以保持“圆点是概念，方块是命题”的视觉探索主线；内部不因此禁止方法、学习目标、来源的其他表达。

推荐阅读时，命题和方法形成完整内容；推荐训练时，学习目标与证据建立映射。图谱只是正式知识的一个投影视图，不需要复制另一套图谱专用数据。

## 6. 另外两个容易被忽略的问题

### 6.1 正确性、来源与个人掌握程度不能混成一个状态

例如用户写下“所有可逆矩阵都可以对角化”，该命题是错误的，但它可能是用户真实的原始理解。

系统不应悄悄修正并抹去来源，也不应把它当成正确知识传播。它可处于待核查或已纠正状态，并保留原始笔记和后续修订记录。

因此需要至少区分：

- **来源/溯源**：是谁写的、AI 是否扩展、引用了哪段资料；
- **知识状态**：待核查、已确认、存在争议、错误或被修订；
- **学习状态**：用户是否理解、掌握或能够应用。

来源最好能定位到具体命题或方法，而非只指向一个宽泛概念节点。

### 6.2 完整知识结构不等于屏幕上必须一次画出的网络

即使内部可以保存大量概念、命题和多元关系，桌面或手机也不应全部展开，造成可视化拥挤。

可测试的交互是：

1. 默认呈现概念骨架及少量显著关联；
2. 点击概念时，显示主要命题、方法、来源与相邻概念；
3. 相邻概念保留半清晰，确保连线仍有语义；
4. 用户继续展开更细的内容；不同视图引用同一个对象，不重复存储。

这是 UI 假设，不是领域强制约束。

## 7. 下一步：用小型知识网反证，而不是证实模型

赞成**先不写代码**。从《动手学深度学习》第二章中选六个概念：

**张量、向量、矩阵、矩阵乘法、链式法则、自动微分。**

重点不是画出一张好看的图，而是检验模型能否自然处理下列场景：

| 测试用例 | 要验证的问题 |
| --- | --- |
| 张量的定义 | 定义能否作为命题表达？不同语境如何限定？ |
| 矩阵乘法的运算规则 | 过程是否有超出命题清单的结构？ |
| 向量与张量的联系 | 怎样表达条件、学科语境及多种关系？ |
| 自动微分与链式法则 | 如何表达多个概念共同参与的命题及依赖？ |
| 一条错误的数学认识 | 如何溯源、保留、纠正且不误导？ |
| 会背链式法则但不会求导 | 是否能区分知道事实与具备操作能力？ |

失败判断标准：为了表达上述普通知识，需要大量特例、重复数据、语义含混或强行拆成不自然的真假命题。出现这些现象时，应修改模型，而不是添加大量补丁规则。

## 8. 决策优先级与建议共识

### 可以先作为讨论基础

- 概念有独立身份，命题也有独立身份；
- 概念可脱离笔记存在，笔记/来源与知识多对多；
- AI 建议需要明确草稿、溯源和人工确认；
- 知识库与试题库功能职责分离；
- 图谱是知识结构的视图，而不是另一套真源。

### 现在应研究，但不要定死

- 除命题外的程序性知识如何表达；
- 学习目标、证据、掌握度与复习风险的区别；
- 命题原子性与语境、条件、真伪状态；
- 多元命题、概念语义关系、学习前置关系的边界；
- 新旧领域对象的兼容与迁移成本。

### 小型原型验证后再决定

- 圆点、方块和关系卡片的全部交互；
- 固定关系类型的具体清单；
- 概念的推荐/突出与“晋升”机制；
- AI 默认提炼流程与需要用户确认的操作边界。

### 建议带入下一轮多模型讨论的三条新共识

1. **命题应当是一等知识对象，但没有充分理由认定它是所有知识唯一的最小单位。**
2. **掌握度来自可观察的知识与能力表现，不等同于命题的记忆提取概率。**
3. **知识网络是组织与探索知识的方式，不意味着一切知识都必须变成图上的圆点或方块。**

最终的目标不是最大化对象数量或理论复杂度，而是找到**足够简单、可以自然表达复杂知识、又允许未来增长的模型**。
