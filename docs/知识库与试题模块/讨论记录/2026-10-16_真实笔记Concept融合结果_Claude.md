# 真实笔记 Concept 融合结果（Claude）

> **性质：** 实验记录，不是产品决策。  
> **日期：** 2026-10-16  
> **实验：** `scripts/experiments/concept-linking-r2/run-local.mjs`，在用户本机运行，DeepSeek-chat，temperature 0  
> **样本：** 用户《动手学深度学习》第 1–2 章笔记，按“章.节”切成 10 篇，从空知识库开始逐篇处理；每篇的候选概念由简单字符检索从已建概念中选出前 8 个  
> **隐私：** 完整报告留在用户本机，下文只摘短片段。

## 1. 汇总

| 项 | 结果 |
| --- | --- |
| 调用 | 10 次全部成功，共约 25k token |
| 知识条目 | 55 条，被校验拒绝 0 条，复用已有条目 0 条 |
| 概念 | 新建 33 个，挂到已有概念 1 次 |
| 模型标注疑似重复 | 0 次 |

合成实验里表现很好的“挂对概念”，在真实笔记中几乎没有发挥空间：各节内容重叠少，而且检索有缺陷（见 3.2）。这次暴露的主要是**概念该怎么建**的问题。

## 2. 表现好的地方

- **笔记中的错误大多保留了原话，并在备注中指出。** 例如回归一节“标签取任意数值时（即标签取离散值）”被标为自相矛盾，`require_grad_` 被标为疑似笔误，`dir(torch.ones)` 也被指出可能有问题。比第一轮 A/B 实验中悄悄改正的情况好。
- **真实的同名异义处理正确。** 笔记中“维度”有三种含义：数据维度指特征数，向量维度指元素个数，张量维度指轴数。模型把它们建成了不同的概念，没有合并。

## 3. 问题（按严重程度）

### 3.1 概念粒度失控（新暴露的主要问题）

33 个概念中有不少不像概念：

- **关系被建成了节点：** “机器学习与深度学习的关系”。按已有共识，这应该是两个概念之间的一条 isA 关系。
- **照抄小标题：** “矩阵与向量/矩阵的积”来自笔记标题“2.3.8/9 矩阵与向量/矩阵的积”，而不是“矩阵乘法”。照抄标题的毛病从知识点层面转移到了概念层面。
- **API 用法与操作独立成概念：** “查阅文档”“非降维求和”“沿轴降维求和”“张量与NumPy数组的转换”“原地运算”等。

合成实验测不出这个问题，因为概念目录是人工预先写好的。让模型从零建库时，它倾向于给每个小节建一个概念。

### 3.2 检索漏掉了“梯度”，x.grad 的测试作废（实验工具的 bug）

第 9 篇（自动微分）多处提到“求梯度”，但第 8 篇刚建立的“梯度”没有进入候选。原因是检索打分没有按名字长度归一化，“张量与NumPy数组的转换”这类长名字靠偶然重合的字排到了前面。模型把 x.grad 相关内容放进了新建的“自动微分（autograd）”，没有挂错，但“x.grad 与数学梯度是否会混淆”这一项没有测到。

### 3.3 陈述中仍有悄悄改正和添加

笔记写的是用“插值法”处理非数值缺失值（代码是 `pd.get_dummies`）。条目的标题和陈述改成了“用独热编码处理”，还添加了笔记中没有的“把缺失值也作为一个指示列”。引用保留了原话，但陈述已经不是用户说的了。

### 3.4 只引用标题，内容是推断出来的

“监督学习”一条的引用只有标题行“## 1.3.1 监督学习”，陈述却是“其任务包括分类和回归”，这是从笔记结构推出来的。唯一性校验没有拦住，因为这行标题在笔记中确实只出现一次。

### 3.5 “概念说明不写内容”的规则对定义型概念不成立

“机器学习”“深度学习”等概念的说明和定义条目几乎是同一句话。这说明规则本身需要调整：概念说明应该是很短的区分标签（例如“机器学习的一类任务”），而不是一段描述。

另外，报告中“疑似写进内容 27 个”有 10 个是报告 bug：同一篇里重复使用同一个新概念的条目被误标，实际是 17 个。

## 4. 建议

| 类型 | 事项 |
| --- | --- |
| 工具 bug，直接修 | 检索打分按名字长度归一化，修复后重跑以补上 x.grad 测试；修正报告中同篇重复概念的误标 |
| 规则漏洞，直接修 | 拒绝只引用标题、不含实质内容的条目；增加结构化的“存疑”字段，模型认为原文有误时写在这里，陈述必须与原文一致 |
| 设计问题，需要讨论 | 概念说明改为短标签；明确“关系不是概念”；给出概念粒度的判断标准，即什么配成为一个概念，API 用法与操作是否单独成概念 |

最后一项是此前讨论中“概念门槛”分歧的延续，现在有了真实数据，建议 GPT-6 与用户先就此讨论。

## 5. 修复后重跑（2026-10-17）

修复了第 4 节前两类问题（检索打分、拒绝只引用标题、`sourceIssue` 存疑字段），在用户本机用同一份笔记重跑。

| 项 | 第一次 | 修复后 |
| --- | --- | --- |
| 条目 | 55 | 53（被拒 2） |
| 新建概念 | 33 | 29 |
| 挂到已有概念 | 1 次 | 4 次 |

**已经解决：**

- **检索：** 第 9 篇（自动微分）的第一个候选就是“梯度”。模型明确判断“候选中的梯度是数学定义，与 PyTorch 自动微分操作语境不同”，没有复用。x.grad 与数学梯度的区分在真实笔记上通过。
- **悄悄改正：** “插值法”一条的标题和陈述都保留了原话，`sourceIssue` 写明“get_dummies 实际是独热编码……此处按原文保留”。`x.shape()`、`require_grad_`、回归“即标签取离散值”也都保留原话并标注了存疑。
- **只引用标题：** “## 1.3.1 监督学习”被拒。

**新发现：**

- “拒绝只引用标题”的规则误拒了 `A.T`（矩阵转置的代码，只有 3 个字符）。原规则按长度判断，已改为只要去掉标题行和代码围栏后还有内容就放行。
- `sourceIssue` 有轻微过度使用：例如 `torch.tensor(X)` 被标注为“更常用 torch.from_numpy”，这是写法偏好，不是错误。
- “导数”被并入“梯度的定义与方向”一条，没有单独成概念。

**仍未解决（属于设计问题，等概念边界讨论）：** 关系被建成概念（“机器学习与深度学习的关系”）、照抄小标题（“矩阵与向量/矩阵的积”）、API 用法与操作独立成概念（“张量内存节省”“查阅文档”等）。

**另外：** 合成实验中带公式的 R05 经常整篇失败。诊断表明原因是模型输出的 JSON 括号层级错误：`sourceIssue` 位于嵌套较深的 item 之后，模型多写了一个 `}`。与公式本身无关。正式提炼功能同样严格解析 JSON，以后调整契约时建议压平结构，并在解析失败时重试一次。
