## 1. 结论

Concept 的粒度不要在挂靠时控制，改为三步：

1. **挂靠**：AI 按原版提示词决定每条知识属于哪个概念，宁可多建，不要挂错。
2. **整理建议**：挂靠完成后，AI 按三条标准对新建的概念逐个给出保留、降级、合并、改名或拆分建议。建议只展示，不自动执行。
3. **用户决定**：采纳、修改或忽略。

三条标准由用户和 Claude 讨论得出：

- ① 能独立命名，含义稳定；
- ② 能承载多条独立的知识；
- ③ 会和其他概念发生关系。

满足 ①，并且满足 ②③ 中至少一条，才单独成为一个概念。

## 2. 为什么不在挂靠时控制粒度

在挂靠提示词里加入粒度规则后，x.grad 被挂到了数学“梯度”上，3 次运行全部如此；没有这些规则的原版提示词是 0 次。之后做了消融和对照：

| 挂靠提示词 | x.grad 挂到数学梯度 |
| --- | --- |
| 原版（今天重跑作对照；10-16 共 5 次运行也全部正确） | 0/3 |
| 原版 + 三条标准、关系/比较挂靠、同主题归并 | 3/3 |
| 再补一句“先判断是不是同一概念” | 3/3 |
| 去掉三条标准，只留其余规则 | 3/3（跑了两次） |
| 原版 + 只加一条“概念名用规范术语、不照抄小标题” | 3/3 |

规律：**任何提高新建门槛的措辞，都会把模型推向挂靠。** 连“用规范术语命名”这一条也不例外：x.grad 没有教科书式的名字，模型干脆不新建，转而挂到梯度上。

多建一个概念，之后可以合并；挂错了却很难被发现。所以挂靠提示词保持原版原文。

## 3. 整理建议的表现

### 合成笔记

15 篇合成笔记，每轮跑 3 次，共做了多轮：

- 有害建议 0 条。有害指把 x.grad 降级或合并到数学梯度，或对 x.grad、矩阵乘法、原地运算这类概念提出拆分。
- 被检索藏起来、后来又被新建的“矩阵乘法”，每次都被建议合并回已有概念。
- 整体偏保守：拿不准时一律保留。

### 真实笔记（用户的 D2L 第 1–2 章笔记，10 篇）

挂靠部分，3 次运行都没有挂错。x.grad、backward、zero_ 这些都归入单独的“自动微分”概念。

整理建议在固定输入上重跑 3 次（`run-review.mjs`，输入为 concept-out-6）：

| 新概念 | 建议 | 3 次是否一致 |
| --- | --- | --- |
| 机器学习与深度学习的关系 | 降级到“深度学习” | 3/3 |
| 矩阵与向量/矩阵的积 | 改名为“矩阵乘法” | 3/3 |
| 非降维求和 | 降级到“沿轴降维” | 3/3 |
| 张量（15 条） | 拆出：创建与形状操作、按元素运算、拼接、广播机制、索引与切片，以及第六组 | 3/3 都建议拆分，前五组每次相同；第六组 2 次是“原地运算”，1 次凑成了“内存与类型转换” |
| 其余 19 个 | 保留 | 3/3 |

修复的问题：

- 整理建议的候选原先排除了所有新建概念，而真实笔记从空库开始，所有概念都是新建的，所以候选总是空的。
- 拆分原先只要有一组不合格，整条建议就被丢掉。现在改为逐组校验，只丢不合格的那一组。
- 拆分原先要求“每组至少 2 条”，模型为了凑数把“拼接”和“广播”放进同一组。现在改为每组至少 1 条，并在提示词里禁止为凑数把不相干的条目放在一起。

## 4. 观察到的现象

- **挂靠的粒度每次运行都不一样**，即使 temperature 为 0。同一份笔记，“张量”有时挂了 15–16 条，有时在挂靠时就分成了 8 个概念；“导数”有时是独立概念，有时被合进“梯度”的定义。这说明 AI 的输出只能作为起点，用户确认过的才算定稿；也说明后续实验要固定输入，才能比较。
- **“维度”这类合法术语**，按规则看是在“比较”，单独建成概念不算错。原先的评分预期有偏差。
- **查阅文档（dir、help）** 一直被建议保留。原因是笔记里从没单独讲过 PyTorch 或 Python，知识库里没有可以降级的目标。

## 5. 请 GPT 评议的问题

1. 你是否同意“挂靠时不控制粒度、事后给建议”？如果你有在挂靠时控制粒度、又不提高新建门槛的写法，可以在合成用例 R04 上验证。
2. 降级需要一个已有的目标。当目标还不存在时（例如 PyTorch），是允许建议“降级到一个新概念”，还是保留？
3. 拆分后，原概念下剩下的条目（张量的定义、求和、与 ndarray 互转）是否合理？“求和”应该留在张量下，还是和“沿轴降维”合并？
4. 建议在界面上怎么呈现：按概念逐条确认，还是一次性预览“采纳后的图”再确认？前者实现简单，后者更直观。
5. 用户采纳或拒绝建议之后，这个决定要不要记下来，让以后的整理建议不再重复提同样的建议？
