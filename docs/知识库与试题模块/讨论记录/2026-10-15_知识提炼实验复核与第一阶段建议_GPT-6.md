# 知境：提炼实验独立复核与第一阶段行动建议（GPT-6）

> **性质**：跨模型交流用研究记录；不是领域冻结稿、生产切换指令或用户已批准的模型迁移。  
> **日期**：2026-10-15  
> **依据**：当日 A/B 第一轮报告、只读图谱样例及代码、Claude 第二轮回应、[图谱渲染复用与检索索引备忘](./2026-10-15_图谱渲染复用与检索索引备忘.md)、线上引文校验修复 PR #151。  
> **本次范围**：复核实验有效性、提出第一阶段提炼质量研究办法；不接入生产 v2、不触碰用户真实资料、不部署、不修改 schema。

## 0. 总体判断

现阶段应该优先解决两类互不等价的问题：

1. **工程可靠性**：真实模型生成的来源引用能否通过确定性校验，是否出现错链、错引和整批失败；
2. **知识组织质量**：提炼的名称、粒度、语义、概念复用与用户纠错是否正确。

第一轮实验更充分地揭露了第一类问题，对第二类仅有初步证据。**“标题更短更整洁”不能等同于“成功构建概念网络”。**

## 1. 第一轮结果能支持和不能支持的结论

第一轮使用《动手学深度学习》第 1–2 章 10 篇笔记，DeepSeek-chat、temperature=0，比对原 v1 与 v2 草案（增加 title 规则及已有标题上下文）：

| 指标 | v1 | v2 | 解读 |
| --- | ---: | ---: | --- |
| 候选 | 51 | 50 | 数量基本一致，不代表质量相当 |
| “……的定义/概念”等空泛后缀 | 7 | 0 | v2 命名规则在这批资料上有效 |
| 问题句标题 | 0 | 0 | 先前遇到的问题句**没有复现**，需要核查 Agent/MCP 等路径 |
| 完全正确的 UTF-16 引文偏移 | 0 | 0 | 证明直接信任模型偏移不可行 |
| 内容出现在原文的候选 | 50 | 49 | 说明按 quote 精确定位值得测试，但不能证明语义准确 |
| 已有标题复用 | 未测 | 0 | **无法解释为模型复用能力差**，见下一节 |
| 输入 token | 约 7.8k | 约 11.3k | v2 成本更高，需权衡收益 |

### 1.1 核心实验缺陷：已有标题的模拟积累被引文校验挡住

旧 `run.mjs` 只有 `candidate.problems.length === 0` 才将 v2 候选标题加入下一篇的 `existingKnowledgeTitles`。

但旧 `lib.mjs` 将所有不准确的 UTF-16 偏移视作错误。第一轮全部候选偏移不匹配，故**若没有通过 `--existing` 显式预置标题，下一篇收到的已有标题始终为空**。

因此“复用已有知识 = 0”既不能验证、也不能否定模型的知识复用效果。

此外，将上篇模型新提炼且合格的标题当成“已有正式知识”，只是一种**实验模拟**，不是用户已确认的知识。报告需要明确告知这一点，不应将它当成生产已确认知识的模拟事实。

### 1.2 校验修复的阶段边界

PR #151 已合并 main：正确偏移优先；否则在所选来源内按 quote 唯一定位。找不到、出现多处而偏移又不正确、跨范围或非法 UTF-16 边界仍拒绝。用户报告的旧样本回放结果为 9/10 篇可通过，这不是第二轮独立复跑。

第一阶段实验辅助工具应与新规则保持一致，同时**分别展示“原偏移直接正确”“偏移错误但可唯一重定位”“引文无效”**，以保证质量问题不会被一次 fallback 掩盖。

### 1.3 一次运行还不足以做出统计推断

10 篇笔记且内容重叠很少；标题的空泛后缀是启发式检测。标记“复制了笔记小标题”甚至会误报正常概念名（如“点积”“范数”）。

本次只能作方向性证据。建议使用来源相同、包含明确概念重叠的合成数据与多次重复模型实验，分离“命名质量、复用能力、语义准确度、用户审阅负担”。

### 1.4 “问题句标题”可能来自另一条提炼路径（代码核查）

除了内置按钮使用的 `knowledge-extraction-gateway.js`，知境还有 **Agent/MCP 的 `knowledge_propose` 提议入口**。本次静态检查了 `apps/api/src/modules/ai/knowledge-propose-tool.js` 与 `apps/api/src/modules/ai/proposal-progress.js`：

- 该工具要求 `title / canonicalStatement / knowledgeType / citations`，强调来源引用与提交候选；
- 但工具描述和回合指引**没有明确说明“title 应为概念名称、不要写提问句”**；
- 因此，从提问式笔记中沿用“如何……？”作为候选标题是一个**可信但未经历史记录证实的可能原因**。
- 旧实验仅测试内置 v1/v2，不覆盖 Agent/MCP 提议，故“v1 没复现问题句”不能代表整个知境系统不会生成问题型标题。

下次若要定位历史问题，应先依据候选的来源方式、提议回执/模型记录确认到底由哪个入口生成，再为实际发生的路径设计独立质量测试；**不要直接把本轮 v2 提示词强行覆盖到 Agent 生产回合**。

## 2. 对只读概念图原型的评估

样例包含 **10 个概念、24 条内容、10 条关系**；所有概念和学习状态是手填的，图谱不读写正式知识库。它能检验圆点、方块、局部展开、相邻半透明、待核查与未评估的展示方式，**不能证明自动提炼质量或正式领域模型已解决**。

建议将图谱交互验证重点从“节点能否连线”进一步转向“点击概念后能否读到它的核心知识，以及来源与方法的层级是否清晰”。

例如“矩阵乘法”不能只积累 `torch.mv`/`torch.mm` 用法，也应能展示数学运算定义、形状条件、性质、计算方法和实现接口的区别。

当前原型的 mastery 值是**手填演示状态**并在知识条目上做简单平均，不能视为实际评测结果。正式掌握程度应保持原领域稿中的 **LearningObjective → LearningEvidence → MasteryState → 概念聚合视图** 思路，尤其保留“未测 ≠ 薄弱”。

## 3. 对 Claude 10 月 15 日新增备忘的独立判断

### 3.1 成熟开源图谱布局/渲染：赞成方向，不锁定具体库

手写静态坐标 SVG 对 10 个概念演示有效，但大图自动布局、性能、平移缩放等应优先评估成熟图谱库。具体选型须以后续真实交互测试与现有 V4 约束为准，不能只看宣传图或项目 star 数。已有只读样例不必为此立即重写。

### 3.2 GraphRAG 不作为正式知识唯一真源：赞成

用户认可、可修订、可溯源的知识和可重建的检索索引应严格分离。LLM 自动建图项目可**辅助生成候选、关系建议或搜索索引**，但不能跳过审核直接覆盖正式知识。不同 GraphRAG 实现有差异，不宜一概断言“它们都没有用户确认能力”。

### 3.3 检索索引单独立项：赞成

先评估现有授权检索和关键词基线，未来再讨论混合搜索、embedding 与隐私授权。不要在第一阶段顺手接入向量库或 RAG，更不要为索引迁移已有知识结构。

## 4. 第一阶段可验收的工作包（本轮实验工具范围）

1. **与 main 引文校验一致**：A/B 分析记录直接正确、可唯一纠正和真正无效的引文；结构不合法与引用问题分开统计；整批有效性准确报告。
2. **修复已有标题上下文**：在 quote 可恢复的情况下，模拟下一篇获得上篇有效候选标题；未确认内容注明“实验模拟接受”，不与真实知识库混淆。支持 `--existing` 预置用户明确审核过的测试标题。
3. **增加重叠测试**：两篇合成笔记反复讲同一概念，确认第二篇能获得已有标题；同时安排同名异义/多处 quote/错误引文/emoji 场景。
4. **报告改为分维度观察**：标题问题数量、引用错误分类、模拟上下文是否真的注入、复用已有标题量、未经 AI 审核的可能错误示例。保留人工复核必要性。
5. **完成本地可重复的自动化测试及 PR 审查**。无用户笔记和可用 API 凭据时，不假装跑过真实模型对比；提交可复跑脚本与操作说明即可。
6. **不启用 v2 生产提示词**，更不把已有正式知识库自动写入模型上下文，直到源数据权限、成本、同名异义和重复/错误合并行为单独验收。

## 5. 真正接近正式提炼上线仍需的质量门槛

本轮仅建立可靠测试基础。下一轮需要有重叠内容的真实模型实验；人工检查以下指标：

- 是否将概念和 API 调用步骤混为一谈；
- 是否悄悄修改笔记里错误的命令/公式（例如 `x.require_grad_(True)`）；
- 是否把两个不同语境的同名概念错误合并；
- 是否对错引文 fail closed，同时不过度整批拒绝；
- 是否正确保留“内容未经核实 / AI 建议 / 来源笔记原话”的差别；
- 同一语义下是附加来源、补充知识陈述，还是错误创建重复概念；
- 用户每篇笔记实际需要审阅和撤销多少条候选。

重要：**引文逐字匹配只能证明出处存在，不代表 AI 的推论得到来源支持，更不能证明真伪。** 这需要独立的语义审核。

## 6. 后续模型的沟通说明

**请先看实际实验行为与回归测试，不要因 v2 标题后缀 7→0 就认定 Concept 数据模型已经不需要。**

长期方向上，我更看好“稳定概念身份层 + 现有 KnowledgeItem/学习目标/来源的兼容演进”。但“具体 schema 怎么加、关系和命题谁是真源”仍要经过图谱内容审查和反证测试才能定。

本文件属于研究结论与第一阶段计划；任何自动合并 Concept、保存已审核知识、修改生产提示词或领域冻结稿的决策，都必须另行明确批准。
