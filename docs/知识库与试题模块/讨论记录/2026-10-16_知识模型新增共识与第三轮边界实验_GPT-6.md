# 知境知识模型：新增用户共识与第三轮边界实验（GPT-6）

> **性质：** 多模型共享讨论记录 + 可重复的研究计划；不是正式领域冻结稿或代码迁移授权。  
> **日期：** 2026-10-16  
> **依据：** 用户在第二轮结果后明确认可的两项设计方向、Claude 已完成的 Hardcases / Concept linking R2 实验及 GPT-6 独立复核。  
> **代码与安全：** 本轮单独新增实验，不修改正式知识库与数据 schema，使用公开合成数据。

## 一、用户新明确认可的方向

### 1. 概念身份和定义条目不是互斥选项

“矩阵加法”“逐元素乘法”都可以成为独立的 Concept（网络圆点），同时有关这些运算“是什么/如何定义”的陈述可以是该 Concept 下的 KnowledgeItem（命题或说明）。AI 把相关内容分类为 **definition** 或 **fact** 时，都可以根据语境成为合理选项；不能因为模型选择 definition 就判定识别失败。

**概念身份的独立性**与**知识内容的分类**属于两个不同维度，概念不等于命题，定义也不必代替概念。

### 2. 允许 AI 主动补充无笔记出处的知识

用户明确允许知境的知识内容不必依附于个人笔记；知识内容的“关联笔记来源”可以为空。这是产品方向，并非“任何 AI 生成内容都应自动确认正确”。

应保留：

- **笔记出处**：可以为空；不得为 AI 补充伪造引文。
- **来源方式/创建方式**：如 AI 建议、用户手写、笔记提炼；AI 即使没有笔记出处，也仍应可区分为 AI 补充。
- **审核与可信程度**：未核查、用户确认、存疑及来源是否可靠需独立表达；AI 无来源的建议初始应为 candidate。
- **知识身份**：AI 补充依然能关联已存在的 Concept，不必为了没有笔记引用就新建概念。

这些首先是语义责任，是否独立字段/表仍需在正式模型设计阶段确定。

## 二、已有真实实验的独立审阅（避免重复劳动）

Claude 最近已经开展两组与本方向高度相关的实验：

1. [Hardcases 合成压力实验](https://github.com/1848956505/Knowra/actions/runs/38903414094)，10 次请求成功。多概念知识、矛盾命题、错误 API 和**AI 无笔记出处补充**均有成功案例。模型在 H05 提议矩阵乘法计算公式，引用 quote=null、来源模式 ai、状态 candidate，这符合用户的新方向。
2. [Concept linking R2](https://github.com/1848956505/Knowra/actions/runs/38904135357)，8 篇笔记重复 3 轮，在预设合成题里正确关联，误挂 0。报告也记录：检索刻意隐藏正确 Concept 时，模型新建了语义重复候选；它能在自由文本中觉察重复，但**没有专门字段表达疑似重复**。其概念 sense 混入知识条目内容，自动规则未能检出。

对 H02、H04 两次复用失败还应更谨慎：模型识别了相同知识，却把旧条目 confirmed 状态复制进“候选”结构，有时增加辅助概念，旧模拟器因此拒绝。不能直接解读为模型没有识别知识复用；可能是**单一输出格式把新建与复用混为一谈**。

Hardcases 中按人工最小 Concept 集合打分也较苛刻：模型在“矩阵的秩”里额外关联了“向量”，并不能直接证明数学意义错误。后续评分应分别报告“必需对象是否遗漏”和“是否挂到了错误对象”。

## 三、本轮新增实验的重点

从上一轮真实失败直接出发，而不是重复容易的分类：

| 测试 | 要验证什么 |
| --- | --- |
| V01 已确认知识的不同表达 | **reuse 输出不包含新 status 或 conceptIds**，由已有条目继承其已确认状态与已有身份；保留原陈述，只添加来源 |
| V02 一份混合真伪的笔记 | 同时新建一条正常 candidate 和两条 disputed，分别指向原有冲突对象；不静默更正原始错误主张 |
| V03 AI 自主补充公式 | 无个人笔记时仍能补充 KnowledgeItem，quote=null、sourceMode=ai、reviewStatus=candidate；不冒充个人原文 |
| V04 检索漏掉原有概念 | 不能硬挂到其他运算；候选新概念保留 **possibleDuplicateOf**，提示人工审查，但不自动合并 |
| V05 矩阵加法的定义 | 已有 Concept 独立存在，定义/事实都可作为相关 KnowledgeItem |

本轮输出契约的核心尝试是：**新建条目、复用条目使用不同 JSON 形状；AI 来源来自受信输入，不由模型主观自称。**

这不是正式 schema 提案，而是减少业务歧义的实验性设计。

## 四、对照验证与决定边界

五个任务均在 **公开合成资料** 上先做无费 mock 测试；在 PR 的 CI、Mac 候选构建等质量门通过后，才将新 workflow 合并 main 并通过既有 Repository Secret DEEPSEEK 进行最多五次付费 API 调用。

一旦完成，应读模型真实候选，不因“格式校验通过”就宣称知识正确：

- V02：模型保留原错误主张还是悄悄纠正？
- V03：公式是否自洽，来源笔记确实为空，AI 来源身份是否保留？
- V04：是否创建“疑似重复”候选而不是静默合并或错误挂靠？
- V01：是否复用旧 KnowledgeItem，且未更改既有 confirmed 状态、归属和正文？
- V05：是否保留矩阵加法 Concept 的身份，而不是另建重复概念？

## 五、暂不做的事情

不修改生产提炼提示词、数据库、MCP、RAG、掌握度算法或用户真实数据；不因一次五样本成功而允许自动合并/自动核实；不使用 GitHub 公开仓库存放真实私密笔记。

**当前产品方向可以更明确了：概念是稳定身份；知识内容可以是定义、命题、程序或 AI 建议；个人笔记来源可为空，但来源类型与审核状态不能缺席；后续融合需要明示重复、冲突和用户确认。**
