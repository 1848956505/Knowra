# 增量确认内存演示

性质：操作闭环实验，不是正式领域模型或 AI 效果证明。

## 范围与入口

概念图 `#/knowledge/graph` →“增量确认演示（实验）”。使用完全合成的三条输入，不读取用户笔记或导入图，不调用模型/API，不写入浏览器存储或知识库。关闭、离开页面或刷新后清空本次演示；关闭弹窗不会清除原图的已导入结果、图层或选中项。演示中切换案例仅取消未提交的另建表单，已作出的选择保留到关闭。

界面并列展示新增条目与原文、一个已有概念候选与旧内容；提供归到这里、另建、暂不决定。另建需填写名称和语境；每条决定均可撤销，改选前先撤销。待定不创建概念或挂靠，不强造父概念。新条目投影保留合成原文，意见独立展示。

归属决定与事实核实、掌握状态不同，本演示不标记知识为正式 confirmed。也不做条目内容去重、关系生成、全图整理、自动选择或跨会话记忆。用户可以选择错误归属：本轮检验的是选择及不变性，而不是替用户判断。

## 模型边界

正式领域仍为 KnowledgeItem、KnowledgeEvidence 等；knowledgeType=concept 不是独立 Concept 身份。图与 concept-linking-r2 的 Concept 是实验模型。

本次使用独立 baseline、proposals、session decisions；不将实验 result.state 作为已确认基线，不将 applyResponse 的 accepted=true 当作用户确认。projectSession 只派生新增概念和新增条目，不修改旧正文或旧 conceptIds。session 不接收外部输入，当前仅通过本演示按钮写入。

## 验收

- 反向传播/backpropagation：归入已有概念，保留新应用条目、原文，旧内容不变。
- 数学梯度/x.grad：另建可取消，确认只产生一个新概念和一条新条目，撤销恢复。
- “检查 grad”：可待定，没有新增挂靠；可撤销回到未决定。
- 首次打开无新增、重复点击不重复、空名称或空语境不能提交。
- 跨案例保留决定，关闭重开与重新挂载清空；原导入图与选中项不变。
- 使用项目 Dialog 焦点管理、Button、TextField、TextAreaField；600px 以下比较区单列。

自动化入口：`incrementalConfirmation.test.ts` 与 `IncrementalConfirmationDemo.test.tsx`；完整检查为 `npm run check:web:v4`。真实浏览器窄屏、键盘与刷新验收需单独记录，不以单元测试代替实图证据。

真实浏览器脚本为 `e2e/incremental-confirmation.spec.ts`，已显式注册 `playwright.mobile-evidence.config.ts`，由 Mobile synthetic evidence 工作流执行。390px 与1440px 合成截图写入该配置的 test-results/mobile-evidence，通过既有 mobile-screenshots / mobile-evidence artifact 上传。测试阻断未模拟的 API、外部请求及 WebSocket；仅模拟外壳必要只读请求，不启用真实服务。
