### 需要优先处理的问题

1. **后端没有验证选区内容真实性**

   创建标注只校验整篇正文哈希，没有验证 `quoteText` 是否真的等于指定位置的正文。我用最小用例验证：正文为 `abc`，传入不存在的 `zzz`，后端仍创建了 `active` 标注。这样的标注未来也可能被当作有效知识证据。

2. **恢复逻辑会错误地恢复为 active**

   标注归档后，即使正文已经发生变化，恢复操作仍直接把状态设置为 `active`，不检查旧正文哈希和当前正文是否一致：[content-annotation-service.js (line 19)](/Users/rabbids/Documents/Codex/知境·Knowra/apps/api/src/modules/knowledge/application/content-annotation-service.js:19)。

3. **标注与知识证据只能“失效”，不能正确恢复**

   归档会把关联 `KnowledgeEvidence` 标成 `invalid`；但恢复或重新定位标注时，不会重新计算证据状态，也不会同步证据的 `noteVersionId`、引用文字和标题路径。结果可能出现：

   `标注 active → 知识证据仍 invalid/stale`

4. **正文修改后，V4 页面不会立即刷新标注状态**

   后端保存正文时会把旧标注标成 `stale`，但前端只在 `noteId` 改变时重新加载标注：[useEditorInspectorData.ts (line 42)](/Users/rabbids/Documents/Codex/知境·Knowra/apps/web-v4/src/features/editor/useEditorInspectorData.ts:42)。当前页面可能继续显示“已定位”，刷新或重新打开后才变成“待重新定位”。

5. **重复文字可能定位错误**

   位置失效后，V4 会搜索第一个相同文本，并没有使用已经保存的 `prefixText`、`suffixText` 和 `anchorFingerprint`，也没有要求匹配唯一：[editorAnnotations.ts (line 111)](/Users/rabbids/Documents/Codex/知境·Knowra/apps/web-v4/src/features/editor/editorAnnotations.ts:111)。一篇笔记里出现多个“因此”或相同公式时，可能高亮到错误位置。

6. **PostgreSQL 的归档与证据失效不是一个事务**

   标注先归档，然后回调更新知识证据和下游题目。如果后半段失败，可能留下“标注已归档、证据仍有效”的部分提交状态。

7. **知识点产品闭环尚未接入 V4**

   后端已经有 KnowledgeItem/KnowledgeEvidence，但 V4 没有：

   - “从此标注提炼知识点”
   - “关联到已有知识点”
   - 查看该标注产生了哪些知识点
   - 查看证据健康状态

   当前首页也明确把知识工作台标成“后端联调未完成”：[HomeView.tsx (line 44)](/Users/rabbids/Documents/Codex/知境·Knowra/apps/web-v4/src/views/HomeView.tsx:44)。
