# 后端 TS 迁移计划

本目录跟踪 `apps/api` 从纯 JavaScript 渐进迁移到 TypeScript 的长期任务。本文是唯一计划与进度入口；每完成一个阶段或目录，更新文末「进度记录」。

## 目标与原则

- **目标**：API 层（约 3.5 万行、327 个 `.js` 文件）获得与 V4 前端同等的类型保障，并让 API DTO 与 `packages/web-core` 共享同一份契约类型。
- **为什么**：日常开发以 AI 编写为主，`tsc` 能在一秒内发现签名错误、漏传参数和字段拼写错误，比等测试或页面验收更早。宽松模式试跑已发现真问题：`modules/ai/assistant-service.js:114` 调用 `fail(code, message, error)`，但 `fail` 只接收两个参数，原始错误原因被丢弃。
- **渐进，不重写**：`.js` 与 `.ts` 长期混用，按目录、按文件推进，每一步都可以单独合并、单独回退。禁止开长期分支一次性改完 327 个文件。
- **不为通过编译而降级**：不用 `any`、`@ts-ignore`、`@ts-expect-error` 压错误；确实无法表达的类型用 `unknown` 加收窄，并在 PR 中说明。
- **不改行为**：类型迁移 PR 不夹带功能改动；发现的真 bug 单独成提交，并补测试。

## 关键前提：Node 24 直接运行 `.ts`

Node 24 默认开启类型剥离，`node src/main.ts` 无需构建即可运行，因此启动脚本、自定义测试 runner、Docker 镜像（`node:24-bookworm-slim`）基本不用改。约束是只能使用可擦除语法：

- 不用 `enum`、`namespace`、构造函数参数属性（`constructor(private x)`）、`import =` 语法；
- 相对导入写 `.ts` 后缀（`import { x } from './y.ts'`）；
- 类型导入使用 `import type`。

阶段 3 开启 `erasableSyntaxOnly` 后，TS 会自动检查这些限制。

### 阶段 2：按目录清零并接入失败门

阶段 1 清零后，把 `typecheck:api` 从报告模式移入主 CI（`ci.yml` 的 fast checks），之后任何新错误都会阻塞合并。若阶段 1 无法一次清零，则按目录推进：为已清零的目录单独建 tsconfig 并先接入失败门。建议顺序（从易到难）：`errors` → `config` / `http` / `presentation` → `modules/sync` → `modules/task-workspaces` → `infrastructure` → `modules/ai` → `modules/knowledge`。

### 阶段 3：逐文件改为 `.ts`

1. `tsconfig.json` 增加 `allowImportingTsExtensions`、`erasableSyntaxOnly`、`verbatimModuleSyntax`，`include` 加入 `src/**/*.ts`。
2. 在 `AGENTS.md` 约定：新建后端文件一律使用 `.ts`；修改旧文件时，若改动较大，顺带迁移为 `.ts`。
3. 优先迁移被引用最多的层：DTO / 共享契约 → 领域模型（`modules/*/domain`）→ repository 接口 → 应用服务 → 路由与入口。
4. DTO 与 `packages/web-core` 的契约类型合并为一份，消除前后端两套定义。
5. 测试文件最后迁移；自定义 runner（`apps/api/test/run-tests.js`）需确认能加载 `.ts`。

**需逐项核实的风险**

- Mac 构建（`apps/desktop-shell/scripts/build.mjs`）用 esbuild 打包，esbuild 原生支持 `.ts`，但 AI worker 入口写死为 `${name}.js`，迁移这些文件时要同步修改。
- `apps/desktop-runtime`、`deploy/` 下的脚本与 Docker 启动命令中写死的 `.js` 路径。
- `scripts/check-v4-boundaries.mjs` 等仓库脚本若按扩展名扫描 API 文件，需同步更新。

### 阶段 4：开启 strict

大部分文件迁为 `.ts` 后，按目录开启 `strict`（每个目录可先用独立 tsconfig）。参考：在纯 JS 上直接开 strict 会有 7817 个错误，其中约 60% 是参数隐式 any（TS7006），会随阶段 3 自然减少。

## 给 AI 与审查者的工作约定

- 每个 PR 只做一个阶段内的一个目录或一类问题，diff 控制在可以人工审查的范围。
- 每个 PR 都要报告 `npm run typecheck:api` 前后的错误数，并运行 `npm run test:api`。
- 类型注释只描述现有行为，不顺手重构；需要改行为时单独提交并说明原因。
- 外部审查（如 ChatGPT 复核）结论记入进度记录，确认稳定后再进入下一阶段。
