Knowra 笔记内容样式

DRAFT内容排版样张更新于 09/24

这份页面把笔记正文里的常见能力放进同一个真实阅读场景中。整体不采用“卡片套卡片”，而是尽量保持 内容优先、结构清楚、强调克制。正文默认是干净的白纸，蓝色只负责交互、层级与关键状态。

普通文本可以包含 粗体、斜体、删除线、高亮文本、内部链接，以及像 torch.nn.Module 这样的行内代码。

标题与正文层级

一级标题适合文档中的大章节；二级标题是最常用的结构层级；三级标题只做轻量分组。视觉上避免为每一级标题都添加厚重容器，而是通过字号、留白和少量蓝色标记建立节奏。

三级标题示例

三级标题使用更紧凑的间距，并保留一个轻量的 # 标识。正文阅读时不会被过度切碎。

列表

无序列表使用品牌蓝色方点，和你当前界面中的蓝色方块语言保持一致：

  • Markdown 是知识库的主要编辑载体。
  • 格式能力应该服务内容，而不是变成装饰性工具条。
  • 同一套正文样式可以复用于知识点、试卷解析和 AI 生成内容。

有序列表把序号改成两位等宽数字，更像“知识索引”，同时不会抢正文：

  1. 先记录知识。
  2. 再抽取知识点与考点。
  3. 最后进入训练、批改与复习闭环。

任务列表保持明确的方形交互感：

  • ✓整理数据增强综述
  • ✓完成 CutMix 主实验配置
  • 补齐 RandAugment 实验记录

引用与提示

真正重要的不是让每个元素都“有设计感”，而是让用户在阅读时几乎意识不到设计的存在。

代码

行内代码已经尽量轻量；完整代码块则保留“工具窗口”的机械感，与现有编辑器边框语言一致。

PYTHONtrain.py
def train_one_epoch(model, loader, optimizer, device):
    model.train()
    total_loss = 0.0

    for images, targets in loader:
        images = images.to(device)
        targets = targets.to(device)
        optimizer.zero_grad()
        loss = model(images, targets)
        loss.backward()
        optimizer.step()
        total_loss += loss.item()

    return total_loss / len(loader)  # epoch mean loss
