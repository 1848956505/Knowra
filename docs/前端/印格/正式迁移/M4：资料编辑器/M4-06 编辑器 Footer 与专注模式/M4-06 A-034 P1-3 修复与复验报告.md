## 2. 根因

1. AppShell 在主页仍会执行编辑器渲染。SSR/列表摘要中当前资料的 `rawMarkdown` 为空，因此主页阶段提前为该 Note ID 挂载了空 Milkdown Host。
2. 从“最近编辑”打开同一资料并取得完整详情后，原复用逻辑只比较 Note ID 与 Host 是否存在，没有比较 Host 实际挂载的 Markdown 与新的 `state.draftMarkdown`。
3. 因 Note ID 未变化，空 Host 被错误复用；打开再关闭源码分栏会强制重挂载，所以正文才在该操作后恢复。
4. 若完整正文恰好在空 Host 异步挂载期间到达，原 `pendingEditorNoteId === noteId` 判断也会跳过新挂载，存在同类竞态窗口。

## 3. 修复

### 3.1 阻止非编辑工作域提前挂载

- `renderEditor()` 在明确的 `home` / `index` 等非编辑 screen 中不再创建 Milkdown Host。
- 若切出编辑器时仍有已挂载或挂载中的 Host，则按既有销毁链路释放，避免摘要正文参与后续复用。

### 3.2 复用必须同时满足正文身份一致

- 编辑器运行态新增 `currentEditorMarkdown`，记录当前 Host 实际挂载或最后变更的 Markdown。
- `reuse-rich-editor` 现在要求 Note ID 相同、Host 存在且 `currentEditorMarkdown === state.draftMarkdown`；完整正文晚于空 Host 到达时转为重新挂载。
- 销毁和启动新挂载时同步清空该身份，避免陈旧正文被误判为可复用。

### 3.3 封闭异步挂载竞态与空白自动保存

- 运行态新增 `pendingEditorMarkdown`。只有挂载中的 Note ID 和 Markdown 均相同时才去重；同 Note ID 从空摘要变为完整正文时会启动新的挂载，并用 mount token 销毁过期 Host。
- 过期挂载失败不会清除当前新挂载的 pending 状态。
- Milkdown 初始 `onChange` 若与 `state.draftMarkdown` 完全一致，直接返回，不调度 autosave；真实用户编辑仍更新草稿并进入既有自动保存链路。
