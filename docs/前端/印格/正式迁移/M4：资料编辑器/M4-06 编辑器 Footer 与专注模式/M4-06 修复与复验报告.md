## 2. P1 修复

### P1-1 专注进入/退出后焦点落到 BODY

- 根因：Footer 专注按钮随 `renderAll()` 重绘，原触发器从 DOM 移除后没有焦点接收方。
- 修复：专注模式变更完成并重绘 Footer 后，查询新生成的 `[data-status-action="toggle-focus"]` 并立即聚焦。
- 结果：进入专注后焦点位于“退出专注模式”按钮；退出后焦点位于“进入专注模式”按钮，`aria-pressed` 分别为 `true` / `false`。

### P1-2 阅读模式进入专注后正文变为可编辑

- 根因：编辑器渲染器使用 `mode !== 'read'` 判断可编辑性，将布局态 `focus` 错当成编辑业务态。
- 修复：有效视图新增派生 `contentMode`；专注布局从 `modeBeforeFocus` 读取 `read` / `edit`，编辑器根据 `contentMode` 决定渲染只读预览或 Milkdown，Shell 仍使用 `mode=focus` 控制布局。
- 结果：阅读模式进入专注后保持预览宿主且不存在 `[contenteditable="true"]`；退出后仍为阅读模式。编辑模式进入专注仍保留可编辑 Milkdown。
- 补充：在“阅读 + 专注”中主动打开源码属于明确编辑动作，会把底层业务模式切换为 `edit`，但专注布局保持不变。
