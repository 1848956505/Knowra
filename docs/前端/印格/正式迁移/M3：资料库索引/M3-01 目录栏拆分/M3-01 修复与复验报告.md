# M3-01 目录栏拆分修复与复验报告

## 1. 修复结论

`执行侧已修复 / 待正式复验`

本轮针对验收退回的 P2 可访问性问题完成修正：目录树的分组折叠、文件夹展开/收起和目录头部辅助菜单均补齐 `aria-expanded` 与 `aria-controls`，并保证被控制的内容节点始终有稳定 ID。原有选择、折叠、增删改、拖拽、右键和内联编辑事件链未改写。

## 2. 原验收问题

验收结论为功能项通过、正式门禁 `REJECTED`。退回原因为：目录树折叠按钮只有 `data-open`，没有维护 `aria-expanded` 与 `aria-controls`，不满足迁移契约可访问性要求（`01-迁移契约与功能对等清单.md:102`）。

## 3. 修复内容

### 3.1 资料分组折叠

`apps/web/lib/navigation/tree-renderers.js` 的 `renderNavigationSection()` 现在：

- 在分组按钮上输出 `aria-expanded` 和 `aria-controls`。
- 使用 `buildLibraryTreeControlId()` 生成稳定的控制目标 ID。
- 折叠时保留内容容器，仅使用 `hidden` 表达不可见状态，避免 `aria-controls` 指向不存在的节点。

### 3.2 文件夹展开/收起

`apps/web/src/controllers/navigation/render/tree-render-controller.js` 的文件夹节点现在：

- 仅在文件夹确实有子内容时输出 `aria-expanded` / `aria-controls`。
- 为每个文件夹子内容容器生成稳定 ID。
- 收起时保留容器并设置 `hidden`，展开时恢复原有内容展示。

### 3.3 目录头部辅助菜单

`#secondary-nav-toggle` 在 SSR 和运行态均维护：

- `aria-expanded="false|true"`
- `aria-controls="library-section-menu"`

这与既有 `data-open` 状态保持同步。
