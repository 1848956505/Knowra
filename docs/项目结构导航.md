# 项目结构导航

当前任务、实现与验收证据见[任务盘点索引](任务盘点与验收索引.md)；资产后续边界见[当前清单](资产生命周期任务/README.md)。


> 本文档是项目生命周期内持续维护的代码定位地图。它不替代开发规范和设计文档，而是帮助开发者和 AI Agent 快速判断“某类改动应该去哪里改、不要去哪里改”。

## 维护原则

1. 新增一级目录、重要模块目录或跨模块入口时，必须更新本文档。
2. 文件职责发生迁移时，更新对应目录说明和“改动入口”。
3. 本文档只描述稳定边界、关键文件和定位规则，不逐函数罗列实现细节。
4. 普通业务源文件理想不超过 250 行；超过 250 行需说明是否职责过多，超过 400 到 500 行且职责混杂时应列入拆分队列。
5. 自动生成文件、bundle、mock 数据、schema、路由配置等可以较长，但不能混入业务逻辑。
6. 当前仍在重构中，若本文档与代码不一致，以代码为准，并在本次改动中修正文档。
7. **必须遵守：**本文档应该在文档框架的基础上进行完善与更新，而不是直接在末尾进行增补。即文档的更新应该是像建房子一样，而不是像贪吃蛇一样末尾增补
8. **变更记录的去向：**本文档只描述**当前**的代码结构。历史变更、bug 修复、版本演进请写到 [`docs/工程变更日志.md`](工程变更日志.md)，不要再回填到这里的「更新记录」一节（该节已于 v2.0.6 删除）。

### `docs/AI功能`

模型接入设置位于 `apps/web-v4/src/features/settings/ModelConnectionSettings.tsx`；`ModelRuntimeStatus.tsx` 只读取既有助手运行状态。API 与桌面分别由 `ai/model-settings.js` / `desktop-shell/src/model-settings.cjs` 保存凭据；`apps/api/test/run-model-settings-tests.js` 可运行已注册的模型设置回归，覆盖三端支持模型与固定错误消息契约。

对话附件基础位于`ai/conversation-attachments.js`与`ai/conversation-attachment-routes.js`，私有schema/store限定原文件和未解析状态；`ConversationAttachmentPicker`仅文件信息与受保护图片本地预览，不发送模型。未审parser目录、依赖和自动调用已移除；当前能力与后续边界见[对话文件输入](AI功能/08-对话文件与图片输入实施计划.md)。

[AI 功能开发工作区](AI功能/README.md) 保存需求共识、用户流程、可插拔架构、数据/工具/权限契约、任务与验收。当前重点为可故障隔离的 AI 底座和对话式笔记 Agent：授权内自动检索，新稿与差异稿先进入成果收件箱，用户确认后采纳。未来正式试题/日常测试与批改走专门系统流程。P0/P1 已有基础记录，新共识差距见 [P1 对话 Agent 补齐方案](AI功能/06-P1对话Agent补齐方案.md)，实施进度统一在 [任务表](AI功能/04-分阶段开发任务.md)；规划与历史验收不代表当前上线能力。

沉浸式助手页位于 `apps/web-v4/src/features/assistant/AssistantView.tsx`，成果审阅为同目录 `AIInbox.tsx`，当前会话成果匹配见 `reviewTarget.ts`，引用历史原文的读取、校验与会话/关闭失效统一由 `useConversationSourcePreview.ts` 管理，工具调用记录的折叠展示、工具标签与结果摘要由 `ConversationTrace.tsx` 负责，按需读取与缓存仍在助手页编排；纯文本安全展示组件为 `ReadableMarkdown.tsx`，输入区附件入口为 `ConversationAttachmentPicker.tsx`。三态合成截图与边界见根目录 [design-qa.md](../design-qa.md)。

P2 计划入口为 API `modules/ai/note-plan.js` 与 `contracts/note-tools-v1.schema.json`，仅构建固定目标、正文/元数据基线与精确差异；业务写入和用户批准必须走后续领域原子提交，不通过该构造器直接写库。

### `apps/android`

Java 原生 Android 在线启动器，独立 Gradle 工程。`ServiceOrigin` 规范化 HTTPS 根地址，`BrowserLauncher` 选定默认 Custom Tabs 浏览器并启动，`MainActivity` 管理显式地址、切换确认与忘记地址。完整网页/TLS/认证归浏览器，不内嵌 WebView、不导入 Node/Electron、不提供离线数据库。构建与限制见 [Android 在线预览版](Android/在线预览版.md)。

### `apps/desktop-shell`

个人 Mac 应用外壳。`src/release-updates.cjs` 提供手动稳定 Release 检查与确认后打开固定发布页；`scripts/verify-distribution.mjs` 校验 ZIP 解包身份；mac-build 工作流提供隔离候选构建，不发布正式 Release。`src/main.cjs` 管理窗口、单实例、安全隔离与退出；`preload.cjs` 提供保存握手、受限草稿和完整备份动作 IPC，`draft-store.cjs` 负责笔记和知识表单的独立原子恢复草稿文件；`runtime-entry.mjs` 在 utility process 启动 SQLite 本地服务。`scripts/build.mjs` 收集程序资源并生成本地签名的 ARM64 `.app`，不包含用户数据。`src/attachment-downloads.cjs` 只接受附件 ID，使用当前 APP 会话与资料集下载、原生另存为并凭临时令牌主动打开；构建收集该模块，`test/packaged-attachments.test.mjs` 使用隔离资料目录验证真实会话与正文链接。`src/backup-transfers.cjs` 检查受信主 frame、当前资料集和退出状态，通过原生目录选择器取得路径，再经私有 utility-process RPC 导出或导入；renderer 只提供动作、资料集与备份 ID。`test/packaged-independent-backup.test.mjs` 验证两独立合成根的完整导出、导入、明确恢复及重启。使用说明见 [Mac 个人应用](离线编辑与同步/Mac个人应用-构建与使用.md)。

构建和安装通过根 `scripts/build-info.mjs` / `release-artifact.mjs` 统一校验版本与完整提交；APP 根资源与内置 Web 保存同一 `build-info.json`，ZIP 旁保存含 SHA-256 的 `.build-info.json` 分发清单。`test/exit-diagnostics.mjs` 仅为顶栏合成验收观察退出阶段，按白名单采集日志、进程状态与失败页面截图；Mac CI 固定路径上传诊断，不收集资料库或凭据。`test/packaged-build-info.test.mjs` 核对真实设置页、静态标识和启动回执；`packaged-app-path.mjs` 只接受构建产物或 `KNOWRA_DESKTOP_TEST_APP` 指定测试副本，不自动启动用户安装的 APP。

`test/editor-readiness.mjs` 为打包附件验收等待精确笔记路由与可见 ready 编辑器，两阶段共用 20 秒，失败仅记录阶段、路由与 ready 状态；原生启动单独计时。

### `apps/desktop-runtime`

`src/http-shutdown.mjs` 统一 HTTP 与 MCP 服务的退出排空：仅回收零输入、从未开始 HTTP 请求的预连接，保留部分请求与响应的自然排空，并额外等待断线后仍执行的 handler。`runtime-server.mjs` 继续负责 MCP、HTTP、同步、AI、SQLite 与目录锁的关闭顺序；外壳只记录固定阶段枚举，不记录请求或用户数据。

`src/knowledge-lifecycle-boundaries.mjs` 只为本地业务事务保存知识回收／恢复的 outbox 描述符；`sqlite-data-store.mjs` 同事务登记，`entity-sync-state.mjs` 保留发送边界、级联失效与后继修改，`sync-engine.mjs` 对冻结解除保持绑定一致。沿用 batch2，私有标识不上传；能力合同要求 `knowledge-lifecycle-v1`。真实存储／页面与发布边界见 [桌面资产补齐](离线编辑与同步/桌面资产补齐-实施与验收.md)。

训练六集合通过 `sync/training-batch-domain.js` 校验领域终态和题目版本；`question-objective-identity.js` 保持存活关系身份、重建已删除关系时产生新 ID。`knowledge-lifecycle-boundaries.mjs` 同时保留四训练主体的明确回收／恢复，`exam-focus-review-boundaries.mjs` 只记录实际考点确认所需审阅依赖前像及 frozen 回执绑定，保持确认后修改父项的既有 Web 语义。能力合同同时要求 `training-assets-v1`，不扩展正式试卷或作答模型。

`authoritative-purge.mjs` 在原有五类手工资产接口前执行联网预检、原 token／世代／版本核验、待核对结果持久化和真实删除事实对账；`sync-execution-gate.mjs` 与 scheduler／configure／disconnect／restore 共用排空边界。云端 `asset-purge-task-state.js` 从实际私有 JSON／SQLite／PG 记录读取任务与历史，`asset-purge-guard.js` 为领域清理补齐失败关闭和事务内世代核验。V4 `store/assetPurge.ts` 仅组织专用清理能力、原预检参数与待核对状态；通用 `permanentDelete` 保持关闭，不能用于离线物理清理。

### `apps/api/src/modules/ai`

`assistant-service.js` / `assistant-routes.js` 保留旧版任务入口与只读回看；`conversation-service.js`、`agent-worker.js` 负责新会话和有界工具循环。`access-service.js` 核查持续授权及逐请求外发，`retrieval.js` 是候选索引与当前授权版本之间的安全入口，`keyword-search.js` 是默认检索和故障回退。`read-context-service.js`、`worker.js` 仍服务旧版短时范围任务；`record-*` 与 `contracts/` 管理私有记录。实际生成受配置、预算及外发门禁控制。

`conversation-records.js` 统一六类会话持久记录的 schema、语义与跨记录引用校验，返回隔离副本，不读写存储；JSON 私有状态及 PostgreSQL/SQLite 适配器直接使用该契约。`conversation-store.js` 保留事务内状态操作与旧契约导出兼容，租约、原子性和数据格式不变。冻结输入、错误优先级及合成适配器边界回归见 API runner 注册的 `ai-conversation-records.test.js`；真实持久化回归仍使用各存储测试。

`agent-request-context.js` 纯组装普通/授权历史、来源凭据哈希、授权问题与无授权消息文本；保持历史过滤顺序和 UTF-16 长度裁剪。`agent-worker.js` 仍负责授权复核、请求来源预算重试、外发及恢复。边界回归见 `ai-agent-request-context.test.js`，mock 请求集成见 `ai-agent-r04.test.js`，由 API runner 显式注册。

`agent-knowledge-provenance.ts` 为 Agent/MCP 提议生成白名单来源摘要，绑定回执与完整来源哈希并调用严格来源验证器；`.js` 保留五个同身份导出。plan/candidate/origin 只声明读取所需的最小视图，未验证字段仍为 unknown；共享 quote hash 仅按 primitive string 支持域调用。提议与提交服务、record-contract 及共享 hash 实现保持独立，不把该叶子称为整个提交链端到端严格化。

`proposal-progress.js` 根据工具结果与当前来源窗口纯计算知识提炼进度、待提交判定和模型提示；不读取存储或执行工具。`agent-worker.js` 消费结果并保留原 `proposalProgress` 导出兼容。纯规则回归见 `ai-proposal-progress.test.js`，现有工具与有界循环场景见 `ai-knowledge-propose.test.js`，均由 API runner 注册执行。

`recovery-scope.js` 登记恢复任务并在关闭时停止新准入、等待在途任务；`runtime-lifecycle.js` 为同一 AI runtime 复用关闭所有权。API 的完整启动恢复链、应用 context 关闭和桌面启动／配置后的恢复复用该边界；原生 HTTP `server.close()` 保持原语义，持库宿主需显式等待 AI 关闭后才断开存储。复现、调用约定及验收见 [启动恢复与关闭竞态](AI功能/p1/启动恢复关闭竞态-修复与验收.md)。

关键词覆盖由 `access-service.js` 的 `findAuthorizedSearchCandidates` 先在当前授权与扫描预算内筛选，`keyword-search.js` 再对最多 300 篇匹配候选验证版本、评分和引文；`verifyRead` 的受信可选单篇上限保护复核前的正文增长，普通 R02 read 默认行为不变。回归入口为 `ai-keyword-coverage.test.js` 与真实数据库条件套件 `ai-keyword-coverage-postgres.test.js`，规则及全空间列表读取边界见 [覆盖验收](AI功能/p2/授权关键词检索覆盖验收.md)。

`reviewed-price-profile.js` 是 API 与 desktop-runtime 共用的 `deepseek-flash` 已复核人民币价格档案；本地有效期到点拒绝，其他模型不能套用。`budget-ledger.js` 按相同计费账户/北京日期保留未知用量占额，刷新价格版本不清空旧预留。公开来源、装配链路及离线边界见 [核价刷新验收](AI功能/p1/核价刷新-2026-10-02验收.md)。

## 共享包

### `packages/web-core`

V3 与 V4 共用的框架无关浏览器业务核心。包含 API envelope/client/workspace API（加载、创建、重命名、收藏、删除与回收站 mutation）、workspace 类型、normalization/cache/loading/write guard，以及 `note-file-actions.ts` 中的副本命名、导出文件名与 HTML 文档生成纯规则；源码不依赖 DOM、React、CSS 或任一应用目录，`dist/` 由各前端的 predev/pretest/prebuild 自动生成。

`src/api/attachment-api.ts` 统一附件列表、上传、重命名、删除预检、校验、恢复、清理状态与重试的九个客户端方法，只依赖注入的 `RequestJson`；`workspace-api.ts` 组合为原有扁平 `WorkspaceApi` 并保留上传输入类型的旧出口。各方法既有请求与宽松响应契约不变。

`src/api/command-note-search.ts` 定义可选 `WorkspaceApi.searchCommandNotes` 能力、当前空间的查询契约以及数量/片段上限，严格验证四字段命中 DTO；它不承担 renderer 交互或授权判定，V4 和服务端分别绑定当前空间与校验 owner。

### `packages/content-anchor`

API 与 V4 共用的无 DOM Markdown 来源投影。输出可见文本到原文 UTF-16 半开区间、结构路径、内容块与标题边界，并提供浏览器可用的 SHA-256、v2 anchor 校验及仅唯一候选自动重定位。不依赖 ProseMirror 坐标，不执行任意首个同文匹配。

`src/index.js` 仅保留显式公共导出，内部模块直依实现，不回导入口。`src/projection.js` 统一 Markdown 投影与范围／块／章节锚点基元，`src/hash.js` 保存原哈希算法；`src/anchor-resolution.js` 编排静态解析、重定位和章节跟随，并复用列表解析。

动态跟随入口：`src/source-edit.js` 定义单步来源编辑及重放，`src/dynamic.js` 负责范围继承与稳定结构身份，`src/source-diff.js` 组合离散源码变更。`src/list-projection.js`、`list-anchor.js`、`list-identity.js`、`list-follow.js` 分别负责列表层级投影、完整子树锚点、列表结构身份继承与成员／父项变化确认，列表不走同文重定位；`test/dynamic.test.js` 与 `test/list.test.js` 覆盖编辑、空块／空项、拆合、移动及边界行为。

`test/dependency-layers.test.js` 防止包内依赖环和实现反向导入公共入口；公共兼容回归固定旧版输出，检查导出全集与内部实现引用。身份影子只共享哈希，继续保留独立公式解析与 S1／S2a 保存契约。

API 的 `annotation-change-context.js` 校验保存映射，`reconcile-annotation-source.js` 协调当前锚点，`annotation-range-preview.js` 生成绑定版本的范围确认摘要。定位侧数据保存在 `Note.annotationStructure`，历史锚点保存在 `AnnotationRevision`；PostgreSQL 迁移为 `e_annotation_tracking`。

V4 的 `annotationTransactionRanges.ts` 处理 ProseMirror 连续映射，`annotationEditJournal.ts` 冻结保存批次并恢复草稿映射，`editorAnnotations.ts` 负责插件状态和装饰。稳定身份迁移期间，`editorBlockIdentity.ts` 维护块 `blockId`、不绘制的 `knowraAnnotation` 重点 mark 与序列化前剥离，`annotationShadow.ts` 把身份推出的范围与现有推算逐事务比对，并在保存时生成身份快照（S1／S2a 影子阶段，只诊断）；服务端对应 `packages/content-anchor/src/identity-shadow.js` 与 API `application/annotation-identity-shadow.js`，本地日志在 `storage/runtime/annotation-shadow.jsonl`。块内偏移模型在 `packages/content-anchor/src/block-offsets.js`，重点绑定的推出与校验在 `identity-binding.js`，API 在 `application/annotation-identity-binding.js` 于新建、正文保存、同正文身份更新及同步后像刷新 `ContentAnnotation.identityBinding`；单次刷新复用解析上下文，SQL NULL 清空与事务回滚由既有仓储／同步边界负责。桌面真实页面回归入口为 `test/e2e/annotation-dynamic.test.mjs` 和 `annotation-list.test.mjs`；API 的 `test/annotation-list-postgres.test.js` 验证真实 PostgreSQL 对等语义与事务回滚，桌面 `test/annotation-list.test.mjs` 验证 JSON／SQLite 恢复及两个 SQLite 设备经 JSON／PostgreSQL 云端同步，`apps/desktop-shell/test/packaged-list.test.mjs` 验证 Mac 打包应用退出重开。列表扩展使用本地逻辑格式 6 和同步实体格式 6，保留已有 SQLite 物理表版本与同步世代。

重点内联化（《重点标记内联化方案》）：`editorKnowraMarks.ts` 定义 mark `knowraMark` 与块属性 `knowraBlocks`，并通过 `createKnowraMarksCodec` 在解析器、序列化器入口与正文标记互转（规则在 `@study-accelerator/shared/knowra-marks`，块内偏移换算复用 `content-anchor` 的 `identityBlockModels`）。`editorKnowraClipboard.ts` 负责复制副本的统一 ID 映射、章节排除关联和代码内的纯文字重点区间；`editorPasteBehavior` 接管含标记的粘贴，`editorBlockIdentity` 按最终插入范围规整，并区分剪切/拖动。I1 只做格式支持，未开放新建入口。服务端 `application/inline-annotations.js` 在保存后从正文派生 `schemaVersion: 3` 的重点行，并在装配层区分"只改标记"的保存（I2）。

S2b-1 块身份表存放在可选的 `annotationStructure.identity`，不替换旧链路 `nodes`：API `application/annotation-change-context.js` 负责随保存写入、沿用或失效；`sync/batch-domain.js` 丢弃不合法的诊断表而保留同步正文。`identity-shadow.js` 的 `validIdentityTable`／`adoptIdentityIds` 校验并沿用非空唯一块 ID，V4 `annotationShadow.ts` 的 `applyBlockIdentity` 在加载或远端整篇替换后回填；远端正文重建编辑基线后再解析重点。`apps/desktop-runtime/test/e2e/annotation-block-identity.test.mjs` 覆盖 SQLite 保存重开及带重点的双设备同步、原位替换与撤销。
