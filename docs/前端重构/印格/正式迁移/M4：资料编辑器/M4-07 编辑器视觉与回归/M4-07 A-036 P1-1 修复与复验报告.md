## 3. 真实状态发现与修复

### 3.1 长附件文件名

- 修复前：Inspector 总宽度没有撑破页面，但 `.resource-meta strong` 保持 534px 自然宽度，父级仅在面板边界硬裁切；`text-overflow: ellipsis` 没有真实生效。
- 修复：`.resource-entry` 改为 stretch，并对 entry/meta 增加 `min-width: 0`、`max-width: 100%` 与 `overflow: hidden`；文件名强制 block 且最大宽度为 100%。
- 修复后：条目和 meta 均为 106px，文件名 `clientWidth=106`、`scrollWidth=534`、`overflow=hidden`、`textOverflow=ellipsis`；Inspector 及页面宽度不变。

### 3.2 200% 缩放重排

- 真实 Chrome 通过五次 `Command + +` 显示“缩放比例：200%”。
- 修复前的 544px 等效 CSS 视口中，主页和编辑器 `scrollWidth=1024`、`innerWidth=544`，页面级横向溢出 480px；根因是 `body` 仍强制 `--app-min-width: 1024px`。
- 新增 `knowra-inkgrid-reflow.css`：700px 以下释放 body 最小宽度，将功能导航收窄为仍保留原生按钮/可访问名称的 56px 图标栏，资料目录改为覆盖层，主区保持 `minmax(0, 1fr)` 流式轨道，并收敛 TopBar 动作。
- 修复后 544×342：主页、资料索引、编辑器三段均为 `scrollWidth=innerWidth=544`；功能栏 56px、FeatureStage/EditorMain 488px、Footer 544px。资料索引需先用现有“折叠目录栏”和“收起详情”按钮释放两个覆盖面板，再打开资料，主路径完整可达。
