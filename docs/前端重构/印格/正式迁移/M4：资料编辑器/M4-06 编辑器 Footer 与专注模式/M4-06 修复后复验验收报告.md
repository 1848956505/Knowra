### M4-06-P1-2 阅读模式进入专注后变为可编辑：已关闭

- 进入前：Shell `data-view-mode="read"`，`[contenteditable="true"]` 数量为 0。
- 进入专注后：Shell `data-view-mode="focus"`，`[contenteditable="true"]` 仍为 0；只读正文保持显示。
- 退出后：恢复 `data-view-mode="read"`，正文继续不可编辑。
- 编辑模式对照：进入专注前后均保留可编辑 Milkdown；专注模式只改变布局，不再隐式改变阅读/编辑业务语义。

## 新发现

### M4-06-P1-3 首页首次打开当前资料时富文本正文为空

- 路径：新建真实页面会话 → 主页“最近编辑” → “打开资料：CLIP”。
- 可复现性：两个独立真实浏览器会话均复现；第二次会话在打开后等待 2.5 秒仍未恢复。
- 实测：Shell 已进入 `edit`，Footer 显示“字数 11993 / 行数 2093 / 链接 27”，但 `.ProseMirror` 仅含空段落 `<p><br class="ProseMirror-trailingBreak"></p>`，可见正文为空。
- 数据对照：不修改资料，打开源码分栏后 textarea 中存在 31669 个字符并显示完整正文；关闭源码分栏触发富文本重新挂载后，`.ProseMirror` 文本恢复。说明资料数据已加载，问题发生在富文本 Host 的挂载或复用同步路径。
- 静态推断：`renderEditor()` 的 `reuse-rich-editor` 分支只刷新保存状态和面板，没有在同一 Note ID 的完整正文晚于空 Host 到达时同步 `state.draftMarkdown`；需要执行方结合启动/主页选中链路确认根因。
- 影响：用户从主页打开真实资料会看到空白编辑器，若直接输入并自动保存，存在用空白草稿覆盖既有正文的风险；属于核心编辑路径功能回归。
- 优先级：P1。
