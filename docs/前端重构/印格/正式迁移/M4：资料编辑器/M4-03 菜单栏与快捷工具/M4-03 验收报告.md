## 功能与可访问性发现

### P1-1 “更多”键盘路径丢失焦点，43 个收纳命令无法从触发器连续访问

- 运行态：激活“更多”后弹层正常渲染，但 `document.activeElement` 变为 `BODY`，没有保留在重新渲染后的触发器，也没有转移到第一个 `menuitem`。
- Escape 路径：手动聚焦“新建笔记”后按 Escape，弹层能关闭，但焦点再次落到 `BODY`，未返回“更多”触发器。
- 源码原因：`menu-events.js` 在切换状态后立即重渲染整个菜单栏，没有安排焦点转移；`menu-state-controller.js` 关闭后也只重渲染，没有恢复触发器焦点。专项测试只验证状态切换与 click 派发，没有覆盖打开后焦点、Escape 焦点恢复和键盘连续访问。
- 影响：M4-03 的核心准出条件要求被收纳命令进入“可键盘操作”的“更多”菜单；当前焦点链在打开时中断，判定键盘不可达。

### P2-1 关闭态菜单触发器指向不存在的 ARIA 控制目标

- 运行态：“文件 / 段落 / 编辑 / 格式 / 视图 / 更多”触发器始终输出 `aria-controls="editor-menu-*"`，但弹层只在打开时渲染；关闭态下 `document.getElementById(aria-controls)` 为 `null`。
- 影响：控制关系在 DOM 中不完整，与项目已在 M3 阶段采用的 `aria-controls` 目标存在规则不一致。
