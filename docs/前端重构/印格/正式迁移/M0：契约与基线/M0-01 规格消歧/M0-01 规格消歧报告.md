建议把当前三张页面原型的正式目标收敛为以下语义尺寸：

| 语义区域 | 正式建议值 | 适用范围 | 说明 |
| --- | ---: | --- | --- |
| `AppShell.FunctionNavigation` / `.sidebar` | **208px** | 主页、索引页、编辑器及其他工作域 | 全局外壳列，只承载跨工作域功能导航。 |
| `Library.DirectoryPanel` / `.catalog` | **232px** | 资料索引页、资料编辑器 | 资料功能专属目录栏，不进入全局功能导航。 |

推荐的正式 Token 语义（供后续 M1 落地，当前不实现）为：

```text

--ink-library-directory-w: 232px
--ink-library-index-inspector-w: 232px
--ink-editor-marginalia-w: 232px
--ink-inspector-wide-w: 300px
```

不要继续使用没有页面语义的通用 `--inspector-w` 承载 232px 和 300px 两种含义。

## 2. 尺寸冲突与建议值

### 2.1 208px 与 232px：功能栏和目录栏不是同一列

### 证据

- 风格文档 §五已将功能栏列为 208px、目录栏列为 232px；§9.5 的职责表也将 `.sidebar` 定为 208px、`.catalog` 定为 232px（`docs/前端重构/Knowra UI 风格设计文档.md:189-191,303-314`）。
- 主页、索引页、编辑器原型的 CSS 均使用 `--sidebar-w: 208px`；索引页和编辑器另行声明目录栏 232px（`docs/前端重构/知境 - 桌面端专业版主页.html:18,65-66`；`docs/前端重构/印格-资料库索引页.html:18,63-81`；`docs/前端重构/印格-编辑器页.html:18-19,58-76`）。
- 正式决策 D-005 已明确“208px 功能导航”和“232px 资料目录/边注”（`docs/前端重构/正式迁移/05-决策与偏差记录.md:29-32`）。

### 冲突来源

风格文档 §9.1 的 ASCII 图仍把功能栏标成 232px、右侧检查器标成 300px（`docs/前端重构/Knowra UI 风格设计文档.md:277-294`）。该图与同一文档的 Token 表、§9.5、D-005 以及三张最新原型不一致。

### 建议

- **208px 只指全局功能导航**，主页、索引页和编辑器共用同一列。
- **232px 只指功能页辅助列**，资料目录、索引详情和编辑器边注分别使用明确组件名。
- §9.1 ASCII 图中的 232px 应视为待规划方修订的旧图示，不应成为执行模型的实现依据。

### 2.2 组件库的 220px 目录示例与页面的 232px

组件库 `.catalog-demo` 的 CSS 和说明文字使用 220px（`docs/前端重构/印格设计系统-组件库.html:150-153,674-680`），但同一组件库的辅助侧栏变量、线条预览和说明均使用 232px（`docs/前端重构/印格设计系统-组件库.html:35-38,186-203,710`）。索引页和编辑器页的实际目标均使用 232px。

建议将 220px 定义为“组件库旧目录演示框的历史示例宽度”，不作为正式生产列宽；正式 `.catalog` 冻结为 232px。需要保留 220px 的视觉示例时，应改名为带 `demo`/`specimen` 语义的展示尺寸，不能与生产 Token 复用。

补充：组件库 `.menu` 同样使用 220px（`docs/前端重构/印格设计系统-组件库.html:295-305`），它是下拉菜单宽度，与目录栏不冲突，应继续保留为菜单组件规格。

### 2.3 300px 通用 Inspector 与 232px 页面辅助栏

#### 事实拆分

1. 风格文档组件 #25 和 §9.1 图示描述的是带“资料预览卡 + 信息分组”的通用宽版 Inspector，规格为 300px（`docs/前端重构/Knowra UI 风格设计文档.md:260-266,277-294`）。
2. 组件库第 16 节的 `.inspector` 也明确写为 300px，并包含 `.preview-card`（`docs/前端重构/印格设计系统-组件库.html:362-376,967-1000`）。
3. 组件库的可折叠 Auxiliary Sidebar 另有 232px 默认宽度、52px 头部和 28×28px 折叠按钮（`docs/前端重构/印格设计系统-组件库.html:196-214,683-710`）。
4. 当前索引页原型已经将详情栏收窄为 232px，且在页尾注释中明确“检查器收窄至 232、去顶部预览白卡”（`docs/前端重构/印格-资料库索引页.html:18,184-189,439-443`）。编辑器边注原型也声明 232px（`docs/前端重构/印格-编辑器页.html:18-19,225-245`）。

#### 建议的命名边界

| 名称 | 宽度 | 组件内容 | 是否进入当前正式迁移 |
| --- | ---: | --- | --- |
| `IndexInspector` | 232px | 资料详情、标签、关联、内容大纲、附件等紧凑信息 | 是，M3 |
| `MarginaliaPanel` | 232px | 信息/大纲/重点/AI 面板、标签和附件上下文 | 是，M4 |
| `InspectorWide` | 300px | 可选的资料预览卡、宽版键值和可折叠 section | 仅作为设计系统/未来显式变体，当前不作为 M3/M4 默认 |

这样既保留组件库的 300px 宽版组件，也不会让“检查器”一词在索引页和编辑器页之间隐含换宽。Q-003 的推荐解决方式是：**Index Inspector 与 Marginalia 是两个 232px 页面变体；300px 仅属于显式命名的 InspectorWide。**

## 3. Tab 激活线

必须区分“模块 Tab”和“文档 Tab”，不能用一个 `active` 视觉规则覆盖两类组件。

### 3.1 模块/视图 Tab：黑色 2px 下划线

- 资料索引页的 `.view-tab.active` 使用 700 字重和 `2px` 黑色下边框（`docs/前端重构/印格-资料库索引页.html:133-139`）。
- 编辑器边注的 `.module-tab.active` 使用 700 字重和 `2px` 黑色下边框（`docs/前端重构/印格-编辑器页.html:240-245`）。
- 组件库 #23 的模块 Tab CSS 明确使用黑色下边框；同一语言通过 `.stretch` 改变排布而不改变激活语义（`docs/前端重构/印格设计系统-组件库.html:270-278`）。

**建议冻结：**索引视图 Tab 和编辑器边注面板 Tab 均使用 `2px solid --ink-border` 下划线 + 700 字重；索引视图左对齐，边注面板四段均分。这里不采用彩色作为结构区分。

风格文档组件 #26 写有“面板 Tab 使用蓝色下边框”（`docs/前端重构/Knowra UI 风格设计文档.md:263-267`），但与组件库“视图切换与面板切换共用同一语言”、索引页原型和编辑器原型的黑线实现冲突。建议将 #26 的蓝线说明视为待修订的旧规格；蓝色激活线只保留给文档多开 Tab。

### 3.2 标签页：白底 + 蓝色 2px 左激活线

- 风格文档组件 #27 明确为白底和顶部 2px 蓝条（`docs/前端重构/Knowra UI 风格设计文档.md:266-268`）。
- 组件库 `.doc-tab.active` 使用 `border-top: 2px solid transparent`，激活时改为 `--ink-accent`（`docs/前端重构/印格设计系统-组件库.html:280-290`）。
- 编辑器原型保留白底/暖纸底、关闭按钮、脏点和横向滚动结构，但当前 CSS 将激活线写成左侧蓝线（`docs/前端重构/印格-编辑器页.html:108-122`），页尾也标注了“左侧 Tab 激活线”（`docs/前端重构/印格-编辑器页.html:650-662`）。

**用户决定：**标签页的正式契约采用“左侧 2px 蓝线”。这项选择覆盖组件库与风格文档当前的顶部蓝线写法；当前编辑器原型的左侧蓝线与新决定一致。后续由规划与验收方将该决定登记到正式决策记录，并同步修订风格文档、组件库和验收证据。

### 3.3 激活线结论表

| `ViewTab` | 下 | 黑色 `--ink-border` | 700 字重、计数等宽 |

## 4. 专注模式

### 4.1 进入专注模式

专注模式只改变布局，不改变资料、标签、草稿或已打开文档的业务状态：

- 隐藏 `TopBar`。
- 隐藏/收起全局功能导航 `FunctionNavigation`。
- 收起资料目录 `DirectoryPanel` 和编辑器 `MarginaliaPanel`，正文获得释放出的空间。
- 保留编辑器主体、文档 Tab 条、当前文档内容、编辑器滚动位置和草稿保护。
- 隐藏折叠侧栏的悬浮展开入口，避免专注模式出现残留外壳控件。
- Footer 不隐藏，继续显示编辑器状态和可用的页面操作。

当前编辑器原型的 `body.focus-mode`、侧栏隐藏、目录/边注折叠和 Footer 保留实现与上述布局方向一致（`docs/前端重构/印格-编辑器页.html:52-53,225-239,650-660`）。

### 4.2 退出专注模式

退出时必须恢复进入前的面板状态，而不是无条件把目录栏和边注重新打开：

- 恢复进入专注前的目录栏展开/折叠状态。
- 恢复进入专注前的边注展开/折叠状态、当前面板 Tab 和面板滚动位置。
- 恢复顶部栏和全局功能导航的可见性。
- 保留当前文档 Tab、草稿、编辑器内容、选择状态和 Footer 状态。

这条“保存并恢复面板偏好”的要求来自迁移契约的专注模式条目（`docs/前端重构/正式迁移/01-迁移契约与功能对等清单.md:60-73`）。原型脚本退出时直接调用 `setCatalog(true)` 与 `setMarginalia(true)`，因此只能作为交互意图证据，不能作为最终状态恢复契约。

## 5. Shell Footer 显示规则

### 5.1 宿主规则

- Footer 是 `AppShell` 的唯一全局宿主，位于 `.shell`/`ShellBody` 之外，固定满宽、32px 高、顶部 2px 外壳线和 24px 水平内边距。
- 主页、资料索引、编辑器和后续工作域只注入自己的状态内容，不重复挂载 Footer，不改变 Footer 的位置、尺寸或滚动边界。
- 主体三栏在 Footer 上方结束，任何侧栏不得覆盖 Footer。
- 页面切换时替换 Footer 内容，不能累积旧页面监听器或同时显示多个状态栏。

这与设计文档组件 #24、正式决策 D-004、组件库第 15 节及三张原型的 DOM 结构一致（`docs/前端重构/Knowra UI 风格设计文档.md:260-265,296-301`；`docs/前端重构/正式迁移/05-决策与偏差记录.md:24-27`；`docs/前端重构/印格设计系统-组件库.html:340-360,923-959`）。

### 5.2 页面注入内容

| 页面 | Footer 内容范围 |
| --- | --- |
| 主页 | 当前工作台、今日工作面、模块/最近编辑统计、连接状态。 |
| 资料索引 | 当前资料视图、浏览范围、条目/收藏统计、连接状态。 |
| 编辑器 | 保存状态、手动保存提示、字数/行数/链接、源码/边注/专注开关、编码、连接状态。 |
| 专注模式中的编辑器 | 仍使用编辑器 Footer 内容；只收起外壳和辅助栏，不隐藏状态宿主。 |
| 知识/训练/学习档案 | 由工作域注入真实状态；无真实状态时显示明确门禁或占位，不虚构数据。 |

三张原型分别在主页、索引页和编辑器页放置 `data-region="shell-footer"` 的 Footer，并将内容按页面替换（`docs/前端重构/知境 - 桌面端专业版主页.html:285-294`；`docs/前端重构/印格-资料库索引页.html:424-437`；`docs/前端重构/印格-编辑器页.html:588-606`）。
