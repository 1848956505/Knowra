# Knowra 正式 UI 迁移目录

本目录用于管理“印格 InkGrid v2.1”从静态设计原型迁移到 `apps/web` 正式前端的全部规划、执行交接与验收记录。

## 角色边界

| 角色 | 职责 | 不负责 |
| --- | --- | --- |
| 规划与验收方（Codex） | 冻结范围、维护契约、拆分任务、审查差异、运行验收、给出通过或退回结论 | 不编写正式迁移实现，不替执行模型修复失败项 |
| 执行模型 | 按单个任务书修改正式前端、补测试、提交验证证据 | 不自行改变架构决策、视觉规格、功能范围和验收门槛 |
| 用户 | 决定重大范围变化、接受有意偏差、指定执行模型 | 不承担模型之间的隐含契约推断 |

执行模型遇到规格冲突时必须停止并提交问题，由规划与验收方在《决策与偏差记录》中裁决后继续。

## 事实来源优先级

发生冲突时按以下顺序处理：

1. 正式前端现有业务行为、API 信封和数据安全约束，以 `apps/web/src/`、`apps/web/lib/` 及测试为准。
2. 本目录的《迁移契约》和《决策与偏差记录》负责说明业务行为如何落到新结构。
3. [`../Knowra UI 风格设计文档.md`](<../Knowra UI 风格设计文档.md>) 负责视觉规则。
4. `../印格-资料库索引页.html`、`../印格-编辑器页.html`、`../知境 - 桌面端专业版主页.html` 和 `../印格设计系统-组件库.html` 仅作为视觉目标，不作为可复制的生产代码。
5. 原型和正式行为无法同时满足时，不允许执行模型自行取舍，必须登记决策。

## 迁移铁律

- 正式目标是当前运行中的 Vanilla JS SPA；不得把 `apps/web/app/` 或 `apps/web/components/*.jsx` 接入主工程。
- 不整页复制单文件 HTML，不复制原型内嵌脚本，不使用原型的 `data-hook` 作为正式契约。
- 保留现有控制器、状态、API 服务、Milkdown 编辑器和数据保护逻辑；结构调整优先落在 Shell、渲染器和 CSS。
- 正式 UI Token 只能在 `apps/web/styles/components/knowra-theme-tokens.css` 中维护。
- 正式运行资源不得依赖 CDN；图标必须进入本地静态资源或受控依赖构建产物。
- 任一阶段未通过验收，不得进入下一阶段。
- 规划文档和验收标准只能由规划与验收方修改；执行模型只提交实现、测试与证据。
