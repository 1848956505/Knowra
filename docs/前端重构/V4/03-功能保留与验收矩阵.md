# 功能保留与验收矩阵

## 1. 使用方式

本矩阵是 V4 的功能底线。每个页面任务必须从这里领取相关条目，并提供自动化测试与运行态证据。视觉完成不能替代功能验收。

V4 已改为 React 技术栈。本矩阵中的 `Shared` 表示“共享框架无关业务能力或契约”，不表示原样复用 V3 controller、event binder 或字符串 renderer。

状态定义：

- `Shared`：复用现有业务实现，V4 只接呈现。
- `Rebuild UI`：重写 markup/CSS，行为语义保持。
- `Verify`：无需重写，但必须回归。
- `Blocked`：缺少设计或真实依赖，不能伪造。

## 2. 全局与启动

| 能力 | 策略 | V4 验收 |
| --- | --- | --- |
| SSR 初始工作区注入 | Shared | 首屏 script 安全嵌入，失败时不阻断客户端恢复 |
| API 代理与响应信封 | Shared | `{ data }` / `{ error: { code, message } }` 不变 |
| 加载优先级 | Shared | SSR → cache → live API → mock fallback 保持 |
| runtime error 上报 | Shared | error/rejection 能进入状态栏且不产生递归异常 |
| 静态资源服务 | Shared + Verify | V4 CSS/JS 可访问，路径越界仍返回 403 |
| 中文输入法 | Verify | 搜索、标题、正文、表单 Enter 不抢占 composing 事件 |
| 全局快捷键 | Shared | Meta/Ctrl+K、Escape 等保持 |

首屏实现允许 V4 第一阶段改为静态 app shell + cache/API hydration；若不保留 snapshot 注入，必须用真实启动性能和恢复测试证明不降低体验，并保持数据优先级语义一致。

## 7. 响应式矩阵

V4-03/V4-04 应基于组件固有宽度重新测量阈值，不直接继承 V3 的数值。最低验收矩阵固定如下：

| 环境 | 必验页面/状态 |
| --- | --- |
| 2048×1024 | 主页、索引、编辑器四种侧栏组合、知识、训练 |
| 1440×1024 | 主页、索引、编辑器双侧栏、搜索打开、长内容 |
| 1280×720 | 索引详情、编辑器紧凑菜单、源码/边注 |
| 1024×768 | 覆盖式目录/边注、菜单边界、关键键盘路径 |
| 200% 缩放 | 索引、编辑器、侧栏开关、长附件、Tab 溢出 |

共同门禁：

- 无页面级非预期横向滚动。
- 正文不因双侧栏压缩到不可阅读宽度。
- 中文菜单不被压成竖排。
- 活动 Tab、更多菜单和侧栏关闭入口始终可达。
- 覆盖层关闭后焦点回到触发器。

## 8. 可访问性矩阵

- 所有动作使用原生交互元素。
- Tab、menu、dialog、tree 等使用正确或等价的 ARIA 关系。
- `aria-expanded`、`aria-selected`、`aria-pressed` 与真实状态同步。
- 图标按钮具有中文 accessible name；装饰图标隐藏。
- 所有核心路径仅键盘可完成。
- `:focus-visible` 清晰且不被 overflow 裁切。
- 错误、保存状态和加载状态通过文本/ARIA 表达，不只依赖颜色。
- 动效尊重 `prefers-reduced-motion`。
- 200% 缩放时核心功能仍可操作。

## 9. 安全与数据矩阵

- 动态 HTML 继续转义；Markdown 预览继续清洗。
- 附件 URL 与不安全 HTTP 图片检测不降低。
- V4 preview 不改变存储格式，不创建独立用户数据副本。
- destructive action 使用隔离测试数据验证；正式数据验证前后记录一致性。
- 自动保存失败时不更新缓存为成功状态。
- 页面切换、关闭标签和导入失败不得吞掉错误。

## 10. 证据要求

每个页面任务至少提供：

1. 相关自动化测试命令与通过数量。
2. 目标视口截图和 DOM 尺寸记录。
3. 控制台 error/warn 检查。
4. 关键键盘与焦点路径记录。
5. V3 退出对象与替代测试列表。
6. 未覆盖项和阻塞项，不得用“视觉已完成”代替。

## 11. React 专项验收

- React Strict Mode 下无重复编辑器实例、重复监听器或重复写入。
- Error Boundary 能捕获组件渲染错误，并提供不破坏数据的恢复入口。
- Store action 不直接修改 React 管理的 DOM。
- 组件卸载后取消请求、timer、observer 与编辑器实例。
- 弹层使用受控状态或明确状态机，关闭后焦点返回触发器。
- 列表 key 使用稳定实体 ID，不以数组下标承载可重排内容。
- 共享 core 不 import React、DOM、CSS 或 `apps/web-v4`。
- V4 bundle 不包含 V3 renderer、event binder、controller 或旧样式。
- Markdown 安全预览若使用 `dangerouslySetInnerHTML`，内容必须经过现有 DOMPurify 安全链。
- React 组件测试以用户行为/ARIA 查询为主，不依赖 CSS Module 哈希 class。

## 12. React Aria Components 专项验收

- page/feature 不直接 import `react-aria-components`，只使用 Knowra `components/ui` 封装。
- Dialog、Popover、Menu、Tooltip 打开和关闭后的焦点路径符合预期；Escape、点击外部和触发器卸载都有测试。
- Tabs、Tree、GridList、Table、TagGroup 等集合使用稳定实体 ID，并覆盖方向键、Home/End、选择、禁用和空集合。
- SearchField、Button、Checkbox、Select 等保留正确 accessible name、description、error 与 disabled 语义。
- Knowra CSS Modules 可完整改变视觉，但不删除 React Aria 所需的 role、ARIA 关系和键盘行为。
- 不把 React Aria 默认 class、内部 DOM 层级或 `data-*` 当作业务动作选择器；状态属性只用于封装层视觉。
- 组件库升级必须先通过 `components/ui` 契约测试、组件展台和关键 Playwright 路径。
- React Aria 未覆盖的业务组件须记录自行实现理由，不得无审计引入第二套完整 UI 组件库。
