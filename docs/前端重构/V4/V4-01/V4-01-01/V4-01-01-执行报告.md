## 2. 扫描方法与范围

### 2.1 扫描对象

- 目录：`apps/web/src/`、`apps/web/lib/`（运行时代码，共 229 个 `.js/.mjs` 文件）。
- **排除**：`lib/editor/milkdown-bundle.js/.css/.map`（esbuild 构建产物，已 gitignore）。
- 探索目录 `apps/web/app/`、`apps/web/components/` 均为 `.jsx`、未接入 `src/main.js`，非运行链路，不参与扫描（`01` 文档 §7 将其列为 V4-08 删除/归档对象）。

### 2.2 查询模式

覆盖 5 个 selector 类 API：`querySelector`、`querySelectorAll`、`closest`、`matches`、`getElementsByClassName`。只识别**字符串字面量** selector，并从中提取全部 class token（先剥离 `[...]` 属性选择器，避免引号内点号误判）。

扫描器实现的完整性要点：selector 实参允许属性值内出现与定界符不同的引号，例如

```js
cell.closest('.milkdown-table-block [data-role="row-drag-handle"]')
```

若按简单 `[^'"]*` 截断会把带 `[data-role="…"]` 的查询漏掉。本轮初版扫描器曾漏掉 5 处此类查询，修复后恢复完整（详见 §6）。

### 2.3 边界决策

- `classList.add/remove/toggle` 是对**模块已持有元素**的 class 状态写入，不是"按 class 查询"，不进入本门禁。
- `classList.contains` 是读取 class 状态，同样违反 P-02，但当前仓库无此用法；如需可在 V4-01-02 一并纳入。
- 变量动态构造的 selector 无法静态判定（如 `sidebar-controller.js` 的 `focusRequest.selector`）。已核对其实际取值全部为 `[data-*]` 属性选择器（`[data-note-tag-input]` 等），非 class。动态 selector 只允许 `data-*` / id，禁止 class——作为文档化限制，不做静态拦截。

## 4. 白名单设计

白名单位于 `apps/web/test/helpers/class-query-gate.js` 的 `EDITOR_CONTRACT_WHITELIST`，**逐条登记**真实存在的插件结构 class，并给每条限定**契约域（domains）**：

- `.milkdown-*`（table-block / image-block / code-block-placeholder）→ 域 `lib/editor/milkdown/`
- `.button-group`、`.children`、`.selectedCell` → 域 `lib/editor/milkdown/table/`
- `.ProseMirror` → 域 `lib/editor/` + `src/controllers/editor/`（导出 controller 读取编辑器宿主 DOM）

**判定规则**：selector 中的每一个 class token 都必须在当前文件所属契约域内逐项命中白名单，才能视为编辑器契约查询。强模型复核时已收紧初版的“命中任一 class 即整体放行”，避免 `.milkdown-table-block .new-visual-class` 借编辑器根 class 绕过门禁。该规则同时满足：

- `.milkdown-table-block table.children td.selectedCell` 整串放行（结构根 class 已在白名单，其余为插件结构随行）；
- `.milkdown-table-block .new-visual-class` 被拒绝（新 class 未逐项登记）；
- 不允许 `src/controllers/` 的非编辑器 controller 查询 `.milkdown-*` 或 `.ProseMirror`（域约束拦截跨域借用）。

**最小性与收紧策略**：不设 `milkdown-` 前缀通配，也不把整个 `lib/editor/` 加入宽泛白名单（任务禁止）。新 class 若要放行，必须显式新增条目并说明契约来源，供强模型复核是否过宽。解耦完成后删除对应登记，清单持续收紧。

## 5. 门禁行为

新增测试 `apps/web/test/v4-01-01-class-query-gate.test.js`（由 `run-tests.js` 自动发现）：

1. **配置自检**：白名单与登记耦合条目字段齐全，便于人工复核。
2. **正向扫描**：全量扫描 `src/`+`lib/`，断言 `违规 === 0`——当前已登记耦合可解释。
3. **端到端负向证明**：在临时目录写入含 `.v4-card-panel` 查询的文件，经 scan+evaluate 全链路断言被判为违规——**新耦合会使测试失败**；同时断言 `.ProseMirror` 在契约域内仍被放行。
4. **混合 selector 负向证明**：即使 selector 已含 `.milkdown-table-block`，同串新增未登记 `.new-visual-class` 仍会被判为违规。

## 6. 扫描过程中的发现与修正

- 初版扫描器（`[^'"`]*` 截断 selector 实参）漏掉 5 处带属性值引号的查询：`table-pinned-actions.js:12`、`table-pinned-state.js:26/98/121/122`（含 `[data-role="…"]`、`[data-pinned="true"]`）。其中 `table-pinned-actions.js` 整体未出现在任务书 §4.3 与手工 `rg` 结果中。改用负向断言捕获完整实参后，共恢复至 **30 处**，全部正确归类，无新增违规。这验证了静态门禁相对人工审计的价值。
- `export-controller.js` 的 `#milkdown-editor .ProseMirror`（controller 读取编辑器宿主以导出 HTML/PDF）属编辑器宿主契约，按审计 §4.3 保留，通过扩展 `.ProseMirror` 契约域至 `src/controllers/editor/` 登记，不列入待解耦清单。
- 强模型复核发现初版“任一白名单 class 命中即放行整个 selector”会连带放行未登记 class；已改为所有 class token 逐项验证，并新增混合 selector 负向回归。白名单条目与契约域本身无需扩大。
