# 现有前端遗留审计

## 1. 审计范围与结论

审计范围：`apps/web/src/`、`apps/web/lib/`、`apps/web/styles/`、`apps/web/app/`、`apps/web/components/` 与 `apps/web/test/`。

结论：当前前端的业务模块化程度足以支持“保留能力、重建呈现层”，但样式入口和 DOM markup 仍是 V2/V3 混合结构。V4 不应在现有 CSS 图上继续开发。本文件记录 V3 遗留事实；React 迁移的最终复用判定以 `05-V4-01 React迁移可复用性审计.md` 为准。

## 2. 当前正式运行链路

```text
GET /
  → src/main.js
  → loadInitialWorkspaceSnapshot()
  → renderHtml() in src/server/shell-html.js
  → /src/styles.css
       → styles/tokens.css
       → styles/components.css
            → 旧组件样式
            → knowra-inkgrid.css
  → /lib/editor/milkdown-bundle.css
  → /src/client.js
       → state
       → element cache
       → controllers
       → event binders
       → workspace load
```

`apps/web/app/` 与 `apps/web/components/*.jsx` 没有接入 `src/main.js`，不是正式运行链路。

## 3. 样式遗留量化

按当前 `styles/components/` 分类：

| 分类 | 文件数 | 行数 | 状态 |
| --- | ---: | ---: | --- |
| V2/旧组件样式 | 21 | 3854 | 仍由 `components.css` 先加载 |
| V3/InkGrid 样式与 Token | 14 | 2530 | 在旧样式之后覆盖 |
| `knowra-*` 兼容代理 | 6 | 12 | 继续为旧直接引用提供别名 |
| 基础 `styles/tokens.css` | 1 | 41 | 文档明确标为旧版，被 V3 Token 覆盖 |
| 聚合入口 `components.css` | 1 | 21 | 同时加载旧层与 V3 层 |
| Milkdown vendor CSS | 1 | 54 | 构建依赖的最小 ProseMirror 基础样式 |

从 `src/styles.css` 与 `milkdown-bundle.css` 递归解析，当前浏览器正式入口会加载 39 个 CSS 文件、约 6502 行；`apps/web` 下全部 CSS（含未接入探索样式与兼容代理）约 6551 行。主要问题不是行数本身，而是同一元素可能先接受旧规则，再由 `.knowra-production-shell` 下的更高特异性规则覆盖。

### 3.1 典型混合结构

正式根节点当前为：

```html
<div class="app-shell workspace-shell app-root knowra-production-shell" ...>
```

其中 `app-shell`、`workspace-shell`、`app-root` 和 `knowra-production-shell` 分别承载不同历史阶段的布局与覆盖语义。其他区域也大量复用 `kb-*`、`workspace-*`、`library-*` 等旧 class，再由 InkGrid 作用域重设视觉。

### 3.2 V4 处理结论

- 不修改 `components.css` 继续叠加。
- V4 新建独立入口，不导入任何上述应用样式。
- Milkdown vendor CSS 可继续单独加载。
- Milkdown 的自定义内容、表格、图片、代码块视觉需要在 V4 内重写；生成 DOM 中 `.ProseMirror`、`.milkdown-*` 等第三方/编辑器结构 class 可以作为编辑器契约继续存在。

## 4. DOM 与事件契约

### 4.1 V3 稳定宿主 ID

`apps/web/src/app/element-cache.js` 集中登记 39 个主要宿主，覆盖：

- Shell：`workspace-shell`、`module-rail`、`global-search-shell`。
- 页面：`home-workspace-view`、`library-index-view`、`work-domain-view`、`editor-workspace-view`。
- 目录与索引：`kb-sidebar`、`folder-tree`、`library-index-*`。
- 编辑器：`kb-workspace`、`note-tabs`、`editor-menu-bar`、`editor-document-head`、`editor-content`、`editor-scroll-region`。
- 边注和状态：`kb-aside`、`aside-tabs`、`aside-content`、`status-indicators`、`status-meta`。
- 菜单与导入：context menu、tab menu、overflow menu、Markdown input 等宿主。

这些 ID 当前是 V3 controller、event binder 和 renderer 的连接点。React V4 应保留对应区域的**产品语义和可访问关系**，但不需要复制 ID 或 element cache；V4 通过组件边界、ref、role/name 和必要的稳定 `data-*` 表达契约。迁移期间不得让 V3 代码用这些 ID 操作 React DOM。

### 4.2 行为属性

正式源码中出现约 245 个唯一 `data-*` 名称，其中既包含行为 action，也包含状态和展示标记。不能把 245 个属性一律永久冻结，应按以下规则分类：

| 类型 | 示例 | V4 处理 |
| --- | --- | --- |
| 行为 action | `data-note-id`、`data-index-open`、`data-tab-close`、`data-status-action` | 保留或通过集中映射迁移；必须有事件测试 |
| 字段定位 | `data-panel-field`、`data-question-inspector-field` | 保留字段语义；避免改为 class 查询 |
| 状态 | `data-selected`、`data-open`、`data-dirty`、`data-left-hidden` | 可重命名，但必须由状态派生且有测试 |
| UI 区域 | `data-ui-topbar`、`data-ui-feature-stage` | V4 可建立新区域标记，不应承担业务 action |
| 纯样式/展示 | `data-accent`、`data-level`、`data-depth` | 可由 V4 组件重新定义 |
| 第三方编辑器 | `data-role`、`data-pinned`、`data-checked` | 按 Milkdown/ProseMirror 与自定义插件契约保留 |

### 4.3 已发现的 class 行为耦合

以下不是普通 CSS 引用，而是 JavaScript 直接查询 class：

| 区域 | 当前查询 | 风险 | V4-01 动作 |
| --- | --- | --- | --- |
| 全局搜索 | `.top-bar-search-control`、`.search-panel-host` | 更换搜索 DOM/class 会导致局部更新失败 | 增加稳定 `data-search-control`、`data-search-panel-host` |
| 编辑器右键菜单 | `.editor-context-submenu-group`、`.editor-context-submenu-trigger`、`.editor-context-submenu`、`.editor-context-panel` | 新菜单 markup 难以替换 | 改为 `data-editor-context-*` |
| 图片工具栏 | `.image-preset-button` | 视觉类同时决定状态同步 | 增加 `data-image-preset` |
| 图片宽度测量 | `.ProseMirror` | 编辑器宿主能力依赖 | 归类为第三方编辑器契约，可保留 |
| Milkdown 图片/代码/表格 | `.milkdown-*`、`.button-group`、`.selectedCell` | 插件生成结构依赖 | 归类为编辑器内部契约；不作为普通 V4 组件 class |

V4 新代码不得增加新的视觉 class 查询。V4-01 应增加静态测试阻止该类耦合扩散，并为第三方编辑器目录设置明确白名单。

## 5. 状态与控制器可复用性

### 5.1 可作为迁移输入，不可整体照搬

- `createInitialAppState()` 提供完整字段清单，可作为 Zustand slices 与类型设计的审计输入，但旧可变对象不直接复用。
- `createControllerActionProxies()` 与 `createAppControllers()` 记录了动作依赖和业务编排，可用于提取 typed command/use case；旧 registry 不进入 React。
- `bindAppEvents()` 记录了事件、快捷键、IME、焦点和拖拽能力，V4 应用 React handler/hook 重写。
- workspace normalization、cache 和加载/恢复决策可以提纯复用；V3 的 SSR shell 注入属于运行时适配，V4 首轮不强制照搬。

### 5.2 需要解耦

多个 controller 仍直接 import 具体 renderer，例如 shell、search、tab、sidebar、navigation 和 editor host controller。新增的 `lib/components/index.js` 目前只是 V3 renderer 的统一导出目录，不是 React 组件库。

React 方案不再引入 V3/V4 双 renderer registry。V4 直接以组件和 Store 派生呈现；只把 controller 中可测试的领域规则、请求次序和错误恢复提取到共享核心或 feature command。不得让旧 controller 根据 `uiGeneration` 操作 React 树。

## 6. 测试遗留

V4-01-01 门禁加入前 Web 测试基线为 150 passed / 0 failed；当前为 151 passed / 0 failed，其中新增的 1 个测试用于保护 V3 class 查询风险基线。

### 6.1 应长期保留的测试

- API client、response envelope 与 service 测试。
- app state、workspace loading/cache/normalization/write guard。
- controller 命令、草稿、保存、选择、导航和错误恢复。
- 事件 binder、键盘、IME、焦点和拖拽行为。
- Milkdown 输入、Markdown、图片、表格、代码块与标注能力。
- renderer 的转义、安全和语义测试。

### 6.2 需要替换而非直接删除的测试

至少 25 个测试文件直接读取 CSS、Shell HTML 或具体 class/选择器，其中 22 个直接绑定 V3/InkGrid 样式入口或结构。这些测试保护了当前 V3，但不能原样成为 V4 验收标准。

典型对象：

- `inkgrid-style-entry.test.js`
- `inkgrid-token-shape.test.js`
- `knowra-redesign-ui.test.js`
- `app-shell-grid.test.js`
- `m4-02-tab-ui.test.js` 至 `m4-07-reflow.test.js`
- `tokens-css-shape.test.js`
- `topbar-search.test.js`
- `v140-*` 至 `v145-*` 的结构型 UI 测试

处理规则：

1. V4 实现对应能力前，旧测试继续保护 V3 fallback。
2. 对应 V4 功能完成时，先新增行为/语义测试，再登记旧结构测试的替代关系。
3. V4 默认切换时删除 V3-only 测试，不以修改正则让旧测试“勉强通过”。

## 7. 未接入 React 探索目录

`apps/web/app/` 与 `apps/web/components/` 共 12 个已跟踪文件，使用 JSX/React 风格，但：

- 不在当前 `src/main.js` 服务入口中；
- `apps/web/package.json` 没有 React/Next 运行依赖；
- `app/globals.css` 仍导入现有 `styles/tokens.css` 与 `styles/components.css`；
- 其 markup 和正式 controller/event/state 没有连接。

结论：将其视为历史探索，不作为 V4 代码起点。V4-08 必须选择“删除”或“移动到 docs 归档”，不能继续与正式前端并列。

## 9. 风险排序

| 风险 | 等级 | 说明 |
| --- | --- | --- |
| 编辑器与复杂弹层 DOM 替换 | 高 | 存在第三方生成结构、选择记忆、焦点和异步挂载 |
| 旧/V3 CSS 意外共载 | 高 | 会让 V4 再次变成覆盖层 |
| renderer 直接 import 导致双轨条件扩散 | 高 | controller 容易同时了解 V3/V4 |
| 结构测试被简单删除 | 高 | 会丢失已有响应式与可访问回归证据 |
| 资料索引和目录树 | 中高 | 事件丰富，包含拖拽、右键、折叠、分页和详情 |
| 公共 Shell 与主页 | 中 | 状态简单，适合作为独立入口首个验证页面 |
| Token 与基础组件 | 中 | 需要视觉决策，但实现可机械拆分 |
| 文档目录和任务模板 | 低 | 可交给轻量执行模型维护 |
