## 1. 品牌原则

印格是一种以**文具感**为核心的视觉方向：暖纸底、墨黑主文字、蓝色强调、硬阴影、零圆角、点阵纸面。它假设用户长期在屏幕前工作，所以让 UI 看起来像一张被网格包裹的纸与几本手册，文字与控件像被印章盖上去一样——克制、清晰、有重量感。

五条原则：

1. **内容优先于装饰**：硬阴影、印章、状态色点都是为了让信息更易读，而不是为了装饰。
2. **可印刷色**：避免饱和度极高的品牌色或大渐变；所有强调色（蓝/绿/橙/红）必须可在低对比度屏幕与打印件上识别。
3. **零圆角、硬位移**：所有阴影都是实心位移（`2px 2px 1px` / `3px 3px 1px` / `4px 4px 0`），不使用模糊阴影；圆角恒为 0。
4. **克制动效**：交互反馈限于 hover 抬升 1px、active 塌入 1px、焦点蓝色实阴影，时长 120–200ms。绝不用弹跳、淡入淡出、模糊模糊。
5. **状态用方点表达**：进行中 = 蓝方点、已完成 = 绿方点、待整理 = 橙方点、错误 = 红方点。永远不用 emoji、不用大色块。

| Token | 值 | 用途 |

## 5. 响应式分档

| 分档 | 范围 | 轨道 | 侧栏 | 主工作区 | 检查器 | 移动 Tab |
|---|---|---|---|---|---|---|
| XL 宽屏桌面 | ≥1440px | 64px | 224px | flex | 288px | 隐藏 |
| 标准桌面 | 1100–1439px | 64px | 208px | flex | 288px | 隐藏 |
| 小桌面 | 860–1099px | 64px | 默认收起，可浮层 | flex | 覆盖式 | 隐藏 |
| 平板 | 768–859px | 64px | 抽屉式 | flex | 覆盖式 | 隐藏 |
| 手机 | ≤767px | 隐藏 | 抽屉式（绝对定位） | flex | 底部 sheet | 56px + safe-area |

**移动端硬约束：**
- 所有可点击目标 `min-height: 44px`、`min-width: 36px`（按钮）/ `36px`（icon 按钮）。
- 文档最后一项与分页必须能被滚动到，且不被状态栏 + 移动 Tab 遮挡。
- 表格行改为两行紧凑列表：第一行 = 图标 + 标题 + 更多，第二行 = 状态 + 位置 + 时间。标题最多 2 行省略。
- 禁止把桌面表格强压到 ≤767px；用 flex 重排 `<tr>` 内的 `<td>`。
- 文本不得逐字竖排；用 `word-break: break-word; overflow-wrap: anywhere;` 配合 `-webkit-line-clamp: 2`。

## 6. 状态契约

9 类状态板已交付在 `印格-demo-状态板.html`，每类都有 HTML 静态示意 + 1 个可交互实装样例（Dialog 完整实现 Tab 焦点陷阱 / Esc / 背景隔离 / 焦点归还）。

| 类别 | 关键契约 |
|---|---|
| Search | 输入即检索，去抖 200ms；空值不触发；空结果保留清除/重置入口；加载用 `aria-busy="true"` + 旋转 spinner |
| Menu | `role="menu"` + `role="menuitem"`；↑↓ 循环、Esc 关闭、焦点归还触发器；危险项必须用 `menu__sep` 分组 |
| Dialog | 打开后自动聚焦首个可聚焦元素（除非触发器声明）；Tab/Shift+Tab 循环；Esc 关闭；背景 `aria-hidden` 隔离（V4-04 升级为 `inert`）；关闭后清空表单 + 错误态；焦点归还触发器 |
| Popover | 复用 Menu 视觉；`hidden` + `aria-expanded` 共同控制；触发器需 `aria-haspopup="menu"`；靠近视口底/右时翻转方向 |
| Sidebar | 宽屏桌面 224px / 标准桌面 1100–1439px 收至 208px；折叠后保留 64px 轨道；移动端绝对定位抽屉 + 遮罩 + Esc 关闭，宽度 ≤ 280px |
| Loading | `aria-busy` + 骨架脉冲 1.4s；不阻塞输入 |
| Empty | 主操作 + 次操作 + 逃生（重置/导入） |
| Error | `role="alert"` 横幅 + 重试 + 逃生（查看日志/反馈） |
| Save | `save-state--{idle,saving,saved,failed}` 类标记；saving 期间 input 仍可编辑；failed 必须 `role="alert"` 横幅 + 重试 + 保留本地草稿 |
| Toast | 默认 2.2s 自动消失；info 蓝影、success 绿影、warning 橙影、error 红；`role="status"` / `role="alert"` 区分紧急程度 |
| 按钮 | `min-height: 36px`（移动 44px）；hover 抬升 1px、active 塌入 1px、focus 蓝色实阴影 `var(--shadow-focus)`、disabled 灰化 |

## 7. V3 禁止继承清单

V3 的笔记应用代码与样式 **不得直接继承** 到 V4。任何复用必须通过 V4-04 的转译层（见 §8）。以下项**明确禁止**：

1. **V3 DOM 结构**：原有的 `.app`、`.sidebar`、`.main`、`.editor` 等选择器及其 DOM 树。
2. **V3 全局 CSS**：`reset.css`、`theme.css`、`layout.css` 等全局样式表；包括 normalize、box-sizing、字体声明。
3. **V3 布局壳**：四区外壳的旧版实现（任何 rail/sidebar/inspector 模板）。
4. **V3 渲染器**：marked.js、CodeMirror 4.x、jQuery 链式调用、Backbone View 渲染。
5. **V3 控制器**：Backbone Router / View / Collection、jQuery 事件总线。
6. **V3 选择器耦合**：依赖类名哈希、特定层级（如 `.x > .y > .z`）的样式。
7. **V3 视觉 Token**：旧色板、旧字号、旧阴影值（不管名字是否与 V4 相同，都必须按 §3 重新声明并验证）。
8. **V3 业务命名**：旧模块名（旧"知识"/"训练场"/"学习档案"）、旧标签语义。

可以**保留**的（按 [03-功能保留与验收矩阵.md](../../../../03-功能保留与验收矩阵.md)）：

- 笔记的增删改查能力、Markdown 解析、双向链接、侧栏树、回收站等**业务行为**。
- 用户配置（主题、快捷键、字号）作为**能力点**，但 UI 表达必须按印格重做。
- 笔记数据模型与导入导出格式（按 V4-01 数据迁移规范执行）。

## 8. V4-04 转译边界

V4-04 是把印格 V4-00.5 视觉基线转译为 React + React Aria 工程实现的阶段。**唯一允许的转译产物**：

### 8.1 允许

- **CSS Variables**：把 §3 的所有 token 1:1 写入 `:root` 选择器，**禁止改名、合并、计算**。
- **CSS Modules**：每个组件独立 `.module.css`，类名哈希化；但**禁止把硬阴影、字号、颜色硬编码**到 module 里，必须引用 token。
- **React Aria**：用 React Aria 的 `useDialog`、`useMenu`、`usePopover`、`useListbox`、`useButton`、`useFocusRing` 等 hooks 替代原生 `<div role="dialog">` 等；状态板里手写的可访问性契约必须由 React Aria 提供。
- **React Aria 的 `inert` 属性**：在 V4-00.5 的 `aria-hidden` 背景隔离基础上，V4-04 升级为原生 `inert`。
- **TypeScript 类型**：把 §3 的 token 写成 `as const` 联合类型导出。

### 8.2 禁止

- **不得复制单文件原型 DOM**：V4-00.5 的 HTML 标记是演示用，禁止把 `<aside class="module-rail">` 等直接搬到 React 组件的 JSX 里。
- **不得复制内联 CSS**：演示页有 700+ 行 `<style>`，禁止把这段原样搬到组件文件里。必须拆分到 `tokens.css` + 各 component `*.module.css`。
- **不得复制 JavaScript**：演示页的 vanilla JS（拖拽手柄、焦点陷阱、键盘导航）禁止搬到 React 组件里。必须用 React Aria 替换；React Aria 不覆盖的部分（如：自定义快捷键）由 `useEffect` 写在 hook 里，不写在组件顶层。
- **不得绕开 React Aria 的语义**：不要因为 React Aria 提供的 ARIA 太多就手动覆盖；也不要在 `useMenu` 之外重新发明 `role="menu"`。
- **不得引入新的设计语言**：V4-04 阶段不允许新增颜色、新增字体、新增阴影、新增圆角。如果真的需要，必须先回到 V4-00.5 走冻结变更流程。
- **不得依赖 V3 组件库作为底层**：Radix、Headless UI、shadcn/ui 等只允许作为语义参考（看 ARIA 实现），**禁止作为最终组件**直接用。V4-04 的视觉必须从印格 token 来。
