# Markdown 笔记应用前端布局构思方案

日期：2026-08-15  
参考：`印格设计系统-组件库_删减版.html`；布局心智参考 Notion、Craft、Linear 的成熟企业级应用模式。

---

## 1. 设计定位

建议把产品定义为一个以 Markdown 笔记为核心、可持续扩展的“纸面工作站”。

- **核心场景**：快速记录、整理笔记、回看与链接知识。
- **未来模块**：知识库、试题库、打卡与待办，以及其他以“条目 + 属性 + 视图”构成的内容模块。
- **视觉方向**：延续组件库的 Neo-Brutalism 文具感——暖纸底、墨黑线条、硬阴影、零圆角、蓝色强调、点阵纸面。
- **布局方向**：采用“模块轨道 + 上下文侧栏 + 主工作区 + 可折叠检查器”的四区外壳，比传统单一大侧栏更适合后续多模块扩展。

一句话概括：

> 左侧像一排模块抽屉，中间是一张放在网格桌面上的纸，右侧是当前纸张的属性卡，底部是小型状态仪表条。

---

## 2. 从组件库继承的视觉语言

这里只继承“视觉和组件气质”，不照搬组件库自身的信息架构与业务命名。

### 2.1 应该保留

| 视觉元素 | 应用方式 |
|---|---|
| 暖纸背景 `#F9F7F2` | 作为应用整体桌面底色 |
| 白色表面 `#FFFFFF` | 作为编辑器纸张、弹窗、菜单和浮层 |
| 沉降面 `#F4F1EA` | 作为 hover、选中前过渡、浅分区背景 |
| 墨黑 `#1A1A1A` | 外壳线、标题、主要文字、边框 |
| 强调蓝 `#2563EB` | 当前模块、当前文档、主按钮、激活工具 |
| 点阵背景 | 用在编辑区桌面、空状态、欢迎页，形成“纸面网格”记忆点 |
| 2px 外壳线 | 用于窗口主分区，例如模块轨道右缘、底部状态栏上缘 |
| 1px 面板线 | 用于侧栏、检查器、列表分区 |
| 硬阴影 2/3/4/6px | 用于按钮、菜单、卡片、弹窗等浮起对象 |
| 零圆角 | 保持强烈的“印刷、纸张、印章”感 |
| 按压式动效 | hover 浮起、active 塌入，时长控制在 0.1–0.2s |

### 2.2 应该改造

| 组件库做法 | 在本应用中的改造 |
|---|---|
| 208px 文字型一级导航 | 改为 56–64px 模块轨道，节省横向空间并支持更多模块 |
| 232px 目录栏 | 保留为“上下文侧栏”，宽度建议 248px，可拖拽调整 |
| 大卡片全边框 | 只用于浮层、模板卡、空状态；不要让所有列表项都变成重卡片 |
| 组件库品牌 Mark | 替换为自己的产品标识，但可保留“蓝方块 + 白底黑边方块错位”的构造手法 |
| 业务图标语义 | 重新映射为笔记、知识库、试题、待办、设置等模块图标 |

### 2.3 可以忽略

- 组件库展示页中的色卡、间距演示、版本标签、章节编号。
- “知境 Knowra”的现有品牌命名。
- 与训练场、学习档案等业务绑定的原始文案。
- 过严的展示规范；真正需要保留的是线条、色彩、阴影、动效和选中态语言。

### 2.4 暗色模式立场

组件库已经提供了一组暗色 token，可把它作为后续主题扩展的基础，但建议一期先专注浅色主题：

- 一期：只交付浅色“暖纸”主题，优先打磨阅读、编辑、打印感与内容层级。
- 二期：如果用户对暗色模式需求明确，再基于同一套线条、阴影和语义色规则扩展暗色主题。
- 不建议一期同时做两套主题，否则 Neo-Brutalism 的硬阴影、点阵密度和纸面质感会在暗色下需要额外调校，容易拖慢核心编辑体验。

## 3. 推荐应用外壳

### 3.1 桌面端主结构

```text
┌────────┬──────────────┬──────────────────────────────────────┬────────────┐
│ 模块轨道 │ 上下文侧栏     │ 主工作区                              │ 检查器      │
│ 64px   │ 248px        │ flexible                             │ 300px      │
│        │              │                                      │            │
│ 笔记    │ 搜索/新建      │ 文档标签页 40px                      │ 信息/大纲   │
│ 知识库  │ 快速入口       │ 编辑器工具栏 44px                    │ 链接/属性   │
│ 试题库  │ 树/列表/筛选    │ Markdown 纸张                        │ AI/统计    │
│ 待办    │ 模块内容插槽    │ 居中 720–880px                       │ 可折叠      │
│        │              │                                      │            │
│ 设置    │              │                                      │            │
├────────┴──────────────┴──────────────────────────────────────┴────────────┤
│ 底部状态栏 32px：当前位置 / 字数 / 保存状态 / 同步状态 / 面板开关             │
└───────────────────────────────────────────────────────────────────────────┘
```

### 3.2 为什么是这种结构

1. **模块轨道负责“我在哪个模块”**  
   类似 Linear 的一级导航，但更紧凑。后续增加模块时，只是新增一个图标入口，不会让左侧树变得臃肿。

2. **上下文侧栏负责“我在当前模块的哪类内容里”**  
   笔记模块显示笔记本和标签；试题模块显示学科、知识点和题型；待办模块显示项目和清单。侧栏内容是模块化插槽，外壳不需要知道内部细节。

3. **主工作区负责“当前内容本身”**  
   记笔记时是编辑器；试题库中可以切换为表格、详情或刷题视图；待办中可以切换为清单、看板或日历。

4. **检查器负责“当前选中对象的详情”**  
   选中一篇笔记时显示属性、标签、双链和大纲；选中一道题时显示答案、解析、来源知识点；选中一个任务时显示截止时间、提醒和关联笔记。

## 4. 一级导航：模块轨道

建议采用 56–64px 的窄轨道，而不是组件库中的 208px 宽导航。

### 4.1 内容顺序

从上到下：

1. 产品标识
2. 全局搜索 / 命令面板入口
3. 全局新建“+”
4. 笔记
5. 知识库
6. 试题库
7. 打卡与待办
8. 弹性空间
9. 通知
10. 设置
11. 用户头像 / 工作区切换

### 4.2 视觉规则

- 轨道背景使用暖纸底。
- 右缘使用 2px 墨黑外壳线。
- 图标默认 20px，2px 方角描边。
- 激活模块：白底方块 + 左侧 4px 蓝色边条 + 图标转为 Fill 或蓝色。
- hover：沉降面背景，图标和文字不加花哨位移。
- 未上线模块可以置灰，或完全隐藏，避免一期界面显得空洞。

### 4.3 模块命名建议

如果“打卡”和“待办”希望合并，建议一级模块命名为：

- **执行**：包含今日、待办、打卡、习惯、日历、统计。

如果两者未来会明显分化，也可以拆成：

- **待办**
- **打卡**

一期建议先合并为“执行”，减少导航数量。

---

## 5. 二级区域：上下文侧栏

上下文侧栏是当前模块的“内容索引”，建议默认宽度 248px，可在 220–320px 之间拖拽调整。

### 5.1 通用结构

```text
┌ 上下文侧栏 ────────────┐
│ 模块标题 + 主操作按钮     │ 52px
│ 模块内搜索               │
├ 快速入口 ──────────────┤
│ 全部 / 最近 / 收藏 / 未整理 │
├ 内容结构 ──────────────┤
│ 文件夹树 / 知识库树 / 筛选项 │
├ 标签或分组 ────────────┤
│ 分类标签 / 项目 / 状态      │
├ 底部 ─────────────────┤
│ 回收站 / 归档 / 模块设置    │
└───────────────────────┘
```

### 5.2 视觉规则

- 侧栏右缘使用 1px panel 线，而不是 2px 外壳线。
- 头部高度 52px，底部 1px panel 线。
- 新建按钮使用 28–36px 的方块图标按钮，保留硬阴影和按压效果。
- 树节点选中态继续使用“左侧蓝色边条 + 白底 + 加粗”。
- 文件比文件夹弱一级：文件使用次级文字色，文件夹使用主文字色和更高字重。
- 数量、时间、快捷键用 SF Mono / Menlo 等等宽字体，强化组件库的文具感。

## 6. 主工作区：笔记编辑器

笔记是一期核心，因此主工作区应该先按“文档优先”设计，再抽象成可承载其他视图的容器。

### 6.1 编辑器布局

```text
┌ 文档标签页 ────────────────────────────────┐
│ 笔记 A  笔记 B  未保存笔记•  +              │ 40px
├ 编辑器工具栏 ──────────────────────────────┤
│ H1 H2 H3 | B I 列表 引用 代码 链接 | 预览   │ 44px
├ 纸张区域 ─────────────────────────────────┤
│                                            │
│        ┌ Markdown 纸张，720px 居中 ┐        │
│        │ # 标题                     │        │
│        │ 正文内容……                 │        │
│        │                            │        │
│        └────────────────────────────┘        │
│                                            │
└────────────────────────────────────────────┘
```

### 6.2 文档标签页

用于同时打开多篇笔记。

- 高度 40px。
- 底部使用 2px 墨黑线。
- 激活标签：白底、左侧 2px 蓝条、加粗。
- 未保存状态：8×8 橙色方块点。
- hover 时未保存点让位给关闭按钮。
- 最后一个标签是“+”，用于新建文档。

### 6.3 编辑器工具栏

工具栏不需要做成厚重顶栏，建议做成紧贴文档的单行工具条。

建议分组：

1. 标题层级：H1 / H2 / H3
2. 行内格式：加粗、斜体、删除线、行内代码
3. 块格式：列表、任务列表、引用、代码块、分割线
4. 内容插入：链接、图片、附件、表格、嵌入
5. 视图操作：编辑 / 预览 / 分屏、专注模式、更多

视觉规则：

- 白底，底部 1px panel 线。
- 图标按钮 28–32px。
- 激活工具使用蓝底白字。
- 组间使用 1px 竖线分隔。
- Tooltip 用黑底白字小方块。

### 6.4 Markdown 纸张

建议编辑器内容区域采用“桌面 + 纸张”结构：

- 外层桌面：暖纸底 + 20px 点阵。
- 内层纸张：白色表面，标准宽度 720px，宽屏模式 880px。
- 纸张可以使用 2px 墨黑边框和 3px 硬阴影，但在专注模式中可弱化为 1px 边框。
- 正文字号 15–16px，行高 1.75，保证中文长文阅读舒适。
- 元信息、字数、时间使用 11–12px 等宽字体。

### 6.5 专注模式

专注模式建议作为一期能力预留：

- 隐藏模块轨道、上下文侧栏、检查器和底部状态栏。
- 只保留纸张、标题、退出按钮和极简保存状态。
- 纸张仍居中，四周保留点阵桌面。
- 快捷键：`Esc` 退出，`Cmd/Ctrl + .` 或自定义快捷键进入。

## 7. 右侧检查器

右侧检查器建议默认 300px，可在 280–360px 之间调整，可折叠成 28px 的方块按钮。

### 7.1 笔记模块中的检查器

建议使用 Tab 或分组折叠：

1. **信息**
   - 标题、所在文件夹、创建时间、更新时间、字数、标签
2. **大纲**
   - 当前文档 H1–H3 标题树
   - 点击跳转
3. **链接**
   - 反向链接
   - 出链
   - 引用当前笔记的试题、任务或知识条目
4. **AI**
   - 总结
   - 提取知识点
   - 生成试题
   - 转为待办

### 7.2 设计原则

- 检查器不是导航，不承载模块切换。
- 检查器只展示“当前选中对象”的上下文。
- 后续模块复用同一个检查器容器，只替换内容。
- 折叠后保留一个 28px 方块按钮作为重新打开入口。

---

## 8. 底部状态栏

底部状态栏高度 32px，上缘使用 2px 墨黑外壳线。

建议内容从左到右：

1. 当前位置：例如 `笔记 / 数学 / 勾股定理`
2. 当前文档状态：草稿、待整理、已确认
3. 弹性空间
4. 字数统计：`1,248 字`
5. 保存状态：`已保存 10:32`
6. 同步状态：绿色云图标 + `已同步`
7. 面板开关：侧栏、检查器、专注模式

状态栏是这个风格里非常适合保留的组件，它能给产品带来“工具软件”的完成度，而且占用空间很小。

## 9. 多模块布局映射

### 9.1 笔记模块

**上下文侧栏**

- 快速入口：全部笔记、最近编辑、收藏、未整理
- 笔记本树
- 标签
- 回收站

**主工作区**

- 文档标签页
- Markdown 编辑器
- 可选预览 / 分屏

**检查器**

- 信息、大纲、链接、AI

---

### 9.2 知识库模块

知识库用于管理“知识点”，建议以“库 > 分类 > 条目”的结构组织。

**上下文侧栏**

- 知识库列表
- 当前库的分类树
- 标签
- 待完善 / 已掌握等状态筛选

**主工作区**

- 默认显示知识条目列表
- 点击条目后进入“列表 + 详情”的双栏视图
- 详情仍复用 Markdown 编辑器

**检查器**

- 条目属性
- 掌握状态
- 关联笔记
- 关联试题
- 复习记录

**布局建议**

```text
上下文侧栏 248px | 条目列表 320px | 条目详情 flexible | 检查器 300px
```

---

### 9.3 试题库模块

试题库的关键是“根据知识点生成试题”，因此布局应突出筛选、生成、练习和解析。

**上下文侧栏**

- 学科
- 知识点树
- 题型：单选、多选、判断、填空、简答
- 状态：待审核、已收录、错题、已掌握

**主工作区顶部 Tab**

- 题库
- AI 生成
- 练习
- 错题本

**主工作区内容**

- 题库：表格或列表视图
- AI 生成：左侧参数表单 + 右侧生成结果预览
- 练习：题干居中卡片 + 底部操作栏
- 错题本：按知识点或错误次数分组

**检查器**

- 答案与解析
- 来源知识点
- 关联笔记
- 生成历史
- 正确率统计

---

### 9.4 打卡与待办模块

如果合并为“执行”模块，建议布局如下。

**上下文侧栏**

- 今日
- 待办
- 打卡
- 项目 / 清单
- 已完成
- 归档

**主工作区顶部 Tab**

- 清单
- 看板
- 日历
- 统计

**检查器**

- 任务标题、截止时间、优先级、提醒
- 关联笔记或知识点
- 打卡 streak
- 完成记录

**视觉建议**

- 待办状态用语义色方点，不用彩色大按钮。
- 看板列之间使用 1px panel 线，不做多层卡片套卡片。
- 任务卡片可以用白底、1px 墨线、2px 硬阴影，避免过重。

## 10. 全局能力布局

### 10.1 命令面板

建议一期就做，即使命令数量不多。

- 快捷键：`Cmd/Ctrl + K`
- 居中浮层，宽度 640px。
- 白底、2px 墨黑边框、6px 硬阴影。
- 遮罩使用 `rgba(26,26,26,0.4)`，不要模糊背景。
- 顶部是大输入框，下面按“最近使用 / 新建 / 跳转 / 命令”分组。
- 新模块上线时只需注册自己的命令，不需要挤占导航空间。

### 10.2 全局搜索

- 模块轨道顶部放搜索图标。
- 上下文侧栏顶部放当前模块内搜索。
- 全局搜索最终汇入命令面板的搜索模式。

两级分工：

- 全局搜索：跨笔记、知识、试题、任务。
- 模块内搜索：只搜索当前模块。

### 10.3 新建入口

- 模块轨道上的“+”：打开全局新建菜单。
- 上下文侧栏头部“+”：新建当前模块内容。
- 命令面板：新建任意类型内容。

### 10.4 收藏与最近使用

- 收藏放在上下文侧栏顶部，作为跨模块快速入口。
- 最近使用放入命令面板空态，同时在笔记侧栏保留“最近编辑”。

## 11. 响应式策略

### 11.1 宽屏桌面：≥1440px

- 模块轨道、上下文侧栏、主工作区、检查器全部显示。
- 编辑器纸张默认 720px，可切换 880px。

### 11.2 常规桌面：1080–1439px

- 模块轨道和上下文侧栏显示。
- 检查器默认收起，需要时以覆盖式面板浮在主工作区右侧。
- 编辑器纸张保持 720px；当视口接近 1080px 时，上下文侧栏自动收窄到 220px，纸张两侧边距同步减小。

### 11.3 小桌面与平板：768–1079px

- 模块轨道保留。
- 上下文侧栏默认折叠，点击模块图标后以浮层展开。
- 检查器改为覆盖式面板。
- 编辑器工具栏可横向滚动。

### 11.4 手机：≤767px

- 改为底部 Tab Bar：笔记、知识库、试题、执行、我的。
- 上下文侧栏改为左侧抽屉。
- 检查器改为底部上拉 Sheet。
- 命令面板全屏化。
- 编辑器纸张全宽，保留 16px 外边距。

关键原则：响应式不是重新设计一套产品，而是让四个区域依次“折叠、覆盖、抽屉化”。

## 14. 最重要的设计决策

1. **不要用一个无限膨胀的大侧栏承载所有模块**  
   用模块轨道 + 上下文侧栏替代。这样后续加模块时，导航复杂度不会失控。

2. **编辑器必须先做好，但主工作区不要写死成“笔记页”**  
   它应该是“视图容器”：一期承载文档视图，未来承载表格、看板、日历、练习视图。

3. **右侧只保留一个检查器容器**  
   不要每新增一个功能就新增一个悬浮按钮或抽屉。检查器按当前对象切换内容即可。

4. **全局功能集中到命令面板**  
   搜索、新建、跳转、模块命令都进入 `Cmd/Ctrl + K`，这是未来功能增长的泄压阀。

5. **视觉重点放在纸张、线条和按压感，不要过度卡片化**  
   这个组件库最有辨识度的是“暖纸 + 墨线 + 硬影 + 点阵”，而不是到处堆彩色卡片。

## 15. 推荐的下一步

如果要继续推进，建议下一步直接产出一版可点击的高保真桌面端原型，优先包含：

1. 笔记模块默认态
2. 多文档标签页
3. 编辑器工具栏
4. 右侧检查器
5. 命令面板
6. 空状态
7. 试题库列表的延展示意

原型阶段还应补齐三类次要但高频的交互：

- 侧栏树：拖拽排序、右键菜单、重命名、移动到。
- 编辑器：撤销 / 重做、版本历史、自动保存与冲突提示。
- 附件：上传中、上传失败、重新上传、粘贴图片后的预览状态。

这样可以尽早验证：印格风格在真实复杂界面中是否过重、点阵背景是否影响阅读、硬阴影在高密度列表中是否需要降档。
