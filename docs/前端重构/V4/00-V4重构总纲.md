# V4 重构总纲

## 1. 背景

当前正式前端使用 Vanilla JavaScript、字符串 HTML renderer、手工 controller/event binder 与多代 CSS 覆盖。该结构曾有效降低迁移风险，但随着目录树、多标签、弹层、富文本编辑、资料边注、知识与训练工作域增长，DOM 状态同步、焦点恢复、组件生命周期和样式隔离的维护成本已经明显上升。

V4 不再是“给 V3 换皮”，而是建立独立 React 前端，并在保持后端与数据契约稳定的前提下逐步接管正式用户路径。

## 2. 目标

- 使用 React + TypeScript 建立可组合、可测试的页面和组件树。
- 使用 React Aria Components 承担成熟的通用交互、键盘、焦点和 ARIA 语义，避免重复实现复杂基础控件。
- 使用 Vite 提供独立开发、构建和预览链路。
- 使用 CSS Modules 与唯一 Design Token 入口隔离组件样式。
- 使用单一应用 Store 管理业务状态，避免 React state 与旧 mutable state 双写。
- 保留 API、本地优先缓存、数据规范化、领域规则和 Milkdown 核心能力。
- 将可复用的框架无关能力逐步提取到共享包，使 V3/V4 迁移期仍只有一份业务事实来源。
- 主页、资料索引、资料编辑器、知识和训练工作域达到功能对等。
- V4 默认切换后删除 V3 Shell、renderer、controller/event binder、旧 CSS 与结构型测试。

## 3. 已冻结技术栈

| 层 | 选择 | 约束 |
| --- | --- | --- |
| UI | React | 只使用函数组件与 hooks |
| 交互组件底座 | React Aria Components | 无默认视觉；经 Knowra `components/ui` 二次封装后使用 |
| 语言 | TypeScript `strict` | 禁止以大面积 `any` 绕过迁移 |
| 构建 | Vite | 不引入 Next.js 或第二套 SSR 框架 |
| 状态 | Zustand 单 Store + slices | 不创建互相调用的多个全局 Store |
| 样式 | CSS Modules + CSS Variables | 全局只保留 reset、Token、基础排版 |
| 编辑器 | Milkdown + CodeMirror | 核心命令/插件复用，React 重写宿主生命周期 |
| 单元/组件测试 | Vitest + React Testing Library | 以行为和可访问语义为主 |
| 端到端 | Playwright | 覆盖关键工作流、视口、焦点和控制台 |

## 4. 非目标

- 不修改 API 路由、响应信封、领域模型或持久化格式。
- 不迁移数据库，不改变附件和 Markdown 存储格式。
- 不重新选择富文本编辑器。
- 不引入 Next.js、Redux、Tailwind、shadcn/ui、MUI、Ant Design、Mantine、TanStack Query 或新路由框架作为首轮依赖。
- 不采用 React Spectrum/Spectrum 视觉组件；选用的是无样式的 `react-aria-components`。
- 不在 page/feature 中直接散落第三方组件 API；React Aria 必须由 Knowra UI 层封装。
- 不把 `apps/web/app/`、`apps/web/components/*.jsx` 直接改名后当作 V4；它们是未接入实验且依赖旧样式。
- 不逐行翻译旧 controller 和 event binder 到 hooks。
- 不让 React 与旧 controller 同时操作同一 DOM 子树。
- 不为追求迁移速度删除功能、降低安全校验或伪造业务状态。

## 5. 复用边界

### 5.1 优先复用

- `apps/web/src/services/` 的 API client 与领域 service。
- workspace cache、normalization、write guard 和加载决策纯函数。
- tree、navigation、search、tag、note、annotation 等纯状态与领域函数。
- editor 中不依赖 DOM 的命令解析、状态模型、Markdown 与安全处理。
- Milkdown schema、commands、plugins 及其内部 DOM 契约。
- `apps/api/`、存储和所有后端业务契约。

这些模块不能长期由 V3/V4 各复制一份；迁移时逐项进入框架无关共享包。

### 5.2 提纯后复用

- 直接调用 `renderAll()`、`renderStatus()` 的状态动作。
- 混合“状态计算 + HTML 输出”的 renderer 文件。
- 混合“命令逻辑 + DOM 定位”的 controller。
- `MilkdownHost` 中可复用的编辑器命令接口与需由 React 接管的 mount/destroy 生命周期。

### 5.3 React 重写

- SSR Shell 与所有字符串 HTML renderer。
- `element-cache.js`、action proxies、全局事件 binder。
- 直接修改 `innerHTML`、style、hidden、dataset 和焦点的 controller。
- 页面布局、菜单、对话框、Tabs、Tree、Inspector 与边注组件。
- UI 状态更新、弹层生命周期、焦点和响应式组合。

React 重写不等于从零实现所有控件：Button、SearchField、Dialog、Popover、Menu、Tabs、Tooltip、Tree、GridList、Table、TagGroup 等优先以 React Aria Components 作为交互底座，再由 Knowra 封装 props、Token 与 CSS Module。AppShell、复杂工作区布局、编辑器外围和业务组件仍由项目自行实现。

## 6. 迁移形态

```text
                         API / persistence / domain contracts
                                      │
                         framework-neutral web core
                  services / models / commands / normalization
                           │                         │
                 V3 Vanilla app                 V4 React app
                 temporary baseline          independent workspace
                 legacy + V3 CSS          CSS Modules + V4 tokens
                           │                         │
                           └──────── cutover ────────┘
                                      │
                              delete V3 runtime
```

迁移期 V3/V4 通过不同应用入口运行，不共享 document，不共载应用 CSS，也不共同管理 DOM。

## 7. 强制原则

### P-01 React 独占渲染树

React 组件树内不得运行旧 `renderAll()`、字符串 `innerHTML` renderer 或缓存 DOM 元素的 controller。命令式第三方编辑器只能管理明确的宿主子树。

### P-02 单一状态事实来源

V4 不包装旧全局 mutable `state`。状态结构可参考旧模型，但由一个 Zustand Store 按 slice 管理；组件通过 selector 订阅，动作通过 store action 或 use case 调用。

### P-03 共享核心只有一份

框架无关业务模块迁入共享包时，V3 import 同步指向共享位置。禁止复制到 `apps/web-v4` 后长期双改。

### P-04 单一视觉来源

V4 不导入 `apps/web/styles/`、`src/styles.css`、`knowra-*`、`InkGrid` 或旧 React 探索样式。CSS Modules 的全局逃逸必须极少且有理由。

### P-05 按用户路径纵向迁移

每个页面任务同时完成组件、状态、事件、异常态、响应式、可访问性和测试，不做全站横向覆盖。

### P-06 编辑器边界显式

React 管理编辑器宿主和外围 UI；Milkdown adapter 管理 ProseMirror 子树、命令与插件。双方通过 typed interface 通信，禁止互相越界修改 DOM。

### P-07 可删除性前置

每个任务登记替代的 V3 模块与测试。V4-09 的退出清单必须归零。

### P-08 真实状态验收

加载、空、错误、保存中/失败、长内容、多标签、窄屏、200% 缩放和中文输入法均属正式范围。

### P-09 可回退但不长期双轨

开发期 V3 是独立回退应用；V4 达标后切换入口并删除 V3，不把 generation 变成永久产品设置。

### P-10 第三方组件必须经 Knowra 封装

`react-aria-components` 只允许在 `apps/web-v4/src/components/ui/` 及经登记的底层组合模块直接导入。页面和 feature 使用 Knowra UI 组件，不依赖第三方 DOM 结构、默认 class 或细碎 API。封装层统一处理 Token、CSS Module、密度、图标、中文文案、错误态和测试契约。

### P-11 行为与视觉所有权分离

React Aria 负责通用控件的 ARIA、焦点、键盘、集合与 overlay 行为；Knowra 负责视觉、业务状态与业务动作。不得为了改视觉绕过 React Aria 的语义结构，也不得用 React Aria 默认 class 作为业务选择器。

## 10. 完成定义

- 默认 Web 入口运行 `apps/web-v4` 构建产物。
- V4 bundle 不包含 V3 renderer/controller/event binder 或旧 CSS。
- page/feature 不直接 import `react-aria-components`；Knowra UI 封装层覆盖实际使用的基础控件。
- React tree 内无旧 `renderAll()`/`innerHTML` UI 注入。
- framework-neutral core 有类型、单元测试和单一来源。
- API、缓存、workspace recovery、草稿保护、附件和数据格式无回归。
- Milkdown 的输入、IME、历史、图片、表格、代码块和标注路径通过。
- Vitest/RTL/Playwright 与全仓测试通过。
- 1024/1280/1440/2048 和 200% 缩放关键路径通过。
- V3 运行代码、旧样式、探索 JSX 与 V3-only 结构测试退出清单归零。
- 架构、开发、部署、版本号和工程变更日志更新完成。

## 11. 变更控制

出现以下情况必须暂停并记录决策：

- 需要改变 API、领域对象、持久化或本地数据格式。
- 需要让 React 和旧 controller 共同操作同一 DOM。
- 需要长期复制共享业务逻辑而不设迁移归口。
- 需要引入新的全局状态库、路由框架或服务端 React 框架。
- 只能通过删除测试、绕过草稿保护或伪造数据完成迁移。
- 视觉目标与可访问性、功能对等或编辑器可用性冲突。
