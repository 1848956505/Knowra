## 1. 交付内容

### 独立 workspace

- 新建 `apps/web-v4`，不修改 V3 正式运行入口。
- 精确锁定 React `19.2.8`、React DOM `19.2.8`、React Aria Components `1.20.0`、TypeScript `7.0.2`、Vite `8.2.1`、Vitest `4.1.10`、Playwright `1.62.1` 等依赖。
- 根级新增 `dev:web:v4`、`build:web:v4`、`test:web:v4`、`check:web:v4` 命令。
- Vite `/api` proxy 复用 `scripts/dev-runtime-ports.js` 的运行时端口解析，不在 V4 配置中固定 API 端口。

### 工程隔离

- `scripts/check-v4-boundaries.mjs` 禁止 V4 相对导入 `apps/web`，并禁止 V4 React 源码使用登记外的 DOM 注入/查询 API。
- `react-aria-components` 只允许由 `src/components/ui/` 直接导入；当前阶段只建立空公共入口，不提前实现 V4-04 组件。
- 如果后续建立 `packages/web-core/src`，同一门禁会拒绝 React、React DOM、CSS 与 `apps/*` import。
- V3 class query gate 继续纳入 V3 全量测试。本次发现并修复 Windows 路径分隔符导致白名单全部失效的问题，未改动 V3 runtime 行为。

### App bootstrap

- `main.tsx` 使用 React Strict Mode，并组合 `AppProviders`、`AppErrorBoundary` 与 `App`。
- 最小 shell 提供 loading、ready、error 和 retry 状态，不接页面业务、不导入 V3 样式。
- `/api/health` resource 校验现有 `{ data: { status } }` 信封；并发与 Strict Mode 重挂载复用同一 Promise，失败或手动重试后才创建新请求。
