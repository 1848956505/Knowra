## 3. 类型与边界

`WorkspaceSnapshot`、`Folder`、`Note`、`Tag`、`Annotation`、`KnowledgeItem`、`LearningObjective`、`Question` 等类型按当前 API DTO 与领域实体核对。学习目标使用实际的 `objective` 和 `knowledgeItemId`；题目来源使用实际的结构化 `sources`，未引入假想的 `sourceIds`。

`scripts/check-v4-boundaries.mjs` 同时验证：

- V4 不导入 V3 runtime/CSS。
- 业务层不直接导入 React Aria Components。
- web-core 不导入 React、CSS、应用模块，也不在可执行代码中引用 DOM 全局。

server data 只保存 API 数据；workspace/navigation/status 保持可序列化；React Provider、storage adapter 和未来 editor engine 实例留在 Store 外部依赖或组件生命周期中。

## 4. 数据恢复与写保护

加载顺序为：兼容 V3 schema 的缓存立即展示 → 真实 API 刷新 → API 失败时保留只读缓存 → 无缓存时进入最小本地恢复模式。Store 提供加载 retry、数据模式写保护，以及 `saving/saved/error` 保存状态和字符串错误消息，不把 `Error` 或 DOM/editor 实例写入状态。
