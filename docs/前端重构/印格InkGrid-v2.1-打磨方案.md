## 0. 背景与目标

v2.0 已确立印格视觉签名（2px 黑边、零模糊硬影、零圆角、暖纸底、800 字重、物理按压交互）。两轮评审暴露六类问题：

| 类别 | 问题摘要 |
|------|---------|
| A. 产品贴合 | Demo 信息架构与真实产品脱节；且真实产品结构（三栏、无顶栏、检查器）与 demo 结构（顶栏+两栏）差异大 |
| B. 色彩体系 | 强调色单一，缺语义色（成功/警告/危险） |
| C. 视觉层级 | 所有元素同为 2px 黑边 + 硬影，主次不分、压迫感强、表格区风格断裂、缺呼吸口 |
| D. 组件覆盖 | 缺弹窗/菜单/Toast/空态/禁用态/加载态，更缺真实产品重度使用的工作面组件（检查器、过滤栏、分页器、菜单栏、状态栏等） |
| E. 可访问性与排印 | `outline:none` 硬伤、字号下限过低、中文 800 字重不成立 |
| F. 品牌与前瞻 | Logo 记忆点弱；暗色模式无预案；规范与 demo 已有 4 处漂移 |

**v2.1 目标**：以真实产品功能清单为底、以印格为视觉语言，**重新设计**资料库索引页与编辑器页的目标结构，并产出可直接指导主工程迁移的设计系统资产。主页作为简化版工作台一并给出（低保真即可）。

## 2. 设计决策（规格冻结区）

以下规格为 v2.1 冻结决策，开发 Agent 不需要（也不应该）再做选择。如有异议，通过桥梁反馈回本文档修订，不要在实现中偷改。

### 2.1 Token 命名收敛

v2.1 起所有 token 增加 `--ink-` 前缀并归类，旧变量名在 demo 内不再出现：

```css
:root {
  /* 基础 */
  --ink-bg: #F9F7F2;
  --ink-surface: #FFFFFF;
  --ink-surface-sunken: #F4F1EA;   /* 新增：无边框内嵌层底色 */
  --ink-border: #1A1A1A;
  --ink-text: #1A1A1A;
  --ink-text-secondary: #666666;
  --ink-dot-grid: #D1D1D1;

  /* 强调与语义（见 2.2） */
  --ink-accent: #2563EB;
  --ink-accent-hover: #1D4ED8;
  --ink-success: #16A34A;
  --ink-success-bg: #DCFCE7;
  --ink-warning: #EA580C;
  --ink-warning-bg: #FFEDD5;
  --ink-danger: #DC2626;
  --ink-danger-bg: #FEE2E2;

  /* 结构 */
  --ink-border-w: 2px;
  --ink-border-w-thin: 1px;
  --ink-shadow-1: 2px 2px 0 var(--ink-border);
  --ink-shadow-2: 3px 3px 0 var(--ink-border);
  --ink-shadow-3: 4px 4px 0 var(--ink-border);
  --ink-shadow-hero: 6px 6px 0 var(--ink-border);  /* v2.0 组件库已在用，正式收编 */
}
```

### 2.2 语义色板

原则不变：**黑白为主角，彩色只做状态点缀**。语义色只允许出现在以下位置，禁止用于装饰、图标常态、标题：

| Token | 主色 | Hover | 浅底 | 允许出现的位置 |
|-------|------|-------|------|---------------|
| accent | `#2563EB` | `#1D4ED8` | `#E0F2FE` | 主操作按钮、激活指示、focus 硬影 |
| success | `#16A34A` | `#15803D` | `#DCFCE7` | 保存成功 Toast、自动保存状态点、云端已连接 |
| warning | `#EA580C` | `#C2410C` | `#FFEDD5` | 未保存提示、「待整理」状态徽标、风险提示 |
| danger | `#DC2626` | `#B91C1C` | `#FEE2E2` | 删除按钮、错误 Toast、回收站相关操作 |

- 语义反馈块统一形态：**浅底 + 2px 同主色边框 + 3px 同主色硬影**（阴影用主色而非黑色，与 focus 蓝影同一套逻辑）。
- 现有标签色（Tag Blue/Green/Purple）定位为「分类色」，与语义色**物理隔离**：分类色永远是 1px 边框无阴影的 tag 形态，不做按钮、不做反馈块。文档中需要新增这条禁令。
- 训练场景的答对/答错反馈组件延至 v2.2。

### 2.3 视觉层级四梯度

放弃 1.5px 方案（亚像素渲染不稳定），改为四档离散梯度：

| 梯度 | 边框 | 阴影 | 适用 |
|------|------|------|------|
| Tier A 浮起层 | 2px 黑 | 4px 硬影（弹窗用 6px hero） | 一级卡片、弹窗、主按钮、拖拽中的元素 |
| Tier B 操作层 | 2px 黑 | 2px 硬影 | 次级按钮、图标按钮、输入框 |
| Tier C 结构层 | 1px 黑 | 无 | 大容器内部的子分区、树节点框、Tab 边框、检查器分区、菜单栏 |
| Tier D 平面层 | 无边框 | 无 | 列表行、树节点、编辑纸面、代码块——仅用 `--ink-surface-sunken` 底色或留白区分 |

**强度分级总原则（写入 D1「设计哲学」章）**：外壳分界、主页卡片、弹窗、主操作用 Tier A/B 全量印格；工作面内部（列表、树、编辑区、检查器内容）只允许 Tier C/D，让内容层安静。D3/D4 即为此原则的验证物。

### 2.4 表格与列表规范

- 数据容器外框维持 Tier A（2px 黑边 + 4px 硬影）；
- 行分隔线 **`1px solid #DDD`**（不采用交替底色：与点阵背景叠加后噪音更大）；
- 行 hover 底色用暖灰 **`#F6F3EC`**（`--ink-surface-sunken` 同源），不用冷灰 `#FAFAFA`。

### 2.5 呼吸感与留白

| 位置 | v2.0 | v2.1 |
|------|------|------|
| 内容区 padding | 40px | 48px（索引页主区同样适用） |
| section 之间垂直间距 | 40px | 64px |
| H1 级标题区 | — | 禁止加边框和底色，直接排在页面底色上 |
| 卡片间距 | 24px | 24px（不变） |

### 2.6 暗色模式预案（只做 token 验证）

v2.1 **不交付完整暗色模式**，只在 D2 组件库页内加切换开关验证 token 体系可行。预案 token：

```css
[data-theme="dark"] {
  --ink-bg: #171512;              /* 暖黑，延续纸感色温 */
  --ink-surface: #211E1A;
  --ink-surface-sunken: #2A2621;
  --ink-border: #E8E4DC;          /* 边框反转为暖白 */
  --ink-text: #F2EFE9;
  --ink-text-secondary: #9C968C;
  --ink-dot-grid: #35312B;
  /* 硬影基因保留：实色、零模糊，但降不透明度避免刺眼 */
  --ink-shadow-3: 4px 4px 0 rgba(232, 228, 220, 0.22);
}
```

验证标准：按钮、卡片、输入框、导航四类组件在暗色下「浮起/按下」物理感依然成立。如实色影在暗底不成立，允许调整 alpha，但**禁止引入 blur**。

### 2.7 品牌 Logo

- 容器 **32×32**；
- 专属几何 Mark（纯 CSS 可实现）：**叠印方块** —— 后层 32×32 蓝色（`--ink-accent`）实心方块，前层白底黑边方块向左上偏移 3px，中央放 800 字重「知」字。隐喻「墨印错位压格」；
- Remix `ri-brain-line` 从 Logo 位退役（可继续作为知识模块图标）；
- 此项允许品牌层面迭代，通过桥梁反馈。

### 2.8 页面结构规格与功能对等清单（v1.2 核心变更）

**总决策：结构与视觉同步重设计。** 新结构由本节冻结；§0.5 基线中的每个功能元素在下表交代去向。

#### 2.8.1 全局外壳（三张页面共用）

│ 顶栏 60px：Logo(32) ｜ 全局搜索(⌘K) ｜ 动作区        │  2px 黑色下边框
├─────────┬────────────────────────────────┬───────────┤
│ 侧栏     │ 主区（随页面变化）              │ 检查器     │
│ 260px   │                                │ 300px     │
│ 上：工作 │                                │ 可折叠     │
│ 域分组   │                                │           │
│ 下：内容 │                                │           │
│ 树       │                                │           │
│ 底：设置 │                                │           │
└─────────┴────────────────────────────────┴───────────┘

- 右侧检查器为常驻第三栏，带折叠开关（折叠后主区扩展）；
- 三栏各自独立滚动，1280px 与 1440px 视口不得横向溢出（对齐 Phase3.1 §7.3 既有约束）。

#### 2.8.4 主页（D5，低保真）

- 结构：全局外壳（无检查器栏）+ 欢迎区（H1 + 数据摘要一行）+ 工作域 4 卡（资料 Tier A 激活卡，其余 Tier C 禁用卡 + 「即将开放」tag）+ 最近编辑表（§2.4 规格）；

- 网格 `repeat(auto-fill, minmax(260px, 1fr))`。

### 2.9 可访问性与排印

1. **删除 `* { outline: none }`**。全局改为：
   ```css
   :focus-visible { outline: none; box-shadow: 3px 3px 0 var(--ink-accent); }
   ```
2. **字号下限 11px**：9px/10px 全部提升；
3. **中文标题字重**：中文标题实际渲染依赖 PingFang SC Semibold，力量感由字号 + 环境构成，不虚标 800；中文标题**移除 `letter-spacing: -0.5px`**；
4. 卡片 hover 物理修正：`translateY(-4px)` 同时阴影 4px → **6px**（浮得越高影子越远）。

### 2.10 规范漂移修正

| 漂移点 | 修正 |
|--------|------|
| 组件库页头 H1 42px 未收录 | D1 字号梯度表新增「Display · 42px / 800」（仅设计系统展示页与营销页） |

### 2.11 迁移风险控制（v1.2 新增，回应「不止换皮」的担忧）

结构重设计路线下，风险靠以下三条约束对冲（写入 D1，并作为未来迁移方案的前置条件）：

1. **data-\* 事件钩子契约冻结**：现有前端为「渲染器输出纯 HTML 字符串 + `data-*` 属性挂事件 → 控制器驱动」的单向数据流架构。新结构的 demo 中，凡对应现有交互的元素，**必须标注现有 `data-*` 钩子名**（如 `data-knowledge-select`、`data-objective-save`，以迁移时的实际代码为准）。迁移时只重写渲染器模板与 CSS，控制器与状态层不动。
2. **分阶段迁移路线**（每步可独立回退，各自走一次测试与验收）：
   - ① 外壳先行：顶栏 + 侧栏工作域分组替换图标切换器，主区内容不动；
   - ② 索引页：主区列表 + 过滤 + 分页 + 右栏预览换新结构；
   - ③ 编辑器页：Tab/菜单栏/状态栏/边注换新结构（Milkdown 挂载逻辑不动）。
3. **功能对等验收**：每阶段迁移完成后，按 §2.8 对等清单逐项核对「去向」落实情况；任何「暂缓/删除」都必须回到本文档记录，不允许在代码评审中口头豁免。
