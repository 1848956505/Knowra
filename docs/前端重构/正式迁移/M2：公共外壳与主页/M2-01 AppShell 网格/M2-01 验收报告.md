## 4. 运行态验收结果

Chrome 运行态检查覆盖 2048×1024、1440×1024、1280×720 和 1024×768，并切换资料索引、编辑器、知识域页面。

### 4.1 通过项

- TopBar 实际高度为 60px。
- StatusBarHost 实际高度为 32px，`z-index` 为 25，位于页面底部。
- 各已检查视口的 `document.scrollWidth/scrollHeight` 与视口尺寸一致，没有页面级额外滚动条。
- 1280×720、1440×1024、2048×1024 下，导航位于左侧，FeatureStage 正确占据剩余主体区域。
- SSR 结构中保留 `#workspace-shell`、`#kb-sidebar`、`#kb-workspace`、`#editor-scroll-region`、上下文菜单宿主、Markdown 导入 input 和初始工作区脚本槽位。

### 4.2 P1 缺陷

#### P1-1：1024×768 下 ShellBody 子项顺序与宽度错误

相关规则：

- `apps/web/styles/components/responsive.css:93-94` 在 `max-width: 1040px` 下设置 `.kb-sidebar { order: 2; }`。
- M2-01 新增的 `apps/web/styles/components/knowra-inkgrid-shell.css:51-59` 将 ShellBody 改为两列 CSS Grid。

运行态实测结果：

- ShellBody：1024×676，Grid 列为 `240px 784px`。
- 预期：`#kb-sidebar` 位于 `x=0`，FeatureStage 位于 `x=240`，宽度约 784px。
- 实际：FeatureStage 位于 `x=0`，宽度仅 240px；`#kb-sidebar` 位于 `x=240`，右侧剩余区域为空白。
- 该问题在资料索引、编辑器和知识域页面均可复现。

这是主布局破坏，符合验收方案中的 P1 定义，不能通过 `CONDITIONAL PASS` 放行。
