## 1. 执行结论

### 1.1 正式映射已经存在的部分

- 正式交互以稳定宿主 ID、`data-*` 行为属性和事件委托为主；`apps/web/src/app/element-cache.js` 集中维护主要宿主节点。
- Shell、搜索、资料树、资料索引、文档标签、编辑菜单、编辑器正文、Footer、资料边注、知识工作域和训练工作域均能找到对应的 renderer、事件 binder、controller/state 入口。
- 现有正式代码和正式测试中未发现 `data-hook`。`data-hook` 不得从三张原型页面复制到正式迁移实现。

### 1.2 必须在后续任务中收口的部分

1. `apps/web/lib/sidebar/renderers.js` 已输出 `data-attachment-rename-form`、`data-attachment-rename-input`、`data-attachment-rename-cancel`，`attachment-rename-controller.js` 也已提供 draft/submit/cancel 方法，但 `apps/web/lib/events/aside-events/` 没有对应的 submit/input/cancel 绑定，当前只有 renderer 测试，没有完整交互测试。
2. `apps/web/lib/library-index/renderers.js` 也会输出索引详情附件的 `[data-attachment-open]`，但 `library-index-events.js` 没有处理该 selector 的分支；现有 `aside-events` 只监听 `#aside-content`，因此索引详情附件入口没有可确认的正式事件路径。
3. `bindWorkDomainEvents()` 覆盖知识/训练工作域的大量 click/input/change selector，但没有同范围的 `events/work-domain-events.test.js`；`phase31-workspace-ui.test.js` 主要验证渲染标记，不等价于事件委托回归。
4. `bindEditorContentEvents()` 与 `aside-events/click.js`、`context-menu.js`、`dblclick.js` 的复杂分支缺少完整 binder 级测试；现有低层 controller/renderer 测试不能证明每个正式 selector 都能从 DOM 事件抵达 controller。
5. Shell 中 `.settings-button` 目前只有可访问名称，没有正式 action selector、controller、state 或测试；按照当前契约它是占位入口，不应在迁移中伪造设置行为。若未来开放设置功能，应先增加正式 selector 和行为契约。

这些项目是映射和测试缺口，不由本任务直接修改。M0-02 的输出是让后续执行模型知道哪些 selector 可直接复用、哪些行为必须先补齐证据。

## 2. 映射规则

本报告把一个视觉控件拆成五层：

| 层 | 正式来源 | 说明 |
| --- | --- | --- |
| 宿主 | `id` 与 `element-cache.js` | 事件监听和 renderer 挂载的稳定容器，例如 `#folder-tree`、`#note-tabs`。 |
| 行为 selector | `data-*` 属性或正式 class/ID | 事件 binder 使用 `closest()`、`matches()` 或 dataset 读取的入口。 |
| 事件入口 | `apps/web/lib/events/` | 只负责读取 selector、阻止默认行为和派发 controller/deps。 |
| 业务状态 | `apps/web/src/app/app-state.js` 及 controller | 记录选择、面板、菜单、草稿、加载和持久化状态。 |
| 回归证据 | `apps/web/test/` | renderer、纯状态、controller 或 binder 测试；四类证据强度必须区分。 |

事件 binder 不是 controller 的替代品：迁移视觉结构时可以移动容器和 class，但不得改掉事件 binder 正在读取的行为属性，除非同时提交 selector、controller 和测试的完整变更。

## 6. Render-only 状态属性与行为 selector 的边界

以下属性用于 CSS、可见状态或读取字段，不应被误当成新的事件契约：

| 属性族 | 来源状态 | 用途 |
| --- | --- | --- |
| `data-active`、`data-selected`、`data-status` | active tab、当前选择、业务状态 | 渲染选中态/状态色；事件通常读取同一控件的另一个 action/id 属性。 |
| `data-open`、`data-left-hidden`、`data-right-hidden`、`data-view-mode`、`data-source-open` | 菜单、侧栏、编辑器视图状态 | Shell/CSS 布局状态；不直接派发业务 action。 |
| `data-dirty`、`data-dragging`、`data-drop-target`、`data-pinned` | 保存、拖拽、表格固定状态 | 交互过程的可视反馈；状态由 controller/plugin 写回。 |
| `data-level`、`data-depth`、`data-outline-index`、`data-role` | 目录/大纲/表格结构 | 结构定位或编辑器内部语义；不是原型 hook。 |
| `data-filter-kind/value`、`data-*-field`、`data-*-id` | 事件读取的 payload | 与 action selector 配套传值；不得只移动视觉节点而丢失。 |

迁移只要保留行为属性和宿主边界，就可以改变 class、网格层级和视觉容器；`data-ui-*` 若新增，只能承担视觉测试或布局语义，不能取代上述正式 action selector。

## 8. 确实需要新增或补齐的 selector

### 8.1 当前行为 selector：不需要新命名，但有两个已有 selector 路径未完整接线

当前正式行为属性已经覆盖迁移契约列出的导航、文档标签、编辑菜单、Footer、边注和索引控件。不要为了新视觉结构重新命名这些属性。

```text

```

后续修复应复用这三个 selector，接入 `aside-events` 的 submit/input/click，并新增事件和 controller 测试；不要新造一套 `data-hook` 或视觉类名来绕过现有 controller。

### 8.2 后续视觉迁移可增加的非行为 `data-ui-*`

如果 M2/M3/M4 需要对新 Shell 容器做结构测试，可增加以下仅用于视觉/布局定位的属性：

data-ui-status-bar-host

这些属性不是动作入口，不得在事件 binder 中替代 `[data-module-key]`、`[data-index-tab]`、`[data-tab-note-id]`、`[data-aside-tab]` 等正式行为 selector。
