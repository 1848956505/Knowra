# 正式 UI 迁移验收与回归方案

规划与验收方依据本文件审查执行结果。验收方不直接修复实现；失败项退回对应执行模型。

## 1. 验收结论

| 结论 | 含义 |
| --- | --- |
| `PASS` | 全部门禁通过，可以进入下一任务或阶段 |
| `CONDITIONAL PASS` | 仅存在已登记、已获用户接受的 P2 偏差 |
| `REJECTED` | 存在 P0/P1、未登记偏差、证据不足或测试失败 |
| `BLOCKED` | 缺少环境、权限或必要决策，无法形成结论 |

## 2. 缺陷优先级

- P0：数据丢失、安全绕过、启动失败、核心路径不可用、无法回退。
- P1：功能回归、键盘不可达、页面级溢出、主布局破坏、视觉目标明显不符。
- P2：不影响任务完成的细节偏差、次级间距或文案问题。

阶段 PASS 要求：P0/P1 为零；P2 必须有负责人、后续任务或批准偏差。

## 3. 每任务自动化门禁

执行模型至少提供：

```bash
git diff --check
npm run test:web
```

涉及编辑器 bundle 时补充：

```bash
npm run build:editor-bundle -w @study-accelerator/web
```

阶段 M6 必须运行：

```bash
npm test
```

测试失败时不得以“与本任务无关”直接忽略；执行模型必须给出失败前后证据，由验收方判断。

## 4. 静态结构门禁

- HTML 语义与视觉顺序一致。
- 正式事件属性与控制器查询一致。
- 无原型 `data-hook` 遗留。
- 无 CDN、内联生产脚本、浏览器原生 `alert/prompt/confirm`。
- 新视觉值来自正式 Token 文件。
- CSS 模块职责清晰，单文件明显膨胀时拆分。
- 旧选择器只在有真实调用方时保留。

## 5. 浏览器视口矩阵

| 视口 | 页面 |
| --- | --- |
| 2048×1024 | 首页、索引、编辑器四种侧栏状态 |
| 1440×1024 | 首页、索引、编辑器、知识、训练 |
| 1280×720 | 首页、索引、编辑器紧凑状态、其他工作域 |
| 1024×768 | 最小支持布局与覆盖式面板 |

每张截图必须记录：视口、数据状态、页面、面板状态、提交或差异标识。

## 6. 编辑器状态矩阵

- 无目录栏、无边注栏。
- 仅目录栏。
- 仅边注栏。
- 目录栏与边注栏同时展开。
- 专注模式。
- 源码编辑器分栏。
- 9 个以上标签及长标题。
- 长面包屑、长中文标题、多标签和附件长文件名。

所有状态检查：无菜单竖排、无控件不可达、活动标签可见、正文不出现页面级横向滚动。

## 7. 功能回归矩阵

### 公共外壳

- 工作域切换、返回资料、全局搜索、设置入口、Footer 状态更新。
- API → cache → mock 的加载恢复路径。
- 网络/运行错误能够在 UI 中表达。

### 资料索引

- 文件夹操作、搜索、筛选、分页、收藏、回收站、资料打开、侧栏折叠。

### 编辑器

- 输入、保存、离开保护、Tab、菜单命令、源码、标签、附件、标注、大纲、专注模式。

### 其他工作域

- 知识与训练查询、编辑入口、资料回链；学习档案门禁。

## 8. 可访问性门禁

- 仅键盘完成：首页 → 资料索引 → 打开资料 → 编辑 → 切换边注 → 返回。
- Tab 顺序与视觉顺序一致，焦点始终可见。
- Escape 关闭搜索、菜单和覆盖式面板，并恢复合理焦点。
- 交互目标有可访问名称和状态。
- 200% 缩放后主路径可用。
- 减少动态效果设置下不依赖位移动画表达唯一状态。

截图不能证明屏幕阅读器兼容；语义和状态需通过 DOM 检查或辅助技术复核。

## 9. 视觉比较方法

1. 使用与目标原型一致的视口和页面状态。
2. 保存原型截图与正式实现截图。
3. 将两张图并排或叠加比较。
4. 先判断结构、宽度、滚动和层级，再判断颜色、字体、间距和细节。
5. 功能真实数据导致的文案差异不算视觉缺陷，但溢出处理必须符合契约。
