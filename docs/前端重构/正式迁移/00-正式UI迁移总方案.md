# Knowra 正式 UI 迁移总方案

## 1. 目标

在不重写业务层的前提下，将“印格 InkGrid v2.1”迁移到当前 `apps/web` 正式 Vanilla JS SPA，并保持已有资料、知识、训练、学习档案工作域及本地优先数据链路可用。

迁移完成后应满足：

- 顶部栏、全局功能导航和 Shell Footer 成为稳定公共外壳。
- 资料目录、资料详情和资料边注是功能页内部可折叠辅助面板。
- 资料索引和编辑器达到原型视觉目标，同时保留所有正式交互。
- 双侧栏、窄屏、多标签和长内容不会破坏编辑器中心工作区。
- 所有迁移均可按阶段回退，不需要一次性替换整个前端。

## 2. 非目标

- 不迁移到 React、Next.js 或其他新框架。
- 不重写 API、领域模型、持久化方案或响应信封。
- 不重新实现 Milkdown、CodeMirror、附件、标注和草稿保护逻辑。
- 不在缺少视觉目标的情况下重设计知识、训练和学习档案工作域内部页面。
- 不交付完整暗色模式；仅保留 Token 可扩展性。

## 3. 已冻结架构

```text
AppShell
├── TopBar
├── ShellBody
│   ├── FunctionNavigation
│   └── FeatureStage
│       ├── HomeWorkspace
│       ├── LibraryWorkspace
│       │   ├── DirectoryPanel
│       │   ├── LibraryIndex / EditorMain
│       │   └── Inspector / MarginaliaPanel
│       └── Knowledge / Training / LearningWorkspace
└── StatusBarHost
    ├── GlobalStatusSlot
    └── FeatureStatusSlot
```

关键约束：

- `AppShell` 负责位置、尺寸、层级、滚动边界和全局状态。
- 功能页面只向 `FeatureStage` 与 `FeatureStatusSlot` 提供内容。
- 目录栏和边注栏不得进入全局导航组件。
- Shell Footer 始终位于主体网格之外；是否显示和显示哪些内容由当前页面状态决定。

## 4. Token 与资源策略

1. `apps/web/styles/components/knowra-theme-tokens.css` 继续作为唯一事实来源。
2. 在该文件中加入 `--ink-*` 目标 Token，并用兼容别名承接现有 `--paper`、`--blue`、`--line` 等变量。
3. 迁移期间允许旧选择器继续通过别名工作；新样式不得重新硬编码颜色和尺寸。
4. 目标图标语言采用设计文档规定的 Remix Icon，但必须本地化为静态 SVG 或通过构建依赖输出，禁止运行时 CDN。
5. 图标替换必须有映射表和测试，不能在同一功能区域混用两套风格。

## 5. 迁移开关与回退

- 在根 Shell 上增加单一迁移标识，例如 `data-ui-generation="inkgrid-v2"`。
- 新样式必须限定在该标识下，避免污染旧工作面。
- 每个阶段只移交一类区域；阶段提交可独立回退。
- 在 M6 清理阶段通过验收前，不删除旧选择器、旧图标或兼容 Token。
- 回退不能更改用户数据，也不能要求数据库迁移。

## 6. 阶段路线

### M0：契约与基线冻结

- 完成正式选择器、控制器、状态和原型区域映射。
- 补全功能对等清单、响应式规则和可访问性规则。
- 保存正式前端与目标原型的基线截图。
- 产出：可以交给执行模型的无歧义任务书。

准出条件：所有 P0 待决项关闭，验收方标记 `M0 PASS`。

### M1：Token、字体与图标资源

- 将 InkGrid Token 收敛到正式 Token 文件。
- 建立旧 Token 兼容别名。
- 本地化目标图标并建立语义映射。
- 不改变页面结构和业务行为。

准出条件：现有页面无视觉崩坏、无外部图标 CDN、Web 全量测试通过。

### M2：公共外壳与主页

- 迁移 TopBar、FunctionNavigation、FeatureStage 和 StatusBarHost。
- 将全局搜索移入 TopBar，但复用现有搜索状态和事件。
- 将模块导航与资料目录物理拆分。
- 主页作为公共外壳的第一张低风险验证页面。
- 知识、训练、学习档案必须仍可进入和返回。

准出条件：外壳视觉通过；全工作域导航、搜索和 Footer 行为通过。

### M3：资料库索引页

- 迁移独立目录栏、索引主区、过滤栏、列表、分页和资料详情栏。
- 保留真实数据、过滤、分页、打开资料和折叠面板行为。
- 覆盖空结果、回收站、长标题、无标签和附件状态。

准出条件：功能对等清单全部通过；1280px、1440px 无横向溢出。

### M4：资料编辑器

- 迁移目录栏、文档 Tab、菜单栏、编辑纸面、资料边注和编辑器状态内容。
- 保留 Milkdown、源码编辑、草稿保护、导入导出、查找替换、标签、附件和标注。
- 加入基于编辑器中心列宽度的容器查询和工具栏降级。

准出条件：四种侧栏状态、多标签、长标题、源码分栏和专注模式全部通过。

### M5：其他工作域兼容

- 让知识、训练和学习档案工作域适配新外壳的可用宽度、顶部栏和 Footer。
- 只处理兼容性和公共组件，不在缺少设计稿时重做工作域内部视觉。
- 验证资料回链、编辑入口和工作域切换。

准出条件：Phase3.1 现有工作域测试与浏览器路径全部通过。

### M6：清理与发布准入

- 删除确认无引用的旧 CSS、图标、兼容别名和废弃结构。
- 更新样式导航、架构文档、版本号与工程变更日志。
- 运行全仓测试和最终多视口视觉验收。

准出条件：无 P0/P1 缺陷、全仓测试通过、验收方签署最终 PASS。

## 7. 阶段依赖

```text
M0 → M1 → M2 → M3 → M4 → M5 → M6
```

M3 与 M4 不并行。两者共享目录栏、状态栏和导航结构，并行会导致选择器与 Shell 契约漂移。

## 8. 变更控制

以下情况必须暂停执行并新增决策记录：

- 需要修改 API、领域对象或持久化结构。
- 需要更换前端框架或引入运行时 React。
- 需要删除现有功能或缩减现有测试。
- 目标视觉和可访问性要求冲突。
- 响应式规则要求改变冻结宽度或交互模式。
- 执行模型发现只能通过绕开草稿保护、缓存恢复或错误处理完成页面迁移。

## 9. 完成定义

只有同时满足以下条件才算迁移完成：

- 本目录的功能对等清单全部勾选。
- `npm test` 通过。
- 目标视口和状态截图全部验收通过。
- 键盘、焦点、缩放和屏幕阅读语义检查无阻塞项。
- 无外部 CDN、无重复 Token 事实来源、无未登记的视觉偏差。
- 旧实现只在确认无引用后删除。
