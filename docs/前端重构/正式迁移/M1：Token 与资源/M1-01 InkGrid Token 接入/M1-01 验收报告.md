## 发现

### P1-1：执行报告漏列实际生产改动，范围扩展未登记

M1-01 README 只授权正式 Token 文件和必要的 Token 形状测试；但当前工作树实际修改了以下 5 个生产 CSS 文件：

- `apps/web/styles/components/aside-tabs.css`
- `apps/web/styles/components/knowra-editor.css`
- `apps/web/styles/components/knowra-library-index.css`
- `apps/web/styles/components/note-tabs.css`
- `apps/web/styles/components/work-domain.css`

这些不是单纯的 Token 声明：它们把编辑器文档 Tab、边注 Tab、资料索引 Tab、工作域 Tab 的激活线宽度或颜色改为新的 Token 组合，属于正式 UI 行为/视觉规则的实际变更。执行报告“修改文件”一节只列出 Token 文件和两个测试文件，没有列出上述 5 个生产文件，也没有在 `05-决策与偏差记录.md` 登记必要的范围偏差或承接关系。

这些改动可能是为了落实 M0-01 已接受的黑线 Tab 规则，但在当前任务书下仍必须由执行方明确说明“属于 M1-01 的必要 Token 消费改动”，或退回到对应样式迁移任务；在范围和证据未收口前不能放行。

### P1-2：canonical 排印 Token 与当前 InkGrid 设计基线不一致

当前 `apps/web/styles/components/knowra-theme-tokens.css` 将正式 canonical Token 定义为：

- `--ink-font-ui: 'SF Pro Rounded', 'PingFang SC', ...`；
- `--ink-font-reading: 'Songti SC', 'Source Han Serif SC', ...`；
- `--ink-type-heading-1: 36px`、`--ink-type-display-sm: 40px`。

但当前设计文档明确规定 UI 字体为 `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`，并规定“全部无衬线”；字号基线为 Display 42px、页面 H1 28px、区块 H2 16px。尤其 `Songti SC` 被兼容别名接入编辑器标题和正文，不能与“全部无衬线”的正式基线同时成立。

Token 形状测试只验证了这些值“存在”及别名关系，没有验证它们与设计基线一致，因此测试通过不能关闭该偏差。当前 `05-决策与偏差记录.md` 没有对应批准记录。
