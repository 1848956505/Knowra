# Android 在线预览 / 启动器

## 本次范围

`apps/android` 是独立 Android Java 工程。首次配置自己的 HTTPS 知境 V4 根地址，明确点击后由系统默认浏览器的 **Custom Tabs 安全标签页**承载网页。通过既有服务的同源 `/api` 使用网页功能，Basic Auth、TLS、Cookie、上传下载与浏览器导航均由浏览器负责。

**这是在线启动器预览，不是完整独立客户端。** APK 不包含 React V4、Node 服务、SQLite 或离线同步；页面 UI 版本取决于所连接服务。本次没有部署服务，也没有确认线上服务已包含仓库最新移动 UI。

当前只构建未签名 APK，不能直接安装。没有创建调试/生产签名密钥，没有发布商店、稳定 Release 或新服务器。安装与真机验收需后续明确授权临时测试签名；生产签名另行处理。

## 为什么没有沿用 WebView / Capacitor

评估的路线是 Capacitor + 共享 V4，以及最小原生 WebView。现有 API、附件、导出依赖同源；桌面运行时依赖 Node/SQLite/fs/Electron IPC，不能直接移植。

原生 WebView 还存在一个不能靠主页面 URL 消除的认证边界：`onReceivedHttpAuthRequest` 只给 host，不提供挑战端口；`shouldInterceptRequest` 不能保证逐跳处理资源重定向。因此限制 HTTPS、校验主页面 origin、只允许 443 都不足以证明 Basic Auth 凭据发送到哪个端口。为避免错误的跨端口认证保证，本版完全移除了 WebView、本地密码输入与手工网络代理。

Custom Tabs 把完整网页安全上下文留在系统浏览器。应用不拦截 TLS 或认证，不向浏览器传 Authorization、Cookie、token、JavaScript 或 postMessage 通道，不预热或预取用户服务。需要独立内嵌客户端时，应另行设计正式登录与受控网络架构，不能用放宽 TLS 或禁用服务鉴权来替代。

## 服务要求与使用

- 用户已经拥有并信任的知境 V4 服务，Web 与 `/api` 位于相同 HTTPS origin 的根路径。
- 系统信任且域名匹配的 HTTPS 证书；遇到证书警告必须停止访问，不绕过。应用只接受 HTTPS 起始地址；浏览器后续导航、证书提示由浏览器控制，不声称应用是网络白名单或出站防火墙。
- 地址如 `https://你的域名`，可带 HTTPS 端口。不接受路径、查询、hash 或 URL 内嵌账号密码。没有硬编码地址、密钥或用户数据。
- 默认浏览器需支持 Custom Tabs。不可用时应用明确失败，保留地址便于重试；不会把页面随意交给接管某个域名的第三方 deep-link 应用。
- 在系统浏览器地址栏确认域名，再由用户自己登录。Custom Tabs 可能沿用浏览器现有会话；应用不读取或保存账号密码，也不判断登录成功。
- 关闭标签页可返回原生连接页，重新打开、修改服务地址或忘记地址。更换地址需明确确认，但不删除旧服务资料或退出浏览器会话。
- “忘记服务地址”只清除此应用的偏好，不删除服务器内容、浏览器 Cookie/缓存或登录态。退出登录应在服务/浏览器完成。
- “已交给浏览器打开”仅表示 Intent 已发出，不代表网络、登录、页面加载或内容保存成功。断网、证书和服务错误应以浏览器显示为准。

## 隐私和权限

应用只存一个 `service_origin` 字符串，不请求 INTERNET、相机、麦克风、位置或存储权限。AndroidX 可能合并一个仅限同签名应用的内部 receiver 权限，CI 对合并 manifest 检查并禁止其他权限。应用备份/设备迁移排除本机配置。浏览器的存储和隐私设置归浏览器，不能用本应用的 `allowBackup` 声称控制浏览器数据。

导出的 Launcher Activity 忽略外部 Intent 的 URL、extras 和自动打开请求；只有用户按按钮才启动服务。包发现只查询 Custom Tabs service 和通用浏览器 handler。起始 URI 经规范化后传给已识别的默认浏览器包，不使用账号密码、附加请求头、任意 Intent URI 或 JS bridge。

## 构建和证据

要求 JDK 17、Gradle 8.11.1、Android SDK platform 35 与 build-tools 35.0.0；AGP 固定 8.9.2，AndroidX Browser 固定 1.8.0，最低 Android 9（API 28）。使用已获许可的 SDK。配置禁止 SDK 自动下载，不运行接受许可或签名步骤。

```sh
# 仓库根目录；有 javac 时同时编译执行纯 Java URI 策略
node --test scripts/test/android-preview.test.js

cd apps/android
gradle --no-daemon -Pandroid.builder.sdkDownload=false :app:assembleRelease :app:lintRelease :app:testReleaseUnitTest
```

产物：`apps/android/app/build/outputs/apk/release/app-release-unsigned.apk`。工作流 `.github/workflows/android-preview.yml` 使用 runner 已存在的 SDK，验证合并权限、APK 未签名、没有生成 debug keystore，保存校验和、源提交与报告。它是检查产物，不能直接安装。

### 验收边界

- 纯 Java URI 策略与源代码合同：不证明 Android 运行时。
- `testReleaseUnitTest`：在 Robolectric API 28/35 模拟连接表单、无浏览器、取消/确认切换、忘记地址、外部 Intent 忽略和固定浏览器包的 HTTPS 启动。不是实际浏览器网络验收。
- unsigned APK + lint：证明可构建和静态检查，不证明真机体验。
- 尚未在 vivo X300 / OriginOS 6 验证浏览器提供者、键盘、Back 手势和返回恢复；不承诺未知平板或 HarmonyOS APK 兼容性。
- 未连接真实用户服务、使用真实用户资料或付费 API。安装验证仍需获准临时测试签名，再通过支持的 emulator/真机与隔离 HTTPS 服务验证真实网页、Basic Auth成功/失败、TLS错误、断网、表单输入、附件和返回重试。不能用 JVM 模拟代替这些证据。
