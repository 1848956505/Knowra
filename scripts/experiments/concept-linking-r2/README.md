# Concept 融合实验第二轮

> 研究用途：只用仓库内公开的合成笔记，在内存中模拟，不读写正式知识库，也不接入在线提炼。设计依据见 [Claude 对首轮结果的评议](../../../docs/知识库与试题模块/讨论记录/2026-10-16_Concept融合实验结果评议_Claude.md) 第 3 节。

## 和首轮的区别

| 首轮的缺口 | 第二轮的做法 |
| --- | --- |
| 提示词点名了“矩阵、矩阵乘法、矩阵加法、逐元素乘法彼此不同” | 提示词只给通用规则，不点名任何具体概念（有测试保证） |
| 干扰项笔记的标题就是概念名 | 笔记标题和正文都不直接写概念名，例如只描述“X * Y 把同一位置的数相乘” |
| 每次发送全部概念和条目 | 目录 29 个概念，每篇只给“检索”返回的 8 个候选及其条目 |
| 正确概念总在候选里 | R07 故意把“矩阵乘法”藏起来，候选里留着点积、逐元素乘法等诱饵 |
| 没有同名异义 | R04：x.grad 不能挂到数学的“梯度”上 |
| 每篇只有一条知识 | R05 两条、R06 四条，允许一次返回多条，并逐条校验 |
| 不检查概念说明 | 新建概念的说明如果写进了条目内容，会被标出 |
| 只跑一次 | 同一设置重复 3 次 |

## 评分口径

每条预期知识按原文片段匹配模型给出的条目，结果分为：

- **正确**：挂到可接受的概念，或在应新建时新建；
- **污染**：挂到明确错误的已有概念。这是最严重的错误，因为不会被发现；
- **挂错**：挂到其他不合适的已有概念；
- **重复新建**：正确概念在候选里却新建了一个。安全，用户可以事后合并；
- **缺失**：模型没有提出这条知识。

R07 新建的概念如果和被藏起来的“矩阵乘法”同名，报告会标出，说明系统可以按名字提示用户合并。

评分是预设规则，存疑时以人工阅读为准。

## 运行

无费用测试：

    node --test scripts/test/concept-linking-r2.test.js

真实调用由 GitHub Actions 的 “Knowledge Concept linking round 2” 在合入 main 时运行一次（15 篇 × 3 次，加每次一轮整理建议，约 48 次 DeepSeek 调用；输出不是合法 JSON 时每篇最多再试一次），之后只能手动触发。报告会写进 Step Summary，并自动评论到 issue #163。

本地不调用模型：

    node scripts/experiments/concept-linking-r2/run.mjs --dry-run

## 用真实笔记在本机运行

`run-local.mjs` 从空知识库开始，按“章.节”把笔记切成多篇，逐篇处理；每篇的候选概念由简单字符检索从已建概念中选出前 8 个。它只读本地文件、只调用 DeepSeek，不写知境数据库。**不要在 Actions 里使用，也不要提交生成的报告。**

    node scripts/experiments/concept-linking-r2/run-local.mjs --notes 笔记.md --out 输出目录

API key 从名字含 DEEPSEEK 和 KEY 的环境变量读取，也可以用 `--key-env` 指定。

## 契约补充（2026-10-16）

- 每条链接新增 `possibleDuplicateOf`：新建概念时，模型怀疑它与某个候选是同一概念，就填那个候选的 id，交给用户决定是否合并。
- 概念说明的检查在“连续 6 字相同”之外，增加条件、计算、结论类措辞的规则（第二轮 R07 的说明换了说法，原规则漏掉）。

## 修复（2026-10-16，真实笔记实验后）

- 检索改为按“名称有多大比例出现在笔记中”打分，不再按重合字数；之前长名字会把“梯度”这类短名字挤出候选。
- 拒绝只引用标题、没有实质内容的条目。
- 每条链接新增 `sourceIssue`：模型认为原文有误时写在这里，陈述必须复述原文，不得改正或补充。
- 新增 R09：故意写错的 softmax 笔记，检验是否保留原话并标注存疑。
- 修正报告：同一篇里复用同名新概念的条目，不再被误标“说明含内容”。

## 粒度规则试行（2026-10-17）

- 提示词加入新建概念的三条标准：能独立命名且含义稳定；能承载多条独立知识；会和其他概念发生关系。满足第一条并满足后两条之一才新建，否则作为条目挂到它描述的概念上。
- 关系、比较不建概念；工具用法挂到所操作的对象或库上，不挂到整门语言；概念名不照抄小标题；同一主题不按参数拆概念。
- 新增 R10（工具用法）、R11（两个概念的关系）、R12（同一个词的比较）、R13（小标题不是概念名）、R14（内容充分、可以新建但不应拆细）。
- 评分新增“类型错误”“名称照抄标题”和 R14 新建概念数；每条链接只归给重合度最高的一段原文，避免共享代码片段的原文互相串号。
- 输出不是合法 JSON 时同一请求重试一次。
- 第一次运行（Actions 39005096794）：类型错误基本消失，但模型变得不愿新建概念，R04 的 x.grad 3/3 挂到了数学“梯度”上（此前为 0）。补充判断顺序：先判断是否同一概念，粒度标准不能作为挂靠理由。R10 改为挂 Python 或 PyTorch 都可接受（dir/help 是 Python 内置函数）。

## 粒度判断移到挂靠之后（2026-10-17）

对照实验表明，挂靠提示词里任何鼓励挂靠的粒度规则都会让 x.grad 挂到数学“梯度”上。因此：

- 挂靠提示词恢复为 10-16 对照版，只加一条“概念名不照抄小标题”。
- 挂靠完成后新增一步整理建议（`REVIEW_PROMPT`）：把新建概念连同条目和检索到的已有概念交给模型，按三条标准给出保留、降级到某概念或合并的建议。建议只展示给用户，不自动执行。
- 合成实验对 R04、R07、R10、R12、R13、R14 的建议评分：理想、可接受，或**有害**（错误的降级或合并，例如把 x.grad 降级到数学梯度）。
- `run-local.mjs` 的报告新增“整理建议”表。
- 补充：单独一条“概念名用规范术语、不照抄小标题”也会让 x.grad 3/3 挂到梯度上（x.grad 没有“规范术语”名，模型就不建了）。对照版本身没有照抄小标题的问题，所以挂靠提示词最终恢复为对照版原文。
- 整理建议新增 `split`：列出要移出去组成新概念的条目组（每组至少 2 条，原概念至少留 1 条）。新增 R15（张量与广播都被藏起来，检验能否建议把广播拆出去）；对 x.grad、矩阵乘法、原地运算提出拆分记为有害。

## 关系提议与知识网络图（2026-10-17）

- 新增 `relations.mjs`：挂靠和整理建议之后，把全部概念（名称、说明、条目标题与陈述，不含笔记原文）一次发给模型，提出 isA、partOf、prerequisiteOf、appliesTo、contrastsWith、relatedTo 六种关系。逐条校验；通过的一律为 `candidate`，有依据条目时 `sourceMode=note`，否则为 `ai`。不改动任何概念或条目。
- `run-local.mjs` 的完整流程最后会跑这一步；`run-relations.mjs` 可以给已有结果单独补跑（1 次调用）：

      node scripts/experiments/concept-linking-r2/run-relations.mjs --result 输出目录/result.json --out 新输出目录

- 生成的 `result.json` 可以在 APP 概念图页（`#/knowledge/graph`）用“导入实验结果”查看，只在页面内存中，不写知识库。
- 结果与问题见 [知识网络图第一版与实验改进](../../../docs/知识库与试题模块/讨论记录/2026-10-17_知识网络图第一版与实验改进_Claude.md)。
- 拆分修通（2026-10-17）：真实笔记里“张量”（16 条）的拆分建议整条被拒（“需要 1 至 4 组”）。现在逐组校验：不合格或与前面重叠的组单独丢弃，上限放宽到 6 组；被拒建议的模型原文写进报告和 result.json（`raw`），便于区分是模型问题还是校验过严。

## 只重跑整理建议（本机）

挂靠的粒度每次运行都会变（真实笔记里“张量”有时 16 条，有时直接拆成 8 个概念），检验拆分等建议时需要固定输入。`run-review.mjs` 读取已有的 `result.json`，挂靠结果原样保留，只重新请求整理建议，可重复 1 至 3 次对比稳定性；输出的 `result.json` 可直接导入概念图页面。只发送概念名、说明和条目，不发送笔记原文。

    node scripts/experiments/concept-linking-r2/run-review.mjs --result concept-out-6/result.json --out concept-out-6-review --repeats 3
- 拆分每组改为至少 1 条：固定输入重跑 3 次（concept-out-6），2 次建议拆分“张量”，但模型为满足“每组至少 2 条”把“拼接”和“广播”、“索引切片”和“原地运算”凑成一组，还把“全部元素求和”放进了“按元素运算”。提示词改为每组必须是同一个概念、组名不写“A 与 B”，单条机制也可成组。
